# ADR-0018 团子先行交付

- 状态：已接受
- 日期：2026-11-19
- 决策者：用户（交付顺序与安装授权）、总架构师（范围与协议）
- 修改：roadmap.md 的 M1 实现顺序；补充 ADR-0012、ADR-0015、ADR-0016

## 背景

原路线要求第一批底层模块（平台、图谱、连接、网关、动作）的设计全部评审闭环后，再按依赖顺序实现，团子要到 M1 末尾才出现。用户明确要求：

> 我是要先把团子做出来，给它弄好通知系统、交互系统、记忆系统这几个系统的接口，而且你完全可以分成多个角色去做这件事，产品定好形态，架构师定好架构，开发约定好协议，你就可以并行开发了

用户暂时不接飞书、Google 等数据源。用户已同意在本机安装 Rust 工具链及 Tauri 和前端 npm 包。

## 决策

1. **新增“团子先行版”交付（M1-P）**，排在数据源和模型之前。范围：
   - MOD-12 宠物客户端；
   - MOD-11 伙伴层子集：人格、状态机、本地台词模板、安静模式、轻度成长；
   - MOD-08 交互层子集：本地接口、本机令牌、事件推送；
   - MOD-09 记忆 v1：用户驱动的记住、修改、遗忘，以及伙伴日记；
   - 通知接收与投递（MOD-06 中 `notify` 的子集）；
   - MOD-01 最小平台：配置、数据目录、SQLite、macOS 凭证库、日志脱敏、审计追加。
2. **不在范围内**：数据源连接器、模型调用、提议执行、开机自启与进程监督、共享。界面中出现的这些入口必须明确显示“暂不可用”，不能假装完成（I5，contracts §5 的 M1 空实现规则）。
3. **按角色推进**：产品角色写形态规格 `design/tuanzi-v1-product.md`；总架构师写协议 `architecture/tuanzi-v1-protocol.md` 和 `src/contracts/` 代码；三个开发角色按目录所有权并行实现客户端、后台和记忆；总架构师逐条对照 invariants 做代码评审和联调，结论写入 `reviews/`。产品规格加协议即为本切片的详细设计。之后 MOD-08/09/11/12 的完整模块设计要吸收这些内容，不能另起一套。
4. **契约只做可加性扩展**：新增可选字段、事件类型和接口在 contracts 变更记录登记；不删除、不改名、不改变既有语义。
5. **平台**：先在 macOS 实测。Windows 代码路径只能出现在 MOD-01 适配层和 MOD-12 平台层（I28），尚未实现的功能明确返回不支持；凭证库不能降级为明文。Windows 实测仍需用户另行安排。
6. **第一批模块的状态不变**：MOD-01/02/03/05/07 的公共问题、MOD-01 独立修订复评仍未闭环。先行版只实现本切片需要的最小平台能力，不代表 MOD-01 已批准。

## 影响

- 团子可以先在桌面上运行，通知、交互和记忆接口先稳定下来；之后数据源和能力接入时，只需调用 `notify`、`MemoryReader/Writer` 和伙伴服务。
- 多了一次“先行版代码 → 完整模块设计”的收敛工作。完整设计如需修改先行版接口，必须走契约变更规则，不能悄悄重写。
- 先行版验收看实际体验（产品规格中的体验清单）。生产力验收门槛（acceptance.md 的 M2 实测）保持不变，不能用先行版的可玩性代替。
