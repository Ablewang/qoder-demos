# ADR-0016 团子伙伴与技术自评

- 状态：已接受
- 日期：2026-11-19
- 决策者：用户（产品与授权边界）、总架构师（设计细化）
- 补充：ADR-0001、ADR-0012、ADR-0014、ADR-0015

## 背景

用户选择“团子”，要求能趴在窗口边冒气泡、自己玩耍、自己听歌。用户家中有 Windows 电脑。用户授权总架构师自行技术评审，强调“足够好玩好用”“足够的扩展性”以及“真的能帮助我们提升生产力”。

## 决策

1. 默认形象采用 B 的扁平团子方向；名字与人格由用户定义。窗口边停靠、鼠标互动、玩耍和听歌是产品功能，不是可有可无的宣传效果。
2. 自主活动限于本机表现：玩小道具、戴耳机听歌、打盹、伸懒腰；不依赖模型逐帧决策，也不会自行发送工作消息、打开应用、修改文件或读取屏幕内容。
3. 听歌默认是静音动作。真实播放仅在用户主动启用后，从安装包内有许可的素材或用户选择的音频播放；可随时暂停和静音。不默认读取音乐目录、控制第三方播放器、订阅服务或启用麦克风。
4. 安静模式、用户拖动、重要工作事项优先于自娱。音乐、活动频率、固定位置由用户控制；养成不锁办公功能，不惩罚，也不靠多发提醒和多记信息刷成长。
5. MOD-12 只处理窗口几何、焦点和权限等平台信号，不能为停靠而截图/OCR。窗口关闭、移动、跨屏时需安全重定位；不可检测时使用固定桌边停靠并明确能力状态。
6. 技术评审和架构冻结由主会话总架构师承担，必须记录证据、问题、修正和未验证项。模块仍需先详细设计、再评审、后实现。用户只需判断实际体验和工作结果，不需阅读技术稿。
7. 技术自评不授权连接数据、运行第三方插件、访问家中 Windows 电脑或代用户执行工作动作。Windows 环境可用，但安装和实测仍待进行。
8. 可玩性与生产力各有验收门槛；不能用动画数量、在线天数或模型调用量代替实际省时。细则见 `design/companion-experience.md` 和 `architecture/acceptance.md`。

## 影响

- Q10、Q11、Q12 关闭。
- 伙伴服务与皮肤契约增加可扩展的自主活动表达；不把每一种皮肤动作加入办公状态枚举。
- 窗口停靠、点击穿透、共享屏幕检测、资源占用须在两个平台做前置验证；Tauri 2 是选择，不是能力已验证的结论。
