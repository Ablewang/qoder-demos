# ADR-0008 以个人为中心，支持有选择地共享

- 状态：已接受
- 日期：2026-11-18
- 决策者：用户
- 关闭问题：Q2
- 补充：ADR-0002

## 背景

用户原话：“目前我自己用，但我个人认为它的设计应该是要面向个人，但是也支持共享一些资源，这样能把多个人连起来。”

## 备选方案

| 方案 | 说明 | 结论 |
|---|---|---|
| 中心化多租户服务 | 所有人的数据和凭证放在一个服务里 | 不采用：和本机运行、数据留本机冲突，合规风险大 |
| 纯单机 | 不考虑任何共享 | 不采用：以后要接入共享就得改底层 |
| **个人节点加可选的共享空间** | 每人运行自己的 agent（个人节点），凭证和原始数据留在本人机器上；需要时把选定资源发布到共享空间，或者给别人的 agent 发请求 | 采用 |

## 决策

1. 每个人运行一个个人节点。凭证永远不离开本人节点。
2. 从第一天起，底层就为共享留好位置：
   - **全局人员标识**：以公司邮箱为锚点（`person:<小写邮箱>`），不同节点可以对上同一个人；
   - **每个实体都带归属与可见范围**：`owner` 和 `visibility`，默认 `private`；
   - **共享只能显式发布**：发布本身是一种对外写入的动作，按 ADR-0007 由用户决定；
   - **别人的请求到我这里，一律变成我的提议**：由我决定，不会自动执行。
3. 共享空间的实现方式（自建服务还是复用飞书多维表格或文档、通信协议是什么）放到里程碑 M4 再定，届时另写 ADR。

## 影响

- 第一阶段只做个人节点，但实体模型、存储主键、审计、提议来源这些地方都要带上 owner、visibility 和来源字段。
- ADR-0002（本机运行）对个人节点继续有效；共享空间是附加的，不改变“凭证和原始数据留在本机”。
