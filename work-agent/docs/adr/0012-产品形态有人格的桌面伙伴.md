# ADR-0012 产品形态：有人格、有记忆、会成长的桌面伙伴

- 状态：部分已接受（用户提出的需求已接受；标“提议”的条目随总体架构一起评审）
- 日期：2026-11-18
- 决策者：用户（需求）、总架构师（提议部分）
- 关联问题：Q7、Q8、Q9、Q10

## 背景

用户原话：“我感觉这个宠物能有培养系统，能跟鼠标交互，有自己的性格，性格是可以指定的，可以被取名字定义口头禅之类的，就跟之前的 openclaw 一样。它有自己的记忆，能记住日常工作中的很多重要信息。”

参考 OpenClaw：

- 人格写在 `SOUL.md`；
- 记忆是人能读、能改的 Markdown 文件，分为用户画像 `USER.md`、长期记忆 `MEMORY.md`、每日笔记 `memory/YYYY-MM-DD.md`；
- 后台的“做梦”任务把每日笔记里值得长期保留的内容整理进长期记忆，整理结果写进 `DREAMS.md` 供人检查；
- 来源不可信的内容不会被整理进长期记忆。

来源：<https://docs.openclaw.ai/concepts/memory>、<https://docs.openclaw.ai/reference/templates/SOUL>

## 决策

### 已接受（用户需求）

1. **产品定位是“陪伴宠物，能协助日常办公”**（用户原话）。产品本身就是这只宠物，协助办公是它的本领。桌面宠物是主界面，Web 控制台和飞书是辅助通道。
2. **人格可以指定**：名字、性格、口头禅、说话风格都由用户设定，也能随时修改。
3. **能和鼠标交互**：可以拖动、点击、悬停，会对鼠标做出反应。
4. **有培养系统**，两部分都要（用户对 Q8 的答复：“1、2 都需要”）：
   - **真实成长**：见识（接入的数据源）、记性（记住的事）、默契（提议被采纳的比例）、陪伴（一起工作的天数）；
   - **轻度养成**：喂食、摸头、心情等互动。
   - 成长后解锁新动作和皮肤，台词也更懂用户。**养成不能锁住功能、不能惩罚用户**：不会饿死，不会闹脾气不干活（约束 I17）。
5. **有自己的记忆**：能记住日常工作里的重要信息（人、项目、决定、承诺、偏好），并在后续工作中用上。

### 提议（总架构师）

6. **宠物只是界面，大脑在后台常驻进程里**：宠物客户端（MOD-12）只负责显示和交互，通过本地接口连到 `work-agentd`。人格、成长、记忆、能力都在后台进程里。这样宠物没打开时，飞书通知和定时任务照常运行；以后换形象或换技术也不影响大脑。
7. **新增伙伴模块（MOD-11）**，负责：
   - 人格档案；
   - 成长状态；
   - 把系统状态映射成宠物的状态和动作；
   - 用人格的口吻生成台词。
8. **人格只影响伙伴自己怎么说话**：
   - 不改变事实信息：数字、人名、时间、链接由结构化字段直接渲染，不经过人格改写；
   - 不影响以用户名义起草的内容：草稿用用户自己的口吻；
   - 不能放宽任何策略：人格不能让它更“自作主张”。
9. **在开会、共享屏幕、全屏演示时自动安静**：根据日历和系统状态判断，宠物收起或只显示一个小角标，不冒气泡。
10. **记忆提前到 M2 实现，作为底座的一部分**。记忆的存储格式见 ADR-0013。

## 影响

- 新增模块 MOD-11（伙伴）和 MOD-12（宠物客户端），交互层要提供事件推送通道。
- 宠物是独立进程，会调用本地接口，所以本地接口不能只靠 Origin 校验，必须有本机令牌认证（见 invariants I18）。
- 演进路线调整：M1 就带一个最简单的宠物；记忆和对话放在 M2；成长和记忆整理放在 M3。
