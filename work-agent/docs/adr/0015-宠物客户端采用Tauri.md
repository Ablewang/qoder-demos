# ADR-0015 宠物客户端采用 Tauri 2

- 状态：提议（用户不熟悉这几种技术，由总架构师给出决定，随架构一起评审）
- 日期：2026-11-18
- 提议者：总架构师
- 关闭问题：Q9

## 背景

宠物要一直开着，要能做透明置顶窗口、点击穿透、跟随鼠标、播放动画，而且要同时支持 macOS 和 Windows（ADR-0014）。

## 备选方案

| 方案 | 跨平台 | 常驻资源占用 | 和主体技术栈一致 | 结论 |
|---|---|---|---|---|
| 原生 Swift | 只支持 macOS | 最低 | 否 | 不满足跨平台要求，排除 |
| Electron | 支持 | 高（自带 Chromium，常驻上百 MB） | 是（全部 TS） | 一直开着的宠物负担太重，排除 |
| **Tauri 2** | 支持 | 低（用系统自带的 WebView：macOS 是 WKWebView，Windows 是 WebView2） | 界面用 TS 和 Web 技术；只有平台层用少量 Rust | **采用** |

## 决策

1. 宠物客户端（MOD-12）用 Tauri 2：
   - 界面层：TS 加 Web 技术，负责动画、气泡、聊天面板；
   - 平台层：Rust，负责窗口、点击穿透、置顶、检测共享屏幕和全屏、开机自启。
2. 动画技术由 Q10（形象和画风）决定：逐帧精灵图用 Canvas 或 CSS；骨骼动画用对应运行时的 Web 版本。
3. 宠物客户端只能通过本地接口和后台进程通信（约束 I24），不能直接读数据库或记忆文件。

## 影响

- 开发环境要装 Rust 工具链；Windows 打包需要 WebView2（Windows 10/11 一般已经自带）。
- 两个平台的 WebView 渲染有细微差别，要在两个平台上分别做视觉验证。
- “按像素判断哪里能点、哪里穿透”要在平台层实现，是 MOD-12 设计的重点难点。
