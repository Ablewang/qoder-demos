# ADR-0022 记忆类型修改保留原条目

- 状态：已接受，待实现验证
- 日期：2026-11-19
- 决策者：总架构师（用户已授权技术自评）
- 取代：先行版 POST /memory/:id/retype 的先遗忘再创建语义

## 背景

HTTP 先 forget 再 remember，第二步失败会丢失原条目，并且丢弃 about。类型与存储层是独立字段；已有 MemoryWriter 允许 profile 中的 fact 和 long_term 中的 rule，不必为修改类型搬文件。

## 决策

1. 修改类型保留 id、layer、file、正文、createdAt、about、敏感度与有效期，只原位替换同一条 Markdown 标记。不再制造遗忘墓碑，不产生 forgotten/created 事件，发布 updated。
2. MemoryBrowser 增加 retype(id, kind, by, evidenceId)，仅本人且当前证据通过 local_edit 校验才能调用；仅接受 rule/fact，日记不允许改类型。升级为 rule 时 origin 改为本次已认证 user:local_edit；降为 fact 保留既有完整 origin。同类型请求不重写条目。
3. 所有校验在写入前完成，使用模块已有同步、冲突检查、单文件原子替换与索引/来源账本事务。失败不能先删除正文；不宣称文件系统与 SQLite 跨介质严格原子或历史快照可恢复。
4. HTTP 不再编排 forget/remember。客户端及撤销始终使用返回 id，允许该 id 与原 id 相同；修改类型不自动切换存储页。

## 验证门槛

- fact/rule 双向修改保持上述字段，只有规则升级建立新用户证据，索引与来源账本一致。
- 无效证据、日记、非法类型以及文件冲突/替换失败均不能删除原正文；无遗忘墓碑或遗忘事件。
- 已认证 REST 与真实无头客户端完成修改后仍可查看并撤销；没有实际 Keychain 或可见桌面访问。

## 影响

原来依赖新 id 或自动搬到另一页的调用方更新为原位编辑。产品仍显示规则/事实类型；用户需要搬存储层时，先行版不提供该功能。该裁决只覆盖先行本地接口，不批准第一批完整平台模块。
