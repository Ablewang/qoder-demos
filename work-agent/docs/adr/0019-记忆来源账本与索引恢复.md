# ADR-0019 记忆来源账本与索引恢复

- 状态：已接受（总架构师技术评审；实现与故障验收待完成）
- 日期：2026-11-19
- 决策者：总架构师（用户已授权技术自评）
- 取代：ADR-0013 中“SQLite 只做索引”的存储边界；补充 ADR-0017 的 I32/I33、ADR-0018

## 背景

先行版记忆首轮代码评审重现 Q14：清空 mem_fts、mem_items、mem_files 后，Markdown 的简化来源无法恢复 evidence/about；短期证据失效后已认证规则也不能恢复。接受自报用户标记会放松 I13/I33，因此不是可用的修复。

## 决策

1. Markdown 继续是正文、类型、敏感度和有效期的权威文件；不把记忆正文放进另一份业务账本。SQLite 中区分可重建索引与持久安全元数据：
   - 可重建：mem_items、mem_fts、mem_files。
   - 不可丢弃：mem_tombstones，以及新增 mem_provenance。
2. mem_provenance 由记忆模块独占维护，存 id、layer、kind、完整 origin、about、归一化文本哈希和 file，不存正文。该表记录已实际接纳的条目，rule 记录只有真实证据通过后才能建立；不是客户端能提交的“已验证”布尔值。
3. 重建索引时，文件的来源标记与账本一致才恢复完整依据和 about；规则必须匹配既有已认证规则账本，或通过当前有效用户证据。只看 Markdown 的 kind=rule/user 标记不算批准。手写无标记行仍只成为事实。
4. 清空可重建索引后，仍用账本判断手改、删行和整文件删除；删除写入已有文本哈希的墓碑并删除对应来源元数据。未修改的重复用户条目不能因重建而清掉另一条遗忘墓碑。
5. 普通写入与来源账本、索引、墓碑在同一 SQLite 事务里更新；现有原子文件替换和手改冲突保护不变。增加后续迁移版本，不改写已执行迁移。旧版本已有合法 mem_items 可在升级事务中补来源账本。
6. “索引可删除后重建”仅指三张可重建表，不能删除整个数据库或安全账本。整个数据库/账本丢失、损坏或历史恢复不在先行版自动恢复保证内；缺少来源或用户批准证据时报告 issue，不静默捏造空依据或接受规则。不得借恢复旧数据库绕过遗忘墓碑。
7. 完整历史快照恢复及跨进程维护仍须后续平台/记忆设计；本决定不授权读取系统备份、真实公司数据或新增凭证，也不放宽 I7。

## 影响与验收

- 公共 MemoryReader/Writer/Browser 和 REST 接口不变；这次修订是持久格式与重建语义裁决。
- Q14 仅在实现及故障测试通过后关闭：完整清空三张索引、短期证据失效、规则/完整来源/about 恢复；重建后删行/整文件产生墓碑；重复用户条目不清墓碑；缺账本规则和外部依据无法恢复时明确 issue。
- 必须准确告知：Markdown 可以编辑，但不能只拷贝正文文件就宣称复制了全部来源、安全证据及遗忘状态。该限制不影响正常本机记住、修改、删除和搜索。
