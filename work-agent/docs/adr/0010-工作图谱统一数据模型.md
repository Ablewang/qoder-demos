# ADR-0010 工作图谱作为统一数据模型

- 状态：提议（随总体架构一起评审）
- 日期：2026-11-18
- 提议者：总架构师

## 背景

POC 用一张扁平的“事项”表，带来三个问题：

- 回答不了“谁在等我”“这个 MR 和哪次会议、哪封邮件有关”这类跨数据源的问题；
- 无法识别同一个人在飞书、邮箱、GitLab 上是同一人；
- 无法表达共享所需的归属和可见范围。

## 备选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| 各连接器各存一套原始结构 | 实现快 | 能力层要逐个数据源适配；无法跨源关联 |
| 只存原始结构，查询时由模型理解 | 灵活 | 慢、贵、结果不稳定，没法做确定性统计 |
| **统一实体 + 关系（工作图谱），原始结构作为附属** | 能力层只认一套模型，可以跨源关联、做确定性统计 | 前期要设计好实体类型；连接器要做字段映射 |

## 决策

采用工作图谱：

- 实体有类型和版本化的属性结构；
- 实体之间是有类型的关系；
- 人员通过身份解析合并成同一人；
- 每个实体都带 owner、visibility、sensitivity、来源信息；
- 实体正文单独存储，可以缺省。

存储用 SQLite，主键是 `(owner, id)`；全文检索用 FTS5 的 trigram 分词（已在本机 Node 24 / SQLite 3.53.4 上验证中文可用）。

## 影响

- 实体类型和属性结构的不兼容变更需要 ADR；新增类型或可选字段不需要。
- 连接器负责把原始数据映射成标准实体；能力层不能读连接器的原始结构。
