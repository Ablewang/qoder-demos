# ADR-0009 连接器采用 MCP

- 状态：已接受
- 日期：2026-11-18
- 决策者：用户
- 关闭问题：Q3

## 背景

用户同意以 MCP 作为连接器标准。MCP 当前版本是 2026-07-28，和本项目相关的变化有：

- 去掉了握手和会话，每个请求自带协议版本和客户端信息；跨调用的状态通过参数里的显式句柄传递。
- 服务端需要向用户要输入时，改用“多轮请求”（MRTR）：服务端返回 `resultType: "input_required"`，客户端补上 `inputResponses` 后重新调用。
- 有了正式的扩展机制；长任务（Tasks）成为扩展 `io.modelcontextprotocol/tasks`。
- Roots、Sampling、Logging 已废弃，新实现不应再用。
- 授权方面：校验 `iss`（RFC 9207）；DCR 已废弃，改用 CIMD。

参考：<https://modelcontextprotocol.io/specification/2026-07-28>、<https://blog.modelcontextprotocol.io/posts/2026-07-28/>

## 决策

1. **每个数据源都是一个 MCP 服务器**。自研连接器（飞书、Gmail、GitLab）按 MCP 实现，目标协议版本是 2026-07-28。
2. **agent 内核是 MCP 客户端**（连接器宿主）。它可以同时挂自研连接器和第三方 MCP 服务器。
3. 在 MCP 之上定义本项目的**连接器扩展** `work-agent/connector`（版本 1），包括：
   - 连接器清单资源；
   - 增量同步工具 `wa_sync_pull`（游标放在参数里传递，正好符合无会话的设计）；
   - 写工具的预演约定；
   - 统一错误码。
   详见 `architecture/contracts.md` 第 3 节。
4. **授权由宿主统一管理**：自研连接器不持有凭证，宿主每次调用时通过 `_meta` 传入短期访问令牌；连接器发现权限不足时返回 `auth_required` 错误，由宿主发起授权（实现 ADR-0007 第 3 条）。
5. **连接器不调用模型**（Sampling 已废弃，而且模型调用必须经过模型网关，见 ADR-0003）。
6. 第三方 MCP 服务器只作为“工具型连接器”（不参与同步）。它们的工具默认按写工具对待，用户在设置里确认之后才能当只读工具用。
7. 自研连接器支持两种运行方式：作为子进程用 stdio 通信，或在开发和测试时直接在同一进程内运行。两种方式走的是同一套 MCP 协议。

## 影响

- 依赖 MCP 官方 TypeScript SDK（需支持 2026-07-28）。
- 自研连接器可以被其他 agent（例如 Qoder）直接复用。
- 同步语义（游标、删除、窗口）不在 MCP 标准里，靠我们的扩展约定保证；第三方服务器无法参与同步。
