# ADR-0014 跨平台：macOS 与 Windows

- 状态：已接受（需求）；具体做法为提议，随架构一起评审
- 日期：2026-11-18
- 决策者：用户（需求）、总架构师（做法）
- 补充：ADR-0002；影响：ADR-0006、ADR-0011

## 背景

用户要求：“我想要兼容 macOS 和 windows”。之前的设计里有三处只适用于 macOS：

- 凭证存在 macOS 钥匙串，通过 `security` 命令读写；
- 后台进程由 launchd 托管；
- 数据目录、检测共享屏幕和全屏的方式也是按 macOS 写的。

## 决策

1. **个人节点（后台进程加宠物）要同时支持 macOS 和 Windows**。Linux 不承诺支持，但不刻意排除。
2. **平台相关的代码只能出现在两个地方**：
   - 后台进程：MOD-01 平台基础里的“平台适配”子模块；
   - 宠物客户端：MOD-12 的平台层（Tauri 的 Rust 部分）。
   其他模块不能出现 `process.platform` 这类判断（约束 I28）。
3. **各项的跨平台做法（提议）**：

   | 方面 | macOS | Windows | 统一方式 |
   |---|---|---|---|
   | 凭证 | 钥匙串 | 凭据管理器 | 凭证库接口加跨平台 keyring 库（候选 `@napi-rs/keyring`，由 MOD-01 验证） |
   | 后台进程自启 | launchd 用户级 LaunchAgent | 当前用户的登录启动项（计划任务或注册表 Run 项，由 MOD-01 选定） | 平台适配提供安装、卸载、状态查询 |
   | 数据目录 | `~/Library/Application Support/work-agent` | `%APPDATA%\work-agent` | 由配置模块统一给出，开发时仍可以用项目内的 `data/` |
   | 运行时分发 | 把 Node 运行时随安装包一起打包（作为 Tauri 附带进程，或用 Node 单文件可执行），用户不用自己装 Node | 同左 | 打包方式由 MOD-01 和 MOD-12 共同设计 |
   | 宠物窗口（透明、置顶、点击穿透、跟随鼠标） | Tauri 2 | Tauri 2 | 由 MOD-12 的平台层封装 |
   | 检测共享屏幕和全屏（安静模式） | 系统接口 | 系统接口 | 由 MOD-12 的平台层检测，再通过 `setQuiet` 上报给后台进程 |
   | OAuth 回调 | 回环地址 127.0.0.1 | 同左 | 不变 |

4. 开发阶段仍然可以直接在 Mac 上用 `node src/...` 运行。

## 影响

- ADR-0006：凭证不再固定用 `security` 命令，改成凭证库接口加跨平台实现（这样也顺带解决了凭证短暂出现在进程参数里的问题）。
- ADR-0011：launchd 改成“由平台适配负责开机自启”。
- 验收时要在 Windows 上做冒烟验证：启动、授权、同步、宠物显示和交互。需要一台 Windows 机器（见 open-questions Q11）。
