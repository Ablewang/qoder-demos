# ADR-0017 架构基线评审修正

- 状态：已接受（总架构师依 ADR-0016 技术自评授权）
- 日期：2026-11-19
- 决策者：总架构师
- 补充或取代范围：ADR-0006 凭证降级做法、ADR-0009 同步与工具信任语义、ADR-0010 图谱读取边界、ADR-0011 Windows 托管语义、ADR-0013 来源与遗忘语义、ADR-0014 平台检测保证；不修改用户决策目标

## 背景

两份独立完整阅读评审发现相同的冻结阻塞：批准后的提议可变、分页窗口缺少完成边界、外部写入结果不明时无安全恢复、记忆和工具输出可能绕过模型过滤、并行模块缺公共接口、扩展与 M2 对话契约不完整。原草案不可直接作为实施基线。

## 决策

1. 决定绑定提议版本与最终参数哈希；批准后的内容冻结。暂停授权后重新检查策略和源系统当前前置条件；授权请求绑定执行步骤、账号和决定，OAuth 不等于批准业务动作。
2. 执行步骤先持久化尝试，再外呼，再持久化结果与审计。结果不明进入核验状态；已成功步骤不重放，不保证幂等且不可核验的写入不得自动重试。幂等是数据源能力，不承诺通用 exactly-once。
3. 窗口分页按持久化快照累计，只有全部分页成功才对账删除；只删除所属 source/stream/owner/window 的对象。幂等要求重复应用安全，不要求持续变化的上游返回字节完全相同。
4. 实体、只读工具结果、记忆及派生数据均保留宿主生成的来源与敏感度；模型与通知在最后出口统一检查。敏感度只能保持或提升，降级必须用户明确决定；规则记忆需要可核验的用户消息或决定，而非调用者自报来源。
5. 本机通知、飞书通知分开授权披露；自动回退不跨越用户的渠道设置。台词、标题、facts 与正文一并过滤。记忆遗忘产生无正文墓碑，防止整理从历史来源重新生成已忘内容；用户主动重新记住可解除对应墓碑。
6. 冻结共享的迁移、事务、审计、事件、授权、图谱分页、工具输出、提议、记忆、对话契约。框架实现属于对应模块，不允许每个并行会话各自创造公共类型。
7. 扩展通过命名空间和版本化登记：实体Schema、授权Provider、能力、报告Renderer、纯素材皮肤。新类型仍需总架构师批准，不承诺未知语义任意接入。v1 代码扩展是受信本机代码；stdio MCP 不等于沙箱，安装授权与工具读写授权分离。
8. 安静模式使用多原因集合，不以单一信号覆盖用户勿扰；未知检测不当作“未共享”。只有已验证的平台能力承诺自动识别，始终提供显式演示模式。窗口内容不采集。
9. Windows 用用户级计划任务验证登录启动、崩溃恢复、重复实例和重启退避；简单 Run 项不作为守护进程监督器。开机自启须用户启用。凭证适配失败不得降级到明文或含密钥的进程参数。
10. M1 提供有生命感的团子与真实数据报告，M2 必须有可测的任务闭环；对话工具规划和记忆编辑前移 M2。审批空实现必须明确拒绝，不得假成功。原“日历工时占比”改为计划会议负荷，不能冒充真实工时。

## 技术状态裁决

- 接受 ADR-0006 的 TS/Node 24、SQLite、JSON Schema 校验方向，原生凭证库候选仍须打包实测；不用平台命令的泄密降级。
- 接受 ADR-0010 图谱方向、ADR-0011 双进程方向、ADR-0012 伙伴层职责、ADR-0013 透明记忆方向、ADR-0014 跨平台适配边界和 ADR-0015 Tauri 2 选择，以本文和修正后的契约为准。
- MCP 2026-07-28 已从官方 versioning 页核验为 current；已核验 npm 官方 SDK 当前发布 1.32.2，但具体 stdio/discover/元数据互操作仍是 MOD-03 的实施前验证门槛，不凭版本号宣称已兼容。
- 技术批准不是功能验收；外部权限、SDK 互操作、原生窗口、系统凭证与安装包仍须实测。
