## 1. 目标与范围

### 1.1 目标

为 macOS、Windows 上的团子办公伙伴提供可恢复、可审计、无凭证明文降级的本机底座。宠物退出不停止大脑；用户未启用登录自启时不得自动注册托管。底座失败必须显式不可用，不能假装仍在同步、记事或执行。可靠恢复与低后台消耗服务于真正省时，不以运行天数、审计数量或模型调用量冒充生产力。

本模块负责：

1. `StorageService`、同步 `Tx`、模块迁移登记、历史校验和、SQLite 备份与维护恢复。
2. `platform_` 和中央 `audit_` 数据所有权；实现 `AuditWriter`，为业务状态、审计和 outbox 的原子提交提供同一数据库事务。
3. `SecretStore` 的系统凭证库适配；非敏感配置、数据目录和结构化脱敏日志。
4. 单实例、后台启动/停止、登录自启、异常退出监督、退避和附带 Node 运行时分发。
5. I23/I24/I28 的依赖检查规则与双平台实施前探针。

### 1.2 不做什么

- 不实现授权流程、刷新令牌策略、连接器协议、能力调度、提议执行器或模型网关。
- 不拥有事件 outbox、订阅检查点、领域状态机；它们归 MOD-06 的 `rt_` 表。
- 不提供业务 HTTP 路由、Cookie/CSRF、一次性控制台登录码；它们归 MOD-08。
- 不采集窗口内容、屏幕、键盘、鼠标轨迹，不枚举窗口；窗口几何和系统安静信号只在 MOD-12 平台层。
- 不编辑人格和记忆源文件，不决定记忆遗忘规则；平台备份不等于记忆服务。
- 不增加远程遥测、云备份、任意脚本插件、安全沙箱或远程代码热加载。
- 本次不执行任何实现、安装、登录授权、自启注册、配置或权限修改，也不访问 Windows 设备。

## 2. 对外接口

### 2.1 冻结接口与注入边界

仅实现或消费 `architecture/contracts.md` 已定义类型，不创建第二套平台公共类型。

| 接口 | 本模块语义 | 消费方/边界 |
|---|---|---|
| `StorageService.registerMigrations(moduleId, tablePrefixes, migrations): void` | 只登记和校验内存清单，不执行异步备份或立即迁移；仅启动登记期可调用 | 受信模块由启动组合根显式登记；前缀与 overview 所有权一致 |
| `StorageService.transaction<T>(work: (tx: Tx) => T): T` | 同步提交；回调返回即结束，不允许 Promise、网络等待、逃逸或嵌套事务 | 持久化模块；能力只拿能力上下文，不直接拿平台存储 |
| `Tx.run/get/all` | 同一连接的同步参数化 SQL；返回值严格落在 `SqlValue` 和契约返回形状内 | `Tx` 非沙箱，跨模块写入仍走相应服务 |
| `Migration { version, checksum, apply(tx): void }` | 每模块严格递增历史、固定校验和、同步数据库变更 | 不增加异步迁移或跨模块依赖字段 |
| `AuditWriter.append(record: AuditRecord, tx?: Tx): void` | 仅追加；传 Tx 时加入原事务，不传则单独提交 | MOD-03/05/07/08/09/11 等按业务需求追加；不直接写 `audit_` |
| `SecretStore.get/set/delete` | 系统凭证库；只有真正不存在才返回 undefined/删除无操作，其他失败抛错 | 仅授权代理、网关供应商认证、本机服务认证；不注入普通能力、皮肤 |
| `Logger.info/warn/error` | 事件名与受控字段，不序列化任意输入或 Error | 绑定模块名的日志实例 |
| `KeyValueStore.get/set/delete` | 平台内部非敏感设置使用；接口实现可复用原则，实例必须绑定命名空间 | 能力 state 的持久化属于 MOD-06 `rt_`，不能借平台 KV 越过表所有权 |
| `EventBus.publish(e, tx?)` | 本模块不实现；验证 MOD-06 能在本数据库 Tx 内写其 outbox | 不向模块暴露数据库文件或第二条写连接 |

同步接口不添加 `async`、`commit`、`close`、`begin`、`exec`、`database` 或新增事务属性。数据库生命周期、异步备份和迁移编排是 MOD-01 启动/维护内部流程，不挂在 `StorageService` 上。

### 2.2 服务装配

- 单个 `work-agentd` 的组合根创建一份底层数据库连接和服务实例，再按模块绑定日志、登记资格、私有设置命名空间与凭证键范围。
- 绑定后的视图仍是同一个冻结接口；调用者不自行填写身份来扩大权限。所有权映射来自受信组合根，不来自连接器/模型清单。
- 模块接收接口，不导入 `src/platform/` 实现。底层连接、已编译语句和事务活动状态均为平台内部对象。
- `Tx` 的内部身份用 WeakMap 识别：所属存储实例、事务代次、活动/rollback-only/结束状态和首个失败；没有公开状态属性。受信组合根为同 Tx 服务装配同步调用边界，服务验证及 SQL 的抛错均先污染关联事务再传播；即使业务捕获错误也不能恢复可提交状态。
- 同 Tx 服务的失败边界和临时权限上下文切换由平台内部闭包装配，模块仍只拿冻结服务接口，不拿连接、WeakMap 或失败回调。MOD-06 等跨模块装配资格与覆盖范围须在 P04/G07 闭环；未闭环不开放该接入，不能仅靠调用方约定不捕获异常。
- 凭证命名、配置读取、生命周期控制、备份控制和审核日志读取尚缺跨模块契约；只在 §8 提需求，批准前不实现临时平台直连入口。

## 3. 数据模型

### 3.1 表和文件所有权

同一 `work-agent.db` 容纳全部模块表；文件物理所有权属于平台，行和 Schema 的业务所有权仍按模块前缀划分。表名、索引、视图、触发器与 FTS 辅助表都遵守所属前缀。

| 本模块表 | 主要字段与约束 | 用途 |
|---|---|---|
| `platform_metadata` | `key TEXT PRIMARY KEY`、`value_json TEXT NOT NULL`；格式版本受校验 | 实例 id、存储格式版本、恢复代次等非敏感平台元数据 |
| `platform_module_registry` | `module_id TEXT PRIMARY KEY`、`prefixes_json TEXT`、登记格式版本 | 记录前缀所有权；启动和历史登记对比，不由模块任意改写 |
| `platform_migrations` | 联合主键 `(module_id, version)`；`version INTEGER > 0`、`checksum TEXT`、`applied_at INTEGER`、`app_version TEXT` | 仅成功迁移记录；不可改历史版本/校验和，不用全局 user_version 代替模块版本 |
| `platform_settings` | `namespace/key` 联合主键、`schema_version INTEGER`、`value_json TEXT`、`updated_at INTEGER` | 平台内部非敏感配置；不得保存 token、secret、PKCE verifier 或工作正文 |
| `platform_backup_catalog` | `id`、`created_at`、`relative_path`、`manifest_sha256`、`scope`、`status` | 本机备份索引；磁盘清单是备份验证依据，数据库目录不能自证有效 |
| `platform_restore_history` | `restore_id` 主键、`at`、`from_backup_id`、`previous_epoch`、`new_epoch`、`status` | 可恢复维护状态；不含密钥，不覆盖审计历史 |
| `audit_records` | `seq INTEGER PRIMARY KEY`；`id TEXT UNIQUE NOT NULL`；`at INTEGER`、`actor_json`、`kind`、`refs_json`、`summary`、`outcome`、`detail_json?`、`record_sha256` | 中央追加审计；kind/outcome 完全沿用 `AuditRecord`，seq/hash 只是内部列 |

补充约束：

- UTC 毫秒只用 INTEGER 存储；顺序使用数据库序号而非墙钟时间，防时钟回拨造成错误排序。
- JSON 仅支持明确可序列化值；不将 undefined、函数、循环引用或 bigint 偷换为字符串。KV 的缺失返回 undefined，合法 JSON null 与缺失不同。
- `audit_` 不对 `act_`、`auth_`、`graph_` 建级联删除外键，业务对象消失后审计仍保留无正文引用。
- `platform_` 不保存 outbox，也不记录产品采纳率、成长或省时计数；可清除统计由相应业务模块拥有。
- 审计保留无正文引用仍可能含人员/项目标识，按私有敏感数据保护，不当作可共享分析表。

### 3.2 数据目录

| 场景 | 根目录 | 要求 |
|---|---|---|
| macOS 发布 | `~/Library/Application Support/work-agent` | 通过当前用户系统路径解析，不拼接用户输入或依赖安装位置 |
| Windows 发布 | `%APPDATA%\work-agent` | 通过系统已知目录解析当前用户 Roaming AppData；不依赖 shell 展开或硬编码盘符 |
| 开发 | 项目内 `data/` | 仅显式开发模式；不得因发布路径失败退到工作目录；凭证键与发布实例分离 |

根目录下布局：

```text
work-agent.db                  平台管理的数据库容器
work-agent.db-wal / -shm        SQLite 管理，不能人工删除
runtime/instance.lock          内核锁的稳定文件，不用文件存在性当锁
runtime/lifecycle.json         无凭证的启动退避/停机/恢复门闩
logs/platform-*.jsonl          脱敏后日志与轮转文件
backups/<backup-id>/           平台备份容器、数据库副本与清单
companion/                     MOD-09/MOD-11 所有，平台不直接编辑
```

- runtime、logs、backups 为 MOD-01 文件；其他模块只能访问分配给自己的文件位置。根路径统一由 MOD-01 解析；下游用各自语言的平台路径工具，不手工拼 `/` 或 `\\`。
- 安装目录只放受信可执行文件和静态资源，不写工作数据库、不复制凭证到包内。
- macOS 新建私有目录/文件的设计权限目标为 0700/0600；Windows 验证当前用户所有权与受控 DACL，不把 POSIX mode 当 Windows ACL。发现现有目录权限宽松应报告并请求修复，不静默改用户现有权限。本次不执行权限设置。
- 路径解析拒绝 NUL、越界、符号链接/重解析点造成的意外跳转和不可信可执行文件位置。日志只保留逻辑位置，避免输出用户名、完整家目录。
- `%APPDATA%` 可能被组织重定向/漫游；WAL 不支持网络文件系统。需验证落盘确为本机且没有被同步服务作为活数据库跨设备同步。不可证明时阻断持久化启动并说明限制，不偷偷换到 `%LOCALAPPDATA%`、禁用锁或改数据库模式；目录策略变更交主会话裁决。
- 数据库与本机备份不是应用层加密保险箱；数据留本机并不等于抵抗系统管理员或已控制用户账号的程序。依赖系统磁盘保护和文件访问控制，不额外索取全盘访问权限。

### 3.3 迁移编号和内容校验

1. 前缀按照 overview 分配；MOD-01 只登记 `platform_`、`audit_`。拒绝空前缀、通配前缀、大小写混淆和前缀重叠。新增能力私有表按批准命名空间登记，不能自领 `audit_`。
2. 每模块版本从 1 连续递增，必须正安全整数；重复登记同一模块、重复版本、乱序、缺历史版本均拒绝。移除能力保留其历史表和登记，禁用不等于卸载数据。
3. checksum 采用 SHA-256 小写 64 位十六进制。迁移发布资源为 UTF-8/LF 的固定源文件；构建清单记录 moduleId/version/文件及不可变辅助资源的内容哈希。不得用 `Function.toString()` 或编译后的格式变化推导历史校验和。
4. `apply` 不读取网络、凭证、时间随机源、环境配置或可变外部文件；只能同步使用 Tx。若引用辅助逻辑，辅助逻辑内容纳入该迁移封存摘要，后续不能改变旧迁移含义。静态准入同时覆盖 apply 及其辅助调用中的 async、Promise/thenable 返回和悬空异步；void 类型签名不证明同步。执行器必须直接检查 apply 的实际返回值，不能只检查外层 work。
5. 发布装载器核验资源哈希与清单，再登记 `Migration.checksum`；数据库历史摘要、登记摘要和资源摘要三者一致才可继续。签名/哈希核验防误改，不承诺抵抗已控制本机进程的攻击者。
6. 已应用版本高于安装包可理解版本，或历史摘要漂移，进入维护阻断；不能修改历史行、重新跑旧 apply 或自动降级。

## 4. 内部设计

### 4.1 I28 代码边界与启动状态

拟实施目录边界（本次不创建代码）：

| 位置 | 职责 | 禁止 |
|---|---|---|
| `src/platform/storage/` | Tx、迁移、审计、备份内部编排 | 业务表 SQL、连接器或模型调用 |
| `src/platform/logging/` | 字段白名单、脱敏、轮转 | 接收并序列化原始 SDK 返回 |
| `src/platform/adapters/macos/` | 数据目录/私有文件、安全凭证、本机锁、launchd、平台进程控制 | 枚举办公窗口、截图/OCR |
| `src/platform/adapters/windows/` | 已知目录/DACL、凭据管理器、锁、计划任务、子进程清理 | Run 项替代监督、提升到 SYSTEM |
| MOD-12 Rust 平台层 | 宠物自身单实例、窗口与系统信号、受限本机认证引导 | 业务数据库、其他账号凭证、办公写工具 |

平台选择入口也在 MOD-01 adapters 内；其余后台代码不出现 `process.platform`、系统命令判断或 OS 专用环境分支。构建/安装专用分支也集中在平台适配或 MOD-12 平台层，不散落到连接器脚本。

依赖检查拟以 TypeScript AST 和真实模块解析为依据，覆盖 import、export-from、require、字面量动态 import、路径别名与包 re-export；检查真实目标路径，不只搜目录字符串。跨模块只允许 contracts，连接器的项目内依赖仅 contracts，pet 禁止后台实现和数据库驱动；标准库/SDK 依赖仍按各模块职责限定。组合入口的装配资格要显式登记并经总架构师裁决，不把任何 cli/脚本目录都豁免。非字面量动态加载、运行时加载未登记代码默认拒绝；同时扫描 OS 判断/命令、数据库句柄和文件位置的非法引用。检查器只防工程越界，不保证查出同进程恶意代码；两平台冒烟仍不可替代。

内部状态流程：

```text
cold → paths_checked → lock_held → lifecycle_checked → backoff_checked
     → attempt_recorded → registered → history_verified → backup_ready
     → migrating → credentials_ready → services_ready → ready
有效停止意图 → stop_blocked（不启动业务）
异常 → maintenance_blocked / retry_wait / circuit_open
退出 → stop_intent_recorded → draining → database_closed → lock_released → stopped
```

- 所有登录、OS 重试、CLI、宠物唤醒、升级与恢复入口先读取有效停止意图；取得同一实例锁后重验 lifecycle 代次，才允许迁移、写本机令牌或启动业务。门闩不可读、不完整或处于恢复/认证轮换未完成时保持对应出口阻断。
- 启动登记前持久化本次运行 attemptId，核对上一尝试的稳定/退出证据与不稳定预算；不能因换入口或登录清零。未取得锁的竞争者不建立业务运行尝试。
- 迁移和本机认证就绪前，MOD-08 不开放业务路由，MOD-06 不启动触发器，MOD-03/07 不启动同步或外呼。
- 单个源未配置不阻止整机 ready；但系统凭证库不可用、本机令牌无法持久化、数据库不可信时不得以无认证服务继续。
- maintenance/retry 状态不是 ready。可留低消耗启动门闩或离线维护入口，但不得开放伪健康业务 API；呈现方式待 §8 接口协调。

### 4.2 StorageService 与同步 Tx

#### 连接策略

- v1 一条 `DatabaseSync` 写连接，放在大脑主进程；不把冻结同步接口改成 Worker 消息 Promise。
- 使用本机 SQLite，开启 foreign_keys，禁止双引号字符串兼容，关闭扩展加载，启用可用且已验证的 defensive 设置。M3 向量扩展须另外评审和验证，v1 不开放任意 loadExtension。
- 设计采用 WAL 与 `synchronous=FULL`，避免已确认决定/started 因 NORMAL 的断电持久性折中丢失。实际存储介质仍需故障测试，不许宣称绝对不丢数据。
- 启动读取 PRAGMA 回值核验实际生效，不以调用未抛错当成功；保留自动 checkpoint，空闲时才尝试被动 checkpoint，不为了收缩 WAL 删除旁文件。
- 初始 busy timeout 目标 250ms，避免同步连接阻塞事件循环数秒。超时后报错，由上层在事务外决定是否有限重试；平台不自动重跑回调。
- SQLite 官方现记录 WAL-reset 修复版本为 3.51.3 及之后（部分旧线有 backport）；发布探针读取 bundled SQLite 版本与修复证明。不能仅凭 Node 24 标签推定已修复。

#### 事务算法

1. 检查 storage 为可用状态且无活动事务；同步执行 `BEGIN IMMEDIATE`，确认底层事务存在，创建带内部代次、active 状态和首错槽的 Tx。
2. 每次 `run/get/all` 在准备及执行前核对实例、代次、active 状态和底层事务存在。参数/返回值校验、prepare/execute 或同 Tx 服务边界发生错误，立即将关联 Tx 不可逆置 rollback-only 并保存首错，再抛出；底层自动回滚则立即失效。即使外层回调捕获错误，后续 SQL 和 COMMIT 仍拒绝，不自动 BEGIN 或隐式自提交。
3. SQL 使用绑定参数的单条 prepared statement。DDL 仅迁移期开放；事务控制、ATTACH/DETACH、破坏性 PRAGMA、扩展加载不向 Tx 开放。`get` 无行返回 undefined；`all` 返回数组；`run` 只返回 `{changes: number}`，不暴露底层 rowid 或 Statement，不接受模型或用户输入的 SQL。
4. INTEGER 读取先保留 bigint，安全范围内转 number，超范围保留 bigint；UTC 毫秒按安全整数校验，BLOB 保持 Uint8Array，不能默默精度截断。
5. 检测外层 work 的实际返回值为 Promise/thenable 即污染事务并报同步契约错误；迁移流程另直接捕获和检查内层 apply 返回值，不能将其丢弃后只检查 work 的 undefined。类型/静态检查覆盖回调及辅助调用的 async/悬空异步。检测不能取消已开始的外部副作用，回调仍禁止网络/密钥库异步调用。
6. 回调结束后仅在 active、无首错且底层事务仍存在时 COMMIT。任何回调、校验、审计、outbox 或提交错误都回滚整个尚存事务；SQLite 已自动回滚时不继续 SQL。清理失败不覆盖首错；无法确认连接回到无事务状态则封锁该 storage，不供下一调用复用。
7. finally 使 Tx 失效；保存引用后再调用抛错。COMMIT/ROLLBACK、rollback-only 或自动回滚之后不得继续用它。外来存储实例、伪造、已结束 Tx 一律拒绝；同 Tx 服务验证失败也通过 §2.2 受信装配污染事务，不依赖调用方继续向外抛错。

嵌套 `StorageService.transaction` 直接拒绝并污染同 storage 的当前 Tx，不隐式 savepoint 或加入外层事务。可选 Tx 服务必须显式传原 Tx；例如事务内忘传 Tx 调用 `AuditWriter.append` 被拒时，当前事务也不能因业务捕获而继续提交。业务接口没有 Tx 参数时，按其冻结语义各自编排，不自行推定任意服务调用都能嵌套。

受信模块守所有权，Tx 不是不可信插件的 SQL 沙箱。authorizer 与迁移 Schema 差分用于防误写：运行期阻止 DDL/破坏审计，迁移期限制所属前缀及对象；不能靠 SQL 正则完整判定 SQLite 语法。authorizer 在准备和执行重编译都可能触发，回调不调用数据库或写审计，违规结果直接 DENY。语句缓存必须绑定安全上下文，不能复用迁移期已授权语句绕过运行期限制；起步可不做缓存。

### 4.3 迁移启动流程

1. **登记期**：组合根登记所有受信模块；只收集 Migration，不发生业务写入。MOD-01 元表初始化也是封存迁移，不使用到处散落的 CREATE IF NOT EXISTS 掩盖版本。
2. **检查期**：读取现有元表和 sqlite_schema；核对模块历史、前缀、应用版本、资源哈希、数据库完整性。新空库与 POC `items` 库分开识别，未知库不自动接管。
3. **备份期**：有待应用变更时先完成独立备份；空新库可以记录无历史数据初始化状态。有旧数据却备份失败，禁止开始任意模块迁移。备份 Promise 在事务外 await。
4. **执行期**：MOD-01 基础迁移优先，其他模块按固定 moduleId 次序、内部 version 升序。迁移只写自己的对象，不支持跨模块 DDL 依赖；需要跨模块调整交主会话编排。
5. **逐版本提交**：一个版本一个同步事务。直接保存 `apply(tx)` 的实际返回值并检查 thenable；读取 then 属性本身抛错也污染事务，不继续成功路径。确认同步完成且 Tx active 后，执行 Schema 所有权及父目标键结构核验；平台内部连接在本事务内检查 integrity_check 和 foreign_key_check。抛错、非 ok、违规行或 foreign key mismatch 均回滚该版本，不能留到终检再发现。验证通过才写 `platform_migrations` 成功记录和 AuditWriter 的 config 类完成记录；最终提交仍须通过 §4.2 的状态核对。模块 apply 不直接写平台历史表，校验不放开公共 Tx 的危险 PRAGMA。
6. **终检期**：全部版本成功后再次运行完整性和 foreign_key_check，确认无缺版本、审计保护有效，再让业务服务 ready；这是附加终检，不代替每版本提交前验证。

失败的版本及其 Schema、历史、完成审计一起回滚；早先合法提交版本保留，业务仍不 ready，失败版本的悬空异步续段持有失效 Tx，不能补写。同一版本内部允许先暂缺再补齐约束，但提交边界必须有效，不能依赖下一版本修补已提交的无效结构。v1 不承诺整个应用升级是一个巨型全库事务，不反向调用旧 apply。需要回退时走维护恢复，而不是在旧程序上强行打开新 Schema。

SQLite 事务仅保护数据库；Markdown/凭证/计划任务不能一起回滚。此处迁移禁止副作用型文件和系统操作。MOD-09 文件格式迁移的协调机制列 §8，不以同事务备份为名假装数据库和文件系统原子。

### 4.4 中央 AuditWriter

- MOD-01 拥有审计 Schema、追加实现、格式验证和存储保护；MOD-07 不拥有 audit 表。MOD-03/05/07 等传入完整 `AuditRecord`，业务 actor/ref 的可信来源仍由各宿主服务负责，平台不从客户端自报建立授权。
- `kind` 仅用 `decision/tool_write/tool_read_content/llm_call/auth/share/config`。迁移、设置、自启和恢复维护记录用 `config` 加受控 detail，不新增平台自造 kind。
- 传 Tx：在受信同步边界中验证结构和 Tx 身份/代次/active/底层事务状态，内部审计语句在同一连接插入；不另开事务、不先提交业务。结构验证、同 id 冲突或 SQL 失败均先污染原 Tx 再抛出，业务捕获错误也无法继续提交。未传：单独同步事务追加。
- 重复 id 且规范化内容哈希一致视为同一条追加的幂等重试；相同 id、不同记录报冲突。规范化采用受信版本化编码：固定字段、UTF-8、明确 JSON 键顺序/数值表达，区分缺省和 null，不改写字符串或 refs 次序；覆盖 at/actor/kind/refs/summary/outcome/detail。具体编码版本须在 P05/P07 闭环，旧行按原版本验证、不重算覆盖旧 hash；不以时间或 summary 相同去重。
- started/ok/error/unknown 都是新记录，不修改上一条的 outcome。`seq` 只定当前数据库分支内顺序，stable id 负责幂等，不要求无缺号或跨历史恢复天然单调。恢复按原分支/seq 提取后来记录，新位置与原位置的受信映射归 P05/P07，不能把新 seq 冒充原历史位置。
- refs 保存必要关联，summary 必须是无正文模板或受控摘要/哈希。detail 按 kind 白名单保存用途、计数、token 用量、耗时、错误码等；禁止原始参数、正文、OAuth code/verifier、Cookie、Authorization、凭证键内真实账号。
- 运行期 authorizer 拒绝审计 UPDATE/DELETE/REPLACE 和触发器/表 DROP；追加使用 INSERT，不能用 INSERT OR REPLACE。可增防误写触发器，但不能把触发器当抵抗同用户直接篡改数据库的安全边界。
- 结构升级必须完整保留旧审计行和 id/hash，不能以重建表名义删记录；只有 MOD-01 封存迁移能修改 Schema。v1 不自动按天清审计。
- 审计失败必须向调用方传播。外呼前 started/审计写入失败就不能外呼；外呼成功后审计结果写失败属于结果未可靠落盘，由 MOD-07 核验恢复，平台不得偷偷重发。
- §5.1 公共契约只给 Writer，没有审核日志 Reader；可视化查询需求列 §8，不能让 MOD-08 直接执行 `SELECT audit_...`。

### 4.5 outbox 同事务接入

所有权固定：业务实体归 MOD-02，游标归 MOD-03，事件和订阅检查点归 MOD-06，审计归 MOD-01。

同步路径的调用顺序（语义示意，非新增接口）：

```text
MOD-02 applySync
  StorageService.transaction(tx)
    写 graph_ 实体/关系/分页快照状态
    cursorCommit(tx) → MOD-03 写 sync_ 游标
    AuditWriter.append(需要审计的记录, tx)
    EventBus.publish(entity.changed 等冻结事件, tx) → MOD-06 写 rt_ outbox
  全部成功才 COMMIT
MOD-06 在提交之后读取 outbox、投递、推进订阅者检查点
```

- 没有 Tx 的 publish/append 是单独操作，不能用于宣称和业务状态原子。
- 事件 id 在 outbox 持久化时固定；回调内只插行，绝不执行异步 handler、SSE 推送或连接器外呼。
- 任一 outbox/游标/审计的结构验证或 SQL 失败先污染同 Tx，业务即使捕获仍全部回滚；进程在 COMMIT 后、投递前退出，MOD-06 从持久行恢复；COMMIT 前退出没有可投递事件。
- MOD-01 不维护第二份 outbox，也不代 MOD-06 写订阅检查点；runtime 服务内部通过受信装配加入原事务，不暴露直接跨表写能力给 MOD-02，也不让 MOD-06 导入平台实现。异常污染与权限上下文恢复须按 P04/G07 统一验证，未闭环不以普通 SQL 成功替代服务失败原子性证明。
- 至少一次投递允许重复；去重与检查点归 MOD-06，动作安全恢复归 MOD-07。存储事务不等于远端 exactly-once。

### 4.6 备份与恢复

#### 备份范围

M1 平台基线提供 **数据库备份**：包含 `platform_`、`audit_` 及各模块数据库表，不含系统凭证、登录令牌、原始接口响应、日志、窗口数据或产品代码。`companion/` 的权威 Markdown 不在此范围，必须标注 scope=db_only；不能宣传为整机人格/记忆完整备份。M2 的一致文件快照需 MOD-09/11 的契约协调。

备份内部步骤：

1. 启动迁移前尚无业务工作；在线手动备份则进入维护静止点，停止新的状态写入、排空在途事务和外呼，不借数据库锁冻结整个 OS。
2. 创建唯一新 backup-id 暂存容器，不能覆盖现有备份。调用 `node:sqlite.backup`，Promise 完成前不标为有效，不在 Tx 回调中 await。
3. 只读打开副本，检查 integrity_check、foreign_key_check、模块迁移向量、审计最高 seq 与行数。校验备份未携带凭证明文。
4. 清单含格式版本、应用/Node/SQLite 版本、实例 id、UTC 时间、scope、迁移向量、数据库字节长度/sha256、审计高水位，不包含工作正文。
5. flush 副本和清单、关闭句柄，再在同卷原子发布完成标记；两平台实际 flush/rename 能力须探针。目录进入 backup_catalog 前完成验证，失败只留明显 incomplete 的本模块暂存，不误用。
6. 控制台应说明备份范围与保留策略；初始设计为最近 3 次已完成数据库备份，最多保留 30 天，当前升级的迁移前备份在升级确认成功前不淘汰。保留清理仅处理平台自己的已完成备份容器；空间不足不能删 live 数据或审计来迁就升级。

不 `copyFile` 活跃的 `work-agent.db`，不分次复制 db/wal/shm 冒充一致快照。SQLite WAL 是持久状态的一部分；checkpoint 不等于全应用数据库+记忆快照。在线 backup 可能反映同连接写入，因此跨文件一致性依赖维护静止点，而非只依赖 backup API 名称。

#### 恢复分类

| 恢复情形 | 安全处理 |
|---|---|
| 迁移中失败，ready 从未开放且无业务/外呼产生 | 可选择迁移前快照；保留失败库/日志证据，仍需用户明确维护确认，不自动覆盖 |
| 历史备份回滚后已有新决定、started、结果或撤销授权 | 不允许直接恢复后启用执行；需保留现有审计、恢复门闩和 MOD-07 核验，见 §8 |
| 数据库损坏/现有审计不可完整读取 | 保留原库及 WAL；不能承诺修复历史或推断未执行，不重新同步后盲重发 |
| 跨设备恢复 | 凭证不搬运，需要重新授权；local token 重新生成，实例/账号绑定由 MOD-03 校验；不恢复出站执行 |
| M2 Markdown/遗忘数据回退 | 不覆盖现有权威源和墓碑；协调 MOD-09 处理，否则只提供离线数据库恢复检查 |

恢复内部步骤：

1. 用户确认目标和会丢失的状态；进入离线维护，关闭调度/外呼。停止大脑并取得同一实例锁；禁止与在线服务并行运行维护命令。
2. 验证备份清单、路径、哈希、Schema 兼容性和完整性。旧包不打开高版本库；不允许从任意外部路径加载插件/迁移代码。
3. 当前库能读时先做安全副本，按原分支/seq 提取备份之后的有效审计，保全模型费用账本及 unknown 占用；无法保证任一边界完整则保留不确定并封锁相关出口。restoreId、代次、阶段和未完成门闩持久写在不随数据库快照回滚的 `runtime/`，在任何 live 切换前完成并核验，不能只写将被回滚的数据库。
4. 在独立新容器恢复副本；可验证的后来审计按原顺序、原规范化版本通过 AuditWriter 追加，同 id 不同内容即冲突。保留原历史位置与新位置映射及引用断档；其持久化载荷归 P05/P07，未闭环不得宣称完整合并。模型账本按 MOD-05 的恢复边界保守处理，旧快照不能复活额度、退款未知用量或自动重发。不得 UPDATE 旧审计或抛弃原库副本。
5. 全部关闭后同卷切换 live 数据库，并将原 db/WAL/SHM 成组移到平台隔离容器。没有活动连接才能执行；各阶段按同 restoreId/捕获代次持久推进，意外退出或阶段不一致仍拒绝业务启动，不能加载新 db 配旧 WAL。
6. 增加平台恢复代次、追加 config 类恢复记录；所有本机认证通道按 §4.8 轮换屏障失效旧世代，未完成不开放。系统凭证不随数据库快照回退，断开源旧凭证不得凭旧 auth 表复活；当前凭证实际有效性与撤销 producer 清理仍归 MOD-03。
7. 动作/授权/事件/记忆/模型预算及对应旧会话、消费者的恢复边界须按 P04/P05 的受信联合协议验证，不能仅凭服务自报 ready 清门闩。只对同 restoreId/代次且所需证据完整的阶段作清除 CAS；迟到确认不清新门闩。当前契约不足仅提供离线恢复检查，保持相关出口阻断，不将数据可读视为可自动执行。

数据库恢复不是修改/删除审计的业务接口；即使保留副本，也不能承诺旧快照天然满足 I21/I30。历史恢复导致审计或外呼知识断档是明确协调阻塞。遗忘也不保证擦除离线备份；保留期限、存在旧内容、选择删除备份和恢复会使旧内容重现的风险必须透明告知。

### 4.7 SecretStore 跨平台设计

#### 键空间与操作

- 系统 service 名使用 `work-agent`；内部键由受信注册映射到实例 id、用途和稳定 SourceId。不得将账号邮箱直接当 Windows 大小写不敏感 TargetName 的唯一身份。
- 设计键族为连接实例认证、模型供应商认证、本机接口认证，开发和发布分离。具体键字符串及凭证拆分由 §8 与 MOD-03/05/08 协调，不在本稿偷偷冻结跨模块约定。
- 每键异步串行执行，set 成功仅在系统 API 明确成功后返回；get 不存在返回 undefined；delete 已不存在可成功，其余错误必须传播。
- 没有 list/export/all/getJson 公共便利接口；序列化、token 组合和刷新属于授权/供应商认证适配器。
- 系统凭证库与 SQLite 无联合事务：授权代理必须先封锁撤销源，再删除凭证，完成后追加审计；删除失败显示撤销待清理，不能假装凭证已删除。恢复时检查系统实际凭证而非仅信任数据库 granted 字段。

#### macOS

候选库必须验证其实际采用系统 Keychain generic-password 查询/add/update/delete API，限定 service/account，不全局搜索或删除别的项。直接桥接候选使用 Security framework 的 SecItem API；具体 keychain 类型、访问控制和签名身份兼容性须在登录 LaunchAgent、命令行与 Tauri Rust 认证引导中共同验证。

不启用跨设备同步凭证，不更改用户钥匙串解锁设置、ACL 或全局访问控制。登录后锁定、用户拒绝、交互不可用和 native module 加载失败是不同错误。没有授权不能自动放宽条目访问范围，也不能每分钟弹重复许可框。

#### Windows

候选库必须验证使用当前用户 `CRED_TYPE_GENERIC`，持久性选择 `CRED_PERSIST_LOCAL_MACHINE`（含义是同一用户在同一电脑后续会话可见，不是向全机用户共享）。不得用 ENTERPRISE 漫游或保存 Windows 登录密码。

直接原生桥接候选使用 CredReadW/CredWriteW/CredDeleteW，并正确释放系统分配内存。官方 CREDENTIALW 目前标示 CredentialBlobSize 上限 5×512=2560 字节；以目标 SDK/原生库实测核验，UTF-8 编码字节和终止符计量必须一致。超过后明确 `secret_too_large`，不能截断、落盘、分块自造协议或把库标称字符串支持当无限长度。OAuth JSON 可能超限，MOD-03 的拆分/组合方式待协调。

计划任务必须在与交互客户端相同的用户上下文读写；登录 token 不可用不降级到 SYSTEM、S4U 或需要保存用户密码的方式。

#### 无泄密降级

`@napi-rs/keyring` 仍为候选，不安装或固定未经验证版本。若无法证明支持所需平台和签名/尺寸/异常语义，阻断发布，评审直接原生桥接方案；替代也必须符合 I7，不是允许方便的备用存储。

禁止：`security ... -w <secret>`、`cmdkey /pass:<secret>`、含 secret 的 PowerShell -Command、明文文件/.env/SQLite、把整个供应商环境继承给子进程、URL/日志/模型输入传密钥。不使用 shell 管道临时绕过；本设计优先进程内原生绑定，不新增凭证工具链。

凭证只在被授权的认证内存中短暂存在；不长期缓存，不在普通业务对象拷贝，不在错误对象中带值。JS string 和 native 库可能产生无法强制擦除的副本，只承诺最短生命周期与可控引用，不能承诺可靠零化所有内存、禁用所有系统交换或保护已被攻陷进程。

### 4.8 本机令牌引导

1. 首次持锁启动在原生凭证认证适配器内用安全随机源生成至少 32 随机字节，编码为 base64url；不由配置文件或环境提供固定 token。先核对持久停止/恢复/认证轮换门闩，不能借启动绕过未完成流程。
2. 存入系统凭证库后读取验证；成功才允许 MOD-08 开放 127.0.0.1:8787 业务服务。库不可用、拒绝或写失败，启动阻断，不生成仅内存临时令牌继续运行。
3. 无轮换门闩的正常后台重启可读取同一 token，不每次重生成。在线重置/恢复轮换则先同步封锁本机认证入口，持久写入 rotationId、新认证世代和未完成阶段，再失效旧验证器及其衍生凭据，全部完成才允许修改系统凭证键。门闩持久化失败也维持本进程封锁，不进入改键步骤。
4. 新 token 的 set/get/验证在 Tx 外进行，仅认证适配器接收秘密。set 成功但 get/验证失败、崩溃或重启遇未完成门闩时，不回退旧内存验证器、Cookie 或仅内存新 token；保持相关入口封锁，经受信恢复流程再次验证。只有同 rotationId/捕获世代的成功验证和持久完成 CAS 才能开放新世代，迟到结果不清后续轮换门闩。
5. Bearer、同源 Cookie、一次性短登录码、SSE 及在途认证请求共同绑定认证世代；轮换关闭旧流并使排队消息/旧凭据失效。每个请求的实际业务入口、异步等待后的响应披露及每次 SSE 投递都核对当前世代和门闩；不因已建连接或早先鉴权成功而沿用旧许可。跨 MOD-08/12 及宿主的最终边界只列 P03/P05 协调，未闭环不可开放轮换功能，不宣称跨网络原子撤权。
6. MOD-12 的 Rust 认证层及受信 CLI 只获取本机接口 token，不读取连接器密钥。WebView 不接收长期 token；native HTTP/SSE 附 Bearer 后投递过滤数据，旧 native 缓存不得绕过服务器世代核验。MOD-08 只接收受信验证器，常量时间比较并校验格式/长度，不接收 SecretStore 或返回 token。短码一次使用、地址栏清除、Host/Origin/SameSite/CSRF 由 MOD-08 验证，没有 localhost 免认证或长期 token 查询参数。
7. 轮换只是本机认证失效与重新引导，不构成新的业务批准，也不恢复被取消的执行。已可能派发的请求保留事实和 unknown 核验，不因旧认证失效改成未执行或重发。
8. 8787 已被其他服务占用时报冲突，不杀进程、不绑定 0.0.0.0、不静默换端口破坏 OAuth redirectUri 或客户端发现。第二启动请求只连接已认证的既有实例；不能因回环端口有响应就认为是可信大脑。

认证 bootstrap 是契约 §11 的要求，不是已实现的 Tauri bridge。其签名身份、跨语言键映射、SSE Bearer 和控制台入口的缺失公共协调列 §8。

### 4.9 单实例、监督与退避

#### 单实例

- daemon、离线维护共享同一 canonical 数据根的内核独占文件锁。候选原生实现为 macOS flock、Windows LockFileEx，非 Node 文件存在判断；native bridge 与包内加载仍需探针。
- lock 文件长期保留，持有 FD/句柄决定锁状态；崩溃由系统释放。禁止按 pid 文件/过期 heartbeat 删除锁，避免 pid 复用和“旧进程仍活着”产生双写。
- runtime 元信息可含实例代次、pid 和启动时间，仅诊断，不当授权或锁依据；不得传到模型或产品统计。
- 计划任务 IgnoreNew、launchd 单 job 只防各自入口重复；手动 CLI、宠物唤醒和升级维护仍靠上述锁。跨登录会话同用户同数据根也必须互斥。
- MOD-12 独立处理脸的单实例；两者不能合成“退出宠物顺带 kill 所有子进程”。

#### macOS 登录监督

用户明确启用后，MOD-01 适配器注册当前用户 LaunchAgent，定义中只有绝对受信可执行路径、固定 daemon 参数和非敏感目录。设计使用 RunAtLoad、KeepAlive 与 ThrottleInterval（初始目标 60 秒）；具体 plist 语义与 launchctl 操作在目标 OS 手册及实测中核验。不得 fork/自 daemonize 脱离 launchd，不依赖其登录 shell PATH。

禁用自启、完整停止后台、卸载/升级分别有明确操作：先记录停机意图并停止/卸载本产品 job，再结束后台，避免 KeepAlive 将有意退出当崩溃拉起。不改全局 LaunchDaemons、系统权限或他人 job。用户退出宠物不触碰 daemon job。原生库或主程序在引导前反复崩溃时，仅靠 OS throttle 不保证有限熔断，必须实测并列发布门槛。

#### Windows 登录监督

使用当前用户级 Task Scheduler 登录触发任务，不采用注册表 Run 项冒充监督。任务 action 直接运行包内受信 Node/daemon 入口，不能仅启动后马上退出的 cmd/PowerShell 包装器，必须让 Task Scheduler 跟踪真实后台进程。

| 设置 | 设计值/要求 | 理由与验证 |
|---|---|---|
| Principal | 当前用户，InteractiveToken，非最高权限 | 只在已登录交互会话运行，不保存 Windows 密码，不用 SYSTEM/S4U |
| Trigger | 当前用户登录；按用户启用注册 | 不是开机全局系统服务；注销后不承诺工作 |
| MultipleInstances | IgnoreNew | 已有运行任务不排队/覆盖；仍需 daemon 文件锁 |
| ExecutionTimeLimit | PT0S | 官方默认 72 小时会终止，必须明确无限时长并测试导出结果 |
| RestartInterval/Count | PT1M / 3，作为 OS 异常退出兜底初值 | 官方最小 1 分钟，不能写秒级重启并声称有效 |
| AllowDemandStart | true | 用户“唤醒”可运行已启用任务；无注册时用受信临时启动路径 |
| RunOnlyIfNetworkAvailable/Idle | false | 离线报告与本机伙伴不依赖网络或系统 idle |
| WakeToRun | false | 不为办公提醒唤醒电脑；休眠遗漏由 MOD-06 补跑 |
| Battery 策略 | 不因电池自动阻止/终止，初始设计需验证 | 否则后台莫名离线；资源策略另按本地测量限制 |

RestartCount 只涵盖任务服务识别为失败的退出，不是对 event-loop 挂死的通用 watchdog，也不是逐次指数退避。异常 exit code、强制结束、注销、系统重启、策略禁止任务和 Windows 更新后状态必须分别测试。若有限重启耗尽，显示离线并提供用户唤醒，不自动创建周期任务规避预算。任务注册被组织策略拒绝时不改注册表绕过，可用户手动启动，但不能标为“监督通过”。

#### 统一应用退避与恢复

- 在 daemon bootstrap 内实现，不新增第三个常驻自研 supervisor。runtime/lifecycle.json 持久保存 lifecycle 代次、autostartPreference、desiredState/stopIntent、当前 attemptId/阶段/稳定确认/退出原因、不稳定累计及已结算 attemptId、notBefore、原因码和 circuit 状态；无密钥，持锁原子替换并核验。恢复不回滚此文件；发布格式/文件持久性仍须 G04/G05。
- 持锁启动先核对上一运行尝试。ready 前失败和 ready 后未达稳定门槛的非有意退出均按 attemptId 一次结算并累计；自动崩溃不能只因没写出退出记录而消失。前一尝试未结束且没有可信退出原因时保留 unknown 并保守占用预算；无法识别的断电/注销不冒充已证明的正常退出。已核验有意停止、系统休眠/关机按对应原因处理，不伪计为业务失败，识别能力仍待双平台验证。
- 新尝试在登记/认证/业务启动前持久建立，记录 ready 不等于稳定。当前同 attemptId 连续可确认运行 10 分钟后才持久 stable 并重置累计；使用单调计时并排除已检测休眠，不以跨重启墙钟间隔补足稳定时间。
- 初始连续不稳定预算 5 次，达到即 circuit_open；不依赖滚动 10 分钟窗口，因此 ready 后 20 秒崩溃或较慢循环也最终耗尽。登录、换入口、窗口流逝不清累计。本人显式修复后重试只授予一次新的尝试，保留旧预算/原因；再次不稳定仍封锁，真正稳定后才重置。该入口须 P02 可信证据，不允许普通调用自报 retry。
- 指数等待初值 5/10/20/40/80/160/300 秒，加约 20% 抖动；重启不得早于平台下限，Windows PT1M 和应用 notBefore 取较晚时间，不虚构 5 秒 OS 重启。持久 UTC 截点重验时钟异常，不能因此取消累计或提前清 circuit。
- 等待用定时器，不忙轮询、不反复拉模型/数据源或弹钥匙串提示；生命周期文件不可安全读写则 fail closed。锁竞争者不建立/结算业务尝试，不修改停止意图或失败预算。
- 可捕获的永久配置/Schema/凭证错误可留低消耗阻断态；无法写出 attempt 的引导前硬崩溃仍只具有 OS throttle/有限 retry 的已知范围，必须通过 G05 验证，不声称应用计数覆盖 bootstrap 之前的一切失败。两层不互相 fork 新实例。
- OS 监督不保证挂起检测。v1 不增加 health-kill watchdog；更强自动终止须另评安全生命周期。

#### 停机意图与临时转托管

- autostartPreference 只表示本人选择未来登录自启，不代表当前应运行。完整停止以 stopIntentId/代次持久置 desiredState=stopped，范围为同实例所有入口、无自动到期；直到本人经 P02 受信 native 唤醒明确解除，登录/升级/恢复不能清除。普通退出脸不写此门闩。
- 完整停机先封锁新业务并持久记录停止意图，再抑制/停止本产品 OS job 和排空当前后台。持久化或 OS 操作失败如实报未完成；不能只因意图已写就报告 stopped。只有确认本实例后台退出及锁释放、要求的 OS 入口已被抑制才报完成。禁用自启和完整停止是不同选择，不自动更改另一偏好。
- 所有入口在业务前、持锁后重验有效停止意图；停止后 job 操作前崩溃，重新登录或 OS 重启最多进入低消耗 stop_blocked，不能 ready。解除按捕获 stopIntentId/代次作受信 CAS，迟到唤醒不清新的停止意图；修改/确认入口仍待 P02/P04，不新增万能 shell 或伪造本人证据。
- v1 本轮不现场接管已运行的临时 daemon。此时启用自启仅注册未来登录定义，macOS 不加载该 job、Windows 不按需启动争锁任务；当前状态仍是 temporary/unmanaged，而不是“已监督”。登记成功与现有 ready 不能证明 OS 跟踪。
- 已启用且无临时持锁者时，可信唤醒优先 OS 入口；确需立即转托管，须本人明确选择后按 P04 排空旧实例、确认退出/锁释放再启动已登记 OS 入口。该联合契约未闭环前不提供立即交接操作。只有 OS 实际跟踪的进程正是持锁 ready 实例才能报 managed；跨登录竞争者正常退让，不耗业务失败预算或反复重启补绑。

#### 停机和连接器树

正常停止按上述持久门闩先关闭新触发/同步/决定入口，取消在途可取消请求，再关闭连接器 stdio、排空有界事务/日志并关闭数据库、释放锁。平台不替执行器把 started 改为 failed；外呼无法排除成功时仍由 MOD-07 核验。

退出目标初始 10 秒，超时只终止本实例确认持有的子进程，不扫描名称杀其他 Node。macOS 用户 agent 用 SIGTERM；Windows 的温和控制路径与包装器退出码、崩溃后连接器清理候选使用 Job Object/原生进程控制，须探针。Job 只包本 daemon 所有的连接器，不能把独立宠物放进去。具体连接器启动/退出配合由 MOD-03 实现，跨模块生命周期接口列 §8。

### 4.10 Node 附带进程分发

选择详细设计方向：**随安装包带精确 Node 24 运行时 + 后台应用文件 + 所需 native 资源，以独立受监督进程运行**。不要求用户安装 Node/npm，不在用户首启下载依赖或运行 npm install。初期不采用 Node SEA 单文件路线，以免把原生库解包/装载变成未经验证的新前提；变更需重新评审。

- macOS 每个目标架构、Windows 每个目标架构使用匹配 Node 和原生模块。Apple Silicon 和 Windows x64 至少列探针矩阵；Intel macOS/Windows arm64 是否承诺作为 §8 发布范围问题，不凭“跨平台”四字自动宣称所有架构可用。
- Tauri externalBin 能携带可执行文件，其他后台资源由安装包资源布局携带；target-triple 后缀与实际包内重命名/资源定位由 MOD-01/12 联合验证。不能把 JS 文件当 externalBin 可执行文件。
- 监督器从持久安装位置启动 Node，再传固定入口路径；未注册自启时可由 MOD-12 平台层请求受信启动，但不能让 daemon 生命周期依赖 WebView/shell child handle。
- daemon 不继承 pet 的全部环境、供应商密钥或开发 NODE_OPTIONS/NODE_PATH；只保留经过批准的最小运行环境。连接器通过 MOD-03 每次调用 _meta 接收必要访问令牌，不从启动参数/供应商环境获取。
- 生产 TS 原生剥离仅能用支持的可擦除语法和实际可解析模块路径；固定运行时上从安装目录验证。类型检查不代替资源存在/ESM/native 装载检查，是否为打包构建输出 JS 不改变冻结接口，但需主会话评审最终打包路线。
- macOS 签名/公证、Windows 代码签名、WebView 运行条件、Node/native 库许可证与包内资源完整性是发布验证项，不把 Tauri 模板成功生成安装包当完成。
- 升级先关闭业务工作、取得维护锁、备份、替换包并迁移；不得覆盖正在运行的 Windows Node/native 文件。保留旧包与迁移前数据库，但旧包只能配兼容旧数据或离线检查，不带新库盲回退。
- 用户移动 macOS app、安装路径含中文空格、Windows 用户级安装、多账号登录及卸载重装必须测试。无法定位原安装包就显示不可唤醒，不在临时目录或 PATH 中猜一个 Node。
- 宠物关闭、崩溃、更新不得隐式终止大脑。必须做关闭脸后真实同步/报告仍可响应的验证，不以 detached 标记或 sidecar 文档推断。

### 4.11 配置、JSON Schema 与日志预算

非敏感平台设置只在平台私有 KV；其他模块的配置与 state 存自己的表。发布不自动读取项目 `.env`。POC 中 clientSecret/apiKey 的 env 路径不能继续作为无凭证库降级；未来如需要一次性开发导入，仍需单独安全流程和授权，不在此实施。

运行时校验候选采用 Ajv 的 draft-2020-12 专用实例；只编译受信登记 Schema，不动态下载 `$ref`、不执行第三方关键词，不启用数据强制转换、删除额外字段或悄悄补默认值来改变审批参数。旧 Schema draft 不能混用同一 2020-12 实例。Schema 归各模块，MOD-01 只校验平台数据/AuditRecord；跨模块公共 validator 包缺口列 §8。

Logger 的内部处理顺序：事件/字段 allowlist → 去除正文和认证字段 → 深度/长度限制 → 固定错误码映射 → 输出 JSONL。未知字段默认丢弃，不输出 Error.message/stack/cause、请求/响应对象、SQL expandedSQL、查询参数、HTTP header、connector stderr 原文或原生异常包装。脱敏不能只靠 token 正则；正文即使不叫 body 也不允许。

Node/native 装载失败与 Logger 初始化前的 stderr 不自动经过此管线。受信启动适配器必须验证其实际输出路径和受控捕获/错误映射，不直接继承到控制台或业务日志；不能证明安全的初始化诊断不发布原文。G09 使用合成秘密/正文占位覆盖这些早期路径，不用屏蔽全部警告替代包内兼容性诊断；具体捕获能力尚未验证。

## 5. 错误处理与降级

以下为平台内部稳定错误分类，不是新增跨模块 TypeScript 联合类型或 HTTP 状态定义；MOD-08 的公开映射需评审。

| 故障 | 本模块行为 | 保留能力/禁止降级 |
|---|---|---|
| work/apply 返回 thenable、Tx 逃逸或外来 Tx | 立即污染关联事务、回滚并抛首错 | 不提交部分写入，不把晚到异步写入补回 |
| SQL/同 Tx 服务错误被业务捕获 | rollback-only 或失效，拒后续 SQL/提交 | 不自动 BEGIN，不在底层自动回滚后隐式自提交 |
| 逐版本完整性/外键/目标键异常 | 回滚本版本 Schema/历史/完成审计，阻断 ready | 不用下一版本修已提交的坏边界 |
| token 轮换写入/读回/持久阶段失败 | 保持对应认证门闩、旧通道失效 | 不旧验证器回退，不仅内存新 token，不复活业务批准 |
| 有效停止意图或不稳定预算耗尽 | stop_blocked / circuit_open，不业务启动 | 不因登录、窗口流逝或 OS retry 清零 |
| 临时进程运行期间注册自启 | 仅未来登录已登记，当前未监督 | 不以注册＋ready 报 managed，不现场伪接管 |
| SQL_BUSY/LOCKED | 有界等待后报错 | 不自动重跑 work；事务外重试归业务调用者 |
| FULL/IOERR/CORRUPT | 停新写入、保存原因码、进入维护 | 不删审计/记忆腾空间，不擅自新建空库 |
| migration checksum/历史/前缀冲突 | 迁移前阻断或回滚当前版本 | 不自动修摘要、跳版本或降级包 |
| 备份失败/无空间/校验失败 | 迁移不开始；不标完成 | 不覆盖当前库，不静默放弃备份 |
| audit 插入失败 | 传播给原业务事务 | started 未可靠落盘不能外呼；结果写失败不假完成 |
| secret 不存在 | get 返回 undefined，删除可无操作 | 由认证模块解释未授权，不伪造 token |
| keychain 锁定/拒绝、logon session 不可用 | 明确不可用，停止相关认证工作 | 不明文/.env/进程参数降级，不改 OS 权限 |
| secret 超系统/库上限 | set 失败，不覆盖旧值 | 不截断、不私自拆分、落盘或上传 |
| 自启策略拒绝 | 展示自启未启用，允许明确手动启动路径 | 不替用户改注册表/全局任务，不声称监督可用 |
| 端口占用/实例锁被持有 | 第二实例退出或连接认证后的原实例 | 不杀未知进程、不删锁、不开另一份数据目录 |
| 网络断开/模型不可用 | 平台保持本机存储、已生成报告路径 | 上层有限恢复；不重启整个 daemon 刷授权 |
| 系统休眠/注销 | 不承诺期间处理；恢复后交 MOD-06/03 补跑 | 不为了任务默认唤醒电脑，不补发过期写动作 |
| 历史恢复信息不足 | 保留维护门闩、禁止自动执行/事件重放 | 不推断“没审计所以没成功”，不重生撤销/遗忘数据 |

平台错误不含工作内容。出现启动永久故障时尽量保留本机可读诊断；宠物仍能保留少量离线动作并准确说明办公离线，具体呈现归 MOD-12，不由平台伪造 PetState 完成态。

## 6. 安全与隐私

### 6.1 信任模型与最小权限

- 本机服务认证、回环绑定和 Host/Origin 由 MOD-08 实施；平台只引导凭证和生命周期，不能因为本机部署免鉴权。
- 代码模块是受信本机代码，TS 接口/Tx/stdio/authorizer 均不等于沙箱；第三方 MCP 信任由 MOD-03 控制。
- 用户级自启与本产品私有文件访问是平台权限范围。不请求管理员、全盘、辅助功能、屏幕录制、麦克风或家中电脑访问；MOD-12 真正需要的平台权限须另行明确引导。
- SecretStore 绝不注入模型/能力/皮肤；任何模块不得把平台日志当作模型输入或共享资源。系统凭证和本机令牌不进数据库备份。
- 启用/禁用自启、变更平台配置和维护恢复写无正文 config 审计；实际系统操作失败必须记录 error，而非只记录操作意图成功。
- SQLite 文件权限防其他用户，不防已控制同一用户的原生代码。macOS Keychain ACL/签名身份、Windows generic credential 的同用户可读性限制必须准确说明，不宣称“只有本应用能取”而不实测。

### 6.2 日志与资源预算

| 项目 | 起步设计预算/边界 | 验证与超限处理 |
|---|---|---|
| 总体静置资源 | acceptance：同设备静置 10 分钟，pet+后台平均 CPU 目标 <2%，常驻总内存目标 <250MB，连接器峰值单报 | 两平台分别实测；未达不扩大养成或调用模型 |

| 隐藏/空闲 | 平台不枚举窗口、不调用模型，不有高频全量扫描 | MOD-12 停无用绘制；连接器按需启动策略由 MOD-03 决定 |

日志失败可丢普通诊断并反馈计数；审计失败不能丢。性能诊断无正文计数仅存本机，不能把它与可清除生产力统计或不可变审计混成一张表。项目内开发命令曾屏蔽实验警告，正式设计不靠全局屏蔽诊断掩盖 sqlite/native 不兼容。普通主动气泡默认每天最多 3 次、勿扰气泡/声音为 0，最终由 MOD-11/12 执行；平台退避提示不能绕过安静策略。

M2 真实省时验证沿用 acceptance：至少 3 个相近真实任务，以同设备/相近输入对比，中位耗时下降目标至少 30%。样本不足或目标未达就记录未达，不用资源指标、动画效果或设计文档替代。

## 7. 测试计划

### 7.1 单测（未来实施，不在本次执行）

- Tx 参数/返回值矩阵：NULL、字符串、REAL、安全整数、64 位 bigint、BLOB、无行；非法值不能持久化。
- 正常提交、回调 throw、COMMIT fail、ROLLBACK fail 保留首错；回调捕获 ABORT、ON CONFLICT ROLLBACK、审计冲突及 outbox 服务验证错误后，后续 SQL/COMMIT 仍拒绝，不能出现隐式自提交，底层事务丢失立即使 Tx 失效。
- 外层 async/普通 thenable、内层 async apply/普通 thenable/抛错的 then 属性均拒绝；外层返回 undefined 不能掩盖内层异步，await 前 A、版本和完成审计全部回滚，晚到 B 通过失效 Tx 拒写。静态负例覆盖辅助函数悬空异步，不以 void 类型编译通过证明同步。
- 闭包保存 Tx、外来/伪造 Tx、嵌套事务、事务内 append 未传 Tx 均拒绝。
- 迁移重复/乱序/缺版本/前缀冲突、历史摘要修改、未来版本、资源哈希漂移；每版本提交前检测非唯一父目标键、foreign key mismatch、违规行和非 ok 完整性结果，坏版本 Schema/历史/完成审计全无，前合法版本保留。同版本先暂缺再补齐可提交，下一版本补坏结构不可绕过。
- 审计同 id 同内容幂等、不同内容冲突、started/ok 分条；禁止 UPDATE/DELETE/REPLACE 与外键级联/触发器绕过。
- Logger 对任意对象、别名字段、URL query、Cookie、_meta、Error cause/stack、SQL 参数、Unicode/换行、循环引用、超长数据均不泄漏；只用合成占位值，不用真实凭证。
- SecretStore mock：缺失、拒绝、锁定、尺寸超限、删除失败、native load fail；每种错误不被吞成未授权。
- 退避时钟回拨/前跳/重启/睡眠、ready 后 20 秒崩溃及慢循环最终熔断，窗口流逝不清累计；attemptId 重复结算不双计、真正稳定才重置、可信有意停止/睡眠不误计，未知退出保守占用不伪报正常。
- 完整停止意图后、OS 操作前/后、退出前/后各点崩溃再登录/升级/恢复都不能 ready；晚到唤醒 CAS 不清新 stopIntent，偏好与当前停机分开，OS 操作失败不报完成。
- 轮换改键前、set 后/get 前、验证/完成 CAS 前各点失败及重启保持门闩；旧 Bearer/Cookie/短码/SSE/排队披露/在途请求失效，迟到旧世代完成不能开放新世代，不回退旧内存 token 或复活执行。
- KV 命名空间隔离、JSON 格式版本、null/缺失、平台设置拒绝秘密字段。

### 7.2 存储集成和故障注入

只在临时测试数据根、合成模块表与合成凭证下执行，不对用户 live 库做 kill/损坏试验。

| 场景 | 操作 | 必须观察到 |
|---|---|---|
| 同步原子页 | 在 graph_/sync_/rt_ outbox/audit_ 每个写点及服务验证点故障，业务捕获异常后尝试继续 | 四方一起提交或全回滚；失败 Tx 后续 SQL/COMMIT 拒绝，游标不领先实体 |
| 事务崩溃 | COMMIT 前/后终止测试 daemon | 前无提交，后业务和 outbox 可恢复；不因投递前崩溃丢事件 |
| 多模块迁移 | v2 的 apply thenable、父键结构、完整性/FK 校验分别失败并重启 | v2 Schema/历史/完成审计全回滚，合法 v1 保留；无 ready、无晚到补写；修复后不重复 v1 |
| 校验和保护 | 改历史资源摘要、用旧包开新库 | 备份/迁移前阻断，无静默重写 |
| WAL 备份 | 有未 checkpoint 已提交页，执行 backup 与校验 | 副本含已提交状态；绝不只复制 main 文件 |
| 恢复切换中崩溃 | 每个 staging/rename/marker 点断开 | 原库保留，不混用 WAL，门闩不清，离线可解释 |
| 审计/远端结果断档 | 备份后产生 started/远端成功再历史恢复 | 不重发；保留后来审计/unknown，执行恢复受阻 |
| 遗忘后恢复 | 合成 Markdown/墓碑快照落后数据库 | 不声称完整恢复，协调未闭环就阻断 M2 自动整理 |
| 资源故障 | 磁盘满、只读、路径重定向、锁被占用 | 不建空库、不删 live 数据、不宽松降级 |
| 单实例/托管身份 | 临时 daemon 持锁后注册自启，再并发 task/launch/CLI/pet/跨登录入口 | 当前临时实例仍报未监督；竞争者不耗业务预算，至多一个持锁者；managed 仅对应 OS 跟踪持锁实例 |
| 停机屏障 | 在停止意图/job 操作/排空/锁释放各点崩溃并重启入口 | 不越有效停止意图，失败不报 stopped，迟到解除不清新代次 |
| 本机认证轮换 | set 成功但 get 失败、阶段切换崩溃、旧 SSE/请求晚到 | 门闩不清，所有旧通道失效、不披露；已派发事实不改未执行或重发 |
| 模型预算历史恢复 | 备份后已耗预算/unknown 占用再恢复旧库 | 不退款、不重发，账本不完整保持模型出口封锁，迟到旧确认不清新恢复门闩 |

### 7.3 两平台实机清单

在另行批准的安装/探针阶段执行；用户家中 Windows 可用不是本次访问许可。每个平台记录 OS build、架构、包 hash、运行时/native 版本、设置导出和时间线，无真实秘密内容。

1. 干净普通用户安装，无系统 Node/npm；非 ASCII/空格路径可启动和 native 装载，数据根位置正确。
2. 合成凭证 get/set/delete、Unicode 值、上限/超限、拒绝/锁定；重登后仍可读、另一用户不可读；不得测时放宽全局 ACL。
3. 明确启用/禁用自启、状态与实际 OS job 一致；未启用从未注册；注销/登录/重启、睡眠唤醒和电池变化不产生错误承诺。
4. 模拟 ready 前失败、ready 后短/慢循环崩溃、native 引导前崩溃、有限 retry 耗尽；记录各范围实际可识别退出原因及不稳定结算。时钟/登录/换入口不清预算，满足 OS 下限/notBefore，无风暴；不得以较慢循环未触发滚动窗口为通过。
5. Windows 验证 InteractiveToken、IgnoreNew、PT0S、PT1M/3 的实际导出及 72 小时边界；不能只用短模拟测试替代长运行 soak。
6. 关闭/崩溃宠物后后台仍活；临时运行时启用只登记未来自启且仍显示未监督。已托管时唤醒走 OS 入口，核实 OS 跟踪与持锁实例一致；停机意图后的重登录/升级不启动业务，OS 操作失败准确呈现。端口冲突不杀未知程序，client 不信任任意 localhost 响应。
7. 连接器树正常停止与 daemon 硬崩溃后无遗留持密钥子进程；不误杀其他 Node/pet。
8. 升级和离线恢复完整演练；在途动作按 unknown 处理，退出码/锁/凭证/session 状态一致。
9. 静置 10 分钟平均 CPU/内存，按动画/音频/隐藏/断网/退避分别测量；连接器峰值独立报告。真实窗口/音频验收归 MOD-12，不以后台测量替代。
10. 本地 HTTP 安全由 MOD-08 联测：Bearer、Host/Origin、Cookie/一次性短码、SSE、CSRF、DNS 重绑定/跨站请求与过期认证；在线轮换 set/get 失败、重启及最后 await 后的世代失效覆盖所有通道。OAuth 仅合成回调测试，真实数据授权另行批准；初始化 Node/native stderr 泄漏负例纳 G09，不输出合成秘密原文。
