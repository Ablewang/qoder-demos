# 体验、生产力与扩展性验收 v1

- 状态：技术评审基线；不是已完成的测试报告
- 日期：2026-11-19
- 负责人：总架构师；实际体验由用户反馈
- 依据：ADR-0016

## 1. 双目标

可玩性和生产力都必须过线。前者不是靠高频打扰，后者不是靠报告数量或动画。每个里程碑要给出可用安装包、测试证据和短场景演示，而非让用户阅读技术稿。

## 2. 首轮生产力验证

先用用户主动选择的一到两周范围建立基线，不偷偷记录全屏、键盘或系统操作。日历只能代表计划会议负荷，不代表实际工作时长；邮件、提交和消息只是事件线索，不把数量换算成工时，也不把缺失数据当作无工作。

| 指标 | 采集方式 | 验收规则 |
|---|---|---|
| 信息整理耗时 | 用户选择一个实际任务，记录手工与辅助完成耗时；排除纯演示数据 | M2 至少 3 个相近真实任务对比，中位耗时下降目标 ≥30%；样本不足或没达到则不宣称省时 |
| 起草到执行闭环 | 查看证据、编辑、决定、发送及结果记录 | 至少一条真实任务完成，含权限不足后恢复；无重复发送、无批准内容漂移 |
| 提议有用程度 | 接受、编辑接受、忽略、稍后，加用户自愿给出的原因 | 展示分母和样本量；忽略不等于错误，接受不等于完成，不把采纳率当唯一优化目标 |
| 漏项与误报 | 用户指定测试事项、真实线程核对，检查已回复/已关闭事项不再提醒 | 错误来源可追溯、可纠正；缺数据时明确“不足以判断” |
| 打扰成本 | 记录投递次数、勿扰期间气泡/声音、同一事项重复提醒 | 默认普通主动气泡上限 3 次/工作日，同类合并；用户发起响应不计；勿扰气泡和声音为 0 |

指标在本地以无正文的事件计数和时间记录，用户可关闭或清除；不能为了计分新增工作数据权限。审计与可清除的产品统计分离。省时需用户确认或实测，模型估算必须标为估算。

## 3. M1：有生命感，并且有一个真实用途

- 团子可取名、改口头禅；自由停放、气泡、摸头、拖动、玩耍、静音听歌及暂停都能用。首次见面不自动落窗；拖放到窗口或屏幕边缘附近，松手后位置不跳动、不吸附；窗口移动、关闭或最小化不改变团子位置；重启恢复按屏幕保存的位置。
- macOS 和 Windows 验证透明、穿透、自由拖放与位置保持、多屏/DPI、重启位置恢复、睡眠恢复、退出宠物后后台存活及唤醒；窗口移动、关闭/最小化不应触发跟随或落到底边。
- 日历、Gmail 元数据、GitLab 在用户授权后同步；单源未配置不阻止其他源工作，报告明确覆盖范围。
- 首次授权后可手动产生近期会议负荷与工作线索报告，不必等周期任务；数字和来源可核验，不伪装成完整时间审计。
- 无模型时本机动作与已生成报告可用；失败明确显示，不无限重试、不伪造完成。
- 勿扰期间音频停止、气泡为 0；系统无法检测共享时显式提示并有一键演示模式。

资源目标需实测：同一设备基线下，静置 10 分钟宠物+后台平均 CPU 目标 <2%、常驻总内存目标 <250MB（不含连接器峰值，连接器峰值单独报告）；动画与音频分别测量，不先承诺 Tauri 能自动达标。隐藏/离屏必须停止无用绘制，空闲动画的模型调用为 0。

## 4. M2：解决任务，而不是只提醒

优先选用户实际耗时最大的流程。若飞书消息权限不可用，先使用已授权的 Gmail/GitLab 事项或用户主动选择的任务，不假造飞书能力。用户输入的内容仍须由用户选择范围，附明确来源。

完成“选事项 → 查背景 → 起草或给选项 → 完整预览 → 决定 → 自动执行 → 核验结果 → 更新记忆/状态”的闭环。测试包括审批后内容变化、编辑越界、授权取消、授权后前置条件变化、请求已成功但回包丢失、崩溃恢复、部分成功和多通道同时决定。

若省时目标未达，不扩养成数值或新皮肤，先修当前生产力流程。用户反馈好用才扩大能力范围。

## 5. 扩展性演练

进入 M2 前用测试扩展验证，而非把扩展性当口号：

1. 新只读连接器：仅新增受信连接器包与登记，复用宿主、授权和同步；未知实体类型需总架构师批准 Schema，不能随意混入。
2. 新办公能力：仅新增能力包、版本清单、配置和渲染器；不得直接读凭证、调用模型供应商或拿写工具。
3. 新皮肤/自娱动作：仅新增纯素材包与语义映射；不修改动作执行器、工作图谱或办公状态枚举。
4. 重启/升级：持久化状态和格式版本可恢复；移除能力可停触发器、不破坏其他数据。用户手改 Markdown 后能重建索引。

v1 扩展安装是本地显式登记，不包含应用商店、远程任意代码或热加载市场。代码插件按受信本机代码管理，非安全沙箱；第三方 MCP 子进程不是隔离容器。安装与授予工具权限分开，不能以只读标记代替信任审查。

## 6. 证据与门槛

技术基线冻结只说明接口与职责可进入详细设计，不意味着 OAuth、窗口系统接口、MCP SDK、打包或资源目标已验证。未实测的平台和外部权限逐项保留为发布门槛；不得用模拟测试冒充真实授权、音频、窗口或跨平台验证。
