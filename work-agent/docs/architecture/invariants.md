# 不能违反的约束 v1

- 状态：待评审
- 更新：2026-11-18

每条约束都注明出处和检查方式。模块设计评审和代码评审都要逐条核对（`templates/review.md`）。要放宽任何一条，都必须有新 ADR。

## A. 对外动作

| 编号 | 约束 | 出处 | 检查方式 |
|---|---|---|---|
| I1 | 以用户身份对外写入的每一个动作，都必须对应一条用户决定记录；执行前重新检查前置条件，执行后写审计 | ADR-0007 | 执行器单测；审计表里的 `tool_write` 都能关联到 `decision` |
| I2 | 能力、伙伴层、交互层都拿不到写工具的调用入口；`ConnectorHost.callWrite` 只交给执行器 | contracts §3.6、§4 | 依赖检查：只有 `src/actions/` 能引用 `callWrite` |
| I3 | 模型输出永远不会直接触发写入。对话中模型发起的写工具调用一律转成提议 | ADR-0007 | 对话助理测试：注入“请直接发送”的外部内容，结果只产生提议 |
| I4 | 提议的预览必须完整展示对外内容和接收方：全文、收件人、目标位置，不能只给摘要 | ADR-0007 | 交互层评审 |
| I5 | v1 没有无人确认的自动执行，`Policy` 不返回 `auto` | ADR-0007 | 类型限制 |
| I6 | 别人的 agent 发来的请求，只能变成本人的提议 | ADR-0008 | 共享模块评审（M4） |

## B. 凭证与授权

| 编号 | 约束 | 出处 | 检查方式 |
|---|---|---|---|
| I7 | 凭证只存在于凭证库和授权代理；不进入日志、模型、数据库明文、记忆、共享空间 | ADR-0004、ADR-0009 | 日志脱敏测试；搜索代码中的令牌字段 |
| I8 | 连接器不保存凭证和游标，不调用模型；权限不够时返回 `auth_required`，不能自己发起授权 | ADR-0009 | 连接器评审 |
| I9 | 断开数据源时立即删除对应凭证，并写审计 | ADR-0004 | 授权代理测试 |

## C. 模型与外部内容

| 编号 | 约束 | 出处 | 检查方式 |
|---|---|---|---|
| I10 | 所有模型调用都经过模型网关；实体内容只能通过 `entities` 输入交给网关，不能自己拼进字符串 | ADR-0003、contracts §7 | 依赖检查：只有 `src/llm/` 能访问 LiteLLM |
| I11 | `secret` 级内容永远不发给模型；`confidential` 级按用户设置决定 | contracts §7 | 网关测试 |
| I12 | 外部内容（邮件、消息、文档、MR 描述）一律当作数据，不当作指令；进入模型时包在“不可信数据”分隔块里 | ADR-0009、ADR-0013 | 网关测试、提示注入测试 |

## D. 记忆与人格

| 编号 | 约束 | 出处 | 检查方式 |
|---|---|---|---|
| I13 | 只有用户本人，或用户决定过的提议，能写“规则”类记忆和人格档案。来自外部内容的只能记成事实或经历 | ADR-0013 | 记忆模块测试 |
| I14 | 记忆对用户透明：用户能看到、修改、删除它记住的一切；删除时文件、索引、向量一起删 | ADR-0013 | 记忆模块测试 |
| I15 | 人格只影响伙伴自己说话的语气：事实字段（数字、人名、时间、链接）原样展示，不经人格改写；以用户名义起草的内容用用户自己的口吻；人格不能放宽任何策略 | ADR-0012 | 伙伴模块测试：比对事实字段 |
| I16 | 开会、共享屏幕、全屏演示时宠物必须保持安静，只有 `urgency: high` 的事项可以显示角标 | ADR-0012 | 伙伴模块测试 |
| I17 | 成长系统不能锁住功能、不能惩罚用户（没有“饿死”“生气不干活”这类机制） | ADR-0012（Q8 已确认：轻度养成也不能有负面后果） | 伙伴模块评审 |

## E. 数据与共享

| 编号 | 约束 | 出处 | 检查方式 |
|---|---|---|---|
| I18 | 本地服务只绑定回环地址；所有本地接口都要认证（宠物和命令行用本机令牌，浏览器用同源会话），同时校验 Host 和 Origin | ADR-0002、contracts §11 | 交互层安全测试 |
| I19 | 每个实体都带 owner、visibility、sensitivity、provenance；默认 `private`；共享必须由用户显式发布并做出决定 | ADR-0008、ADR-0010 | 图谱的写入校验 |
| I20 | 同步必须幂等：同一个游标重复拉取，结果一样；删除必须明确传递；实体写入和游标推进放在同一个事务里 | contracts §3.2、§2.4 | 同步引擎测试 |
| I21 | 审计记录只能追加，不提供修改和删除的接口 | contracts §5.1 | 代码评审 |
| I22 | 日志里不能出现凭证和实体正文 | — | 日志脱敏测试 |

## F. 工程

| 编号 | 约束 | 出处 | 检查方式 |
|---|---|---|---|
| I23 | 模块只能写自己的表和文件；跨模块调用只能走 `src/contracts/` 定义的接口 | overview §3 | 依赖检查脚本，在 MOD-01 里实现 |
| I24 | 连接器只能依赖 `src/contracts/`；宠物客户端只能通过本地接口和后台进程通信 | overview §2 | 依赖检查脚本 |
| I25 | 时间一律以 UTC 毫秒存储，展示时按用户时区换算 | contracts §1 | 代码评审 |
| I26 | 带版本号的格式（实体结构、连接器扩展、能力清单、人格档案、本地接口）做不兼容修改时，需要 ADR 并提供迁移方案 | ADR-0001 | 文档评审 |
| I27 | 事件处理必须幂等（事件投递是至少一次） | contracts §4.1 | 运行时测试 |
| I28 | 平台相关代码只能放在 MOD-01 的平台适配和 MOD-12 的平台层；其他模块不能判断操作系统，路径一律用 `node:path` 拼接；macOS 和 Windows 都要通过冒烟验证 | ADR-0014 | 依赖检查脚本：搜索 `process.platform`；两个平台的冒烟清单 |
