## 2. 模块设计的并行安排

总体架构 v1 评审通过并冻结后，按批次开并行会话。**同一批内的模块只依赖已经冻结的 `contracts.md`，彼此独立。**

| 批次 | 模块 | 为什么排在这一批 |
|---|---|---|
| 第一批（底层，改起来代价最大） | MOD-01 平台基础、MOD-02 工作图谱、MOD-03 连接层、MOD-05 模型网关、MOD-07 动作层 | 其他模块都建立在它们之上。动作层 M2 才实现，但它的数据结构和状态机现在就要定下来 |
| 第二批 | MOD-04a/b/c 三个连接器、MOD-06 能力运行时、MOD-08 交互层服务、MOD-09 记忆、MOD-11 伙伴、MOD-12 宠物客户端 | 第一批的设计确定后，接口细节更清楚。MOD-12 已定 Tauri 2（ADR-0015），形象已选团子（ADR-0016），平台窗口探针与素材制作在 MOD-12 |
| 第三批 | CAP-01 时间去向 | 依赖运行时和图谱 |

实施前门槛：MOD-01 验证系统凭证与双平台监督进程；MOD-03 验证 MCP 官方 SDK 的版本/发现/stdio/元数据及错误互操作；MOD-12 验证透明/命中穿透/自由拖放与位置保持/按屏幕保存及启动恢复/DPI/安静信号；窗口移动、关闭或最小化不应改变团子位置，首次见面不自动落窗。`WindowAnchor` 公共合同保留，不作为当前自动停靠要求。探针失败需回到 ADR，不准为了赶进度跳过。

每批设计可同时编写，但跨模块协调由主会话处理。缺接口记在本模块未决问题，主会话汇总 open-questions，避免各会话同时改同一公共文件。

## 3. 实现顺序（每个模块的设计批准后才开始）

```
MOD-01 ─┬─▶ MOD-02 ─┬─▶ MOD-03 ─▶ MOD-04a/b/c ─┐
        ├─▶ MOD-05 ─┤                          ├─▶ MOD-06 ─▶ CAP-01 ─┐
        │           └──────────────────────────┘                     ├─▶ M1 验收
        └─▶ MOD-08 ─▶ MOD-11 ─▶ MOD-12（窗口和动画可以提前，先用模拟数据）─┘
```

**团子先行版 M1-P（ADR-0018，2026-11-19）**：

- **提前实现的内容**：团子客户端、伙伴层子集、本地接口、通知投递、本地提醒、记忆 v1，以及最小平台层。
- **依据**：
  - `design/tuanzi-v1-product.md`；
  - `architecture/tuanzi-v1-protocol.md`。
- **数据源和模型**：都不接。
- **并行开发**：三个开发角色按协议 §1 的目录所有权并行。
- **对后续模块设计的约束**：之后的 MOD-08/09/11/12 完整设计必须吸收先行版的接口，不能另起一套。
- **不受影响的事项**：MOD-01 等第一批模块的评审门槛不变。

## 4. 并行会话启动说明（每个会话的第一条消息）

```
你负责 work-agent 的 <模块编号 模块名> 的详细设计（这次只写设计文档，不写代码）。
开工前必读：
  docs/README.md、docs/00-vision.md、
  docs/architecture/ 下五份文档（overview、contracts、invariants、roadmap、acceptance）、
  docs/design/companion-experience.md、docs/adr/0016、0017、
  docs/adr/ 下与本模块相关的 ADR：<列出编号>、
  docs/poc/time-audit-poc.md（如果本模块要迁移 POC 代码）
交付物：docs/modules/<模块编号>-<名称>.md，用 docs/templates/module-design.md 模板，状态写“待评审”。
规则：
  - 只能使用或实现 contracts.md 已定义的接口；需要新接口或修改接口时，写进自己模块的未决问题并回报主会话，主会话统一写 open-questions，不要自己改公共文件；
  - 逐条说明本模块怎样满足 invariants.md 中相关的约束；
  - 涉及外部接口的事实（字段、限制、权限），要附官方文档链接；
  - 不要修改其他模块的文档。
```

## 5. 总架构师的评审要点

- 是否越过了 `contracts.md`，有没有私自增加跨模块依赖；
- 是否逐条满足相关的约束（invariants）；
- 数据所有权：是否只写自己的表和文件；
- 第一批模块之间：数据结构是否互相对得上（例如动作层的审计和模型网关的审计字段）；
- 每次评审结论写进 `docs/reviews/`。
- 用户已授权总架构师自行技术评审（ADR-0016）；无需请用户读技术稿，但不能省略测试与真实体验验收。
- 冻结的是职责、核心安全语义与登记边界；模块未决项在实现前必须闭环，新增可选接口走主会话批准，不承诺零变更。
