## 1. 定位与设计目标

**一只陪伴宠物，能协助日常办公。** 宠物是“脸”，后台常驻进程是“大脑”。

1. **能长期扩展**：新数据源只需加一个连接器，新本领只需加一个能力插件，新形象只需换宠物皮肤，都不用改内核。
2. **能放心交给它做事**：以用户身份对外的写入都要经过用户决定，可以预览、可以追溯。
3. **它的人格和记忆是用户的**：人格由用户设定；它记住的东西用户都能看到、修改、删除。
4. **数据边界清楚**：凭证、原始数据、发给模型的内容、记忆、共享出去的内容，各有明确的边界和审计。
5. **为多人互联留好接口**：现在只做个人节点，但底层不挡以后接入共享。
6. **陪伴和省时分别验收**：团子有安静的自主生活，办公必须有真实任务闭环；所有扩展通过版本化注册，平台与协议假设先做探针，不能以概念图或类型检查代替功能验收。

**依赖方向只能向下**：
- 宠物客户端只能调用本地接口；
- 伙伴层不直接调用连接器；
- 能力层只能通过能力上下文访问下层；
- 连接器只依赖 `src/contracts/`。

## 4. 关键数据流

### 4.1 同步：数据源 → 工作图谱

```
调度器 ──到点──▶ 同步引擎 ──取凭证──▶ 授权代理
                    └─ tools/call wa_sync_pull {stream, cursor, window}
                       （访问令牌放在 _meta 里）──▶ 连接器 ──▶ 飞书 / Gmail / GitLab 接口
                    ◀── {entities, relations, identities, deletions, nextCursor}
                    ├─▶ 工作图谱 applySync（实体写入和游标推进在同一个事务里）
                    └─▶ 事件总线 entity.changed
```

### 4.2 从能力到宠物：通知怎么变成宠物的反应

```
time-audit 每周一 9:00 运行 ──▶ ctx.publishReport + ctx.notify(“本周报告已生成”, facts)
伙伴层收到通知：
  ├─ 安静模式判断：正在开会或共享屏幕？→ 先不冒气泡，只显示角标，会后再提醒
  ├─ 宠物状态机：idle → alert（举牌子 / 跳一下）
  └─ 台词生成：事实字段原样保留，只让人格包装语气
        例：“老板～上周日历安排了 14.5 小时会议，最长的是周三需求评审。要看看吗？”
                     └──────────── 这些数字直接来自报告数据，不经过模型改写 ────────────┘
宠物客户端：冒气泡 → 用户点击 → 打开报告
```

### 4.3 提议 → 决定 → 执行 → 按需授权（ADR-0007）

```
“待回复追踪”能力发现：张三 2 天前问了接口进度，我还没回
  └─ ctx.propose({ title, rationale, evidence:[消息],
       options:[ A 发送草稿回复（可编辑）, B 约 15 分钟会议, C 明早提醒我 ] })   系统自动追加“忽略”
动作层：提议入库 ──▶ 伙伴层：宠物进入 alert，用人格口吻说明来龙去脉
用户在宠物气泡里点 A（或展开改草稿；离开电脑时也可以在飞书卡片上决定）
  ──▶ 记录决定 ──▶ 执行器：策略 → 前置条件（线程里还没有新回复）→ 取凭证
       ├─ 缺少 im:message 权限 → 状态变为 waiting_auth → 宠物：“这件事需要你再授权一下飞书消息权限” → 用户授权 → 重新核验策略、账号和当前前置条件
       └─ feishu.send_message ──▶ 核对结果 ──▶ 写审计 ──▶ succeeded ──▶ 宠物：开心的动作
成长系统：采纳了一次提议 → 默契度增加（真实成长；喂食、摸头属于轻度养成，ADR-0012）
记忆：日记里记一笔“回复了张三关于接口进度的询问”
```

### 4.4 和宠物聊天（对话助理）

用户从宠物右键菜单选择聊天，说“帮我回一下张三”，或者“记住：周五下午不排会”；宠物本体左键单击、双击只做养成互动，不打开聊天面板：

- 伙伴层把对话交给对话助理能力：
  - 系统提示里注入人格档案，以及记忆中的画像和长期记忆；
  - 通过模型网关做多轮工具调用；
  - 只读工具直接执行。
- **模型发起的写工具调用一律转成提议**，不会直接执行。
- “记住……”这类话写进 `user.md` 或 `memory.md`；宠物要明确回应“记住了”，并给出可以撤销的入口。
- 外部内容里藏的指令（提示注入）最多只能变成一条等用户决定的提议，或者一条带来源的“事实”记忆；永远不能变成规则。

### 4.5 记忆的形成

```
日常：事件和对话 ──▶ 伙伴写当天日记 journal/日期.md（带实体链接）
用户说“记住……” ──▶ 直接写进 user.md 或 memory.md（来源：用户）
每晚整理（M3）：日记 → 候选 → 打分 → 写进 memory.md；整理记录写进 dreams.md
               来自外部内容的候选只能作为事实，不能变成规则（ADR-0013）
使用：能力通过 ctx.memory 读取；对话时注入画像和长期记忆摘要；按需全文检索日记
```

## 5. 数据边界

| 数据 | 存放位置 | 能否发给模型 | 能否共享 |
|---|---|---|---|
| 凭证 | 只在凭证库里；访问令牌只在调用连接器时短暂出现在内存中 | 永远不能 | 永远不能 |
| 原始接口响应 | 不持久化 | 不能 | 不能 |
| 实体元数据 | 工作图谱 | 能，受敏感度约束 | 只有用户逐项显式发布的才能 |
| 实体正文 | 工作图谱正文表（按数据源配置决定是否拉取） | 按敏感度和用途，每次都审计 | 同上 |
| 人格档案 | `data/companion/persona.md` | 能（作为系统提示） | 可以发布为“人格模板”（M4） |
| 记忆（画像、长期、日记） | `data/companion/` 加索引 | 能，按条目的敏感度 | 只有逐条显式发布的才能 |
| 审计日志 | MOD-01 中央 `audit_` 表，只能追加 | 不能 | 不能 |

## 6. 部署

```
用户启用登录自启（macOS：launchd LaunchAgent；Windows：用户级计划任务）
  ├─▶ work-agentd（Node 24，随安装包打包，大脑）
  │     ├─ 本地 HTTP 127.0.0.1:8787：接口、事件推送、OAuth 回调、Web 控制台
  │     ├─ 子进程：connector-feishu / connector-gmail / connector-gitlab（stdio MCP）
  │     ├─ 飞书长连接（事件、卡片回调；待 Q6 验证）
  │     ├─ <数据目录>/work-agent.db（SQLite）   <数据目录>/companion/*.md（人格与记忆）
  │     └─ 系统凭证库：service=work-agent（凭证、本机接口令牌）
  └─▶ 宠物客户端（Tauri 2，脸）── 本机令牌 ──▶ work-agentd
```

- 数据目录：macOS 是 `~/Library/Application Support/work-agent`，Windows 是 `%APPDATA%\work-agent`；开发时用项目内的 `data/`（ADR-0014）。
- 宠物客户端退出不影响大脑运行；大脑没有运行时，宠物显示“睡着了”，并提供“唤醒”按钮。
