# 愿景与范围

- 状态：草案（待用户确认）
- 更新：2026-11-18

## 背景

- 用户角色：研发，同时承担产品工作。
- 日常工具：飞书（IM、日历、文档）、公司 Google Workspace 邮箱（Gmail）、GitLab。
- 用户目前说不清时间主要花在哪里，所以先要把时间去向弄清楚。

## 一句话定位

**一只陪伴宠物，能协助日常办公。**（用户原话：“我想做的是一个陪伴宠物，能协助日常办公”）

- 产品本身就是这只宠物：它有名字、有性格、会成长，记得用户工作中的重要事情。
- 协助办公是它的本领；所有能力最终都通过它表达出来。
- 主界面就是桌面宠物。Web 控制台是辅助界面，用来设置、看长报告、编辑记忆；飞书是用户离开电脑时的通道。
- 陪伴要落到实处：结合工作数据关心用户。比如连着开了三小时会，它提醒你歇一下；深夜还在提交代码，它会说两句。不做和工作无关的空洞互动。

## 它能帮用户做什么

在用户授权后读取工作数据，帮用户：

1. 看清时间去向，找出最耗时的环节；
2. 盯住没收尾的事：别人在等我、我答应了别人、别人欠我；
3. 提醒、起草、给出选项。用户决定后它自动执行，需要权限时它会发起授权（ADR-0007）；
4. 随着时间推移越来越懂用户：记住人、项目、决定和偏好（ADR-0012、ADR-0013）；
5. 以后可以和同事的伙伴互联，共享选定的资源（ADR-0008）。

## 设计原则

1. **逐源授权**：每个数据源都要用户明确授权后才读，可以随时断开并删除凭证。
2. **先决定，再执行**：以用户身份对外做的任何事都要用户决定过。
3. **数据留本机**：原始数据、凭证、记忆只存在本机；发给模型的内容要可控、可审计。
4. **记忆透明**：它记住的一切，用户都看得到、改得了、删得掉。
5. **陪伴但不打扰**：开会、演示时自动安静；人格让它更亲切，但不能歪曲事实。
6. **底层先行**：以后难以修改的部分先设计定型，功能按插件方式往上加。
7. **文档驱动**：所有决策和设计落到 `docs/`，实现能追溯到文档。

## 第一项能力

时间去向报告：用一到两周的数据弄清时间去向，决定下一项能力做什么。

## 暂不做

- 共享空间（M4 再做）。
