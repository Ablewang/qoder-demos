## 已实现

| 模块 | 文件 | 说明 |
|---|---|---|

| OAuth | `src/oauth.ts` | PKCE、state 单次使用并绑定 provider、令牌刷新（兼容飞书刷新令牌一次性和 Google 不重发刷新令牌） |
| 存储 | `src/db.ts` | 单表 `items`；按时间窗替换同步结果，标题不变则保留分类 |
| 飞书连接器 | `src/connectors/feishu.ts` | 主日历的日程视图；消息读取探针 |
| Gmail 连接器 | `src/connectors/gmail.ts` | 只读邮件头，区分发出、收到、通知类邮件，过滤推广和社交邮件 |
| GitLab 连接器 | `src/connectors/gitlab.ts` | 用户事件流，补充项目链接 |
| 模型 | `src/llm.ts` | LiteLLM 分类，生成观察与建议 |
| 报告 | `src/report.ts`、`src/render.ts` | 会议时长（重叠只算一次）、专注时段、类别、最耗时会议 |
| 界面与命令行 | `src/server.ts`、`src/cli.ts` | 绑定 127.0.0.1，校验 Host 和 Origin；`serve` / `run` / `probe-feishu-im` |

## 相对于正式架构的局限（总体架构必须解决）

1. 数据模型是扁平的“事项”，没有人、会话、线程等实体，也没有跨数据源的身份关联。
2. 连接器是硬编码列表，没有能力声明、增量同步游标，也没有统一的限流和重试。
3. 没有写操作和审批通道。
4. 模型调用分散在业务代码里，没有统一的脱敏、审计和成本记录。
5. 功能写死成“报告流水线”，没有能力插件和触发器（定时、事件）。
6. 没有记忆和检索层。

## 可复用

OAuth 与凭证管理、三个连接器的接口调用和字段映射、报告统计算法、本地服务的安全校验。
