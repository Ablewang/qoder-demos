## 1. 产品设定

### 1.1 名称与一句话定位

- 名称：**Lumi**；浏览器标题：**Lumi · 生活助手**。
- 页面描述：**Lumi 生活助手：穿搭、吃饭、住宿、出行和本地清单。使用模拟数据。**
- 界面品牌仅为 Lumi 文字，不加星光 Logo、渐变、口号或假账户。
- 形态：以 H5 为入口、兼容桌面的个人生活助手原型。
- 定位：用一个生活问题，获得简短建议、可操作卡片和少量继续提问的入口，减少穿什么、吃什么、住哪里、怎么走之间的切换。
- 默认背景：杭州，武林广场为出行演示起点；不代表用户真实所在地。

来源：[页面元信息](../index.html)、[应用壳](../src/App.tsx)。

### 1.2 面向谁、解决什么

| 使用背景 | 典型问题 | 本期提供的帮助 |
| --- | --- | --- |
| 城市通勤与日常生活 | 明天穿什么、这周天气怎样、午饭吃什么、怎么走 | 单日与多日天气示例、穿搭、餐厅选项、出行比较 |
| 周末城市轻出游 | 西湖玩一天、住哪里、出门带什么 | 一日行程、住宿与地点示例、准备清单 |
| 在家安排生活 | 做道简单菜、整理房间、记住取快递 | 菜谱、居家任务、确认后加入本地清单 |

这些是设计场景，不是经过用户访谈验证的结论或具体用户画像。

### 1.3 产品角色与语气

Lumi 是安静的生活工具，不是展示 AI 能力的舞台。先给结论，再用卡片展示细节；界面直接、中性，不使用陪伴口号、营销问候或交易成功暗示。既有 mock 的生活化回复保留，本轮补充了三个场景及简短过程摘要，详见 09。

| 维度 | 设定 | 体现 |
| --- | --- | --- |
| 语气 | 克制，功能与操作优先 | 今天、新对话、清单 |
| 结果 | 简短正文 + 结构化卡片 + 少量追问 | 不必读整篇攻略才找到操作 |
| 过程 | 可观察但默认收起 | 实时状态标题，可手动展开摘要与步骤 |
| 控制 | 用户决定发送、停止、收藏与确认 | 不自动创建提醒或继续重试 |
| 可信 | 说明模拟与存储边界 | 演示数据、本机保存、无后台通知、地图示意 |
| 失败 | 给出可恢复下一步 | 已停止生成、再试一次、缺少时间先追问 |

这是产品角色与文案规范，不是已接入模型的系统提示词。本期没有真实 Agent；回复来自本地规则、固定数据与有限历史，输入框不是通用 AI 服务。

### 1.4 设计原则

1. 对话为主，首页与例句帮助起步。
2. 清晰而不是堆丰富信息；不同时展示多个装饰层。
3. 按钮结果明确：展开是本地展开，收藏是本地保存，追问会发请求，百度入口是外部打开。
4. 等待、文字增量、思考摘要、步骤、卡片与结束状态各在固定位置。
5. 颜色、触控目标、焦点与状态共用底层规范。
6. 不承诺实时天气、房态、价格、路况、准点通知或已下单。

## 2. 能力范围与真实性边界

| 范围 | 实际能力 | 不应理解为 |
| --- | --- | --- |
| 穿搭 | 杭州演示天气、小时天气、多日预报、穿搭建议 | 实时天气、衣橱识别或购物 |
| 吃饭 | 餐厅示例、菜谱、食材清单、展开步骤 | 实时营业/排队、订餐、任意菜谱数据库 |
| 住宿 | 两个住宿示例、收藏/位置、居家整理任务 | 房态、预订、支付或酒店保证 |
| 出行 | 固定目的地的模拟方案、一日行程、准备清单 | 本地语音导航、实时交通、任意目的地规划 |
| 附近 | 咖啡馆与便利设施示例、位置弹窗 | 用户真实附近 POI 搜索 |
| 记事 | 有限北京时间提醒建议；直接填写事项与可选设备本地未来时间，确认后保存 | 系统闹钟、后台通知、重复提醒或通用日期解析 |
| 历史与清单 | 本机会话/清单/分区草稿/最近访问；完成、移除、8秒删除撤销；应用打开期间的阅读与卡片状态恢复 | 账户、跨设备同步、刷新后的阅读/表单/勾选/撤销恢复 |
| 地图 | 可选百度 GL 底图、标注示意图、百度 URI | 已验收真实 SDK 或已开始导航 |

路线终点示例：西湖湖滨音乐喷泉、杭州东站、灵隐寺。其他终点或不支持的出发点说明限制，不猜测路线。行程每站有位置，仅受支持的站点提供路线按钮。

## 3. 信息架构

```text
Lumi 应用壳（顶部 + / 左栏新对话；切页不停止生成）
├─ ≥1024px：左栏首页 / 对话 / 清单、历史、设置
├─ <1024px：顶栏品牌标识直接回首页；左侧菜单抽屉提供完整导航
│  └─ 首页和清单有底部快捷导航；/chat 与 /chat/{id} 无底栏
├─ 非当前会话状态条：进展 / 查看或续聊 / 明确停止
├─ 首页                              /
│  ├─ 今天 + 设备本地月日星期、演示天气
│  ├─ 穿搭 / 吃饭 / 住宿 / 出行；三条常用问题
│  └─ 输入框（home 草稿）
├─ 独立新对话                        /chat
│  ├─ 新对话 / 今天想安排点什么？
│  └─ 输入框（new 草稿）；首次发送才创建会话
├─ 历史对话                          /chat/{id}
│  ├─ 用户问题、过程摘要/计划、流式正文、十一类卡片
│  ├─ 最新回复建议；复制 / 重新生成或再试一次 / 分享
│  └─ 输入框（按会话 ID 草稿；发送键兼作停止）
├─ 清单                              /saved（无输入框）
│  ├─ 全部 / 提醒 / 收藏与待办
│  ├─ 事项、备注、可选日期时间内联表单
│  └─ 完成 / 恢复未完成 / 移除 + 独立8秒撤销
└─ 弹层：菜单、当前演示位置、设置、地点位置详情
```

“对话”优先活动会话，其次最近访问会话，再回首条历史；无历史去 `/chat`。新对话不增加空历史、不清空旧会话、不停止请求。历史标题“最近对话”，不显示条数或本机保存页脚；设置在导航底部。会话页只高亮当前历史条目，不同时高亮“对话”。

页头显示会话名、清单、新对话或 Lumi，没有口号或模拟 Badge。<1024px菜单键后有「L＋圆点」品牌首页链接，44×44px命中，不用先开菜单；≥1024px左栏「标识＋Lumi」直接回首页。两处保留URL参数与原生链接行为，不停止生成、不清草稿。首页、新空页、有效会话有输入框；清单和失效会话无输入框。失效会话展示“这段对话不在当前浏览器里”与返回首页。

来源：[App](../src/App.tsx)、[应用布局](../src/app.module.css)。

### 4.2 底层组件库

实际基础组件：Button、IconButton、Chip、Card、Badge、Spinner、Skeleton、LumiMark、Modal、ToastProvider/useToast。不把未实现的 Tabs、Rating 或独立 Drawer 组件列成已有能力；抽屉是 Modal 的 variant。

- Button：主、次、弱、危险操作，加载与不可用状态。
- IconButton：菜单、关闭等，必须有无障碍名称。
- LumiMark：复用favicon几何，默认24px，装饰SVG不进入无障碍树。手机／平板首页链接使用26px、命中44×44px；桌面品牌24px、菜单标题22px。SVG本身不承担操作，链接负责名称与键盘行为。
- Chip：追问与选项，支持选中/不可用。
- Card / Badge：内容与必要提示；生活卡片的“演示数据”为普通辅助文字。
- Spinner / Skeleton：真实 mock 等待过程，不用动画冒充已完成。
- Modal：sheet 与 drawer 两种形式；Esc、关闭键、遮罩均可关闭。背景 inert、焦点约束持有至退出结束，随后恢复入口焦点。
- 手势：手机 sheet 向下拖动关闭，<1024px菜单 drawer 向左拖动关闭；短滑回弹、纵向滚动不误关闭抽屉。输入、控件与真实地图不接管；sheet 内容仅在相关滚动容器到顶时接管。没有鼠标拖动、多档吸附或 Android 系统返回关闭。
- Toast：普通反馈约4秒；清单删除另有独立8秒撤销槽，可跨页，不等于系统通知。

来源：[共享组件](../src/ui/index.tsx)、[共享样式](../src/ui/ui.module.css)。

### 4.3 桌面与手机布局

- 左栏常规260px，≥1600px为280px；<1024px隐藏。
- 主内容独立滚动，输入框停靠底部。聊天页去掉底栏，首页与清单保留底部快捷导航。
- 首页桌面四列入口、手机两列；非当前会话有状态条。
- 发送断点768px，与导航断点不同：≥768px且非输入法组字时 Enter 发送、Shift+Enter 换行；<768px Enter 换行，点击发送。
- 保留`100dvh`与VisualViewport适配；手机／平板页头左右padding取最小间距和安全区的最大值，顶部高度加安全区。Chrome模拟视口不是软键盘或真实刘海验收。

来源：[Composer](../src/features/chat/Composer.tsx)、[应用视口适配](../src/App.tsx)。

### 5.2 对话页

目标：新问题有独立起点，旧会话可回；看进展、拿卡片、停止或恢复。

#### 独立空页 `/chat`

```text
手机：菜单 / [L· 首页] / 新对话 / 杭州 / +（无主题键与底栏）
桌面：保留左栏，页头另有主题、设置
------------------------------------------------------
[若旧会话存在：状态 / 查看或续聊 / 明确停止]
                      新对话
                今天想安排点什么？
          （没有消息、卡片或新增空历史）
------------------------------------------------------
[ 问问 Lumi                                     ↑ ]
                内容为模拟数据，仅供体验
```

首次发送成功接受后即创建UUID会话与消息、进入 `/chat/{id}`，不等待回复完成。旧请求活动时可编辑new草稿；全局拒绝第二次发送并保留草稿，明确停止或等待后再发。

#### 有效会话 `/chat/{id}`

```text
菜单 / [L· 首页] / 会话标题 / 杭州 / +
------------------------------------------------------
[若另一会话在生成：跨页状态 / 查看 / 明确停止]
                                      [ 用户问题 ]
[实时状态或完成摘要                         > ]
  手动展开：简短思考摘要、待办/进行中/完成步骤
助手增量正文（无头像、身份标签或大容器）
[ 场景图标 · 标题                    演示数据 ]
[ 数值/列表/步骤/时间/地图、具体操作与限制      ]
[后续建议，仅最新回复]
[结束状态：失败/停止/保留上次完整回复，若有]
复制 / 重新生成或再试一次 / 分享（图标组）
                               [回到最新圆形键]
------------------------------------------------------
[ 问问 Lumi                              ↑ / 停止 ]
                内容为模拟数据，仅供体验
无手机底栏；首页可点顶栏品牌，清单、历史通过菜单抽屉
```

- 用户气泡中性柔和底，助手无容器正文；不显示重复身份或“模拟响应”。会话顶部保留淡色纯文字日期，不加装饰线。
- 思考与计划合在默认收起的过程区。用户手动展开后不自动收起；只有status时是一行状态。单一结果只有简短思考，不虚构计划。
- 完成显示“已完成 N 步 · 用时 X 秒”或“已思考 X 秒”；停止、失败以未完成状态表达。精确动态模板见08。
- 卡片完整到达后展示，不逐字段生成半张表单。
- done回复重新生成：新正文/过程/卡片在请求内缓冲，只有done替换；失败或停止保留旧完整结果并显示提示。
- 切页恢复阅读位置、跟随、菜谱展开、路线方式、餐厅/酒店排序、准备清单勾选；仅本次App打开有效，刷新不恢复。数据改变不套用原卡片状态。
- 滚轮/触摸主动阅读或卡片本地操作暂停跟随；新用户消息和“回到最新”恢复。导航不停止请求。
- 复制附带卡片要点，成功图标变对勾1.5秒、title变“已复制”，无障碍名称仍“复制回复”。分享仅在支持Web Share且回复done时显示，取消不弹错误，不支持时隐藏、可用复制替代；不生成公开链接、图片或自动上传。
- 最后一条动作常显；桌面旧回复悬停/聚焦时显，触屏全部可见。失败用“再试一次”，操作不在结束提示重复出现。

## 6. 十一类生活卡片原型

| 卡片 | 内容结构 | 实际交互 |
| --- | --- | --- |
| 天气穿搭 | 温度/天气、元信息、四时段、三项穿搭、提示 | 通勤/户外追问 |
| 多日预报 forecast | 杭州未来5天；日期、符号、天气/建议、降雨%、低高温 | 高降雨日带伞提醒、对应日穿搭追问 |
| 餐厅 | 三门店的名称、评分、人均、距离、标签 | 收藏/移除、位置、按价格排序/恢复推荐顺序 |
| 菜谱 | 耗时/份量/难度、食材、四步展开、提示 | 整份食材加入/移除、步骤展开/收起 |
| 住宿 | 两住宿的名称、评分、区域、价格、标签、描述 | 收藏/移除、位置、本地价格排序 |
| 路线 | 起终点、公交/步行/驾车/骑行、推荐方案摘要、时间/距离/费用/步骤、地图 | 本地切换、百度外链；四模式在390px单行，极窄视口允许换行 |
| 一日行程 itinerary | 四站时间、标题、详情与位置 | 每站看位置，两站有受支持路线；整份行程保存为一个task |
| 准备清单 checklist | 三组九项原生勾选、已备好n/9 | 勾选仅本次应用恢复；全部保存为一个task，不生成九个条目 |
| 附近地点 | 名称/类别/距离/地址、范围说明 | 查看位置，无收藏或扩大搜索 |
| 提醒 | 北京时间、内容与边界 | 确认加入/移除本地清单，无定时调度 |
| 居家任务 | 编号、任务标题与说明 | 每项加入/移除，更轻松计划追问仍固定任务 |

通用结构：语义图标+标题+普通“演示数据” → 主要信息 → 每项动作 → 提示/范围边界 → 本地操作或少量追问。只有一层外边框，内部以分隔线与留白组织；弱操作首项与正文对齐，无灰色内面板。

所有发问按钮在任一会话生成中禁用；收藏、位置、展开、排序、路线切换、勾选仍可用。固定列表不扩大搜索。准备清单勾选与saved task的done相互独立：保存不自动勾选，完成保存项也不改变卡片勾选。

## 7. 关键用户流程与状态

### 7.1 从首页开始

```text
首页 → 概览骨架 / 异步mock → 演示天气、四入口
├─ 入口或问题 → 发送被接受 → 本机会话 /chat/{id}
└─ 新对话 → /chat 空页 → new草稿 → 首次发送才建会话
→ 实时过程标题（手动展开摘要/计划） → 增量正文
→ 完整卡片 → 最新建议 → 结束状态（若有） → 动作组
→ 本地收藏/展开/勾选/排序/位置/路线比较或下一问
→ 切首页、清单不中断；“对话”优先活动会话
```

### 7.2 请求过程、停止和失败

| 状态 | 看到什么 | 可做什么与结果 |
| --- | --- | --- |
| 待响应 | status或收起的思考/当前步骤 | 编辑草稿、停止、导航、展开过程 |
| 普通流式 | 过程摘要、增量正文与光标 | 停止；不允许第二请求 |
| 正常完成 | 正文、卡片、最新建议、复制/重新生成/分享 | 下一问或本地操作 |
| 普通停止 | 部分结果、已停止生成、未完成步骤 | 重新生成；复用问题和助手ID |
| 普通失败 | 这次没能完成请求：{原因}、未完成步骤 | 再试一次；不自动重试 |
| done再生成 | 重新生成状态，旧完整内容保留 | 停止/草稿/本地操作；新结果到done才替换 |
| 再生成失败/停止 | 旧完整结果、保留提示 | 再试一次；旧结果不标为部分结果 |
| 切页/历史/新建 | 事件继续写所属会话，非当前页状态条 | 导航、草稿、清单填写；第二发送拒绝且保草稿 |
| 刷新普通请求 | pending/streaming变aborted | 重新生成，无后台续传 |
| 刷新done再生成 | 旧done内容保留，statusText清除 | 缓冲丢弃，不保证专用中断提示恢复 |

全局只一个聊天请求。停止取消控制器，迟到事件由身份检查忽略。输入≤2000字符、空白不发；home/new/会话各自持久草稿，提交成功才清空。

过程协议：thinking字符串摘要≤2000字符；plan为1–8个唯一ID步骤；step只running/done。重复plan和未知step忽略，步骤只前进；正文开始后thinking忽略。用时在首个正文冻结，刷新保留；无过程回复不凭空生成用时。“未完成”由停止/错误状态推导，不写入步骤存储。它们是演示摘要，不是真实模型思维链或后台任务执行。

### 7.3 收藏与清单

```text
看到餐厅/酒店/菜谱/任务/行程/准备清单
→ 用户确认收藏或加入 → 本地状态与反馈
→ 按钮变已收藏/已加入，可移除
→ 清单 → 筛选 → 完成或移除 → 8秒内撤销删除
```

不因收到卡片自动保存。禁止本地写入会提示刷新可能丢失；本次不将未注入的真实写入故障算作UI验收。

### 7.4 直接填写与对话提醒分开

```text
添加小事/记一件小事 → 内联表单
├─ 取消：关闭、清错、还原焦点、保本次字段，不新增
└─ 保存：事项/备注/可选设备时间校验
   ├─ 非法/非未来/DST跳时 → 错误与字段焦点
   ├─ 无时间 → task
   └─ 有效未来时间 → reminder（ISO dueAt）
→ 本机保存；无通知；完成/移除/8秒撤销

对话提醒或“记下明晚取快递”固定例句
├─ 缺时间 → 追问，无提醒卡
├─ 重复提醒 → 说明不支持
└─ 有限北京时间解析 → 确认卡 → 用户加入
```

两套时间规则不能混用：表单为设备时区、拒绝过去；mock为有限北京时间、按规则可顺延一次。完整规则见08与09，不宣称闹钟或后台通知。

### 7.5 地图

```text
路线或地点
├─ 无AK → 有标注SVG示意 + 百度外链
└─ 有AK → 用户选择加载 → SDK
   ├─ 成功：真实底图 + 固定演示标记/线路
   └─ 失败/超时：提示 + 示意 + 重试
打开百度地图 → 第三方网页/应用处理
```

## 8. 网络、地图和数据设定

### 8.1 模拟网络

- 统一API客户端，不在业务展示直接读取fixture。
- Promise、setTimeout、真实Response、ReadableStream、SSE；不是后端HTTP，也不伪造网络面板记录。
- 首页等待约450–900ms；对话首字约500–1000ms，慢网增加延迟。计划和摘要安排在首字窗口内，不因新增过程额外拉长整体节奏；具体时序以09和mock实现为准。
- 默认失败率0，设置提供慢网、下一次失败、恢复正常；AbortSignal取消等待和流，超时覆盖完整请求。
- 关闭mock可走原生fetch，但真实服务端、认证与实时数据仍未实现。

来源：[client](../src/api/client.ts)、[server](../src/mock/server.ts)、[SSE校验](../src/api/sse.ts)。

### 8.2 地图

- 百度GL仅配置浏览器端AK且用户点击加载后接入。本次未提供AK，不申请、不代填、不填假key，真实SDK/WebGL不算已验收。
- BD-09近似点位、时间/费用/线路为mock；方向/位置参数编码，不把聊天文字当HTML。
- 不自动读取定位或把聊天内容发送给百度SDK。

来源：[BaiduMap](../src/features/map/BaiduMap.tsx)、[百度加载与链接](../src/lib/baidu.ts)。

### 8.3 本地数据

- `lumi:v1`保存会话、清单、外观、drafts（home/new/有效会话ID）、lastConversationId。草稿只接收字符串并截到2000，不存在的访问ID清空。
- 最多最近创建30段，清理淘汰草稿；标题首问前24字符串单位，历史按updatedAt降序；visit不改变排序。
- 清单去重、新项在前，可切done；撤销原位置与条目，仅本次8秒槽有效。
- 重试复用助手ID；done再生成失败/停止/刷新保留旧完整结果。
- 普通生成刷新为aborted，statusText清除；过程摘要/完成步骤/冻结用时随消息保存，无后台续传。
- 阅读/跟随/卡片展开/排序/路线/勾选为App refs；表单/筛选/首页滚动为常驻面板，仅应用内恢复，不承诺刷新恢复。

来源：[AppStore](../src/store/AppStore.tsx)、[useChat](../src/hooks/useChat.ts)。
