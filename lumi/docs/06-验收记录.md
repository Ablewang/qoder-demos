# Lumi 验收记录

## 1. 交付结论

当前验收日期：2026-11-18。

本期前端原型包含：Vite + React 18 + TypeScript、自建基础组件库、中性双主题、桌面与手机布局、首页、流式对话、思考摘要/计划进度、十一类生活卡片、会话历史和本地清单。菜单、设置、输入框和消息操作栏已精致化；方案以 [04 第9.4节](04-开发计划.md) 为准，三方评审见 [05 第8章](05-评审纪要.md)，具体实测见第13章。

未实现真实 Agent 服务端，没有部署公网。所有生活数据为 mock；提醒只是本地清单，不提供到点通知。百度地图 SDK 接入代码已实现，但未提供 AK，不能把示意地图和外链测试计为真实 GL 底图验收。

第2～12章保留前轮验收历史；操作减负见第9章、原视觉打磨见第10章、手势见第11章、去AI味减法见第12章。当前精致化、消息协议、新场景与最新验证以第13章为准，历史测试数和配色不能当作当前结论。

## 3. 桌面和手机共同通过的十类浏览器场景

1. 首页加载完成；衣、食、住、行四个入口分别得到对应卡片；回复底部不会被输入框遮挡；地图方案切换和外链参数正确。
2. 菜谱展开步骤、保存食材；提醒确认加入清单；刷新持久化；清单完成、撤销完成和移除。
3. 慢请求可以停止；重新生成不会重复增加用户问题。
4. 一次 503 失败可重试；清淡追问得到新回复；新会话不会再次消费同一次故障。
5. 主题弹窗、Tab 焦点约束和 Esc；深色主题；未知目的地不生成猜测路线，其他城市明确当前演示边界。
6. 餐厅位置弹窗、百度 marker URI、收藏与居家任务加入清单。
7. 离开活动会话时取消旧请求；下一会话正常完成，旧会话仍是中断状态且没有迟到卡片；重新打开保留中断记录。
8. 空输入不可发送、2000 字限制；Shift+Enter 换行；模拟 composing Enter 不发送；桌面 Enter 发送、手机 Enter 换行。
9. 演示位置弹窗明确未请求定位权限；附近便利设施卡片和位置弹窗可用。
10. 320 / 375 / 768 / 1024px 宽度没有文档横向溢出，输入入口保持可达。

自动化输入法用例是模拟浏览器 KeyboardEvent，不等于真实中文输入法、iOS/Android 软键盘或微信内置浏览器验收。

## 4. 集成修整与首轮失败记录

- 修正默认午饭入口和“住一晚”的意图识别，避免被泛化的附近搜索吞掉。
- 一次故障改为内存消费键，不使用原生 history.replaceState 修改 Router 管理的地址；设置可显式重新触发一次故障。
- 未知目的地、不同出发点和其他城市明确限制，不静默生成杭州猜测路线。
- 只有简短追问继承上下文，旧西湖问题不再影响新的未知目的地问题。
- 提醒缺少时间先追问，重复提醒明确不支持；不同标题同一时间的清单 ID 不冲突。
- 修正手机城市入口被样式隐藏的问题，插画前景使用共享主题 token。
- 对话内容使用 ResizeObserver，懒加载卡片变高时继续跟随底部；用户主动滚离底部时不强制拉回。

首轮 14 项浏览器测试有 2 项桌面失败，页面观察到回复中途结束，且该轮运行期间仍在修改源码。停止源码修改后，两项独立复测均通过；随后完整 20 项测试均通过。没有通过放宽超时或跳过失败用例来交付。

同时修正测试完成断言：只检查当前最后一条助手回复，避免新回复失败时误匹配上一条“模拟响应”。测试期间固定源码，避免热更新影响活动请求。

## 6. 明确未验证与不支持项

### 待配置或真机验证

- 百度 AK、授权域名/Referer、真实 GL 底图加载、真实 SDK 绘制/卸载和设备 WebGL。单元测试中的 SDK 替身不替代这些验收。
- 外部百度网页实际可达性、百度 App 唤起、第三方路线结果；当前已验证本地链接地址与参数，没有把外部服务结果算作完成。
- 真实 iOS / Android / 微信浏览器、软键盘、安全区、手势、屏幕阅读器。手机视口和 CSS 安全区支持不等于真机验证。
- 浏览器禁用 localStorage 或容量耗尽时的真实 UI 操作。本地写入异常提示已实现，但本次浏览器脚本未注入此故障。
- 页面级超时恢复未单独浏览器测试；完整请求超时、reader 取消、计时器释放和中文超时异常已单元测试。

### 本期不提供

真实 Agent、实时天气/价格/房态/路况、登录、云同步、实时定位、下单预订、支付、后台通知、系统闹钟和重复提醒。

接入百度底图时按 README 配置浏览器端 AK 并重启开发服务；接真实 Agent 时按统一 API / SSE 协议实施服务端及认证，不将关闭 mock 开关视作后端已完成。

## 11. 手势与退出过渡验收（2026-11-17）

用户反馈“bottom sheet 的手势关闭”未实现。原有把手只用于装饰，本轮补齐真实触屏操作；方案见 04 第 7 章，独立移动交互／架构评审及采用条件见 05 第 6 章。

### 本轮交付

- 手机≤767px的菜单、设置、演示位置及卡片地点弹层共用下拉关闭：入场结束后可拖把手／标题栏；内容区只有从触点到弹层的所有滚动容器均在顶部、向下拉且浏览器事件仍可取消时接管。普通竖向滚动、嵌套历史滚动、输入控件和真实地图区域不抢手势。
- 位移跟手，仅独立遮罩变淡；向上拉有阻尼。下拉达到高度25%（最低48px、最高120px），或位移超过24px且最近80ms速度≥0.6px/ms时关闭，否则240ms回弹。取消触摸只回弹。
- 关闭按钮／Esc／遮罩／下拉统一退出过渡：手机从当前位置下滑出屏，桌面淡出，结束后卸载、归还焦点、释放背景inert及滚动锁；退出期间阻止重复点击。菜单导航和菜单→设置保持即时切换。减少动态效果时保留跟手，但回弹和退出立即完成。
- 清单触屏左滑移除、右滑完成／取消完成，未过阈值回弹，无滑开驻留态；先竖向移动交给页面滚动，pointercancel不执行，鼠标不启用，屏幕两侧16px内不接管。按钮及键盘操作保留。
- 删除门槛为条目宽度40%（最低64px），完成门槛35%（最低64px）；同向快速滑动速度≥0.6px/ms时，删除至少72px、完成至少48px。手势删除先180ms退出（减少动态效果时立即），再按id查最新条目及位置；原8秒跨页撤销恢复id、位置、完成状态和日期。
- 阈值越过时可选8ms振动，仅支持设备且已有用户激活时尝试，不承诺iOS支持。未新增依赖，没有修改mock、真实后端或地图授权边界。

### 发现的问题与处理

1. 多日天气原先逐行堆叠信息过高，改为雨概率／温度右侧紧凑排布；行程操作对齐、卡片ghost首项缩进统一。
2. 路线四按钮虽处于同一flex行，中文仍折成两行。增加文字nowrap、窄屏横向内距8px；≤340px允许整颗按钮换行，不逐字竖排，不放宽溢出检查。
3. 首页截图原先可能仍是加载骨架，改为等待“演示天气”出现；卡片合辑原先吸顶栏遮挡路线标题、“回到最新”覆盖内容，完整组件捕获时临时增高视口、隐藏应用壳与悬浮键，恢复真实视口后继续操作。没有修改应用布局以迁就截图。
4. checklist原提示“逐项完成”与整份task保存不一致，改为“勾选只在这张卡片里记录；加入清单后按整份保存，可在「清单」页标记完成。”并补精确浏览器断言；没有偷偷拆成九条任务。
5. 阅读恢复测试原采样位置距底部不足90px，按现有跟随规则本就会追底。改为采样至少距底120px的阅读位置，生产近底门槛未改。
6. 最终复跑有1项mock流中取消单测超时：测试每次仅推进100ms虚拟时钟就等待下一事件，而随机剩余延迟可能超过100ms，停止推进导致死等。改为异步消费事件并持续驱动计时器，首次delta就取消；检查AbortError、无后续卡片／done和计时器清空，增加0／0.5／0.999固定随机值。相同逐事件等待模式的慢网用例也改为持续驱动。不放宽5000ms测试超时，不修改生产取消或延迟规则。
