## 4. 对话与输入框

### 4.1 Composer

来源：Composer／Composer；App／draftKey、send；Store／load、appReducer。

| 类型 | 当前原文／行为 |
| --- | --- |
| 输入框 ARIA | 向 Lumi 提问 |
| placeholder | 问问 Lumi |
| 发送／停止 ARIA | 发送消息／停止生成 |
| 页脚 | 内容为模拟数据，仅供体验 |

不再显示“Enter 发送 · Shift + Enter 换行”。交互仍是 ≥768px 且非组字 Enter 发送、Shift+Enter 换行；<768px Enter 换行、按钮发送。最多 2000 字，无计数器；空白不发送，提交 trim。首页／new／会话 ID 分区草稿持久保存，只有成功接受发送才清当前草稿。当前会话忙碌时可编辑、按钮停止；其他页仍可输入，发送被全局忙碌保护拒绝并保草稿，不创建空会话。清单与失效会话无 Composer。

### 4.2 消息、单一过程区与结束状态

来源：Chat／Chat、ProcessBlock、processLabel、isLive、isGenerating；UseChat／send、stop；Store／applyEvent、settle。

对话不显示重复身份名与“模拟响应”，读屏仍有“Lumi 回复”。会话顶部保留淡色创建日期，格式为zh-CN设备本地月日、无年份；不是消息气泡内的身份标记。用户为右侧正文，助手为正文与卡片；消息区域role=log、aria-live=off、ARIA“与 Lumi 的对话”。

**只有一个默认折叠的 process 区域：**收到 thinking 或非空 steps 才显示；展开在同一个区内显示模拟过程文字与计划步骤，不把 thinking 和 plan 分成两个独立面板。这是本地演示解释与进度，不是实际模型思维或真实工具执行。无过程的等待仍显示服务状态／“正在加载…”。本次 App 会话中按消息 ID 保存开合，刷新不恢复。

| process 条件 | 折叠按钮原文／模板 |
| --- | --- |
| pending／streaming | 首个 running step 的 title；无 running step 时“思考中” |
| aborted 且有步骤 | 已停止 · 完成 {done数}/{总数} 步 |
| error 且存在未完成步骤 | 第 {第一个非done下标+1} 步未完成 |
| done 且有步骤、thinkingMs 有值 | 已完成 {总步数} 步 · 用时 {秒数} 秒 |
| 无步骤或 error／aborted 的时间兜底，thinkingMs 有值 | 已思考 {秒数} 秒 |
| 时间无值的兜底 | 思考已中断 |

秒数 = `max(1, round(thinkingMs / 1000))`，不是实时秒表；thinkingMs 是有过程时从助手 createdAt 到首个 delta 的毫秒耗时，不是所有步骤总用时。done 有步骤但无耗时也显示“思考已中断”；error 所有步骤都 done 时按耗时兜底。步骤结束后非 done 的可见注为“未完成”；读屏后缀依次“，已完成”“，未完成”“，进行中”“，未开始”。running spinner、pending 点与 done check 为隐藏装饰。

| 状态／类型 | 当前原文／模板 | 说明 |
| --- | --- | --- |
| 初始服务状态 | 正在理解你的需求… | 有过程后不与 process 并列重复显示 |
| 无卡分支第二状态 | 正在整理适合你的建议… | 无 thinking／plan 的分支 |
| 普通正文 | {模拟回复全文} | delta 增量，见09 |
| 完整再生成初始 status | 正在重新生成，原回复已保留… | 旧正文／卡片不清空 |
| 再生成进展 status | 重新生成中 · {服务状态或running step标题} | 新过程与正文缓冲，不实时替换旧结果 |
| error ending（role=alert） | 这次没能完成请求{有error时“：”+error} | 简洁单行结尾，无旧大重试区块或网络兜底段落 |
| aborted ending | 已停止生成 | 不再显示“已收到的内容为部分结果”长段 |
| done 再生成停止 notice（role=status） | 已停止重新生成，原回复已保留。 | 保留旧完整结果 |
| done 再生成失败 notice | 重新生成未完成，原回复已保留。{错误信息} | 紧接错误，不另加“已保留上次完整回复”标题 |
| 回到最新 ARIA／title | 回到最新 | 离底约90px出现，恢复跟随 |
| 隐藏 live status | Lumi 正在回复，你可以停止生成。／回复已结束。 | 当前生成／其他状态 |

完整 done 再生成在请求内缓冲 thinking、plan、step、delta、card、suggestions；**仅收到 done 才原子替换旧结果**。失败／停止恢复旧 done、卡片、过程与追问；刷新保留旧 done、清 statusText、丢弃缓冲，不续传，也不额外承诺刷新中断 notice。普通 stopped／error 保留已收到的部分正文与过程，不补齐未收到卡片。

阅读位置／跟随、菜谱展开、路线方式、价格排序、checklist 勾选与 process 开合只在当前 App 会话的 viewState refs 保留；卡片 key 含消息 ID、下标及完整 JSON，数据改变不复用旧卡状态。刷新仅恢复持久的消息与清单，不恢复这些阅读交互。

### 4.3 回复动作

来源：Chat／copy、share、replyText、cardSummary、actions。

- 非生成中的消息才显示动作。复制仅在有正文或卡片时显示：ARIA“复制回复”，title“复制”；成功 check 与 title“已复制”约1500ms后恢复，无“回复文字已复制”成功 Toast。
- 复制／分享文本为 trim 正文 + 每张卡片的摘要，以换行连接，不包含 thinking／steps、错误 notice 或追问。摘要见09第12节。
- 最后一条助手，或任何非 done 助手可重试：普通 ARIA／title“重新生成”；error 或带保旧 error 的 done 为“再试一次”。busy 禁用。复用原问题与助手 ID，不重复用户消息。
- 分享的ARIA／title为“分享”，仅done且支持navigator.share时出现；不支持时隐藏，可改用独立复制按钮，不自动回退clipboard。用户取消分享不提示错误，其他分享异常／复制权限拒绝见第10节。原生分享交由用户在系统面板选择，不生成公共会话URL。
- 桌面精细指针下，较早消息动作默认低显露、hover／焦点显示；不是删除动作。
