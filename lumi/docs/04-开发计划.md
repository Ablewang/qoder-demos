# Lumi 开发计划

## 1. 本期目标与边界

交付可本地运行、可构建的 Vite + React + TypeScript 生活助手 H5，同时适配桌面浏览器。用同一套自建底层组件与设计 token 实现统一风格。衣、食、住、行通过对话及结构化卡片连接；日程作为本地轻量能力。

不实现 Agent 服务端，不部署公网，不接入登录、支付、订餐、订房或设备通知。所有天气、商家、费用、路线时长与 Agent 回复都明确标记为模拟数据，不能当作真实决策依据。百度地图底图是独立可选的真实第三方集成：有 AK 时加载真实地图，没有 AK 时展示示意与百度地图跳转。

## 2. 分阶段计划

| 阶段 | 工作 | 产出 | 验收标准 |
| --- | --- | --- | --- |
| A：产品探索 | 产品经理、视觉设计师、架构师并行讨论 | 产品设计、设计规范、技术方案 | 每类场景都有用户问题、卡片、可执行交互；MVP 边界明确 |
| B：方案对齐 | 主负责人评审冲突，形成统一落地约定 | 评审纪要、开发计划 | 唯一的 token、响应协议、目录及 mock 策略 |
| C：基础建设 | Vite 工程、TS 严格模式、基础组件、网络层 | 可复用 UI、fetch-compatible 客户端、SSE 流 | 业务不直接使用 mock 数据；可取消、可超时、可重试 |
| D：功能实现 | 首页、对话、历史、本地提醒、衣食住行卡片、百度地图封装 | PC + Mobile 完整主流程 | 所有入口和操作有结果，没有空按钮 |
| E：验收与修整 | 类型检查、构建、自动测试、浏览器实测 | 验收记录 | 桌面与移动端无横向溢出；失败/停止/重试可恢复 |

## 3. 实施顺序与依赖

```text
产品 / 设计 / 架构文档（并行）
  → 协议与视觉规范评审
  → 基础组件与 mock 网络（可并行）
  → 对话状态机与业务卡片（可并行）
  → 百度地图与本地持久化
  → 集成、PC / Mobile 浏览器走查
  → 构建与交付记录
```

主负责人：协议对齐、应用壳、首页、对话状态机、集成和最终验收。
产品角色：使用场景、范围控制、文案和动作真实性。
设计角色：视觉层级、组件状态、响应式和无障碍。
架构角色：请求边界、流式协议、取消/超时、地图生命周期。
实现期间采用独立文件责任边界，避免多人修改同一文件。

## 4. 工程约束

- 项目独立放在 `lumi/`，不修改工作目录中的其他工程。
- React 18、TypeScript 严格模式、Vite；图标使用 Lucide 线性图标。
- 样式使用 CSS 变量 + CSS Modules，业务样式不自行定义另一套按钮/间距/颜色。
- 请求统一经过 API 客户端，mock 使用 Promise + timeout + Response + ReadableStream，保持 fetch / SSE 体验。
- 环境变量控制 mock 与真实 API 切换；失败率默认 0，演示错误使用明确调试开关，不能随机破坏正常体验。
- 当前城市默认为杭州演示，不声称通过定位识别用户所在城市。
- 网络状态不能通过固定动画伪造，流式状态由实际收到的事件驱动。
- 会话和清单仅保存在本机浏览器；不自动采集或上传个人数据。
- 只对地图调用百度第三方；URL 参数编码，不把用户文本拼进 HTML。

## 6. 操作减负迭代方案（2026-11-17）

用户反馈常用入口难找、操作疲劳。本轮先以手机/平板首页、清单、恢复对话各两步的实测为依据，再独立评审方案，收敛后实施；不重做视觉、不增加后端或依赖。

| 顺序 | 实施方案 | 验收门槛 |
| --- | --- | --- |
| 1 | 手机/平板常驻“首页 / 对话 / 清单”，桌面侧栏对应入口；“对话”回活动或最近访问会话，“新建”进入独立空对话页，首次发送才建记录 | 三条路径各一步；回首页不新建记录；历史与新建含义明确 |
| 2 | 切页保留单活动请求，非对话页显示进度、查看与停止；只有显式停止或刷新才中断 | 请求始终写原会话；忙时新问题不发送、不丢草稿、不自动排队 |
| 3 | 首页、新对话、各会话独立持久化草稿；本次页面会话内保存滚动位置、菜谱展开与路线选择 | 切页/历史切换恢复状态；展开不突然追底；迟到的布局恢复不覆盖用户滚动 |
| 4 | 清单移除聊天大输入框，就地新增事项：标题1–80字、备注最多300字、可选设备本地日期时间；确认后保存任务或提醒 | 空标题不可保存；过去/无效时间明确提示；取消不创建；保存即见，仍无通知 |
| 5 | 删除用独立8秒撤销槽恢复原位置及完成状态，普通提示不能覆盖；多次删除只撤销最后一次 | 跨页可撤销；防重复恢复；刷新不承诺恢复撤销槽 |
| 6 | 完整回复重新生成时保留旧内容，新结果完整后替换；失败/停止/刷新仍保留原成功结果 | 不重复用户消息；历史只取目标问题之前；无完整原结果仍走普通重试 |
| 7 | 固定餐厅/酒店/附近数据改成本地排序或比较；路线切换现有方案，明确有限示例范围 | 不用新请求冒充新推荐；无“扩大搜索”的虚假动作 |
| 8 | 集成、构建、单测、桌面/手机Chrome实测；同步原型、文案、数据规则、截图与验收 | 320/375/390/768/1024/1440px、双主题、慢网、失败、导航、编辑与撤销覆盖；未真机项目明确保留 |

草稿随本地会话保存；阅读/卡片状态仅在当前应用打开期间保持，不宣称刷新后恢复阅读位置。最近访问会话与更新时间分开记录。表单设备时区与Agent生成的北京时间明确区分。768–1023px也适配可视视口，安全区仅由最底层导航计算。

本轮实施与验收已完成：最新版生产构建、134项单元测试、38项桌面/手机浏览器回归全部通过；直接事项、跨页撤销和新对话草稿另有专项Chrome操作及截图。首轮阅读恢复测试的变量作用域错误已修正并独立复测后重跑全量；实际过程和未验证边界见06第9章。

## 7. 手势与过渡交互方案（2026-11-17）

用户反馈“bottom sheet 不能手势关闭”等交互缺失。本轮逐项排查了移动端常见手势，发现三类缺口：底部弹层只画了把手，不能拖动；所有弹窗点关闭后会瞬间消失，没有退出过渡；清单只能点小按钮完成或删除。本轮不改视觉风格、文案语义和数据，不新增依赖。

| 顺序 | 实施方案 | 验收门槛 |
| --- | --- | --- |
| 1 | 手机宽度（≤767px）底部弹层支持触屏下拉关闭：把手与标题栏在入场结束后可拖动；内容区从触点到弹层的所有滚动容器均在顶部且向下拉时接管；真实地图、输入框等区域不接管。跟手位移、仅遮罩变淡，向上拉有阻尼 | 下拉超过弹层高度 25%（最低 48px、最高 120px），或位移超过 24px 且最近速度 ≥0.6px/ms 即关闭，否则回弹；正常滚动不被打断；松手不误触按钮 |
| 2 | 关闭按钮、点遮罩、Esc、下拉关闭统一走退出过渡：手机下滑出屏，桌面淡出；动画结束后再卸载并归还焦点。导航类关闭（菜单内跳页）保持即时 | 过渡期间不重复触发关闭；系统“减少动态效果”时立即关闭；原焦点归还、背景 inert 解除逻辑不变 |
| 3 | 清单条目触屏横滑：左滑露出“移除”，右滑露出“完成/取消完成”；越过阈值松手执行，否则回弹，不保留滑开态。删除仍走 8 秒撤销槽；鼠标不启用，原按钮保留 | 左滑门槛 40%（最低 64px）；右滑 35%（最低 64px）。同向快扫速度 ≥0.6px/ms，删除至少 72px、完成至少 48px；竖向移动交给页面滚动；取消不执行；屏幕两侧 16px 内不接管 |
| 4 | 越过阈值时可选触觉反馈（设备支持振动且已有用户激活，单次 8ms），回到阈值内可再次触发一次 | 不支持的设备静默跳过；减少动态效果时保留跟手，回弹和退出立即完成 |
| 5 | 手势判定抽成纯函数做单测；手机 E2E 用 Chrome 真实触摸事件（CDP）覆盖下拉关闭、回弹、内容区滚动、横滑删除/撤销/完成；桌面确认无拖动 | 构建、单测、全量 E2E 通过；同步原型、文案与验收文档 |

不做：Android 返回键关闭弹层（需额外写入浏览器历史，会与菜单内跳页冲突，留到下一期与路由一起设计）、下拉刷新、长按菜单。

本轮已完成：构建和140项单测通过，全量浏览器回归50项通过、桌面触屏专用6项跳过；最终手势专项复测12项通过。首轮跟手／速度采样修正、键盘操作复测、双主题截图及真实设备边界见06第11章。

## 8. 视觉与文案减法（2026-11-17）

用户确认“去掉一些 AI 味”，本轮只减包装，不砍功能，不修改 mock 回复、请求协议、地图逻辑或已验收的手势。

1. 首页去掉营销横幅、渐变、问候、生活鸡汤与大字水印；以日期、天气、四个生活入口和三条常用问题组成普通工具首页。
2. 应用壳去掉星光标记、口号、假个人空间和重复快捷提问；保留首页／对话／清单、历史和设置。输入框直接写“输入问题”，不诱导闲聊。
3. 卡片去掉副标题与餐厅／酒店占位插画，保留正文、语义图标、评分星、模拟来源及全部操作；平面中性色取代多色装饰，主色只用于操作与选中。
4. 保留浅深主题、44px 操作目标、焦点、mock 请求等待／错误／重试、清单撤销与下拉／横滑手势。
5. 更新受影响的精确文案断言；构建、单测与全量桌面／手机浏览器回归后，同步当前原型、完整文案、截图和验收记录。历史视觉方案保留为迭代记录，不再描述为当前版本。

本轮已完成：最终构建、140项单测与50项浏览器回归通过，桌面触屏专用6项跳过；样式收尾后两设备首页专项再次通过。双主题布局、八类卡片、手势与18张更新截图见06第12章。

## 9. 精致化与消息类型规范（2026-11-18）

用户反馈：①移动端菜单和设置不好看；②整体发“脏”，输入框尤其明显；③希望多几种场景卡片，并规范回复类型（思考中、计划、任务等）；④消息底部操作栏要优化；整体参考 ChatGPT、DeepSeek、豆包的精致度。

改造前截图（`/tmp/lumi-shots/before/`）诊断出的“脏”的来源：蓝灰页面底色 #f4f6fa 与白卡片、灰内块三层叠色；控件统一用深灰 #8793a4 描边（输入框、建议、主题选项、次要按钮）；天气卡三层嵌套灰块；用户气泡为高饱和主色；操作栏只有孤立图标、文字按钮和最右侧“模拟响应”；菜单里“新对话”粗边按钮、“对话”导航与历史条目同时高亮两处。

### 9.1 方案

| 编号 | 方案 | 验收门槛 |

### 9.2 回复类型规范

一条助手回复由以下固定槽位从上到下组成，每类只出现在自己的位置：

| 槽位 | 类型 | 来源 | 呈现 |
| --- | --- | --- | --- |
| 1 | 等待状态 | `status` | 尚无思考与计划时显示一行转圈文字 |
| 2 | 思考 | `thinking`（文本增量） | 可折叠区：生成中标题为“思考中”，展开显示浅色思考摘要；正文开始后自动收起为“已思考 N 秒”；用户可再次展开 |
| 3 | 计划与任务 | `plan`（步骤列表）+ `step`（单步状态：running/done） | 与思考同一折叠区下方的步骤清单：待办空心点、进行中转圈、完成对勾；收起时标题汇总“已完成 N 步”；停止或失败后未完成步骤显示为“未完成” |
| 4 | 正文 | `delta` | 无容器正文，流式光标 |
| 5 | 结果卡片 | `card` | 11 类结构化卡片 |
| 6 | 后续建议 | `suggestions` | 浅色胶囊 |
| 7 | 结束状态 | 本地状态 | 失败、已停止、保留原回复 |
| 8 | 操作栏 | 本地 | 复制、重新生成、分享 |

约束：思考为“理解与依据摘要”，不是冗长推理；不出现星光、渐变或拟人化表情；闲聊和拒答（非杭州城市）可以没有计划步骤。思考时长由客户端在收到首个正文时计算，刷新后保留。重新生成期间新事件仍缓冲，原回复保持可见，顶部状态显示当前步骤名。

不新增依赖，不接真实服务，不做点赞点踩（无处上报会成为假反馈），不做 Android 返回键关闭、语音输入、附件上传。本轮也不做会话分组／重命名／单条删除、清空本机数据（列入下一期）。

### 9.4 评审后修订（以本节为准，覆盖 9.1、9.2 中的冲突项）

三方评审纪要见 05 第 8 章。合并后的实施口径：

1. **底色与强调色**：采用视觉评审的完整 token 表（浅色 bg #ffffff、sidebar #f9f9f9、soft #f4f4f5、hover #efeff0、selected #e7e7e9、分隔线 #ececee、卡片／输入框线 #e3e3e3、控件线 #8e8e93、正文 #1f1f1f、muted #5d5d5d、faint #6e6e6e；深色 bg #1c1c1e、sidebar #161618、soft #2c2c2e、hover #2a2a2d、selected #333336、分隔线 #2c2c2e、卡片线 #3a3a3c、控件线 #76767b、正文 #ececec、muted #aeaeb2、faint #98989d）。主操作色改为近黑／近白；蓝色 accent（#2563eb／#7aa7ff）只用于链接、焦点环和地图路线。深色卡片底等于页面底。深色色板只保留一份：首屏前由 `index.html` 内联脚本按本机设置写入 `data-theme`。
2. **移动端底栏**：会话页与新对话页隐藏“快捷导航”底栏（菜单抽屉提供首页／清单），首页与清单页保留；移动端页头去掉主题切换（移到设置），只剩菜单、标题、城市、新对话。桌面不变。
3. **过程区（原槽位 1–3 合并）**：思考与计划合为一个无容器折叠行，生成中也默认收起，标题行即为实时状态（转圈＋当前步骤名，无步骤时为“思考中”）；用户手动展开后不再自动收起。标题按状态固定：完成“已完成 N 步 · 用时 X 秒”（无步骤为“已思考 X 秒”）；停止“已停止 · 完成 a/b 步”；失败“第 k 步未完成”；无用时记录时为“思考已中断”。用时＝请求发出到首个正文。没有思考和计划时只显示一行 status。天气、菜谱等单一结果不出计划，只出简短思考，避免装出过程。
4. **协议时序**：`status → plan → step(s1 running) → thinking… → s1 done / s2 running → delta… → 末步 done → card → suggestions → done`；计划与思考都在原首字延迟窗口内，首字仍 500–1000ms、总时长不变；末步必须在卡片前完成。校验：thinking 文本为字符串；plan 1–8 步、id 唯一非空；step 状态仅 running/done；新增意图 `day_plan`、`checklist`；未知事件仍整体拒绝。
5. **状态语义**：未知 step id 忽略；步骤只前进不回退；重复 plan 忽略；首个正文后的 thinking 忽略；thinking 截断 2000 字。`thinkingMs` 由带 `at` 的事件在首个正文时计算。“未完成”在渲染时由 `aborted/error` 推导，不写入存储。重试／重新生成创建新消息体时显式清空 thinking/steps/thinkingMs；重新生成期间旧回复上方始终显示“重新生成中 · 步骤名”。
6. **结束状态与操作栏**：后续建议只在最后一条回复显示；停止与失败也显示操作栏，“重新生成”只在操作栏出现一次（结束状态只剩一行文字）。图标按钮名称保持“复制回复”“重新生成”，新增“分享”（无 Web Share 时隐藏）。复制成功图标变对勾 1.5 秒，不再弹提示；复制内容附带卡片要点。桌面端非最后一条用透明度隐藏、聚焦可见；触屏常显且按钮 40px。文案：“重试重新生成”改“再试一次”，“已停止生成，已收到的内容为部分结果”改“已停止生成”，占位“输入问题…”改“问问 Lumi”。
7. **新卡片操作**：forecast 第一天与今日数据一致，操作为发送“周六穿什么”“提醒我周六早上八点带伞”；checklist 卡片内可勾选（状态随阅读状态恢复）并可“全部加入清单”；itinerary 每站“看位置”，只有武林广场出发可达的西湖／杭州东站／灵隐寺给“看路线”，整份行程可加入清单。意图顺序：reminder > checklist > day_plan > route > recipe > weather > …；“我的清单”不触发 checklist。
8. **菜单抽屉**：宽 min(300px, 85vw)，侧栏底色，无圆角；对话框名称“菜单”，视觉标题“Lumi”；导航行 44px、历史行 40px；“历史会话”导航即唯一滚动容器；运行中圆点移到对应会话行；去掉计数与“仅在本机保存”（移到设置）。手势在 <1024px 启用，锁 x 轴向左跟手、向右阻尼，锁 y 轴放行滚动；退出动画名纳入 `drawerOut`；减少动态效果同样生效。
9. **设置**：分组标题＋无底色列表；外观为分段控件（role=group“外观”，按钮名不变）；演示网络改单选三行“正常网络／模拟慢网络／下一次请求失败”，当前项以对勾与“当前”标示（不进入按钮名称），一次性失败被消费后自动显示为正常；“恢复正常”按钮保留名称、仅在有演示状态时可用。
10. **卡片减重**：单层卡片（1px #e3e3e3、圆角 16、移动端内边距 16），卡内无灰底块；天气卡用分隔线；地点／任务图标去色块；卡内按钮统一 32px 视觉（44px 命中）、浅填充无描边、圆角 8。建议胶囊 36px、浅描边透明底。

### 9.6 品牌标识与一键首页（2026-11-18）

用户补充对话页需要快速回到首页，并建议使用形象图标或现有favicon。本轮复用favicon的圆角方块「L＋圆点」，不使用附件中的机器人／闪光星：保持安静生活工具定位，不新增装饰头像或依赖。
