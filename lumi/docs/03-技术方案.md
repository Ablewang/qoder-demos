## 1. 技术选型与依赖
- Vite 7.x + React 18.3.1 + TypeScript 5.9.x：SPA、快速 HMR；保留 React 18，不引入 SSR 框架。
- react-router-dom 6.30.x：`/` 为首页/对话空态，历史会话可定位到 `/chat/:conversationId`；地图是覆盖视图，不另建页面。
- **zustand 5.x**：消息按 ID 订阅，避免 Context 在每个 delta 时广播全树；状态迁移由纯 reducer 执行，便于测试。
- Context + useReducer 适合低频共享状态，但本项目需额外拆 Provider/选择器；zustand 的一个小依赖更务实。
- CSS 变量 + CSS Modules，lucide-react 具名导入；原生 fetch/Streams/AbortController，不引入 axios 或 SSE SDK。
- 日期用 Intl，ID 用 crypto.randomUUID，className 自写 cn；本期纯文本展示，不引入 Markdown/日期/大型 UI 库。
- 版本为兼容基线而非“最新”声明；实施时选择对应版本线的安全补丁、提交 lockfile，CI 用 npm ci。
- 使用 Node 24 LTS；Vite 7 最低要求 Node 20.19+/22.12+，当前环境 24.22.1 满足要求。

## 3. 底层组件库与 tokens
- props 继承原生属性；回调 onXxx，布尔 disabled/loading/open；variant=primary/secondary/ghost/danger/link，size=sm/md/lg。
- 可聚焦组件用 React 18 forwardRef，具名导出 Props/displayName；所有组件支持 className，用 cn 过滤空值后拼接。
- 输入用 value/defaultValue；浮层用 open/defaultOpen + onOpenChange；生命周期内禁止切换受控/非受控模式。
- Button 默认 type=button，loading 设置 aria-busy 并防重；IconButton 强制中文 aria-label；导航使用 a，不用 div 点击。
- Textarea 配 label/id、aria-invalid/describedby；生成中仍可编辑；手机 Enter 换行，PC Enter 发送，IME composing 时不发送。
- Dialog 封装原生 dialog.showModal，支持 drawer/sheet/modal 的布局变体；打开管理焦点/背景 inert，关闭归还焦点。
- Chip 使用 button，只有筛选切换才用 aria-pressed；只读标签不可加 tabindex；卡片含按钮时禁止外层再包 button。
- 消息列表与独立 polite 状态区分离，播报步骤变化/完成而非逐字播报；错误一次 alert，焦点环和热区≥44px。
- reduced-motion 下禁用入场/平滑滚动，光标常亮、骨架静止；loading 保持尺寸，颜色不是唯一状态信息。

组织：tokens.css 保存 primitive + semantic，themes.css 覆盖主题，组件尺寸引用 02 的 component/layout 变量，不发明同义色名。

## 4. API 协议 v1 与完整类型
使用产品 snake_case 字段、9 个 intent、7 类卡片；不另设 weather/outfit/food 等同义 intent。单轮 0～1 卡片。
时间 ISO 带时区，日期 YYYY-MM-DD；温度℃、金额元，距离/时长按产品指定字段单位，不统一偷换为米/秒。
产品 wire 判别字段 card_type 保留；API 边界规范化为 Card.type 供 React 穷举渲染，业务 data 字段原样保留。
技术扩展：protocol_version/conversation_id/seq、history、retryable，以及推荐路线 polyline；不改产品展示字段。

| Method | Path | 请求 | 成功响应 |
|---|---|---|---|
| GET | `/api/home/overview` | query: HomeQuery | 200 JSON HomeOverview |
| GET | `/api/conversations` | 无；本期不分页 | 200 JSON ConversationList |
| POST | `/api/conversations` | CreateConversationRequest | 201 JSON ConversationSnapshot；已有 ID 返回 200 |
| GET | `/api/conversations/:id` | path: ID | 200 JSON ConversationSnapshot |
| PUT | `/api/conversations/:id` | ConversationSnapshot | 200 JSON ConversationSnapshot；path/body ID 一致 |
| DELETE | `/api/conversations/:id` | path: ID | 204 无 body；幂等 |
| POST | `/api/chat` | ChatRequest | 200 `text/event-stream; charset=utf-8`，SSEWireEvent |
| POST | `/api/reminders/:id/confirm` | ConfirmReminderRequest | 200 JSON ReminderResult；id 等于 draft.reminder_id |

JSON 失败 ErrorResponse：400 参数、404 不存在、409 冲突、429 限流、500/503 服务异常；非 2xx 不解析 SSE。
界面错误码沿用产品 timeout/network_error/server_error/stream_interrupted，另有 storage_unavailable/map_load_failed。
SSE message_id 必须等于请求目标助手 ID；seq 从 1 单调递增，重复忽略、缺号报协议错；一个 done 或 error 后关闭。
HTTP 200 后业务异常发 error，不能再改 HTTP 状态；传输断流直接读流拒绝；未收到终态的 EOF 是失败。
卡片可先收到完整 card 事件，但存入临时缓冲；**done 原子提交卡片和 chips**。error/aborted 丢弃临时可执行结果。
不使用 EventSource：POST body、取消、鉴权由统一 fetch 客户端处理。wire→Card 的结构规范化只发生在 API 边界。
外部 JSON 先作为 unknown 校验版本、联合字段、数值/长度/URL/坐标；不以 `as SSEEvent` 代替 guard。
未知卡片/intent 保留文字并提示“不支持的内容”；未知事件/协议版本终止流，避免将缺失结果判为成功。
## 5. Mock 网络层详细设计
### 5.1 选择与架构

| 维度 | MSW 2.x | 自研 fetch 适配层 |
|---|---|---|
| 网络真实度 | 拦截浏览器请求，Network 面板/第三方客户端联调方便 | 原生 Request/Response/Streams，无实际 HTTP 往返 |
| 流式/取消 | 支持 ReadableStream，仍需验证 SW/浏览器/测试环境差异 | 直接控制分块、背压、signal、中途故障 |
| 成本/扩展 | 依赖、worker 文件、注册时机、HTTPS/作用域；适合复杂接口 | 少量路由/延迟/流代码；本期端点可控 |

**选择自研适配层**，不 monkey-patch window.fetch；业务统一调用客户端，mock/真实端只替换 transport。
满足真实异步 fetch 消费语义，但 mock 不会出现真实 Network HTTP 条目；提供请求日志/调试浮层。
产品“Network 面板一致”项需评审改为“请求生命周期可观察”；若必须有浏览器网络条目，再将 transport 替换为 MSW。
```text
组件 → controller/actions → api/endpoints → api/client（超时/错误/SSE）→ api/transport
  VITE_USE_MOCK=true  → mockFetch → Request 路由 → 延迟/失败计划 → 意图/生成器
                                → Response + ReadableStream → 同一 SSE parser
  VITE_USE_MOCK=false → window.fetch → 真实网关（相同 method/path/body/事件）
localStorage ← localRepository ← 持久化订阅；mock 历史/提醒端点复用同一仓库
```
```ts
const ready = import.meta.env.VITE_USE_MOCK === 'true'
  ? import('../mock/server').then(m => m.mockFetch)
  : Promise.resolve(window.fetch.bind(window));
export const transport: typeof fetch = async (input, init) => (await ready)(input, init);
```
环境变量是字符串，禁止 Boolean('false')；VITE_API_BASE_URL 默认当前 origin，用 new URL(path,base) 生成绝对 API URL。
只接管 API origin 下 `/api/`；图片、百度脚本走原生网络；未实现 mock API 返回 404，绝不回落真实后端。
### 5.2 延迟、abort 与失败

片段中的 route/config/generator/guard 对应目录职责，均由本项目实现；此处只展示关键算法。
```ts
export function delay(ms: number, signal: AbortSignal): Promise<void> {
  return new Promise((resolve, reject) => {
    if (signal.aborted) { reject(signal.reason); return; }
    const cleanup = () => { clearTimeout(timer); signal.removeEventListener('abort', abort); };
    const abort = () => { cleanup(); reject(signal.reason); };
    const timer = setTimeout(() => { cleanup(); resolve(); }, ms);
    signal.addEventListener('abort', abort, { once: true });
    if (signal.aborted) abort();
  });
}
export const mockFetch: typeof fetch = async (input, init) => {
  const req = new Request(input, init), url = new URL(req.url);
  if (!isApiOrigin(url) || !url.pathname.startsWith('/api/')) return fetch(req);
```

### 5.3 真实 Response 与 SSE 流
```ts
export function createSSEStream(events: AsyncIterable<SSEWireEvent>, signal: AbortSignal,
  cfg: { chunkMin: number; chunkMax: number }): Response {
  const encoder = new TextEncoder(), iterator = events[Symbol.asyncIterator]();
  const life = new AbortController();
  let finished = false, abort: () => void = () => {};
  const cleanup = () => signal.removeEventListener('abort', abort);
  const body = new ReadableStream<Uint8Array>({
    start(c) {
      abort = () => {
        if (finished) return;
        finished = true; life.abort(signal.reason); cleanup(); c.error(signal.reason);
        void iterator.return?.().catch(() => {});
      };
      signal.addEventListener('abort', abort, { once: true });
      if (signal.aborted) abort();
    },
    async pull(c) {
      if (finished) return;
      try {
        await delay(randomInt(cfg.chunkMin, cfg.chunkMax), life.signal);
        const next = await iterator.next();
        if (finished) return;
        if (next.done) { finished = true; cleanup(); c.close(); return; }
        c.enqueue(encoder.encode(`data: ${JSON.stringify(next.value)}\n\n`));
        if (next.value.type === 'done' || next.value.type === 'error') {
          finished = true; cleanup(); c.close(); void iterator.return?.().catch(() => {});
        }
      } catch (error) { if (!finished) { finished = true; cleanup(); c.error(error); } }
    },
    cancel(reason) { finished = true; life.abort(reason); cleanup();
      return iterator.return?.().then(() => undefined); }
  });
  return new Response(body, { status: 200, headers: {
    'Content-Type': 'text/event-stream; charset=utf-8', 'Cache-Control': 'no-cache' } });
}
```
pull 利用背压而非无限 enqueue；生成器是无网络副作用的异步序列，确保一个终态；取消清理 timer/listener/iterator。
error 事件是业务终态，controller.error 是传输异常；另造无 done EOF 的测试，不能把缺失终态判为完成。
### 5.4 超时必须覆盖整个流
```ts
export async function withRequest<T>(run: (signal: AbortSignal) => Promise<T>,
  userSignal: AbortSignal, timeoutMs: number): Promise<T> {
  const controller = new AbortController(), abort = () => controller.abort(userSignal.reason);
  userSignal.addEventListener('abort', abort, { once: true });
  if (userSignal.aborted) abort();
  const timer = setTimeout(() => controller.abort(
    new DOMException('请求超过时间预算', 'TimeoutError')), timeoutMs);
  try { controller.signal.throwIfAborted(); return await run(controller.signal); }
  catch (error) { throw controller.signal.aborted ? controller.signal.reason : error; }
  finally { clearTimeout(timer); userSignal.removeEventListener('abort', abort); }
}
await withRequest(async signal => {
  const response = await transport(chatUrl, { method: 'POST', signal,
    headers: { 'Content-Type': 'application/json', Accept: 'text/event-stream' }, body: JSON.stringify(request) });
  await assertChatResponse(response);
  for await (const event of parseSSE(response)) applyEvent(event);
}, userController.signal, 60_000);
```
JSON 总预算 8s，chat 总预算 60s；首字（含 headers 等待）15s、读流空闲15s watchdog 均由同一 controller 控制。
收到首个有效事件清首字 timer；每次收到字节/heartbeat 重置 idle timer，不重置总预算；所有 timer 在 finally 清除。
禁止 fetch 返回 headers 后就结束 scope；JSON 解码、SSE 读流都在 run 内。主动停止 AbortError→aborted，TimeoutError→error。
### 5.5 统一 SSE parser
```ts
export async function* parseSSE(response: Response): AsyncGenerator<SSEEvent> {
  if (!response.body) throw new Error('EMPTY_STREAM');
  const reader = response.body.getReader(), decoder = new TextDecoder('utf-8', { fatal: true });
  let buffer = '', data: string[] = [], terminal = false;
  try {
    while (true) {
      const chunk = await reader.read();
      buffer += chunk.done ? decoder.decode() : decoder.decode(chunk.value, { stream: true });
      enforceBufferLimit(buffer, data);
      let end: number;
      while ((end = buffer.indexOf('\n')) >= 0) {
        const line = buffer.slice(0, end).replace(/\r$/, ''); buffer = buffer.slice(end + 1);
        if (line === '' && data.length) {
          const value: unknown = JSON.parse(data.join('\n')); data = [];
          const event = validateAndNormalizeEvent(value); // wire card_type→Card.type
          terminal = event.type === 'done' || event.type === 'error';
          yield event; if (terminal) return;
        } else if (line.startsWith('data:')) data.push(line.slice(5).replace(/^ /, ''));
      }
      if (chunk.done) break;
    }
    if (!terminal) throw new Error('STREAM_INCOMPLETE');
  } finally { await reader.cancel().catch(() => {}); reader.releaseLock(); }
}
```
支持半个中文 UTF-8、多 data 行、同块多事件、跨块 CRLF；注释心跳及 event/id/retry 不参与 JSON，业务类型在 data.type。
协议约定 LF/CRLF，帧以空行结束；单帧256KiB、消息另限容量；实现逐段累计字节限制，不能只在入块时检查一次。
关联 ID/seq 在 controller 验证；真实服务建议每10s发 `: ping\n\n`，不自动重连 POST 或重放有副作用事件。

## 6. 对话状态机与本地持久化
| 当前状态 | 触发 | 下一状态/处理 |
|---|---|---|
| 无消息 | send | 用户消息done，助手pending；展示“正在想…”（产品thinking的UI映射） |
| pending | 首个status/delta/card/suggestions | streaming；headers不算首字 |
| pending/streaming | delta | 追加text；只更新活动消息，保持其他对象引用 |
| pending/streaming | status | step_id更新工具状态，不暴露内部推理 |
| pending/streaming | card/suggestions | 完整校验后进入临时缓冲，不开放执行操作 |
| pending/streaming | done | flush文字，原子提交cards/chips，done，清活动请求 |
| pending/streaming | error/5xx/timeout/断流 | error，保留部分文字，丢缓冲卡/chips，标“内容不完整” |
| pending/streaming | 用户停止/切换/删除 | aborted，保留文字，丢缓冲卡/chips，显示“已停止生成” |
| done/error/aborted | 迟到事件 | 忽略；终态不被旧请求覆盖 |

发送：trim/1～200字校验→同步占用activeRequest→建消息→持久化→请求→读流→flush→清理，全局仅一个活动生成。
生成中可写草稿，禁止再发送/chip；AbortController/reader在controller运行时，不进store或localStorage。
事件与旧finally均校验conversation_id/message_id/request_id；每次attempt新request_id，避免旧请求清掉新锁。
delta用rAF或约32ms批量合并；card/终态先flush文字。停止先flush并标aborted再abort，立即允许下一问。
重试/已停止后的重新生成：复用原用户/助手ID，清原部分文字与error，新request_id，不重复气泡，不接续残片。
成功回复的版本式重新生成列为扩展：新助手ID、variantOf，选中版本存selectedReplyByUserId，只开放分支最后一条。
history只含此前选中done文本，不含本次query重复项、其他版本、error/aborted；最近20轮/约16K字，不做token精确计量。
status工具步骤为短暂状态，完成后移除；done空结果显示空态；错误码和停止文案分别遵守01，不以取消冒充错误。

显式订阅 + localRepository，不无差别persist整个zustand：
- `lumi:conversations:v1`：schemaVersion/snapshots/savedAt；`lumi:preferences:v1`与`lumi:reminders:v1`独立。
- 500ms防抖保存，发送/终态/停止/删除强制flush，pagehide尽力同步写；不依赖beforeunload保住所有数据。
- 保存Message/Conversation/选中版本，排除controller、工具步骤、地图、DOM；精确用户定位/凭证不持久化。
- 启动校验/迁移，残留pending/streaming改aborted，不自动续流/重发；坏数据仅隔离Lumi key并提示。
- 最近50会话、每会话200消息、序列化约2MiB；先裁剪旧非活动会话，超限提示清理，不宣称浏览器固定配额。
- 所有读写try/catch；禁用/配额不足降级内存并显示“历史未保存”，不能伪报成功。
- mock历史端点读同一repository；POST/PUT/DELETE幂等，PUT拒绝updatedAt更旧快照，避免延迟同步覆盖新轮；无存储复用同一内存兜底。
- 终态可PUT同步；失败只标待同步，不能把已完成回复改error；删除保留tombstone，避免远端列表复活记录。
- storage事件只合并非活动会话；同会话多标签编辑提示单标签操作，不承诺CRDT或无损并发。
- reminder确认由mock端点先验证未来时间、按reminder_id去重，再保存pending；存储失败返回storage_unavailable，不给“已设置”。
- scheduler只在页面可见时核对到期；保存notified_at扩展元数据避免重复提示，重开已过期提示“已过期”，不承诺准点/后台通知。
- 本地内容敏感，提供清空入口；React转义纯文本，无原始HTML注入；不得自动把mock历史上传真实账号。

### 7.1 单例脚本加载器

URL为 `https://api.map.baidu.com/api?v=1.0&type=webgl&ak=...&callback=...`，全局BMapGL，不混用旧BMap。
VITE_BAIDU_MAP_AK是可见浏览器key，必须设JSAPI域名白名单；不在VITE_*放服务端私钥。
baidu-map.d.ts仅声明实际Map/Point/Marker/Polyline方法、Window.BMapGL和BaiduSDK接口，不引入any全局。
```ts
let sdkPromise: Promise<BaiduSDK> | undefined;
export function loadBaiduMap(ak: string): Promise<BaiduSDK> {
  if (!ak.trim()) return Promise.reject(new Error('MAP_NO_AK'));
  if (window.BMapGL?.Map) return Promise.resolve(window.BMapGL);
  if (sdkPromise) return sdkPromise;
  sdkPromise = new Promise((resolve, reject) => {
    const script = document.createElement('script');
    const name = `__lumi_bmap_${crypto.randomUUID().replaceAll('-', '')}`;
    const callbacks = window as unknown as Record<string, unknown>;
    let settled = false;
    const finish = (error?: Error) => {
      if (settled) return; settled = true; clearTimeout(timer); script.onerror = null;
      const sdk = window.BMapGL;
      if (error || !sdk?.Map) {
        script.remove(); callbacks[name] = () => {}; sdkPromise = undefined;
        reject(error ?? new Error('MAP_INVALID_SDK')); return;
      }
      delete callbacks[name]; resolve(sdk);
    };
    callbacks[name] = () => finish();
    const timer = setTimeout(() => finish(new Error('MAP_LOAD_TIMEOUT')), 10_000);
    script.onerror = () => finish(new Error('MAP_LOAD_FAILED'));
    const url = new URL('https://api.map.baidu.com/api');
    url.search = new URLSearchParams({ v: '1.0', type: 'webgl', ak, callback: name }).toString();
    script.src = url.href; script.async = true; document.head.append(script);
  });
  return sdkPromise;
}
```
共享SDK Promise而非Map实例，onload不算就绪，callback验全局；失败重置Promise，用户最多显式重试一次。
移除script不能保证请求取消；失败保留有上限的noop callback防迟到异常，重试独立callback，旧finish不结算新Promise。
组件卸载只忽略自身结果，不能取消其他等待者；AK鉴权错误可能不触发onerror，callback超时/初始化异常都降级。
若SDK已就绪但瓦片空白，提供“地图无法显示”切换占位入口，不依赖未验证的私有鉴权事件。

- 地图React.lazy/Suspense，不从总barrel静态引用；首页模块可拆chunk；真实构建静态环境分支裁剪mock动态import。
- lucide具名导入，百度SDK运行时外链不进首包；首屏JS gzip目标≤180KiB，不含外链，CI记录实际体积。
- zustand按messageId选择器 + MessageItem memo；delta批量更新；卡片只done时提交，不为每字触发地图/列表重渲染。
- 长历史先显示最近40条，向上批量加载并保锚点，不提前加虚拟列表库；路线≤500点，列表≤3项，提醒查询≤5项。
- TS strict/noUncheckedIndexedAccess/noUnusedLocals/Parameters，target ES2022；不使用未覆盖的toSorted等新API。
- ESLint flat config：typescript-eslint推荐、hooks/exhaustive-deps、react-refresh；禁止显式any与未处理Promise。
- 脚本：dev=vite，typecheck=tsc -b，lint=eslint . --max-warnings 0，test=vitest run，build=tsc -b && vite build。
- 单测：01全部入口/chips/意图优先级/实体/能力开关、seed重现、abort清timer、5xx resolve、超时、背压、reader.cancel。
- SSE测试：每字节拆中文、跨块CRLF、多data/多事件/heartbeat、坏JSON/未知类型/超限、重复/缺号、缺done EOF。
- 状态测试：停止/完成竞态、旧finally、原位重试、卡缓冲提交/丢弃、刷新中断、quota/坏数据、提醒去重/过期。
- 组件/地图测试：IME、防重/焦点、StrictMode destroy、单例加载/迟到callback、无AK不请求、URI坐标顺序和编码。
- 浏览器：Chrome/Edge111+、Firefox115+、iOS Safari16.4+、Android Chrome111+；微信内置浏览器另做实机验收。
- 视口320/375/390/768/1024/1440；浅深色、键盘/横屏/缩放/reduced-motion、无存储/无WebGL/无AK不阻断对话。

## 10. 真实后端迁移与评审门禁

1. 对齐01/02/03差异：本地历史本期必做、7类卡/9intent、单卡done提交、tokens、mock路线来源、调试可观察口径。
2. 后端实现同method/path/JSON/SSEWireEvent；request_id幂等、提醒按ID去重、断连取消；status只含工具步骤、不含内部推理。
3. 网关禁SSE缓冲、及时flush、10s heartbeat，服务超时大于客户端；跨域明确CORS/OPTIONS/凭证策略。
4. 设置VITE_USE_MOCK=false、VITE_API_BASE_URL为网关origin并重建；业务组件、store/reducer、SSE parser零改动。
5. 鉴权只在api/client注入（建议同源HttpOnly cookie + CSRF）；远端按ID与本地缓存合并，不覆盖活动/待同步版本。
6. 同一契约/弱网/取消用例通过，验证代理不合并SSE、UTF-8、唯一done、停止释放任务、同步失败不丢历史，再灰度。
