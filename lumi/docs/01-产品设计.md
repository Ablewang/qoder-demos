## 1. 产品定位与原则

### 1.1 定位与价值

Lumi 是「帮你少想一步」的个人生活助手：用一句自然语言，获得一个简短结论和一张可操作卡片。
覆盖衣、食、住、行及轻量提醒，不做百科问答平台，也不做本地生活交易平台。
核心价值：减少查天气、找餐厅、看路线之间的切换；先给能照做的建议，再给依据。
P0 强调可用、清爽、可信：示例能跑通，按钮有结果，失败能恢复，不把演示包装成真实服务。

### 1.2 目标用户（两类）

| 画像 | 生活状态与设备 | 高频时刻 | 需求与成功感 |
|---|---|---|---|
| 小林，28 岁通勤上班族 | 城市独居；手机为主，工作时用 PC | 出门前、午饭前、下班前 | 迅速决定穿什么、吃什么、怎么走；不用读长答案 |
| 阿杰，26 岁周末轻出游者 | 和伴侣逛城市或周边；手机为主 | 周五规划、到达陌生街区后 | 有 2～3 个住吃选项，能看位置、比较路线；不需要复杂攻略 |

### 1.3 设计原则

1. **先结论后依据**：文字通常 30～60 字，最长 80 字；结构化细节交给卡片。
2. **少选项、能行动**：列表最多 3 项，一张卡片通常 1～2 个主要操作，不堆筛选器。
3. **对话是主线**：快捷入口、追问 chip 都生成清晰的用户消息；返回地图后不丢对话位置。
4. **过程可见、控制在手**：思考、流式、失败、中断都有状态；不自动反复重试。
5. **诚实且克制**：标明演示数据、本地存储和提醒限制；不用 emoji、不承诺订房或后台通知。

## 2. 核心场景

> 统一回复形态：短文字 → 一张卡片 → 2～3 个追问 chip。卡片类型共 7 种，见第 6 章。
> 「住」选择酒店民宿推荐（P1）：复用地点、列表和地图。家务可以设提醒，缴费、账户和交易不做。
> 下列例句覆盖产品方向；标注 P1 的不是 P0 验收项，不能用假成功文案冒充支持。

### 2.1 衣：天气＋穿搭｜`weather_outfit`

- 例句 1：「今天上海穿什么合适？」；例句 2：「明天上海会下雨吗，要带伞吗？」；例句 3：「周六去杭州玩，穿什么？」（P1 扩展城市与日期）
- 文字：「上海今天早晚偏凉，建议长袖加薄外套；下午有雨，出门带伞。」
- 卡片：`weather_outfit`；展示城市、日期、天气、温度区间、穿搭、提示；不是服装商城。
- 操作：P0「看明天」（发送完整问题）；P1「设带伞提醒」（生成待确认提醒，不直接创建）。
- 不做：识别衣橱、上传照片、商品购买或身材评价。

### 2.2 食：吃什么／附近餐厅｜`food_recommend`

- 例句 1：「中午吃什么好？」；例句 2：「上海南京西路附近有什么川菜？」；例句 3：「人均 100 元以内，适合两个人的餐厅？」
- 文字：「给你选了南京西路附近 3 家餐厅，先看看人均 78 元的蜀香小馆。」
- 卡片：`restaurant_list`；最多 3 家，显示店名、菜系、人均、评分、距离、一句推荐理由。
- 操作：P0 卡片级「看地图」、每项「导航」；P1「详情」「打电话」「换一批」。
- 边界：评分、价格、距离均为演示数据；不声称实时排队、一定营业或保证符合预算。

### 2.3 食：简单菜谱｜`recipe`（P1）

- 例句 1：「番茄炒蛋怎么做？」；例句 2：「冰箱有鸡蛋和土豆，能做什么菜？」；例句 3：「给我一道 15 分钟能做好的晚饭。」
- 文字：「番茄炒蛋，约 10 分钟。先炒蛋盛出，再炒番茄，最后合炒。」
- 卡片：`recipe`；菜名、耗时、难度、份量、食材和最多 6 步做法。
- 操作：「展开步骤」（本地展开，非网络 action）、「复制食材」「换一道」。
- 边界：普通家常菜，不给治疗、过敏安全或营养医疗承诺；无食材库存管理。

### 2.4 住：酒店／民宿推荐｜`hotel_recommend`（P1）

- 例句 1：「周六在杭州西湖附近住一晚，500 元以内。」；例句 2：「外滩附近有什么性价比高的酒店？」；例句 3：「推荐适合带猫的民宿。」
- 文字：「这里有 3 个西湖附近的住宿示例，先看看每晚 468 元的湖畔小院。」
- 卡片：`hotel_list`；最多 3 家，展示名称、类型、评分、每晚价格、位置、日期、亮点。
- 操作：「看地图」「导航」「详情」「打电话」；不出现「立即预订」按钮。
- 边界：价格、宠物政策、房态须以商家确认为准；不提供下单、支付或外部交易跳转。

### 2.5 行：路线／方式对比／导航｜`route_plan`

- 例句 1：「从南京西路到虹桥火车站怎么走？」；例句 2：「南京西路去外滩，打车和地铁哪个划算？」；例句 3：「从南京西路导航去外滩。」
- 文字：「建议坐地铁；这是耗时和费用的演示对比，真实路线请查看地图结果。」
- 卡片：`route_plan`；起终点、推荐方式、地铁公交与驾车对比、百度地图预览。
- 操作：P0「看路线」（地图视图）、「导航」（百度地图 URI）；P1 切换方式、设出发提醒。
- P0 卡片展示两个方式的对比行，地图只绘制推荐方式；不实现四套 Tab 和复杂路线编辑。
- 「导航」指打开百度地图 App／网页版查看路线，不是 Lumi 自己提供实时语音导航。

### 2.6 行：附近设施｜`nearby_search`（P1）

- 例句 1：「附近有便利店吗？」；例句 2：「最近的药店在哪？」；例句 3：「南京西路附近哪里能停车？」
- 文字：「这里有 3 个南京西路附近的便利店示例，可在地图上看位置。」
- 卡片：`poi_list`；名称、类别、距离、地址、营业说明，可在地图中标注。
- 操作：「看地图」「导航」；有电话时显示「打电话」，无电话不显示。
- 与餐厅区分：找吃饭地点走 `food_recommend`；便利店、超市、药店等设施走本 intent。

### 2.7 轻量日程／提醒｜`reminder`

- 例句 1：「明早 8 点提醒我带伞。」；例句 2：「每周五晚上 8 点提醒我倒垃圾。」（重复提醒 P1）；例句 3：「我今天还有什么事？」
- 新建文字：「明天 08:00 带伞，请确认时间后设置。打开 Lumi 时才能收到提醒。」
- 卡片：`reminder`；`draft` 模式展示内容和准确时间；`list` 模式查询已存提醒，最多 5 条。
- 操作：P0「确认设置」后保存；P1 修改、删除、完成；保存后按钮变「已设置」，不可重复点击。
- 本地存储，无云同步；页面可见时到点用通知条提醒。关闭页面、锁屏或后台不保证触达。
- P0 仅一次性提醒；时间缺失或已过去先追问，不默认猜一个时间，不创建卡片副作用。
- 再次打开页面，对未通知且已到期的提醒提示「已过期：带伞」，不伪装成准点提醒。

### 2.8 闲聊与能力边界｜`chitchat`／`fallback`

- `chitchat` 例句：「你好」「你是谁」「谢谢」；纯文字：「我是 Lumi，帮你处理天气、吃饭、出行这些小事。」
- `fallback` 例句：「帮我订机票」「替我缴水费」「写段代码」；纯文字说明不支持，并给可用能力建议。
- 两者 `cards=[]`；都有 2～3 个 chip。信息不足仍保留原 intent，先文字追问、暂不出卡片。

## 3. MVP 范围与交付边界

### 3.1 优先级

| 项目 | P0：1～2 天必须闭环 | P1：P0 后增补 | P2：本期不做 |
|---|---|---|---|
| 对话 | 单活动会话、文字输入、流式、停止、失败重试、chip、新对话 | 历史会话列表、本地持久化、复制回复 | 登录、云同步、语音、图片 |
| intent／卡片 | 6 个 intent、4 类卡片：天气、餐厅、路线、提醒；另有闲聊和兜底 | 菜谱、附近、酒店三个 intent／卡片 | 多意图编排、整套旅行计划 |
| 地图 | 百度 JS API；一个复用地图视图，路线／餐厅标点；导航跳转 | 方式切换、其他设施、酒店标点 | Lumi 内实时导航、地图直接搜索 |
| 天气／餐厅 | 固定演示区域和有限数据；仅 6.4 标 P0 的字段与操作 | 未来预报、更多菜系、预算、图片详情 | 真实天气／商家数据、排队、评价 |
| 提醒 | 一次性草稿、确认保存、本地查询、页面内提醒 | 重复、修改／删除／完成、独立提醒列表 | 系统推送、日历同步 |
| 首页／定位 | 时段问候、天气条、4 入口、3 示例；明示默认地点 | 用户主动定位、城市切换、今日待办 | 自动个性化推荐 |
| 布局 | PC 简单侧栏＋对话，手机单栏；同一地图视图 | PC 地图抽屉、移动详情弹层 | 多主题、复杂仪表盘 |

### 3.2 限定规模，避免「假 P0」

- P0 只做上海南京西路演示区域、今天／明天天气、3 家固定餐厅、外滩／虹桥站两组路线。
- 「附近／这里」在 P0 指默认演示地点，不指用户真实位置；首页、卡片和地图都展示「演示位置：上海南京西路」。
- 非演示城市、日期、地点，回复「目前只演示上海南京西路，要看看这里的吗？」并给有效 chip，不伪造查询结果。
- 两组路线只对比 `transit` 和 `driving`；费用为 mock 估算，百度地图路线独立说明来源。
- 单次最多一张卡片；不做联动攻略、复杂编辑表单、交易、账号、真实 Agent 或真实商家搜索。
- P0 仅保留当前会话内存，新对话清空消息；提醒独立保存在本地。历史列表和删除管理均 P1。
- 实施顺序：第 1 天搭首页、对话、请求状态与四类简卡；第 2 天接百度地图、提醒和双端异常验收。
- 优先砍图片、详情、历史和高级字段，不砍真实地图、取消请求、失败重试或模拟标识。

## 4. 信息架构与页面清单

### 4.1 结构

首页就是对话页的空状态：问候／今日概览／快捷入口／示例 → 输入框。
发送第一句后，空状态切换为消息流：用户文字 → Lumi 文字／卡片／chip → 输入框。
卡片打开地图；关闭地图返回原消息位置。详情、历史和独立提醒列表是 P1，不能露出不可用入口。

| ID | 页面／视图 | P0 内容 | P1 扩展 |
|---|---|---|---|
| V1 | 首页／对话主视图 `/` | 空态与消息态共用；顶部 Lumi、新对话；底部输入 | 保存会话、恢复消息 |
| V2 | 导航侧栏／抽屉，无独立页 | 新对话、当前会话标题、演示说明 | 时间倒序历史列表、我的提醒 |
| V3 | 地图视图，无须独立路由 | 覆盖主视图；返回、百度地图、来源说明、地点／路线信息 | PC 改右侧抽屉，地图方式切换 |
| V4 | 详情视图（P1） | 不显示入口 | 餐厅／酒店图片、信息、地址、电话、地图按钮 |
| V5 | 我的提醒（P1） | 在对话查询，无独立页 | 今天／以后／已完成列表 |

地图沿用选中的 `message_id` 和 `focus_id`，不要求后端 ID 查询；刷新不承诺恢复 P0 会话。
移动端系统返回先关闭覆盖视图／抽屉，不直接退出；关闭后恢复消息、草稿及滚动位置。

### 4.2 响应式差异

| 区域 | 手机：<768px | PC／平板：≥768px |
|---|---|---|
| 会话区域 | 单栏；顶部菜单打开导航抽屉 | 左侧约 220px 简单侧栏；窄屏可收起 |
| 消息区 | 可用宽度内单列，卡片无横向溢出 | 居中最大约 760px，卡片仍纵向排列 |
| 输入 | 底部常驻，适配软键盘和安全区；显式发送按钮 | 底部常驻；Enter 发送、Shift＋Enter 换行 |
| chip | 可横滑的单行，确保最后一个能被看到 | 可换行，不超过两行 |
| 地图 V3 | P0 全屏，信息面板在底部 | P0 同一覆盖视图，信息面板在右侧 |
| 详情（P1） | 底部弹层，可关闭、可滚动 | 右侧抽屉；和地图互斥，不多层叠加 |

操作触达区至少 44px，颜色不作为唯一状态标识；停止、重试、返回都有文字或可访问名称。

## 5. 关键用户流程与请求体验

### 5.1 首次进入

打开 H5 → 即时显示问候＋默认演示位置 → 天气条骨架 → mock 请求。
成功 → 显示今日天气；失败 → 天气条「天气暂未获取到 · 重试」，输入及入口仍可用。
P0 不主动弹定位授权，不需要登录或引导问卷。页脚固定有「Agent 演示数据，仅供参考」。
P1 点击「使用我的位置」才请求授权；拒绝／5 秒超时保留演示位置并说明，不能标成「当前位置」。
浏览器定位不是 BD-09，进入百度地图前须转换；未配置对应区域数据时仍明确使用演示推荐。

### 5.2 发起对话与获得卡片

输入／点击入口 → 创建用户气泡 → 创建回复占位「正在想…」→ 发起可取消 mock 请求。
首字到达 → `streaming`，文字逐段输出 → 收到完整终态 → 一次展示卡片和 chip → `done`。
生成中可输入草稿，禁止第二次发送和 chip 点击；发送按钮变「停止」。完成后恢复。
点 chip → 展示其完整 `query` 为用户消息 → 走同一请求流程，不直接偷偷替换卡片。
创建提醒回复只是草稿 → 点「确认设置」→ 本地写入成功 →「已设置」＋说明；失败可再次确认。

### 5.3 卡片进入地图／详情

点「看地图／看路线」→ V3 加载态 → 真实百度 JS API 加载 → 标点或调用路线规划。
餐厅列表默认包含所有点；单项导航使用该项地址和坐标。路线只绘制选定的推荐方式。
地图成功 → 信息面板同步；地图／线路失败 → 保留地址和 mock 对比，显示「重试地图」，不让整段对话失败。
点「导航」→ 用户主动点击触发百度地图 URI → 手机尝试 App、不可用时使用网页版；PC 打开网页版。
无法打开 → 提供「打开百度地图网页版」链接和可复制地址；不做连续自动跳转。
返回 → 关闭覆盖视图，回到原滚动位置。P1 点详情 → 同样保留上下文，不新增聊天消息。

### 5.4 请求失败与重试

等待超过 15 秒无首字／HTTP 异常／输出断开 → `error`，停止等待，按钮恢复。
无输出 → 错误提示＋「重试」；已有文字 → 保留并标「内容不完整」，不展示可执行卡片与 chip。
点重试 → 原助手消息重新生成，清空旧部分内容，保留原用户气泡；换新的 `request_id`。
最多手动连续重试 3 次后追加「可以稍后再试，或换个说法」，仍可手动重试，不无限自动请求。
地图失败仅重试地图；首页天气失败仅重试天气；不重新发送整段 Agent 问题。

### 5.5 中断生成

思考中／流式中点「停止」→ 取消当前请求及输出 → `aborted` → 已有文字保留＋「已停止生成」。
未输出时仅显示停止标记；卡片和 chip 不出现；输入草稿保留，立即允许发送下一问。
显示「重新生成」（P0，复用重试），不另做普通成功消息的重新生成入口。
取消后旧请求迟到的数据一律忽略；新对话同样取消未完成请求，不允许串入下一段会话。

### 5.6 mock 体验的硬要求

- 不是点击后直接填静态文字：要经过可观察的 HTTP 请求生命周期，具备 pending、成功、错误、取消。
- 由浏览器内 mock 请求层返回数据，不接真实 Agent 服务；具体拦截／流式实现由架构师确定。
- 首字等待 600～1200ms，文字每 40～80ms 输出一小段，整次通常 2～4 秒；卡片在终态完整到达后显示。
- 必须能演示首字前失败、流式中断、停止后忽略迟到数据；开发测试可指定故障，默认成功，不随机破坏演示。
- 每次重试是新请求；连续双击发送／确认／重试不产生重复消息或重复提醒。
- 网络面板与界面状态一致；只播放打字动画、不支持请求取消的实现不验收。

## 6. Agent 响应协议（产品视角）

### 6.1 请求、回复与状态

产品约定单请求单 intent、单回复 0～1 卡片；流式传输格式由技术方案决定，业务字段不另起同义名。

| 对象／字段 | 中文含义 | 示例与约束 |
|---|---|---|
| 请求 `request_id` | 一次尝试 ID | `req_002`；重试必须不同 |
| 请求 `message_id` | 目标助手消息 ID | `msg_002`；原位重试保持不变 |
| 请求 `query` | 完整用户问题 | `南京西路去外滩怎么走`；1～200 字 |
| 请求 `context.demo_location` | 演示地点 | Location；P0 固定南京西路 |
| 请求 `context.now` | 本地时间基准 | `2026-11-17T20:00:00+08:00`；相对日期据此计算 |
| 回复 `request_id`／`message_id` | 归属关联 | 与请求一致，用于丢弃取消后迟到结果 |
| 回复 `intent` | 意图枚举 | `route_plan`；见 6.2 |
| 回复 `text` | 可流式的文字 | `建议坐地铁，以下是演示对比。`；最多 80 字 |
| 回复 `cards` | 卡片数组 | 通常 1 张；闲聊、兜底、澄清时 `[]` |
| 回复 `suggestions` | 追问数组 | 完成时 2～3 个；见 6.5 |
| 回复 `status` | 界面生命周期状态 | `thinking / streaming / done / error / aborted` |
| 回复 `error` | 失败原因 | 仅 error 时有 `code`、`message`；其他时候 `null` |
| 回复 `created_at` | 消息时间 | 带时区 ISO 时间，如 `2026-11-17T20:00:02+08:00` |

顺序：thinking → streaming → done；等待／输出中可转 error 或 aborted。终态之前卡片操作不可用。
status 是前端合成的生命周期，不要求取消后服务再发 aborted；卡片与 chip 在 done 时原子展示。

### 6.5 suggestions：可独立执行的完整追问

每项只有 `label`（chip 上≤10 字）和 `query`（发送全文，≤200 字）；done 时 2～3 项，error／aborted 无。
追问需明确城市、日期、目标，不靠模型记忆。P0 使用 fixture 生成完整 query，不实现自由上下文推理。
「怎么过去」只能绑定明确对象：用户未选对象时写「去第一家怎么走」，query 带第一家店名和起点。

| intent | label 示例 → 对应 query 示例（后续列亦需生成完整 query） |
|---|---|
| weather_outfit | 看明天 → 明天上海穿什么；中午吃什么 → 南京西路附近午饭吃什么 |
| food_recommend | 看天气 → 今天上海天气怎么样；去外滩 → 南京西路去外滩怎么走 |
| route_plan | 看天气 → 今天上海天气怎么样；记个提醒 → 明天早上8点提醒我出门 |
| reminder | 今天的事 → 今天有哪些提醒；看明天天气 → 明天上海天气怎么样 |
| recipe | 换一道 → 土豆炒蛋怎么做；买食材 → 南京西路附近有哪些超市 |
| hotel_recommend | 看外滩住宿 → 外滩附近住一晚有哪些酒店；附近吃饭 → 西湖附近有什么餐厅 |
| nearby_search | 找药店 → 南京西路附近有哪些药店；找超市 → 南京西路附近有哪些超市 |
| chitchat／fallback | 今天穿什么 → 今天上海穿什么；吃点什么 → 南京西路附近吃什么；去外滩 → 南京西路去外滩怎么走 |

P0 chip 只指向已有 fixture；去餐厅直接点卡片导航，不生成第三组路线对比。P1 才开放「去第一家」追问。

### 6.6 mock 匹配和澄清规则

先拒绝交易／超范围请求（预订、付款、缴费、买票、写代码等）→ fallback；避免「订酒店」误判推荐。
其余按优先级匹配，最多一个 intent；问候只在整句为问候／感谢时识别，不能吞掉带任务的长句。

| 顺序 | 关键词示例 | intent |
|---|---|---|
| 1 | 提醒、记得、别忘、待办、还有什么事 | reminder |
| 2 | 怎么走、怎么去、怎么过去、导航、路线、打车、地铁 | route_plan |
| 3 | 怎么做、做法、菜谱、冰箱、能做好的、做什么菜 | recipe |
| 4 | 酒店、民宿、住一晚、住哪里 | hotel_recommend |
| 5 | 便利店、超市、药店、加油站、ATM、停车、厕所 | nearby_search |
| 6 | 吃什么、餐厅、好吃、午饭、晚饭、川菜、咖啡 | food_recommend |
| 7 | 穿什么、天气、下雨、带伞、温度、冷不冷 | weather_outfit |
| 8 | 你好、谢谢、你是谁等完整短句 | chitchat |
| 9 | 未命中 | fallback |

匹配后再检查能力级别与 fixture：P1 未上线返回 fallback；缺必要参数返回原 intent＋澄清文字＋chip。
不实现通用 NLP；提醒只覆盖明确「今天／明天＋小时」及查询模板，其他时间问用户确认。
所有首页例句／chip 必须纳入测试样本；未知 query 可兜底，但已展示的入口不能跳到错误能力。

### 6.7 错误码与本地降级

| code | 文案 | 恢复方式 |
|---|---|---|
| `timeout` | 等得有点久，这次没有回复成功。 | 重试当前回复 |
| `network_error` | 网络好像断了，检查后再试试。 | 重试当前回复 |
| `server_error` | Lumi 开了个小差，再试一次吧。 | 重试当前回复 |
| `stream_interrupted` | 回复中断了，内容可能不完整。 | 保留文字，原位重试 |

地图 `map_load_failed`、路线 `route_not_found` 是视图内错误，不改助手 intent；显示地图重试／地址与导航链接。
定位 `location_denied` 为 P1 非阻断提示；提醒 `storage_unavailable` 提示「无法保存，请检查浏览器设置」，不显示成功。

| 入口标题 | 副文案 | 点击发送 query |
|---|---|---|
| 今天穿什么 | 看天气配穿搭 | 今天上海穿什么合适 |
| 吃点什么 | 附近餐厅示例 | 南京西路附近有什么好吃的 |
| 怎么去 | 看路线比方式 | 南京西路到外滩怎么走 |
| 记一件事 | 确认后设置提醒 | 明天早上8点提醒我带伞 |

入口点击即发送，提醒仍要确认保存；P0 不显示「酒店」「菜谱」等尚未上线入口。
固定 3 条可跑通的示例：「明天上海会下雨吗？」「南京西路附近人均100元的餐厅」「南京西路到虹桥站怎么走？」
首次无历史会话：「问一句，少想一步。」；提醒空态：「今天暂无提醒，要记一件事吗？」
输入占位：「问问 Lumi，比如『中午吃什么』」；空白不可发送，去除首尾空格，最多 200 字。
超过限制提示「最多输入200字，精简一下吧」；生成中保留草稿，键盘发送同样遵守禁止并发规则。

## 8. 文案风格指南

- 像靠谱朋友：用「你」，不用「您／亲」；自称「我」或「Lumi」，不卖萌、不说教。
- 先建议后依据，最多两句／80 字；理由≤16 字，按钮通常2～6字，chip≤10字。
- 不用 emoji；天气与状态用图标而不是表情字符。不用波浪号、连续感叹号或长篇道歉。
- 数字用阿拉伯数字；温度℃、时间24小时制、金额元；距离<1000用米，否则公里保留1位小数。
- 不确定要说清：「目前只有演示数据」「营业时间请向商家确认」，不说「一定有房」「不会堵」。
- 好：「建议带伞，下午有雨。」坏：「亲，根据专业分析，您今天最好带伞哦～」
- 状态统一：「正在想…」「已停止生成」「重试」「重新生成」「已复制」「已设置」「地图加载中」。
- 到期通知：「提醒：带伞（08:00）」；延迟到达：「已过期：带伞（原定08:00）」。
- 全站显示「Agent 演示数据，仅供参考」；地图标识百度来源，提醒固定小字「打开 Lumi 时提醒」。
- 本地数据清浏览器即丢失，不上传提醒内容；电话、导航打开外部服务前由用户主动点击。

## 9. 成功指标与验收

### 9.1 P0 验收清单

- 首页4入口、3示例、每种已展示chip都能跑通；6个intent、4种卡片准确匹配，无P1死入口。
- 模拟请求有等待和流式；首字前失败、流式失败、重试、停止都可稳定复现；没有重复气泡和迟到串流。
- 百度JS地图真实加载；路线和餐厅标点均可查看，导航能打开百度；加载失败能独立恢复。
- 提醒需确认才保存；重复确认不多建；刷新能查询本地提醒；页面可见到点提示，关闭后不承诺推送。
- 375px手机、768px窄屏、1440pxPC无横向溢出；键盘不挡输入；地图返回恢复滚动位置。
- 用1～2天工期验收最小字段，不以P1高级卡片、图片详情或历史管理阻塞P0。
