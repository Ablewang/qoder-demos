# Lumi 多角色讨论与落地纪要

> 本文是第一轮产品/设计/架构草案的最终收敛版本。01～03 保留各角色原始意见，不能把草案中的 P0/P1、字段、版本或默认地点当作实际实现清单。实际协议以 `src/api/types.ts` 为准，验证结果以 06 为准。

## 1. 参与角色与过程

1. **产品经理**：独立产出产品定位、目标用户、衣食住行场景、MVP 优先级、回复卡片与流程，文档 01。
2. **UI/UX 设计师**：独立产出视觉理念、双主题 token、组件状态、响应式、卡片线框和无障碍规则，文档 02。
3. **前端架构师**：独立产出技术分层、fetch-compatible 模拟网络、SSE、状态机、百度地图与后端迁移方案，文档 03。
4. **独立产品体验评审**：第二轮完整阅读三份方案，对主负责人决策提出赞成/反对意见，不再重复写产品方案。
5. **主负责人**：对齐范围、协议、token、地点、行为真实性；负责应用壳、首页、会话状态机、集成与验收。
6. **设计系统 / 网络测试 / 生活卡片地图工程角色**：按独立文件责任边界并行实现，由主负责人核对实际代码和测试结果。

这是两轮讨论：先并行提案，再对冲突和具体取舍进行评审。各角色原稿保留，实际交付不伪称所有原稿条目都完成。

## 2. 第一轮观点与最终取舍

| 议题 | 原始意见或冲突 | 最终决定 | 理由 |
| --- | --- | --- | --- |
| MVP 场景 | 产品把酒店/菜谱/附近列 P1；用户本次明确衣食住行 | 衣食住行均交付；菜谱、附近与居家清单采用轻量卡片 | “住”不能留不可用按钮；复用现有列表/地图组件，避免复杂流程 |
| 默认地点 | 产品草案上海南京西路；视觉示例杭州 | 统一杭州武林广场附近的演示数据 | 同一产品不混用城市；不申请定位权限，不暗示当前真实位置 |
| 提醒 | 草案有页面内定时通知、重复提醒 | 仅确认后加入本地清单，可完成/移除；不做定时调度或系统推送 | H5 后台/锁屏无法可靠保证触达；不把待办包装成闹钟 |
| 视觉 | 设计草案松石绿 #35695C、16px 卡片 | 暖白 #f8f9f6、苔绿 #2e6557、20px 基础卡片 | 维持自然、安静气质，轻量圆角更适合 H5；全局只有一套组件实现 |
| 场景配色 | 草案紫/黄/紫/蓝分场景 | 低饱和 sage/peach/sand，小面积图标点缀 | 减少色彩数量，正文和按钮仍引用共享语义色 |
| 首页 | 草案五入口与单列问候 | 四类主题卡 + 三例句，概览只保留天气与一句生活建议 | 首页不堆商家评分/距离/价格；对话结果才展开细节 |
| 历史 | 产品原 P0 内存；架构要求本地持久化 | 会话与清单 localStorage，保留最多 30 段会话 | 原型也应能够回来继续用，但不引入登录或云同步 |
| 状态管理 | 架构推荐 zustand | React Context + useReducer | 本期单活动请求、有限历史，少一个依赖；性能风险后续用实际测量决定 |
| 网络模拟 | 有人建议 5% 随机故障 | 默认失败率 0；显式一次失败/持续失败/慢网开关 | 默认体验稳定，异常演示可复现；失败不自动重试 |
| fetch 与网络面板 | 产品草案希望类似真实 Network 条目 | fetch-compatible transport + 真 Response/ReadableStream/SSE | 用户要求 Promise+timeout 网络体验，不实现 HTTP Agent；明确 mock 并非真实网络包，不伪造 Network 面板 |
| 地图 | 产品草案建议百度路线服务；本次路线本身 mock | 百度 GL 可选真实底图 + mock 折线；无 AK 为 SVG 示意与百度 URI | 不把模拟时长、线路伪装为地图路线服务；AK 未配置是明确验证边界 |
| 软件版本 | 架构草案 Vite7/TS5.9 等多依赖 | 已安装 Vite6.4.6、React18.3.1、TS5.7.3、Router6.30.6、Lucide0.468、Vitest3.2.7 | 满足用户约束，版本由 lockfile 固定；后续为真实浏览器验收仅增加 Playwright 开发依赖，不增加 UI/业务依赖 |

## 3. 第二轮独立体验评审意见

评审赞成：统一杭州、暖白绿色、四类交付、Context 与单一协议；反对继续沿用上海示例、五入口或默认随机 5% 故障。

必须守住的五条验收原则：

1. **提醒即清单**：使用“已加入清单/待办”，禁止“届时提醒你”；确认前展示不提供到点通知。本地存储被禁用时提示刷新可能丢失，不能静默报持久保存成功。
2. **首页克制**：地点、天气、一句建议；四张主题卡只有标题和副句；保留三例句；320px 下仍可到达输入框。
3. **mock 不偷换**：未知真实地点明确本期限制，不静默套用杭州查询；“那家”等模糊上下文不要虚构身份；追问 chip 发送明确文字。
4. **默认稳定**：一次故障消费后允许成功重试；慢网可停止；超时可恢复；重试不重复追加用户问题。
5. **地图诚实**：无 AK 写“路线示意，非真实底图”；百度按钮仅表示外部打开，不是已开始实时导航；SVG + URI 不计为 GL 底图真实验收。

主负责人接受这五条，作为浏览器走查和最终交付说明的边界。

## 4. 实际交付的统一约定

### 4.1 回复与卡片协议

`ChatRequest`：`conversationId`、`query`、`city`、可选有限 `history`。

SSE 事件：`status`、`delta`、`card`、`suggestions`、`done`、`error`。

| intent | 实际 card.type | 第一轮产品草案名称 |
| --- | --- | --- |
| weather_outfit | weather | weather_outfit |
| food_recommend | restaurants | restaurant_list |
| recipe | recipe | recipe |
| hotel_recommend | hotels | hotel_list |
| route_plan | route | route_plan |
| nearby_search | places | poi_list |
| reminder | reminder | reminder |
| home_care | home | 新增的居家清单轻量场景 |
| chitchat | 无卡片 | chitchat/fallback 合并为无卡片边界回复 |

卡片字段与 discriminated union 以 `src/api/types.ts` 为唯一依据；不同时维护两套 snake_case/camelCase 字段，也不加入无用兼容映射。

实际接口仅 `GET /api/home/overview` 与 `POST /api/chat`。历史/收藏是本地状态，不实现模拟 CRUD 服务。接口切换不要求业务组件修改，但真实服务端仍须对齐协议、认证和真实数据来源。

### 4.2 底层 UI

实际基础组件：Button、IconButton、Chip、Card、Badge、Spinner、Skeleton、Modal、ToastProvider/useToast。组合完成业务结构；未使用的 Rating、Stat、Tabs、Drawer 等不提前创建空实现。

- CSS Modules 引用 `src/styles/tokens.css` 中的背景、表面、边框、文字、主色、点缀、圆角和动效语义值。
- 浅色/深色/跟随系统，持久化用户选择。
- 手机单栏，底部吸底输入；桌面 >=1024px 显示 248px 侧栏。
- 对话列有限宽，用户浅色气泡右对齐，Agent 无气泡文字排版；卡片完整到达才展示。
- PC Enter 发送、Shift+Enter 换行；手机 Enter 换行；中文输入法 composing 不误发。
- 模态支持 Esc、焦点管理与安全区；reduced-motion 下减少动画。

### 4.3 请求与交互

- 业务组件不读取 mock fixtures，统一使用 `getHomeOverview` / `streamChat`。
- 用户停止通过 AbortController 取消等待与推送，已收结果保留为部分结果。
- 每段响应绑定会话 ID 与消息 ID，迟到事件不会污染另一会话。
- 失败/中断可重试同一问题，不增加重复的用户消息。
- 用户滚离底部时不强制吸底，提供回到最新。
- 收藏/提醒须明确用户点击后写入本地，Agent 回复不自动创建副作用。

## 5. 操作减负独立评审（2026-11-17）

### 5.1 已确认的问题

Chrome实测手机390px及平板768px：回首页、进清单、恢复历史各需打开菜单再选择，共两步；桌面为一步。手机“＋”称新建却实际回首页。慢网络中切页会取消回复。另核实清单添加自动发送固定取快递例句、删除无撤销、重新生成先清空、换批仍返回同组示例。

### 5.2 独立评审与修正

主负责人提出方案，由独立产品体验/前端架构角色完整读取相关实现作只读评审，初评为条件通过；以下条件并入开发约定后，主负责人通过方案进入开发，而不是将条件通过当成代码验收。

- 独立空对话路由，回首页不新建，最近访问不等于更新时间；隐藏请求完成后仍有查看入口。
- 成功接受发送后才清源草稿；对话按ID隔离；滚动恢复拒绝过期回调，用户主动滚动可终止恢复；完成后展开不追底。
- 完整旧回复在重新生成时保持done，新结果缓冲至done再提交，进度单独显示；失败、显式停止和刷新保留旧成功结果；重试历史不含后续消息或重复的目标用户问题。
- 日期输入明确设备时区，拒绝无效/过去时间；检查本地时间解析回环，避免DST不存在的时间静默偏移；手机和平板可视视口适配，底部安全区不重复计入。
- 独立8秒撤销槽可点击且不被普通提示覆盖，原位置/完成状态恢复，防重复；连续删除仅最后一条可撤销。
- 本地调整不得继续声称换批或扩大搜索，固定演示范围必须可见。

### 5.3 自评审结论

方案通过：先减少导航步骤与打断，再补输入和恢复，不增加账户、实时生活数据、后台通知或多请求排队。手机底部导航占用少量高度，但清单取消大聊天输入框，短屏输入高度受限；这是明确取舍。实际开发与测试结果以06新增验收章节为准，不能仅凭方案通过声称功能已通过。

## 6. 手势与退出过渡独立评审（2026-11-17）

由独立移动交互设计／前端架构角色只读评审 04 第 7 章及弹层、清单、嵌套菜单、地图和浏览器测试实现，结论为条件通过。主负责人采用以下条件后实施；不是把评审通过当成功能验收。

- 从触点到弹层逐层检查滚动位置，不能只看 modalBody；浏览器已开始原生滚动、事件不可取消时不接管。内容顶部向下时在方向判定早期阻止滚动，跨过 8px 才跟手。
- 遮罩改为独立伪元素，仅遮罩变淡，不让弹层内容一起变透明。退出只写结束关键帧，从当前位移继续，不先跳回原位。
- 仅最上层弹层响应；入场结束后再拖动。关闭幂等，退出期间阻止重复点击并保留焦点约束、背景 inert 和滚动锁；动画事件校验目标和动画名，兜底计时器随卸载清理。菜单跳页和菜单→设置仍立即关闭。
- 不保留 open=false 的地点弹窗节点播动画，避免 location=null 导致内容清空、标题闪变。真实地图 ready 时才禁用该区域的弹层拖动；示意图不禁用。
- 去掉鼠标拖动，保留关闭按钮、Esc、遮罩；减少动态效果时跟手保留，回弹和退出立即完成。振动仅为可选，不承诺 iOS 支持。
- 清单使用 Pointer Events + touch-action:pan-y；只认主触点，竖滚交给浏览器，pointercancel 回弹；无滑开驻留态。删除阈值由 35% 提高到 40%，快速删除至少 72px，删除过渡期间按钮禁用；执行时按 id 查最新条目和位置，撤销恢复原状态。
- 屏幕两侧 16px 内不接管清单横滑，减小系统边缘手势冲突。保留按钮替代，动作色块文字满足 AA。

实际测试、首轮失败及修复记录见 06 第 11 章。Chrome 触摸输入不等于真实 iOS／Android 验收，真实百度底图仍受 AK 边界约束。

## 7. 视觉与文案减法评审（2026-11-17）

用户批准“减包装，不砍功能”。本轮主负责人按产品／交互视角自评审，另由独立测试角色只读核对文案断言、样式实现角色处理约定的装饰删除；未重新开展用户访谈。

- 去掉首页营销横幅、星光、渐变、英文眉题、大字水印和重复口号，把入口写成“穿搭／吃饭／住宿／出行”。天气、常用问题、对话和本地清单保留。
- 去掉没有账号能力却形似个人资料的“我的日常空间”，改为明确“设置”；删除侧栏重复提问，不删除首页的同类问题与自由输入。
- 卡片只保留标题与数据，删除副标题和占位插画；评分星、天气图标、地图／本地保存／模拟数据说明具有语义，不随星光装饰一起删除。
- 浮层保留必要阴影与动效，普通面板改为平面；不把“减法”误做成删除加载、失败、重试、撤销、无障碍或手势。
- 独立测试核对发现路线入口改名还需同步条件分支，否则地图外链与骑行降级断言会被静默跳过；设置按钮改名后应限定在“菜单”弹窗内，新对话标题使用 h1 精确定位。已按该建议更新，不删除测试。

取舍：首页不再展示 dailyTip，mock 数据本身与全部回复维持不变；减少展示性图案，但保留蓝色操作状态与双主题。功能是否通过以06第12章实测为准。

## 8. 精致化与消息类型方案三方评审（2026-11-18）

用户反馈“移动端菜单和设置不好看、整体发脏（尤其输入框）、要更多场景卡片和规范的回复类型、操作栏要优化”，并以 ChatGPT／DeepSeek／豆包为精致度参照。主负责人先写出 04 第 9 章方案，再由三个独立角色只读评审（不改代码），结论合并为 04 §9.4。

| 角色 | 关键意见（必须改） | 处理 |
| --- | --- | --- |
| 产品／交互 | 移动端底栏、输入框、页脚三层叠加是“脏”的主因；思考和计划合并且默认收起，避免跟随滚动时跳动、违背安静定位；标题按完成／停止／失败固定文案；建议只在最后一条显示；停止与失败统一走操作栏；一日行程的“看路线”必须真能执行；新意图关键词顺序写入测试；一次性失败消费后不能仍显示“已开启” | 全部采纳。“清空本机数据”“会话分组”列为下一期 |
| 视觉设计 | 给出双主题完整 token 并实测对比度，修正方案中 3 处不达 AA 的辅助色；蓝色只留链接、焦点、地图；去掉移动端底栏和页头主题键；输入框、发送键、卡片按钮、过程区、抽屉、设置的具体尺寸；深色色板去重 | 全部采纳；底栏改为“会话页隐藏、首页／清单保留”，兼顾此前“快速回首页”的反馈 |
| 前端架构／测试 | 重试时 `patch` 会残留旧思考与步骤；重新生成时状态行会被“有思考即隐藏”吞掉；三类事件、两意图、三卡片需严格校验；reducer 语义（未知 id、只前进、截断、计时带 at）；“未完成”渲染时推导；计划与思考放进首字窗口，不拉长慢网总时长（E2E 余量只有约 2.6 秒）；抽屉手势、CSS 特异性与减少动态效果；列出会失效的断言与改法 | 全部采纳；断言按原意更新，不删测试 |

主要分歧与取舍：

- **过程区是否展开**：原方案“生成中展开、出正文自动收起”；产品与视觉都认为会跳动且显得在“表演思考”。取默认收起、标题即实时状态。
- **单步结果要不要计划**：天气、菜谱、提醒等只有一个结果，不出计划步骤，只给一句简短思考；比较类（吃、住、行）、行程和清单才有 2–3 步计划。
- **底栏去留**：视觉建议全部去掉，产品建议会话页隐藏。取产品方案：会话页与新对话页隐藏，首页、清单页保留，抽屉提供同样入口。
- **复制提示**：改为图标变对勾，不弹提示，减少重复反馈。实际实现保持ARIA名称“复制回复”，成功时title变“已复制”1.5秒；不将title变化宣称为真实屏幕阅读器播报验收。

实施和实测结果见 06 第 13 章。

## 10. 品牌首页入口独立评审（2026-11-18）
