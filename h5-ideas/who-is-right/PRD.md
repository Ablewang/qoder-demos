# 家里谁说得对 · 粗略产品文档

> 状态：点子阶段 / 待开发
> 一句话：长辈的育儿老话、转发的养生文章，帮你判断"靠谱 / 不靠谱 / 有一半道理"，生成一张长辈愿意看的大字卡——**而且它敢说"这条长辈是对的"**。

---

## 1. 这个点子是怎么来的

这是**两个点子 + 一场争吵**的产物：

- **林晓（34 岁，杭州二胎妈妈）** 提了"老理儿对不对"：
  > "婆婆说'娃发烧要捂汗'，我心里知道不对，但一开口就像在吵架。"
  > 关键句："它也会说'这条婆婆是对的'。**我不是要赢她，是想有个台阶让我们都能下来。**"
- **老周（67 岁，退休语文老师）** 提了"爷爷转发靠谱榜"：
  > "我在群里发养生文章，儿子嫌我信谣言，又不明说。"
  > 想法：家人投票靠谱 / 别信，必须写理由。"有理由我就服气，比光被说'假的'强。"

**圆桌上吵起来了**（关于转发靠谱榜）：
- 林晓："我婆婆天天转'隔夜菜致癌'，我太需要了。"
- 老周（反悔了）："投票打分？这是当着全家批老人的作业。我当了一辈子老师，老了倒成了挨批的学生。"
- 强哥："我妈也转，我从来不吭声，回个'好'，她高兴就行。"
- 沈老师（心理咨询师）一锤定音：**"老人转发不是在传播信息，是在说'我惦记你'。一打分，爱就变成了错。"**
- 老周："要是不打分，我能接受。"

→ 于是产生了融合版本：**不打分、不排名、不公开；先接住"惦记"，再私下讲道理。**

**评审意见**：
- 投资人老K：**唯一投票给它**。理由——
  1. 自带跨代传播：年轻人做卡片，转给长辈，每张卡片都是一次传播
  2. 立场中立，敢说"老人对了"，两代人都愿意用
  3. 老话库越积越多，是别人抄不走的内容资产
  4. 能延展：养生谣言 → 反诈 → 用药提醒
- 风险：**医疗内容出错，口碑就毁了**。

---

## 2. 核心设计原则

1. **中立裁判，不站队**：结果有三种——✅ 长辈说得对 / ⚠️ 有一半道理 / ❌ 现在不这么做了
2. **先接住情感，再讲道理**：卡片开头永远是"谢谢惦记"，而不是"这是谣言"
3. **私下，而不是当众**：卡片设计成适合**私聊**发给长辈，不鼓励在群里公开反驳
4. **有出处**：每条结论都附权威来源（卫健委、儿科指南、辟谣平台等）

## 3. 两个入口

### 入口一：育儿老话（林晓的场景）

输入："发烧要捂汗" →

```
┌──────────────────────────┐
│ ⚠️ 有一半道理               │
│                            │
│ 妈说得对的地方：             │
│ 发烧怕冷时确实要注意保暖       │
│                            │
│ 现在医生的建议：              │
│ 体温升高时要散热，捂太多       │
│ 可能让体温更高（"捂热综合征"） │
│                            │
│ 来源：XXX 儿科指南            │
└──────────────────────────┘
       [生成给长辈看的大字卡]
```

### 入口二：长辈转发的文章（老周的场景）

粘贴文章标题或链接 →

1. 先生成一张**"谢谢惦记"卡**（任何情况都可以发）："妈，看到了，谢谢你惦记我们 ❤️"
2. 如果内容不靠谱，额外给一张**大字版说明卡**，可以选择私下补发："不过这个说法医生是这么讲的……"

### 大字卡（给长辈看的）

- 超大字号、高对比度、少字
- 语气像子女说话，不像科普文章
- 长按保存，私聊发送

## 4. 功能范围

### MVP

1. **老话库**：先人工整理 **200 条高频老话**，每条有结论 + 一半对在哪 + 出处（投资人建议：先别做开放输入，先把库做扎实）
   - 育儿类："孩子要捂""小孩不能吃盐""学步车有用""把尿"……
   - 养生类："隔夜菜致癌""酸碱体质""吃啥补啥"……
2. **搜索 / 选择**老话 → 结果页
3. **大字卡 + 谢谢惦记卡**生成
4. **"这条长辈是对的"**的条目要占一定比例，并在首页突出展示——这是产品的态度

### 第二版

5. **开放输入**：库里没有的，交给 AI 判断（明确标注"AI 判断，仅供参考"，并要求附出处）
6. **语音输入**：用手机输入法的语音转文字即可，不用自己做录音
7. **"今日老话"**：每天一条，适合发家族群（且是那种"老人说得对"的）
8. 延展：反诈话术识别、用药常识

### 明确不做

- 不做家庭成员打分、排行榜（圆桌讨论的结论）
- 不做在群里公开"辟谣"的功能

---

## 5. 技术方案

- MVP：**纯前端** + JSON 老话库，几乎零成本
- 大字卡：Canvas 生成图片
- 第二版开放输入：后端代理调用大模型，限定输出格式（结论 / 一半对在哪 / 建议 / 出处）

---

## 6. 风险

| 风险 | 应对 |
|---|---|
| 医疗内容出错 | MVP 只用人工审核过的库；每条附出处；底部声明"不能代替就医" |
| 变成"子女教训长辈"的工具 | 强制先出"谢谢惦记"；设计上鼓励私聊 |
| AI 胡编 | 开放输入放第二版，且必须带出处，没有可靠出处就说"不确定" |
| 地域差异（各地老话不同） | 允许用户投稿老话，人工审核入库 |
