## 0. 一页摘要

| 项 | 推荐 |
|---|---|
| MVP 主线 | **育儿为主线**，另加约 20 条长辈最常转发的养生说法，让「谢谢惦记」入口也能用 |
| MVP 规模 | **先上线 60 条审核过的条目**（育儿 40 + 养生 20），再逐步扩到 200 条；不为凑数降低审核标准 |
| 「长辈说得对」占比 | 目标 ≥ 25%，选题时主动去找，但不为凑比例改结论 |
| 技术 | Vite + TypeScript 纯静态页面，老话库是构建时打包进去的 JSON；Canvas 自己画卡片；不需要后端、不需要登录 |
| 搜索 | 前端「两字词组」模糊匹配 + 同义词表，200 条在手机上不到 1 毫秒 |
| 卡片 | 1080×1440 竖图，正文 84px 粗体（在手机上全屏看约等于 29 号字），每行 ≤ 10 字、≤ 5 行，暖白底黑字 |
| 审核 | 专业审核（儿科医生 / 注册营养师）+ 语气审核，**两人都签字才能发布**；构建脚本会拦住没审核完的条目 |
| 第二版 AI | 先查库 → 只在白名单资料里检索 → 模型必须引用原文片段 → 服务器核对引文真实存在 → 找不到依据就说「不确定」；AI 结果**不能生成给长辈的大字卡** |
| 排期 | 开发约 7 个人日；**真正的瓶颈是内容审核**，60 条审核完约需 2~3 周，可以和开发并行 |

## 1. 待定问题的回答

### 1.1 MVP 先做育儿还是养生？

**推荐：育儿为主线，养生只做「长辈转发」最高频的 20 条。**

理由：

1. **人群更清楚**：育儿的使用者是 25~40 岁的妈妈，她们就是做卡片、转给长辈的人；传播路径是「妈妈群里互相推荐 → 各自私聊给长辈」，很清楚。
2. **场景更急**：「孩子发烧了婆婆要捂」是当下就要解决的矛盾，用户有动力马上打开；养生文章不回也没什么后果。
3. **权威来源更集中**：育儿主要靠《中国居民膳食指南（2022）》里的婴幼儿部分、国家卫健委的婴幼儿照护文件、儿科临床指南，好找、好核对。
4. **养生赛道已有人做**：「辟谣」本身已经有中国科协「科学辟谣」平台等在做，我们的差别不在「辟谣」，而在「谢谢惦记」和「敢说长辈对」。所以养生只需少量条目，让第二个入口能跑通即可。

需要注意的风险：育儿涉及婴儿，出错代价更高。应对办法是每条都加「这些情况要马上去医院」（红旗提示），并且育儿条目必须由儿科医生审核。

**需要你拍板的选项：**
- A. 育儿为主 + 20 条养生（**推荐**）
- B. 只做育儿，「谢谢惦记」入口第二版再做（最聚焦，但老周的场景就没了）
- C. 育儿、养生各一半（覆盖广，但审核压力翻倍，两边都浅）

### 1.2 200 条老话怎么整理、谁来审核？

**推荐：先做 60 条精品上线，再按「用户搜了但库里没有」的词扩充到 200 条。** 整理流程见第 5 节。

审核人有三个选项，**需要你拍板**：

| 选项 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| A（**推荐**） | 找 1 位儿科医生 + 1 位注册营养师兼职，按条付费审核；页面写明审核人的资质（可以只写职称不写全名） | 可信度最高，出错时有人兜底，也是对外讲的「卖点」 | 要花钱、要找人，速度受对方时间限制 |
| B | 不请专家，每条只改写权威来源原文，并把原文引用贴在条目里 | 零成本、快 | 改写时可能理解错；出问题没人兜底；不能说「医生审核」 |
| C | 和医院科普号或医生自媒体合作，对方出审核，我们给署名和流量 | 不花钱，还带来流量 | 谈合作慢，对方可能想加广告、改语气 |

折中做法：先用 B 把初稿准备好，再请 A 里的专家集中审核，这样专家只需要「看对错」，不用从零写，费用和时间都能省一大半。

### 1.3 产品名

| 候选 | 好处 | 问题 |
|---|---|---|
| 家里谁说得对 | 一看就懂，年轻人觉得好玩 | 有「分输赢」的味道；长辈看到会觉得「你是来跟我争的」 |
| 老理儿对不对 | 「老理儿」带着尊重和亲切；是一个问题，答案可能是「对」 | 「老理儿」是北方口语，南方用户可能觉得生分 |
| 谢谢惦记 | 最温暖，最符合圆桌精神 | 光看名字不知道是干什么的，不利于搜索和推荐 |

**推荐：产品名用「老理儿对不对」，卡片功能叫「谢谢惦记卡」。** 原因是产品名决定了长辈第一眼的感受：「老理儿」是在说长辈的经验，而不是在说长辈的错。如果你担心南方用户，备选是「老话对不对」。
「家里谁说得对」可以留作对年轻人宣传的口号（比如分享文案「婆婆说要捂汗，家里谁说得对？」）。

**需要你拍板**：用哪个名字。

### 1.4 方案阶段新发现、也需要你拍板的问题

1. **给长辈的大字卡上，要不要放产品名或二维码？**
   - 推荐：**默认不放**，只在最底下放一行小字出处。卡片要像「孩子自己说的话」，一放产品名就变成「孩子拿 App 来教育我」。传播靠年轻人之间分享结果页，不靠长辈那张卡。
   - 代价：少了一条「长辈看到卡 → 扫码」的传播路径。可以加一个开关，让用户自己选「带上小标识」。
2. **部署在哪？** 要在微信里顺利打开，最好用**已备案的域名 + 国内云存储 / CDN**（例如阿里云 OSS、腾讯云 COS）。你有没有已备案的域名？如果没有，可以先用 Qoder Sites 托管做内测，但微信里能不能正常打开要实测。
3. **用户投稿怎么收？** MVP 没有后端，推荐先用一个在线问卷链接（如腾讯问卷）收集，人工看。
4. **要不要统计「搜了但没搜到」的词？** 这是扩充老话库最好的依据。推荐用第三方统计（如百度统计）的自定义事件只记录搜索词，不记录任何个人信息。

## 2. 技术方案

### 2.1 MVP 总体结构

```
浏览器（微信内置浏览器为主）
 ├─ 静态页面（Vite + TypeScript，单页应用，用 # 号路由）
 ├─ sayings.json（构建时从内容表格生成，只包含「已发布」条目）
 ├─ 搜索：前端模糊匹配 + 同义词表
 └─ 卡片：Canvas 绘制 → 转成图片 → 用户长按保存
没有后端、没有登录、不收集个人信息
```

- 依赖管理用 pnpm，框架尽量轻：页面只有 4~5 个，推荐 **Preact 或原生 TypeScript**，打包后控制在 100KB 以内（不含老话库）。
- 老话库约 200 条 × 每条约 1.5KB ≈ 300KB，压缩后约 80KB，一次性加载即可，不用分页请求。

### 2.2 老话条目的数据结构

```ts
type Verdict = 'right' | 'half' | 'outdated';
// right    = ✅ 长辈说得对
// half     = ⚠️ 有一半道理
// outdated = ❌ 现在不这么做了（不用「错误」「谣言」这类字眼）

type Category = 'parenting' | 'health';

interface Source {
  org: string;          // 发布机构，如「中国营养学会」
  title: string;        // 文件或指南名称
  year?: number;
  url?: string;
  quote?: string;       // 支撑结论的原文摘录（审核时核对用）
  verified: boolean;    // 是否已核对原文；false 的条目不能发布
}

interface Saying {
  id: string;                 // 如 "parenting-fever-sweat"
  category: Category;
  tags: string[];             // 小分类：发烧、喂养、睡眠、饮食……
  ageRange?: string;          // 育儿条目适用年龄，如 "0-6月"
  title: string;              // 标准说法：「发烧要捂汗」
  aliases: string[];          // 各地不同说法：「捂一身汗就好了」「发烧盖厚被子」
  verdict: Verdict;

  elderRight: string;         // 长辈对在哪（必填！即使是 ❌ 也要写出发点对在哪）
  nowAdvice: string;          // 现在医生 / 指南的建议
  whyChanged?: string;        // 为什么以前这么说、后来为什么变了（给年轻人看，帮他理解长辈）
  redFlags?: string;          // 什么情况要马上就医（育儿条目基本必填）

  sources: Source[];          // 至少 1 条 verified=true

  bigCard: {
    lines: string[];          // 大字卡正文，≤ 5 行，每行 ≤ 10 字
    sourceLine: string;       // 卡片底部小字出处，≤ 20 字
  };

  review: {
    status: 'draft' | 'reviewing' | 'published' | 'retired';
    medicalReviewer?: string; // 专业审核人（职称即可）
    toneReviewer?: string;    // 语气审核人
    reviewedAt?: string;      // 审核日期
    nextReviewAt?: string;    // 下次复审日期（默认 1 年后）
  };
}
```

几个关键设计：

- **`elderRight` 必填**：这是「先接住惦记」在数据层的体现。即使结论是 ❌，也要写出「怕孩子冷着」「想让家人吃好」这类出发点。结果页上它永远排在第一位。
- **`bigCard` 单独写**：不是从 `nowAdvice` 自动缩写的，而是人工写的「孩子对长辈说的话」，审核时也要过语气关。
- **构建时自动检查**（构建脚本）：不是 `published` 的不打包；没有 `verified` 来源的报错；`elderRight` 为空报错；大字卡超过 5 行或某行超过 10 字报错；`nextReviewAt` 已过期的给出警告。**内容安全靠机器把关，而不是靠记得检查。**

### 2.3 搜索方式

200 条规模不需要搜索服务，前端即可：

1. **整理输入**：去掉标点空格、全角转半角；套用同义词表统一说法（娃 / 宝宝 / 小孩 / 孩子 → 孩子；发烧 / 发热 → 发烧；捂 / 盖 / 裹 → 捂 ……），同义词表也作为内容的一部分维护。
2. **切成两字词组**：「发烧要捂汗」→「发烧」「烧要」「要捂」「捂汗」。
3. **打分**：用户输入的词组有多少命中条目的标准说法、别名、标签；命中标准说法的分数最高，其次是别名，再次是标签；整句完整出现额外加分。
4. **显示前 5 条**，低于阈值就算「没找到」。
5. **没找到时**：显示「库里还没收这句」+ 同分类的热门条目 + 投稿链接；**「谢谢惦记卡」照样能做**——回应惦记不需要先判断对错。

这样也能处理「粘贴一篇文章标题」的情况：标题里的「隔夜菜」「致癌」会命中对应条目。

> 粘贴链接：MVP 无法读取文章内容（浏览器跨域限制，微信公众号文章也防抓取），所以提示用户「请粘贴标题或其中一句话」。第二版有后端后也建议保持这种方式。

### 2.4 大字卡和「谢谢惦记」卡的生成

- **自己用 Canvas 画**，不用「把网页截图成图片」的库（html2canvas 一类）。原因：在微信里截图库常出现字体错位、表情符号缺失、图片模糊；自己画只要处理文字换行和几个图形，完全可控。
- **字体用手机系统自带的粗体中文字体**（苹方、思源黑体等），不下载网络字体（中文字体动辄几 MB）。
- **不在卡片里用 emoji**：不同手机显示不一样，有的老手机显示成方块。✅⚠️❌ 改成自己画的小图标 + 文字。
- **保存方式**：Canvas 转成图片后放进 `<img>` 标签，提示「长按图片保存，私聊发给长辈」。微信内长按图片可以保存或直接转发给朋友，这是目前最稳的方式（自定义分享卡片需要公众号资质，MVP 不碰）。
- **称呼可选**：妈 / 爸 / 奶奶 / 姥姥 / 外婆 / 自己填。卡片文字里的「{称呼}」自动替换。

四种卡片模板：

| 卡片 | 用在什么时候 | 开头 |
|---|---|---|
| 夸夸卡 | ✅ 长辈说得对 | 「{称呼}，您说得对！」 |
| 补充卡 | ⚠️ 有一半道理 | 「{称呼}，谢谢您惦记」 |
| 说明卡 | ❌ 现在不这么做了 | 「{称呼}，谢谢您惦记」 |
| 谢谢惦记卡 | 任何时候，不需要判断对错 | 「{称呼}，看到了」 |

> 夸夸卡是这个产品的「态度」：长辈说对了，孩子主动发一张「您说得对，医生也这么讲」——这可能是长辈收到过最开心的一次「科普」。

### 2.5 第二版：开放输入（接 AI）

**后端**：一个云函数（国内云厂商的函数计算 / 云函数即可），只做一件事：`POST /api/judge`，输入一句话，返回结构化结果。大模型选国内合规的服务商接口。

**处理流程（防胡编）：**

```
用户输入
  │
  ├─① 高风险词拦截：用药剂量、停药、癌症治疗、孕期用药、偏方治病……
  │     → 不判断，直接回答「这个要问医生」，给出就医提示
  │
  ├─② 先查老话库（同样的模糊匹配，阈值更低）
  │     → 命中就直接返回人工审核过的条目，不调用 AI
  │
  ├─③ 在「白名单资料库」里检索
  │     资料库 = 我们人工收集的权威文件原文切片
  │     （膳食指南、卫健委文件、儿科指南、科学辟谣平台文章……）
  │     → 一条相关资料都检索不到 → 返回「不确定，建议问医生」，不调用 AI
  │
  ├─④ 调用大模型，只把检索到的资料片段喂给它，要求：
  │     · 只能依据给定资料回答，不能用自己的知识补充
  │     · 严格按格式输出：结论 / 长辈对在哪 / 现在的建议 / 引用的资料编号 + 原文
  │     · 依据不足就输出「不确定」
  │
  ├─⑤ 服务器核对：
  │     · 引用的资料编号是否真的存在
  │     · 引用的「原文」是否真的出现在那条资料里（逐字比对）
  │     · 任何一项不通过 → 改为「不确定」
  │
  └─⑥ 返回结果，页面明确标注「AI 判断，未经医生审核，仅供参考」
        同时把这条输入放进「待审核」队列，人工审核后可以正式入库
```

**两条硬规定（建议）：**

1. **AI 结果不能生成给长辈的大字卡**，只能生成「谢谢惦记卡」。理由：大字卡是用孩子的口吻发给长辈的，未经审核的内容一旦出错，伤害的是家里的信任，而且出错的截图会落到我们头上。
2. **AI 不使用三档正式结论**：AI 只能给「看起来靠谱 / 看起来有出入 / 不确定」这种更软的说法；「✅ 长辈说得对 / ⚠️ 有一半道理 / ❌ 现在不这么做了」只给人工审核过的条目。

其他：相同输入做缓存（省钱、结果一致）；按设备限制调用频率；不存储任何个人信息。
**合规提醒**：对外提供生成式 AI 服务在国内有相关管理规定（如《生成式人工智能服务管理暂行办法》），上线第二版前需要核实是否需要备案或登记、使用哪种接入方式最合规——**这一条上线前必须单独确认**。

页面上**不放「分享到群」按钮**，所有出口都是「保存图片 → 私聊」。

### 3.6 大字卡设计规范（给 60 岁以上读者）

画布 1080×1440（3:4 竖图）。在微信聊天里点开后图片会撑满屏幕宽度，大约缩小到原来的 1/3，下表的「手机上实际大小」按这个换算：

| 元素 | 画布字号 | 手机上实际大小 | 说明 |
|---|---|---|---|
| 开头称呼句 | 96px 粗体 | ≈ 33 号字 | 「妈，您说得对！」 |
| 正文 | 84px 粗体 | ≈ 29 号字 | 每行 ≤ 10 字，≤ 5 行 |
| 结论标签 | 56px 粗体 | ≈ 19 号字 | 图标 + 文字 |
| 底部出处 | 44px 常规 | ≈ 15 号字 | 一行，长辈不一定看，给信任感 |

```
┌──────────────────────────────┐  1080
│                               │
│  ▍✅ 医生也这么说               │  ← 结论标签（图标+文字）
│                               │
│  妈，您说得对！                 │  ← 96px 粗体
│                               │
│  一天一个鸡蛋                   │  ← 84px 粗体，行距 1.5 倍
│  蛋黄也要吃                    │
│                               │
│                               │
│                               │
│  ─────────────────            │
│  出处：中国居民膳食指南（2022）   │  ← 44px
└──────────────────────────────┘  1440
```

可读性要求：

1. **对比度**：暖白底（#FFF6E5）+ 近黑字（#1F1F1F），对比度约 16:1，远超无障碍标准最高级 7:1；不用浅灰字。
2. **不只靠颜色区分**：老年男性色弱比例不低，✅⚠️❌ 必须同时有图标和文字。
3. **只用粗体、不用细体和斜体**；不加花哨背景、不加水印纹理。
4. **少字**：整张卡正文不超过 50 字；一屏看完，不需要放大、不需要滑动。
5. **语气像孩子说话**：用「您」；不用「谣言」「错误」「伪科学」「智商税」「你不懂」；用「医生说」「现在建议」「以前条件不一样」。
6. **上线前找 3~5 位 60 岁以上的长辈，在他们自己的手机上实测**：能不能不戴老花镜看清、看完的第一反应是什么。

「谢谢惦记卡」不带出处、不带结论，画面更温暖（可以有一个手绘小插图，如一碗汤、一束花），文案从 5 条模板里选：

- 「{称呼}，看到了，谢谢您惦记我们」
- 「{称呼}，收到啦，我们会注意的」
- 「{称呼}，您也照顾好自己，我们都挺好」
- ……（模板也要过语气审核）

## 4. 12 条示例老话

> 说明：
> - 育儿 6 条、养生 6 条；结论分布：✅ 5 条、⚠️ 3 条、❌ 4 条。
> - 出处只写我确信存在的权威来源；具体文件名、年份、原文页码不确定的，标「待核实」。**所有条目入库前都要由审核人核对原文，把 `verified` 改为 true。**
> - 这些是**初稿**，不是审核过的医学内容。

### 育儿

#### 1. 发烧要捂汗 —— ⚠️ 有一半道理

- **别名**：捂一身汗就退烧了 / 发烧盖厚被子 / 发烧不能吹风
- **长辈对在哪**：孩子刚开始发烧时，常常手脚冰凉、打寒战、喊冷，这时候给孩子适当保暖是对的。
- **现在的建议**：不再发冷、身上开始发烫后，就要减少衣服和被子，帮助散热；捂得太厚反而让体温升得更高，小婴儿被捂得太严还有「捂热综合征」的危险。退烧药按说明书或医生建议使用。
- **为什么以前这么说**：退烧时人会出汗，看起来像是「汗出来烧就退了」，其实是体温下降时身体在散热，出汗是结果不是原因。
- **马上就医**：3 个月以下的宝宝发烧；精神很差、叫不醒；抽搐；呼吸困难；持续高烧不退。
- **出处**：国内儿科发热处理相关临床指南（中华医学会儿科学分会相关指南，**具体文献待核实**）
- **大字卡**：
  ```
  {称呼}，谢谢您惦记
  孩子打冷战时
  盖暖和点是对的
  不冷了就减被子
  捂太厚反而更烧
  ```

#### 2. 学步车能让孩子早点走路 —— ❌ 现在不这么做了

- **别名**：坐学步车学走路快 / 学步车解放大人
- **长辈对在哪**：想让孩子早点学会走、大人也能腾出手干点活，这个心思完全能理解。
- **现在的建议**：学步车并不能让孩子更早学会走路，还容易翻倒、滑到台阶边摔伤。让孩子多在安全的地面上爬、扶着家具站，自然就会走了。
- **为什么以前这么说**：以前家里人手紧，学步车能让孩子「自己待着」，看起来还在练走路。
- **出处**：美国儿科学会（AAP）关于婴儿学步车安全问题的政策声明（**年份待核实**）；国内相关建议**待核实**
- **大字卡**：
  ```
  {称呼}，谢谢您惦记
  学步车容易翻倒
  医生说帮不了走路
  让娃多爬多扶站
  自己就会走啦
  ```

#### 3. 小婴儿要喂水，不然会上火 —— ❌ 现在不这么做了

- **别名**：宝宝要多喝水 / 吃奶的孩子也得喂水 / 不喂水会上火
- **长辈对在哪**：怕孩子渴着、怕「上火」，这份心是对的；孩子开始吃辅食以后，确实要开始喝水。
- **现在的建议**：6 个月以内纯吃母乳的宝宝，一般不需要额外喂水，奶里的水分已经够了；吃配方奶的按说明正确冲调即可。添加辅食后再开始少量喝水。
- **为什么以前这么说**：以前奶粉冲得浓、天气热又没空调，大人觉得孩子「嘴干」「上火」就喂水。
- **出处**：中国营养学会《中国居民膳食指南（2022）》中的婴幼儿喂养部分；世界卫生组织（WHO）关于 6 个月内纯母乳喂养的建议
- **大字卡**：
  ```
  {称呼}，谢谢您惦记
  半岁前喝奶就够
  奶里水分很足
  等加了辅食
  再慢慢喝水
  ```

#### 4. 有奶就喂母乳，奶粉比不上 —— ✅ 长辈说得对

- **别名**：母乳最好 / 能喂母乳就别喝奶粉
- **长辈对在哪**：完全正确。母乳是婴儿最好的食物，医生和指南都是这么建议的。
- **现在的建议**：建议出生后 6 个月内纯母乳喂养，之后添加辅食，并可以继续喂母乳。**补充一句**：如果妈妈奶不够或有特殊情况，用配方奶也是安全的选择，妈妈不用有压力。
- **出处**：世界卫生组织（WHO）婴儿喂养建议；中国营养学会《中国居民膳食指南（2022）》婴幼儿喂养部分
- **大字卡**（注意最后两行：避免这张卡被拿去给奶不够的妈妈施压）：
  ```
  {称呼}，您说得对！
  母乳确实最好
  医生也这么说
  奶不够时用奶粉
  也一样放心
  ```

#### 5. 小孩多去外面玩，别老盯着电视手机 —— ✅ 长辈说得对

- **别名**：出去跑跑别看电视 / 老看手机眼睛要坏
- **长辈对在哪**：完全正确。白天多在户外活动，对预防近视有明确好处；小孩子看屏幕的时间也确实要限制。
- **现在的建议**：鼓励孩子每天在户外活动（国内近视防控建议中常见「每天户外 2 小时」的说法，**具体文件待核实**）；2 岁以下尽量不看屏幕，2~4 岁每天不超过 1 小时。
- **出处**：世界卫生组织（WHO）关于 5 岁以下儿童身体活动、久坐和睡眠的指南（2019）；教育部等八部门《综合防控儿童青少年近视实施方案》（2018）；国家卫健委儿童近视防控相关技术指南（**具体名称待核实**）
- **大字卡**：
  ```
  {称呼}，您说得对！
  多去外面玩
  对眼睛真有好处
  少看手机电视
  ```

#### 6. 多晒太阳就不缺钙 —— ⚠️ 有一半道理

- **别名**：晒太阳补钙 / 抱出去晒晒长得快
- **长辈对在哪**：晒太阳时皮肤能合成维生素 D，帮助身体吸收钙，户外活动也对孩子好。
- **现在的建议**：小婴儿光靠晒太阳往往不够，指南建议宝宝出生后数日起每天补充维生素 D（具体剂量听儿保医生的）；健康足月、正常吃奶的宝宝一般不需要额外补钙。半岁以内避免阳光直射，隔着玻璃晒效果很差。
- **出处**：中国营养学会《中国居民膳食指南（2022）》婴幼儿喂养部分
- **大字卡**：
  ```
  {称呼}，谢谢您惦记
  晒太阳是好的
  医生说还要每天
  补点维生素D
  别隔着玻璃晒
  ```

### 养生

#### 7. 隔夜菜致癌 —— ⚠️ 有一半道理

- **别名**：剩菜不能吃 / 隔夜菜有亚硝酸盐
- **长辈对在哪**：剩菜确实不能随便放，放久了、放不对会变质，尤其是夏天。
- **现在的建议**：「致癌」说得太重了。及时放进冰箱、尽快吃完、吃之前彻底热透的剩菜，亚硝酸盐一般远到不了有害的量；真正要防的是细菌。绿叶菜和凉拌菜尽量当顿吃完，有异味、发黏的不要舍不得。
- **出处**：国家食品安全风险评估中心、中国科协「科学辟谣」平台相关解读（**具体文章待核实**）
- **大字卡**：
  ```
  {称呼}，谢谢您惦记
  剩菜要当心，对！
  及时放冰箱
  吃前热透就行
  变味了别心疼
  ```

#### 8. 吃饭七分饱 —— ✅ 长辈说得对

- **别名**：饭吃七分饱 / 少吃一口活到九十九
- **长辈对在哪**：完全正确。吃饭不吃撑、控制总量，有助于保持健康体重。
- **现在的建议**：膳食指南强调「吃动平衡」、控制总能量、保持健康体重，和「七分饱」是一个意思。
- **出处**：中国营养学会《中国居民膳食指南（2022）》（「七分饱」字面表述**待核实**，核心原则确定）
- **大字卡**：
  ```
  {称呼}，您说得对！
  吃饭七分饱
  医生也这么讲
  ```

#### 9. 口味淡点好，少吃盐 —— ✅ 长辈说得对

- **别名**：吃咸了伤身 / 少吃咸菜
- **长辈对在哪**：完全正确。吃盐多和高血压等慢性病关系密切。
- **现在的建议**：成年人每天食盐不超过 5 克；酱油、咸菜、腊肉、加工食品里也有不少「看不见的盐」。
- **出处**：中国营养学会《中国居民膳食指南（2022）》；世界卫生组织（WHO）关于减少盐摄入的建议
- **大字卡**：

  ```
  口味淡点好
  一天盐不过5克
  咸菜酱油也算
  ```

#### 10. 一天一个鸡蛋，身体好 —— ✅ 长辈说得对

- **别名**：每天吃个鸡蛋 / 早上一个蛋
- **长辈对在哪**：完全正确。鸡蛋营养好，指南就是这么建议的。
- **现在的建议**：一般人每天一个鸡蛋，蛋黄也要吃，不用因为怕胆固醇就扔掉蛋黄。有特殊疾病的听医生的。
- **出处**：中国营养学会《中国居民膳食指南（2022）》
- **大字卡**：
  ```
  {称呼}，您说得对！
  一天一个鸡蛋
  蛋黄也要吃
  ```

#### 11. 酸性体质容易生病，要吃碱性食物 —— ❌ 现在不这么做了

- **别名**：酸碱体质 / 喝碱性水调体质 / 酸性体质易得癌
- **长辈对在哪**：多吃蔬菜水果、少吃大鱼大肉，这个建议本身是好的。
- **现在的建议**：人体血液的酸碱度由肺和肾自己调节，稳定在很窄的范围内，吃什么都改变不了「体质的酸碱」；花钱买「碱性水」「碱性食品」来防病治病没有依据。
- **出处**：人体生理学基本常识；中国科协「科学辟谣」平台相关文章（**具体文章待核实**）
- **大字卡**：
  ```
  {称呼}，谢谢您惦记
  多吃菜少吃肉
  这点说得对
  身体酸碱自己会调
  不用买碱性水
  ```

#### 12. 喝骨头汤补钙 —— ❌ 现在不这么做了

- **别名**：吃啥补啥 / 骨头汤壮骨头 / 老人喝骨头汤防骨质疏松
- **长辈对在哪**：想给家人补身体的心意是对的，热汤喝着也舒服。
- **现在的建议**：骨头汤里的钙其实很少，脂肪和嘌呤倒是不少（痛风、血脂高的人要少喝）。补钙更靠谱的是奶和奶制品、豆制品、深绿色蔬菜；膳食指南建议每天吃奶类 300~500 克。
- **出处**：中国营养学会《中国居民膳食指南（2022）》
- **大字卡**：
  ```

  骨头汤钙很少
  补钙喝牛奶
  吃豆腐更管用
  ```

| 一级 | 国家卫健委及其发布的文件；中国营养学会膳食指南；中华医学会各分会的指南和专家共识；世界卫生组织 | 可以单独作为结论依据 |
| 二级 | 国家食品安全风险评估中心、中国疾控中心、中国科协「科学辟谣」平台、三甲医院官方科普 | 可以作为依据，最好配一条一级来源 |
| 不采用 | 自媒体、百科词条、商家文章、AI 生成内容 | 只能作为「找选题」的线索，不能当出处 |

### 5.2 整理流程

```
① 收集选题        用户访谈 / 宝妈群 / 科学辟谣平台历年榜单 / 用户投稿 / 未命中搜索词
      ↓
② 合并说法        同一个意思的不同说法合并成一条，各地叫法放进「别名」
      ↓
③ 写初稿          内容编辑按数据结构填写；每个结论都要贴上来源原文摘录
                  （可以用 AI 辅助起草文字，但每句话都必须对得上原文）
      ↓
④ 专业审核        育儿 → 儿科医生；养生 → 注册营养师 / 相关科室医生
                  核对：结论对不对、来源原文是否支持、有没有遗漏就医提示
      ↓
⑤ 语气审核        换位成长辈读一遍：有没有居高临下？「长辈对在哪」是真心的吗？
                  禁用词检查；大字卡是不是像孩子说的话
      ↓
⑥ 发布            两人都签字 → 状态改为 published → 构建脚本检查通过才会上线
      ↓
⑦ 复审            每条每年复审一次；指南更新时（如膳食指南出新版）相关条目全部复审；
                  用户点「我觉得这条不对」累计到一定数量也触发复审
```

### 5.3 内容工具

审核医生大概率不会用代码仓库，所以：

- **内容放在在线多维表格里**（飞书多维表格或腾讯文档表格），一行一条，字段和数据结构一一对应，审核人直接在表格里改状态、写意见。
- **导出脚本**：把表格导出成 CSV → 转成 `sayings.json` → 运行检查规则 → 不通过就报错，不会上线。
- 每次发布记录一个版本号，出问题可以马上回退到上一版。

### 5.4 「长辈说得对」怎么保证比例

- 选题时**专门去找**长辈说对了的老话：膳食指南、卫健委科普里大量建议本来就和老话一致（少盐、七分饱、多走路、早睡、母乳……）。
- 首页「长辈说得对」区只放 ✅ 条目，至少 8 条轮换。
- **不为凑比例改结论**——一旦被发现「硬说长辈对」，中立裁判的信誉就没了。

## 8. 内部评审与修订（2026-11-17）

三个视角各自挑错，结论直接改方案。**本节优先于前文。**

### 8.1 产品视角

| 发现的问题 | 修订 |
|---|---|
| 「家里谁说得对」「老理儿对不对」都在暗示「人」之间有输赢 | 内测名改为 **「老话查一查」**：查的是一句话有没有依据，不评判任何人。页面上不出现「谁赢」「谁对」这类字眼 |
| 原方案把「谢谢惦记」写成「强制先出」「一定先出」，等于替用户打感情牌 | **改为可选**：结果页和首页都只是提供一个入口；文章入口不再强制先出谢谢卡；谢谢卡模板里加入不煽情的写法（如「收到啦，我看看」） |
| 「长辈说得对」目标 ≥ 25%，会诱导为凑比例改结论 | **删掉比例目标**。首页只如实列出结论确实是 ✅ 的条目，有几条就几条 |
| 60 / 200 条、专家审核还没落实，不应阻塞本地产品开发 | 本地内测版用「少量真正核对过来源原文的低风险生活常识 + 明确标注的待核验演示条目」先跑通全流程；条数和专家审核放到正式化阶段 |
| 品牌标记要不要上卡 | 做成开关，**默认关闭** |
| 统计埋点、AI 开放输入 | 本地内测版**都不做**：纯前端、无第三方埋点、无后端、不收集任何数据 |

### 8.2 事实内容安全视角

| 发现的问题 | 修订 |
|---|---|
| 「长辈对在哪」设为所有条目必填，会逼着编辑在整体危险的说法里硬找「对的一半」 | 改为：**只有 ✅ 和 ⚠️ 必须写「长辈对在哪」；❌ 条目禁止写这个字段**，最多写一句「可以理解的出发点」（如「怕孩子着凉」），并在页面上明确这不是在说这个做法对 |
| 「发烧要捂汗」原判 ⚠️ 有一半道理 | 捂汗作为退烧办法本身有风险（尤其小婴儿），不能因为「发冷时可以保暖」就判一半对。**改判 ❌ 现在不这么做了**，「发冷时适当保暖」放进建议里讲 |
| 「仅供参考」「不能代替就医」被当成兜底 | 不再用「仅供参考」给结论兜底；结论错了就是错了，门槛要挡在发布前。页面只保留一句事实性的说明：「本地演示，不是医疗建议；身体不适请就医」 |
| 原方案写「审核：儿科主治医师」的示例、「医生也这么说」等字样 | **任何地方都不得自称经过医生审核**。核对状态只有两种：**「来源原文已核对」**（编辑把结论和权威来源原文逐字对上，附链接、摘录、适用范围、核对日期；这不是医生审核）和**「待核验 · 演示」**。卡片文字从「医生也这么说」改为「指南也这么建议」这类对得上来源的说法 |
| 出处写「XXX 相关指南（待核实）」也能出现在条目里 | 待核实的出处**不得作为公开医疗建议**：待核验条目在界面上整体标注「演示，未核验」，不能生成任何断言性大字卡；构建脚本强制检查 |
| 来源引文可能被编辑凭印象「补全」 | 引文必须是来源页面的逐字摘录，必须同时有 URL；没 URL 的条目不能填引文。内测版的引文由调研时实际打开的页面摘录 |
| 医疗类条目（婴儿喂养、发烧、用药相关）即使找到原文，适用范围复杂 | 内测版**只把低风险生活常识**标为「来源原文已核对」，包括有明确年龄范围的少看屏幕、2～3 岁自主进餐与 2 岁后清淡口味等日常习惯；婴儿喂养、补铁补钙、发热、疾病及发育安全等医疗相关条目一律保持「待核验」，等专业审核流程落实后再说 |

### 8.3 前端可读性视角

| 发现的问题 | 修订 |
|---|---|
| 「每行 ≤ 10 字」只算了正文，没算称呼：「{称呼}」可能是 4 个字的「外婆奶奶」 | 门槛按称呼最长 4 字计算；称呼输入框限 4 字；画卡时再实测每行宽度，超宽先缩字号（最小 72px），仍超宽则自动折行，绝不溢出画布 |
| 卡片用 emoji 表示结论，部分手机会显示成方块 | 卡片里不用 emoji，结论用自己画的色块 + 文字 |
| 页面本身也可能被长辈直接看到 | 页面加「字号：标准 / 大 / 特大」切换，窄屏 360px 在「特大」下也不得横向溢出 |
| 导出方式 | Canvas → 图片（`<img>`），手机长按保存；桌面提供「下载图片」按钮。不使用截图类库 |
| 真机长辈试读 | 内测版**没有做**真机 60 岁以上长辈试读，只做了浏览器窄屏模拟；正式化前必须补 |

### 8.4 内测版的内容门槛（构建脚本 + 自动测试强制执行）

1. `id` 唯一；标题、别名非空。
2. ✅ / ⚠️ 必须有「长辈对在哪」；❌ 不得有。
3. 「来源原文已核对」条目：只能是低风险（`risk: low`）；每条来源都要有 https 链接、逐字摘录、适用范围、核对日期；链接域名必须在白名单（中国营养学会、国家卫健委、中国政府网、中国疾控、世界卫生组织等官方域名）。
4. 「待核验」条目：可以没有链接，但**只要写了摘录就必须有链接**；必须写明待核验点。
5. 大字卡：最多 5 行；称呼按 4 字计，每行 ≤ 10 字；出处行 ≤ 20 字；只有「来源原文已核对」的条目允许有可导出的大字卡。
6. 面向用户的解释、建议、待核验提示和卡片正文禁用贬低与虚假背书说法（如谣言、伪科学、智商税、愚昧、你不懂、仅供参考、医生已审核、医生也这么说等）；来源原文摘录保留原貌，不用禁词替换引文。
7. 任何一条不满足，`pnpm build` 直接失败。
