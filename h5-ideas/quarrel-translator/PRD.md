# 吵架翻译器 · 粗略产品文档

> 状态：点子阶段 / 待开发
> 一句话：把"气话"翻译成"人话"，再告诉你对方会听成什么。

---

## 1. 这个点子是怎么想出来的

**出发点**：头脑风暴的要求是"有趣、有用、有意义、有创意、有亮点"，我想找一个能**同时**满足这几点，而且 MVP 很轻的点子。

**思考过程**：

1. **观察到的真实问题**：大部分争吵不是因为事情本身，而是因为**说法**。"你怎么又不回消息！"背后其实是"我有点担心 / 我觉得被忽略了"。一句话的措辞就能把沟通变成吵架。
2. **已有方法论，但没人用得上**：非暴力沟通（NVC，马歇尔·卢森堡）把表达拆成 **观察 → 感受 → 需要 → 请求** 四步，道理很多人知道，但**在气头上根本想不起来**。缺的是一个"当场能用"的工具。
3. **AI 恰好擅长这件事**：改写语气、识别情绪、推断背后的需要，正是大模型的强项，技术上没难度。
4. **"翻译器"这个比喻是让它变好玩的关键**：如果叫"沟通改写助手"就很无聊、像说教；叫"吵架翻译器"，把"情绪语"当成一门外语，立刻就有了梗感和传播性。
5. **真正的亮点——反向翻译**：只做"温和改写"是常见功能。我想加一个反转：**显示"对方可能听到的意思"**。比如你说"随便你"，对方听到的是"我对你很失望，懒得跟你说了"。这个落差让人有"啊原来是这样"的顿悟感，也是最适合截图分享的部分。

**五个维度的自检**：
- 有趣：翻译器梗 + 对方听到的版本，天然有反差笑点
- 有用：真的能拿去发，减少一次吵架
- 有意义：帮人好好说话，修复关系
- 有创意：把 NVC 包装成"翻译"，并且做双向
- 有亮点：原话 vs 翻译 vs 对方听到的，三栏对照卡片

## 2. 目标用户与场景

| 用户 | 典型场景 |
|---|---|
| 情侣 / 夫妻 | 微信上吵起来，想发但又怕越说越僵 |
| 子女 ↔ 父母 | 被催婚、被唠叨，想表达不满又不想伤人 |
| 职场 | 想怼同事/领导，需要一个"体面版" |
| 家长 ↔ 孩子 | 想发火前先换个说法 |

核心场景：**"我手指已经放在发送键上了，但我犹豫了一下。"** —— 产品就是在这一秒介入。

---

## 3. 核心功能

### MVP（第一版只做这些）

1. **正向翻译（气话 → 人话）**
   - 输入：一句或一段想说的气话
   - 选择：对象关系（伴侣 / 父母 / 朋友 / 同事 / 孩子）
   - 输出三块：
     - **对方可能听到的**：TA 大概率会怎么理解这句话（亮点）
     - **你真正想说的**：拆解成 观察 / 感受 / 需要 / 请求
     - **人话版本**：可直接复制发送的改写，提供 2~3 种语气（温和 / 坚定 / 带点幽默）
2. **一键复制** 人话版本
3. **对照分享卡**：生成"原话 / 对方听到的 / 人话版"三栏图片，可保存分享

### 第二版

4. **反向翻译（对方的气话 → TA 其实想说）**：收到一句很冲的话，帮你读懂背后的情绪和需要，再给你一个回应建议。
5. **冷静 10 秒**：点"翻译"后先播放一个 10 秒呼吸动画再出结果（可关闭）——既是仪式感，也真的让人冷静。
6. **本地历史**：只存在浏览器本地，可以回看"我以前都在为什么生气"。
7. **常见气话图鉴**：预置一组高频气话（"随便你""你总是这样""我没事"）的翻译，作为冷启动内容和 SEO / 传播素材。

### 明确不做

- **不做"火上浇油模式"**（把话改得更狠）：虽然好玩，但违背产品初衷，且会被滥用。
- 不做社交 / 社区，不让用户发布别人的聊天内容。

## 4. 页面结构（草图）

```
[首页]
  标题：吵架翻译器
  副标题：把气话翻译成人话
  ┌──────────────────────┐
  │  输入你想说的那句话…    │
  └──────────────────────┘
  对象：(伴侣)(父母)(朋友)(同事)(孩子)
  [ 翻 译 ]
  下方：常见气话图鉴（可点击直接试）

[结果页]
  ① TA 可能听到的    —— 用"刺耳"的视觉（红色、碎裂感）
  ② 你真正想说的     —— 观察 / 感受 / 需要 / 请求 四个小卡片
  ③ 人话版本         —— 语气 tab 切换 + [复制]
  [生成对照卡] [再翻一句]
```

视觉方向：像一个"翻译软件"的界面（左右语言切换："情绪语 ⇄ 人话"），强化梗感。

## 5. 技术方案（建议，开发会话可再定）

- 前端：Vite + 原生 TS 或轻量框架，移动端优先的单页 H5
- AI：需要一个**后端代理**调用大模型（API Key 不能放前端）。可选：
  - Qoder Sites 的后端函数
  - melo-cli fun 项目（Lambda 后端）
  - 任意 Serverless
- 模型输出约定为 JSON，前端只负责渲染：

```json
{
  "heard_as": "对方可能听到的意思",
  "observation": "客观发生了什么",
  "feeling": "你的感受",
  "need": "你的需要",
  "request": "你希望对方做什么",
  "rewrites": {
    "gentle": "温和版",
    "firm": "坚定版",
    "humor": "幽默版"
  },
  "risk_flag": false
}
```

- 分享卡：前端 Canvas / html-to-image 生成
- 隐私：**服务端不落库用户输入**，历史只存 localStorage / IndexedDB

### Prompt 要点

- 人话版必须保留用户的真实诉求，不能变成"无底线退让"或空洞的鸡汤
- 改写要像真人会说的口语，避免"我感到……我需要……"的机械 NVC 腔
- 结合"对象关系"调整称呼和语气

---

## 6. 风险与边界

- **危机场景**：如果输入涉及家暴、自伤、威胁等，`risk_flag=true`，不做改写，改为展示求助资源（如心理援助热线）。
- **不是心理咨询**：页面底部注明工具性质。
- **"PUA 话术"误用**：不提供操控性改写（如愧疚绑架），prompt 中明确约束。
- **内容安全**：输入可能含辱骂，需要模型侧做好安全处理。

---

## 7. 衡量是否成功

- 翻译后**复制率**（真的拿去用了）
- **对照卡分享率**（传播）
- 7 日回访率（吵架是高频事件……）
- 可选：结果页加一个"这次有用吗 👍/👎"做质量反馈
