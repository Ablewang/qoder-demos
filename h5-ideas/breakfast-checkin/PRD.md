# 早点铺我还在 · 粗略产品文档

> 状态：点子阶段 / 待开发 · **意义最大，但也最难，建议先小范围试点**
> 一句话：独居老人每天在常去的早点铺扫个码，说一声"今天挺好"，顺手订明天的包子；哪天没来，老板或街坊顺路去敲个门。

---

## 1. 这个点子是怎么来的

这是圆桌讨论里**评价最高（第 1 名）的融合点子**，由两个看起来毫不相关的人碰出来的。

- **沈老师（45 岁，心理咨询师，做过社工）** 提了"我还在"：
  > "社区里一位独居老人去世三天后才被发现。"
  > 想法：老人每天点一下大按钮"今天挺好"，到中午没点就提醒子女或邻居。
- **强哥（38 岁，江西县城早餐店老板）** 提了"明早留几个"（熟客预订明早包子），并且在圆桌上说：
  > "我店门口住着好几个独居老人，**哪天谁没来买油条，我心里就打鼓**。"

于是：**早点铺老板本来就在"看着"这些老人**。与其让老人对着手机点一个按钮（会忘、会烦），不如把"报平安"长在老人**每天本来就要做的事**里——去吃早饭。

强哥的原话："这个我真能干，不花钱，还能多卖俩包子。"

### 为什么这个融合很妙

- 沈老师原版的问题（投资人老K指出）：老人忘点就误报，几次之后子女就麻木了。**老K的改法是"把签到绑在老人本来就会做的事上"**——早点铺正是这件事。
- 强哥原版的问题：熟客发微信就能订包子，链接是多余的（被老K列为"该死"的点子）。但**加上"报平安"之后，链接就有了不可替代的意义**。
- 安全网由**真实的熟人**组成（早点铺老板、街坊），而不是冷冰冰的监控。这符合圆桌得出的洞察：**"好产品长在已有的关系和习惯里。"**

---

## 2. 角色

| 角色 | 做什么 |
|---|---|
| **老人** | 每天在早点铺扫码（或老板帮点），"今天挺好"；可以顺便订明天的早饭 |
| **早点铺老板** | 店里贴一张码；看一个"今天谁还没来"的名单 |
| **守护人**（子女 / 邻居 / 社区网格员） | 老人自己指定；老人连续没出现时收到提醒 |

---

## 3. 核心流程

```
老人第一次：在老板帮助下登记（称呼 + 守护人联系方式），老人本人同意
  ↓
每天：老人到店 → 扫店里的码（或报名字让老板点） → "今天挺好 ✓"
       顺手："明早留 2 个肉包"（可选）
  ↓
老板端：一张"今天的熟客"名单，到了的打勾，没到的灰色
  ↓
老人连续 N 天（老人自己设，默认 2 天）没出现，且没提前说"我去儿子家了"
  ↓
提醒守护人："X 阿姨两天没去早点铺了，方便的话打个电话问问"
```

## 4. 功能范围

### MVP（只在一家店试点）

1. **店铺码**：一张打印出来贴在店里的二维码
2. **老人登记**：称呼、守护人、"几天没来提醒"——**必须老人本人同意**
3. **报平安**：扫码后一个超大按钮"今天挺好"
4. **老板名单**：今天谁到了、谁没到
5. **请假**："我这几天去儿子家" → 暂停提醒
6. **提醒守护人**：见下文"技术难点"

### 第二版

7. **订明早**：顺手预订明天的早饭，老板看到明早的备货单
8. **多店 / 社区版**：菜市场、理发店、棋牌室也可以成为"报平安点"
9. **子女端**：子女主动打开就能看"妈最近一周都去吃早饭了"（被动查看，不推送）

### 明确不做

- **不定位、不监控**，只记录"今天来没来"（沈老师的伦理边界）
- 不收集健康数据
- 不承诺"安全保障"——这是一个"多一双眼睛"的工具，不是急救系统

---

## 5. 技术方案与难点

独立开发者阿木把"我还在"归为**"一个人很难做好"**，主要卡在**推送提醒**和**出事担责**。

### 提醒怎么发（最大难点）

手机网页发不了推送通知。几种绕法：

| 方案 | 优点 | 缺点 |
|---|---|---|
| **老板人工提醒**（MVP 推荐） | 零技术成本，最有人情味；老板本来就认识 | 依赖老板 |
| 微信服务号订阅消息 | 能自动发 | 需要认证服务号，每条要用户提前订阅 |
| 企业微信群机器人 | 能推到家庭群 / 社区群 | 需要建群 |
| 付费短信 | 最可靠 | 有成本，需要实名 |

**MVP 建议**：系统只负责生成"谁该被关心了"的名单，**由老板或社区网格员打电话**。技术简单，也更像真实的熟人网络。

### 其他

- 需要后端：存店铺、老人、每日记录
- 老人身份：不做账号，用"店铺 + 称呼 + 一个四位数"即可
- 老人不会扫码：允许老板代点（老人报名字，老板打勾）

---

## 6. 风险（这个点子风险最高，必须想清楚）

| 风险 | 应对 |
|---|---|
| **责任问题**：真出事了，是否被认为"系统没提醒到" | 明确说明是"邻里互助工具"，不是安全保障服务；不做任何承诺性宣传 |
| 误报太多，守护人麻木 | 阈值由老人设（默认 2 天）；支持请假；先让老板确认再通知 |
| 隐私 | 老人本人同意；只记录"来没来"；数据不外泄 |
| 老人觉得被监视、伤自尊 | 话术是"报个平安""顺便订早饭"，不说"监护" |
| 冷启动：一家店才能跑起来 | 先找一家真实的早点铺试点，比做产品更重要 |
