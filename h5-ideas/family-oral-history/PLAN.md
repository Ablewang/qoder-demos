## 1. 待定问题逐条回答

### 1.1 MVP 是否录原声？（重点）

#### 微信内置浏览器的真实限制

**核验结论分级**：微信官方文档用于接口规则；浏览器文档和录音库介绍用于兼容性线索；本会话未做手机真机试验。以下“可行”不等于“已经验证可用”。

| 能力 | 已知限制 | 对我们的影响 |
|---|---|---|
| 网页录音（getUserMedia） | 必须是 HTTPS 安全上下文、宿主允许麦克风、用户授权。iOS 14.3 是 WKWebView 支持采集的重要版本线索，但微信版本、系统权限、设备和内核实现共同决定可用性；安卓 XWeb/X5 也不能仅凭 API 存在判定成功 | 不必有公众号，但必须在老人实际使用的手机、微信和网络上测授权、采集和上传；不承诺“所有微信都能录” |
| MediaRecorder 直接出文件 | MIME/编码随浏览器而变，常见为 AAC/MP4 或 Opus/WebM；采集成功不代表另一台手机能播放 | MediaRecorder 用 `isTypeSupported` 选择格式并跨端验证；推荐候选为 Web Audio 采集 + mp3 编码，不宣称编码库能补齐缺失的麦克风权限 |
| 麦克风授权 | 系统给微信的权限、网页给站点的权限是两层；拒绝后可能需要进设置。是否重复弹框由环境决定 | 权限说明不等于系统授权；第一次先解释，再通过实际点击触发采集，不自动反复弹权限 |
| 来电、锁屏、切后台 | WebView 可能暂停、结束采集或被系统回收；无后台持续录音保证 | 检测中断、保存已确认写入的片段；用户主动点击再继续。提示不要锁屏，不承诺不中断或零丢失 |
| 录音后播放 | iOS 音频路由可能切换，外放音量可能异常；蓝牙耳机也需检查 | 结束后释放采集资源；测试录前/录后音量、外放和蓝牙 |
| 播放与剪贴板 | 播放通常需要手势；复制接口也可能在 WebView 失败 | 由真实“播放”点击启动，不在异步请求后假定自动播放一定成功；复制失败提供可长按复制的完整话术 |
| JS-SDK 录音（wx.startRecord） | **官方“权限对照表”给未认证订阅号、认证订阅号、未认证服务号、认证服务号都列出了音频接口**。JS 安全域名须通过 ICP 验证；后端获取并缓存 ticket、按完整页面 URL 签名；一分钟后触发 `onVoiceRecordEnd` | PRD 将录音与“必须认证公众号”捆绑过严。应以实际账号后台接口权限及域名绑定结果为准，而非直接要求企业认证服务号 |
| JS-SDK 音频保存 | `uploadVoice` 产生 `serverId/media_id`；官方注明有效期 **3 天**，必须服务端及时下载持久化。微信侧音频可能需转码后跨端播放 | 收到 media_id 立即转存并核对文件，再告知成功；失败重试必须在有效期内。localId、media_id 都不是永久音频档案 |
| 分享与提醒 | 官方权限表中分享能力与音频能力不是同一权限档；网页也不能向普通家族微信群自动发消息。不把公众号、企业微信机器人当普通家庭群的推送入口 | MVP 人工复制“问题 + 链接”、人工转发更新；PWA 通知等不能作为微信内长辈的可靠提醒 |
| 域名访问 | 未备案或境外托管不等于必然被微信封禁；实际与域名信誉、安全策略、网络和站点内容相关。备案也不是免封保证 | 测移动/联通等实际网络、首开和二次打开、Wi-Fi/蜂窝；被拦截时查明原因，不只机械换域名 |

> **方案 C 的关键纠偏**：普通微信私聊/群聊语音没有面向任意 H5 的官方读取/导出接口，手机端没有可依赖的“语音另存音频文件”标准闭环。收藏、转文字和聊天备份不等于拿到可上传的音频文件。产品不能要求子女破解聊天数据库、安装来历不明的提取工具，也不能称“转存上传只多一步”。

#### 方案对比

| 方案 | 做法 | 老人 / 子女负担 | 原声 | 技术代价与判断 |
|---|---|---|---|---|
| **A 输入法语音转文字** | 在文本框用系统输入法听写 | 老人要找到输入法话筒、核对文字；也可子女代写 | 无 | 最快验证“是否有人问、愿不愿讲”，**不能验证音色留存和听原声价值**。方言、口音和错字需接受；网页不能代用户启动输入法听写 |
| **B 外部浏览器录音** | 右上角 → 在 Safari/Chrome 打开 → 重新授权/可能重新进家族 | 老人步骤多、容易迷路；适合子女协助一次 | 有 | HTTPS + getUserMedia/MediaRecorder；不作为默认老人流程，保留为家属帮助选项 |
| **C 普通微信语音转存** | 发语音给子女，再提取上传 | 老人熟悉，但子女拿文件不可靠 | 理论上有 | **不列入 MVP 正常流程**；没有官方通用导入桥梁 |
| **C′ 子女当面代录 / 合法已有音频导入** | 子女在长辈旁边用页面录，或上传对方同意保存的录音文件；注明“由小明代录” | 老人无需操作；子女需参与采访 | 有 | MVP 可行兜底。电话/微信通话不能默认在同一台手机被网页同时录下；远程需对方知情同意、设备本身支持或第二台设备外放采集（音质较差） |
| **D 微信内页面录音（推荐候选）** | 微信打开 HTTPS 页 → 点击录音 → 停止并保存 | 老人一次主动作；首次有授权 | 有 | Web Audio + mp3 或经跨端验证的 MediaRecorder。需真机支持；先做有截止时间的验证，不为长尾老设备写庞大兼容层 |
| **E 微信 JS-SDK** | startRecord → stop/onVoiceRecordEnd → uploadVoice → 后端下载 | 老人轻；开发者要处理签名、账号、域名和临时媒体 | 有 | **已有账号和备案域名时值得优先验证**；单条 60 秒，续讲分段；不是“必须企业认证才可用” |
| **G 公众号会话收音** | 老人向公众号发语音；官方消息回调带 MediaId，后端下载 | 老人要关注/打开新会话；子女先帮忙绑定家族和问题 | 有 | 官方可行的 C 改造，但这是发给公众号，不是读取发给子女的私聊；还要验证账号下载权限、回调验签、排重、转码和问题归属。MVP 默认不新增此入口 |
| **H 手机录音机 + 文件上传** | 长辈在录音机录好，再从文件选择器找文件上传 | 老人高、子女中 | 有 | 可以支持家属导入，不能称“一个按钮”老人流程；格式需真实跨端播放验证 |
| **F 微信小程序** | 原生录音与卡片分享 | 老人较低；首次进入和授权仍存在 | 有 | 仍需类目、备案/审核和隐私声明，个人主体能做哪些能力以实际审核为准；超出本次 H5 MVP，验证后再定 |

#### 推荐与决策条件

**推荐保留 MVP 的原声存储与收听：D 直录通过验证后上线，A 文字和 C′代录兜底；已有可用公众号时增加 E 的对照验证。**

1. 原声包含口音、笑声、停顿，和文字回答是不同价值。A 可以验证对话习惯，但不应拿它的结果宣称有声书需求已经验证。
2. 原声可用不等于长辈一定要独立录；C′能先验证“家人真的会听并追问”，代录必须诚实标注。
3. 两天只做**可行性筛查**，不能穷尽微信机型兼容性。确认阶段不录家庭内容，只用明确同意的测试声音；本会话仍停留在方案。

**决策门（批准开发后第 2 个工作日结束）**：
- 在至少 4 个目标组合（较新/较旧 iOS 微信、新安卓、3 年以上旧安卓；有鸿蒙家庭再加该机）完成 60 秒和 3 分钟的录制、上传、跨 iOS/安卓播放，每个组合连续通过 3 次，并跑通拒绝授权/断网恢复 → D 作为主流程；后续 60+ 用户首次无帮助完成率目标 ≥ 80%。
- 少数目标手机失败 → 对这些家庭明确展示 A/C′，不让老人反复试；旧 iOS <14.3 不承诺 D，可测试 E 或由家属代录。
- 已有公众号且 D 在多数目标手机失败 → 验证 E；通过后以 60 秒分段进入 MVP，排期增加账号接入与转存工作。
- 无可用直录路线 → **MVP 仍保留 C′原声档案 + A 文字**，暂缓“老人独立一键录音”的承诺；若用户选择纯文字验证，单独标记其验证边界。
- 微信访问被拦/过慢 → 先查域名信誉和网络，再评估国内托管及备案；国内托管涉及的新资源和费用须另行批准，不能把备案日历时间藏在两天验证内。

### 1.2 是否需要公众号？

**默认不为 MVP 新注册公众号，不要求家人关注。** 先问用户是否已有公众号、域名及可用开发权限；如果已有，E/G 都应重新评估，不能因为 PRD 的资质误解排除它们。

| 公众号能力 | 实际接入条件 | MVP 替代 |
|---|---|---|
| 音频接口 | 官方权限表四类均列“有”；账号后台实际权限 + ICP 验证过的 JS 安全域名 + 服务器签名 + 3 天内媒体转存 | 有条件的页面录音 D、子女代录 C′ |
| 自定义分享卡片 | 该账号的分享接口权限及 JS 签名，不能套用音频权限结论 | 通用、无故事正文的网页标题；子女复制“问题 + 链接”，复制失败可长按 |
| 模板/订阅通知 | 账号及类目权限、平台时效/次数限制、用户授权；不是任意网页或普通微信群推送 | 子女在原有家族群人工发链接 |

留存跑通后，再根据主要卡点比较公众号或小程序；小程序也不是“录音、提醒全无门槛”的解决方案。

### 1.4 年度书是否收费、怎么收？

- **MVP 不收费**，也不做年度书。先回答"能不能坚持 4 周、12 周"。
- **第二版候选**：
  - 免费：按人生阶段整理的在线有声书；**原声和导出不设付费墙**。免费导出是权益建议，不等于承诺无限容量、平台永不下线或永久链接永远可用。
  - 付费：实体书按单收费（印刷/寄送成本 + 服务费；99–199 元仅价格假设，须供应商报价和小规模付费意愿验证），可加印给家人。线上 PDF 可以免费基础版、付费定制排版，但不阻止原始档案导出。
  - 收款：先通过具备合适经营资质的第三方店铺完成下单/退款/物流；仍要确认主体和税务，第三方店铺不自动消除合规要求。MVP 不接支付、不配置收款。
  - 纸书二维码仅放非秘密的故事定位入口，**不印老人 bearer 链接、不印临时签名音频 URL**；扫码后仍须家族身份。送书不自动授予音频权限，家人可另获邀请。域名变更与停服需保留导出方案。
- **原则**：不靠“付钱才能取回长辈声音”获利。录音有成本，未来如果须调整容量/资费，提前告知并始终保留已有资料免费导出，不把长期保存说成无条件保证。

### 1.5 我补充的待定问题

| 问题 | 推荐 |
|---|---|
| 录音交互：按住说话还是点一下开始、再点一下结束？ | **点一下开始、再点一下结束**。按住 1 分钟手很累，一松手就断；第一次按住时还会弹授权框把按住打断；iOS 长按还会弹出系统菜单。按钮上写清楚"点一下，开始说" / "说完了，点这里" |
| 一分钟是硬限制吗？ | **软限制**。到 1 分钟时轻轻提示"可以接着说，说完点按钮"，5 分钟自动结束并保存。"一分钟"是降低心理门槛的说法，不是规定 |
| 老人录完要不要先试听确认再发送？ | **默认停止后发送，不强制试听**；第一次明确说明向哪些家人分享。只有后端 ready 才报成功；重说成功后替换上一段。若试用者频繁说错，可改为下一状态的一个“发给家人”按钮，增加一步但降低误发 |
| 老人能不能不等问题、自己想讲就讲？ | **能**。没有待回答的问题时，老人页显示“想说什么就说什么”；不把“没人问”当负面提示 |
| 不再使用后数据怎么办？ | 家族可确认后删除（含媒体，完成状态可查）；运营停止时计划提前通知、开放至少 90 天导出。明确备份清除期与突发故障边界，不声称瞬间删除全部外部副本 |

## 2. 技术方案

### 2.1 总体结构

```
 子女 / 听众手机（微信内置浏览器）        老人手机（微信内置浏览器）
        │  家族页、抽题、听、然后呢              │  只看一题、录音
        └──────────────┬──────────────────────┘
                       │ HTTPS（JSON + 音频上传）
                ┌──────▼───────┐
                │  后端函数      │  校验链接口令/成员身份、读写数据、
                │  （API）      │  签发短时音频播放地址
                └───┬──────┬───┘
                    │      │
             ┌──────▼──┐ ┌─▼─────────────┐
             │ 数据库    │ │ 私有对象存储    │  mp3，只能通过短时签名地址访问
             └─────────┘ └───────────────┘
```

问题库 MVP 阶段是**前端内置的静态 JSON**，不进数据库（改起来简单，也省接口）。

### 2.2 前端

| 项 | 选择 | 理由 |
|---|---|---|
| 构建 | Vite + TypeScript，建议 pnpm | 便于构建静态前端，不需 SSR；这是选型建议，不是已有工程事实 |
| 视图 | Preact + 手写 CSS | 页面少但录音状态较多，轻量组件足够；不安装大型 UI 库。若后续确定使用已有 React 项目则保留 React，无需为体积重写 |
| 路由 | 子女首页、加入家族、老人页、回答详情、故事墙 | 应用中使用普通路径；**邀请/老人秘密放 URL fragment**，首开显式 POST 兑换会话后移除 fragment，不把 bearer token 放日志路径 |
| 录音 | 候选 xiangyuecn/Recorder 的 mp3 编码路线 | 项目声明有相关环境支持；需审核锁定版本、依赖许可证和已知问题，并做本项目真机采集/编码验证；若原生 MediaRecorder 格式已跨端通过，也可选择更小的实现 |
| 本地暂存 | IndexedDB 保存已编码片段和上传意图 | 防断网丢失；**不能保证清缓存、卸载微信或系统回收后恢复**。暂存失败须明确告知，不能显示虚假的“已保存” |
| 样式 | CSS 变量、语义按钮、系统无衬线字体 | 控制字号/对比度/触控尺寸，不禁止系统字体缩放 |
| 体积目标 | 首屏 JS < 80KB（gzip，不含延迟加载编码模块） | 作为预算实测；编码器预加载不申请权限，准备好后让老人点击，避免自动录音 |

音频候选参数：单声道、16kHz、32kbps mp3。1 分钟约 240KB，5 分钟约 1.2MB，**需试听确认方言、低声和环境噪声的清晰度**。如音质不足用 24kHz/48kbps，五分钟约 1.8MB；码率选择不改变录音权限问题。

### 2.3 后端选型

| 维度 | Qoder Sites 后端 | melo-cli fun 项目 | 国内云 + 自有备案域名 |
|---|---|---|---|
| 已知技术 | 静态前端 + **Deno Edge Function** + function_backend 私有数据库（PostgreSQL 数据类型）+ 单个私有 Storage 桶 + Secrets | 本机 skill 文档列 Node24/Python/Java17 的 Starlink Lambda，前端 Vite 等模板；baas-hub 申请 MySQL，使用内部 GitLab/登录 | 腾讯云函数/CloudBase + COS，或阿里云函数计算 + OSS；数据库按方案选择 |
| 应用 API | 浏览器调用同源 `/functions/v1/app/api/...`；Function 用平台 SDK 访问 DB/Storage，自己验证家族会话 | Node24 API；模板、网关路由、部署权限及公网准入批准后验证 | 自己配置同源或严格 CORS、会话与资源策略 |

| 微信/地域 | 本会话 `get_context` 返回 runtime.region=global；**这不能证明数据库/文件物理存储地，也不能证明必定境外或未备案**。需确认数据地域、大陆网络表现、域名状态 | skill 提供 testing/prod-CN 等基础设施环境，最终环境以项目配置和平台批准为准 | 可明确选境内资源；网络/备案/微信风控仍需实测 |
| 归属 | 需要核对当前账号条款、数据处理范围和导出能力 | 内部平台凭据/资源**不等于可用于个人公开业务**，须先确认授权，不能默认成本由公司承担 | 自己控制账号与资源，也要履行隐私告知和成本责任 |
| 费用 | 计费、容量、带宽和备份额度尚未查询，不承诺免费 | 计费、对象存储和公网使用政策待确认 | 服务器/请求/容量/出站流量/域名等合计评估，不预报“几十元以内” |
| 验证重点 | 无 Qoder 账号也能访问；应用 Cookie/Bearer 经 Gateway 正确传递；跨家族隔离；上传签名、音频播放、文件 Range、撤销权限、备份恢复 | 个人/公司用途授权、公网匿名可达、上传限制、数据库唯一约束及会话、私有存储 | 境内地域、备案条件、预算与安全配置；不是“无需验证” |

**建议顺序**：
1. 个人/用途未确认时，**优先研究 Sites 的匿名入口 + 自有家族认证方案**，不是立即创建或发布。匿名入口只提供壳，Database/Storage 默认私有，所有内容经后端授权；上线时改变入口访问策略需要另行确认。
2. 如果已有授权的 fun 工作流，且允许此产品存储真实家庭内容，可选 fun 的 Node24 + MySQL + 私有对象存储；不能为了模板方便自动把家族资料放进公司基础设施。
3. 面向大陆真实家庭长期运行，优先选能确认**境内数据存储、备份/导出和网络质量**的方案。Sites 若无法确认这些条件，改用国内自有云；已有备案域名可缩短等待，新的备案常需数周，取决于服务商和主体。
4. 不同时实现两个后端，也不承诺换云“只改两处”：Deno 与 Node、PostgreSQL 与 MySQL、SDK 查询与事务能力都有差异；迁移时还涉及媒体搬迁、会话、域名和恢复校验。

**Sites 的隔离要点**：用新 `function_backend` 模型，前端不直接访问 DB，不持有平台服务密钥。数据库租户隔离只隔离 Site，**同一 Site 内各家族仍须 Function 对每次读写强制过滤 family_id**。自有会话按应用身份校验，不把昵称、前端传来的 role 或 Qoder UID 当授权凭据；生产前验证实际 Gateway/Provider 凭证传递与入口保护。

**容量示例（不是报价）**：一个讲述人每周 1 分钟，52 周约 12.5MB mp3；10 个家庭一年约 125MB。多人重复播放带来出站流量，备份另占容量。MVP 代录单文件候选上限 20MiB、最长 5 分钟，格式仅接受通过播放测试的 MP3/M4A/WAV；大小/时长要服务端核验，不能只相信文件扩展名。

### 2.4 数据模型

这是字段设计，不是本阶段要执行的 SQL。

```
family 家族空间
  id, name
  invite_token_hash, invite_version, invite_expires_at
  passcode_hash                  加盐慢哈希，具体算法兼容所选运行时
  recovery_secret_hash           发起人私下保存的管理恢复码，与家族口令不同
  created_at, deleting_at

member 成员
  id, family_id
  display_name, relation         昵称 / 儿子、孙女等，仅显示，不证明现实身份
  role                           organizer | storyteller | listener（由后端赋予）
  addressed_as, birth_decade      讲述人可选，不收集完整生日；称呼可统一“你”
  storyteller_token_hash, link_version
  revoked_at, created_at

session 设备会话
  id, family_id, member_id, token_hash
  credential_version, expires_at, revoked_at
  scope                          member 或 storyteller_limited
  created_at, last_seen_at

ask 一次提问
  id, family_id, storyteller_id, asked_by_id
  bank_question_id, question_bank_version
  text                           已发问题快照，不因题库更新变更
  depth, life_stage
  kind                           question | continue | free
  parent_story_id                 续讲父段
  status                         pending | answered | skipped
  created_at

story 一段回答
  id, family_id, ask_id, storyteller_id
  type                           audio | text
  audio_key, duration_sec, codec, bytes, sha256
  text                           文字回答；未来转写与原始文字应分字段
  recorded_by_id, consent_at      本人 / 子女代录；保存与家族分享同意时间
  life_stage, thread_root_id
  upload_state                   pending | ready | failed
  client_submission_id            同一上传的幂等标识
  replaced_story_id               重说成功后替换的上一段
  created_at, deleted_at

then_reaction 然后呢
  family_id, story_id, member_id   (story_id, member_id) 唯一
  created_at                     一个成员对一段故事只占一票

followup 文字追问
  id, family_id, story_id, member_id
  text                           最多 120 字，纯文本
  status                         open | answered | declined
  answered_by_story_id, created_at
```

**计数定义**：`then_count = COUNT(该 story 的 then_reaction)`，表示点过的**不同应用成员数**，不是播放人数也不是实名认证人数。首按保存一票，再按只给轻微动画，不发重复请求；可再次取消。文字追问不隐含“然后呢”投票；只写追问的人也会进入待续讲提示。MVP 不存每次敲按钮次数、不做榜单，不把 100 次点击说成 100 人在听。

**追问与续讲**：每段故事最多一条当前续讲 ask，以 `(storyteller_id, parent_story_id, kind)` 唯一约束防并发重复；关联所有未回答的 followup。列表只展开最新两条，其他可由家属查看，长辈不需处理评论流。续讲保存后，仅标记本次呈现的追问已回答，后来的追问保留。长辈跳过不发“拒绝”通知、不反复催。

**写入一致性**：上传只有 `ready` 故事可被播放；幂等键按 `(family_id, member_id, client_submission_id)` 唯一。同一键不同内容拒绝。同一问题允许多段续讲，通过 thread_root_id 和 parent_story_id 串联。跨表父子关联必须属于同一家族。fun 可使用实际支持的事务；Sites 文档没有承诺任意事务，不直接依赖未确认的 upsert/increment。用唯一插入/条件更新、分步状态和读取时补齐的方式协调“反应 → 续讲 ask”，发布前验证并发。

**老人页一次只显示一件事**：本次明确发送的 ask 优先（消息可带非秘密 ask_id），之后为未处理追问/续讲，再为其他待问题；没有待办时可以自发讲。每位讲述人默认只保留一个未答普通问题，子女新发时选择替换或稍后发送，避免堆积任务。

**MVP 收敛**：每个家族先只有一位讲述人，其他人是发起人/听众；模型保留 storyteller_id，第二版才做多位老人同时加入、切换和提醒。与 PRD 的多位老人第二版边界一致。

### 2.5 接口（MVP）

以下 `/api` 是逻辑路由；Sites 部署实际添加 `/functions/v1/app` 前缀。身份均由后端会话解析，不采用浏览器传来的 member_id/role 授权。

| 接口 | 用途 | 权限 |
|---|---|---|
| `POST /api/families` | 创建单讲述人家族、发起人会话，返回邀请信息和管理恢复码 | 匿名、受频率/容量限制；仅此创建操作产生发起人角色 |
| `POST /api/join` | 邀请随机串 + 口令 + 昵称换取**新听众**会话 | 不允许指定既有成员，更不允许恢复 organizer |
| `POST /api/storyteller/session` | 老人 fragment 随机串兑换受限会话 | 仅该讲述人的待问题、录音、本人故事与删除请求 |
| `GET /api/family`、`POST /api/asks` | 家族信息 / 发题 | 成员；普通待题最多一条 |
| `GET /api/storyteller/current` | 当前题目、续讲提示 | 讲述人会话 |
| `POST /api/uploads` | 分配服务器控制的 pending story_id、object_key 和短时上传地址 | 讲述人录本人 / 发起人代录；有幂等键 |
| `POST /api/uploads/:id/complete` | 检查存储实际字节、格式与归属后标记 ready | 与上传意图相同的身份；错误不得宣称发送成功 |
| `GET /api/uploads/:id` | 查询上传不明结果，避免重复保存 | 与上传意图相同的身份 |
| `POST /api/stories/text` | 文字回答或子女代记 | 讲述人/发起人；限长、纯文本 |
| `GET /api/stories`、`GET /api/stories/:id/audio` | 分页故事墙 / 获取 5 分钟播放地址 | 家族成员；老人会话仅本人范围 |
| `PUT /api/stories/:id/then` | 设置想听 / 取消，人数幂等 | 听众/发起人；长辈不对自己的故事投票 |
| `POST /api/stories/:id/followups` | 新追问 | 听众/发起人，限长限频 |
| `DELETE /api/stories/:id` | 删除本人故事或家族故事 | 本人/发起人；发起人不能以全局 story_id 绕过家族范围 |
| `POST /api/members/:id/reinvite` | 指定成员的一次性换设备邀请 | 发起人；原会话可撤销 |
| `POST /api/family/revoke-access` | 撤销指定成员/老人链接及其会话，或轮换邀请与口令 | 发起人再次确认；两种操作含义不同 |
| `POST /api/organizer/recover` | 管理恢复码找回发起人并轮换旧凭据 | 独立恢复凭据；不是家族口令 |
| `DELETE /api/family` | 删除家族及媒体 | 发起人会话 + 再输入口令 + 明确确认 |

### 2.6 音频的录、存、播

1. **采集**：权限解释 → 用户点按钮申请麦克风 → 确认采集开始才显示“正在听你说”。默认一分钟软提示，五分钟结束分段。编码片段尝试写入 IndexedDB；Web Audio PCM/编码内存、CPU和中断恢复在真机验证，不依赖库名自动保证流式持久化。
2. **停止**：点“说完了”释放资源、完成文件并创建本地幂等上传意图。明确说明点击后会向家族发送；如果本地保存失败，不能提示“已在手机保存”。
3. **上传**：优先“后端验身份/配额 → pending 意图 → 签名直传（不覆盖）→ 服务端核实 → ready”。服务器控制路径 `families/{familyId}/{storyId}/audio`，客户端不能选择别人文件。限制实际字节、MIME/格式与时长；不只信文件名或客户端 duration。
4. **恢复**：响应丢失先查询同一意图，文件已就绪则不再写；确认未上传才以同一幂等标识补传。退避重试最多 3 次，之后在**页面下次打开、仍有本地草稿且身份有效时**继续；WebView 关闭后不承诺后台重传。上传无效/身份撤销立即停止。`ready` 后才显示“发好了”，清本地缓存。
5. **播放**：验证故事家族归属后签 5 分钟地址，测试 `<audio>` 外放、iOS/安卓、Range/拖动；过期需重新鉴权。签名 URL 是 bearer 能力，**会话撤销后已经签发的 URL 可能仍可用至到期**。要求立即停止访问时改为鉴权代理；但已下载副本无法追回。
6. **重说**：新片段上传成功后再替换旧片段；新录失败不删除旧录。无覆盖式上传；文件与数据库分步成功需协调，24 小时未完成的 pending 文件按精确 ID 清理。删除故事及其子追问要确认联动范围。
7. **备份与导出**：上线前确认提供方备份/恢复能力，目标每日备份、RPO≤24小时/RTO≤1个工作日（验收目标，未承诺平台已满足）；每段原声可下载。打包导出在正式长期试用前补齐，不用“永久免费”替代可携带性。停止服务前计划至少 90 天导出窗口，但突发平台故障不保证可持续提供。

### 2.7 免账号的家族身份（邀请链接 + 口令）

“免账号”指无手机号/微信 OAuth/注册密码，**不等于没有后端身份、会话和管理恢复凭据**。

| 入口 | 怎么进 | 权限与风险 |
|---|---|---|
| 家族邀请：`/j#i={随机串}` | 邀请有效期默认 7 天，另发随机 6 位口令；首开输入昵称 | 只创建 listener，可听/追问/抽题。昵称是自报称呼，不是身份验证；不显示全体名单供选择冒名 |
| 老人专属：`/s#t={随机串}` | 私聊点开 → 后端兑换受限会话，无口令输入 | 可看自己的题、录自己的音、删自己的故事；不能看全家资料、管理成员、删除家族。持有链接者仍可能冒用讲述人，这是免输入的明确取舍 |
| 发起人 | 创建时自动授予私有会话；单独保存管理恢复码 | 管理成员、代录、删除与导出；不出现在家族邀请里，不可凭口令+“我是小明”获得 |

- 邀请/老人串至少 128 位随机，凭据仅存哈希；短口令加盐慢哈希。**不建议生日/电话尾号等可猜口令**，链接和口令尽量私聊分开发。每个邀请+请求来源限频，5 次失败后退避 15 分钟，不因陌生人试错锁住所有家人。
- 会话优先 Secure/HttpOnly/SameSite Cookie；验证 Sites Gateway 转发应用 Cookie 的配置，采用同源 API、固定 Origin 校验及 CSRF 防护。平台过滤默认凭据不意味着自有认证已跑通。
- 秘密放 fragment，兑换后移除；GET/分享预览机器人不应消耗链接或建会话。`Referrer-Policy: no-referrer`、敏感响应 `no-store`、日志不记录请求体/口令/会话/签名链接；页面标题只用通用名称，不泄露题目和故事。
- **轮换邀请不自动注销已有成员**；泄露时必须同时撤销对应会话/凭据版本。老人旧链接及由其换出的会话同时撤销；已签音频地址等到到期，已下载副本无法撤回。
- 普通成员换手机：发起人发一次性、限时、指定成员的重新邀请；可撤销旧设备。发起人换手机：独立恢复码。所有管理凭据丢失时不靠猜口令冒充管理员；MVP 由人工支持核查恢复，无法核查则不恢复高权限。
- 该设计适合明确同意的小规模信任家族，无法保证持有链接的人现实中就是某位长辈。需要更强真实身份校验的家庭，应改用更强认证，并接受多一步登录。

### 2.8 隐私

- **匿名可见的只是页面壳**，故事 API/音频都要业务鉴权。`noindex` 是不收录声明，不是访问控制；浏览器隐藏按钮也不是权限。持续测试跨家族 IDOR、越权签名和越权删除。
- 长辈首次明确看到：“你点‘说完了’后，这段会发给你家里加入的这些人。想删掉，随时告诉小明。”显示家族成员范围；初次“知道了”同时确认保存/家族分享，不将深度话题默认为同意，仍可跳过。
- 代录前单独征得长辈及其他被录者同意，注明代录人；不录未告知的通话。分享邀请会赋予其他人听取权限；提醒不要公开转发。技术无法阻止家属录屏、转述或另存。
- 故事删除立即停止新的 API 展示/签名，媒体精确删除失败要显示处理中，不假报完成；备份按已告知保留期（目标≤30天，取决于供应商合同）清除，恢复备份时重放删除标记，避免复活已删内容。
- 不收集手机号码/真名/完整生日、不接广告或公开推荐、不做声纹识别或训练；**不用 AI 模仿或生成长辈的声音**。第二版第三方转写必须单独告知服务商和用途，不能悄悄把音频送给 AI。
- 面向国内真实家庭，先确认数据/备份地域、境外处理和平台分包商政策；涉及跨境时适用的告知、同意和法律要求上线前核查，不把勾选同意视为全部合规已经完成。
- 家族中 14 岁以下听众由监护人邀请/同意，不额外收集孩子真实资料。故事可能涉及其他亲人的敏感信息，提供编辑文字/删除、家属提示勿讲身份证/病历等具体隐私。
- 深度话题只给选择，不诱导创伤自述。老人“这个不想说”不会发布拒绝通知；有人去世、失联或讲不完时不发羞辱/打卡提醒、不用“再不问就来不及”制造焦虑。
- 上线前写一页简短隐私说明：运营者、收集目的/范围、存储地域/期限、删除/导出、联系方式、服务停止安排。这里是方案，不替代法律审查。

### 3.3 老人端（只有一个按钮）

#### 适老化设计标准（目标值）

参考工信部适老化通用设计规范和 WCAG 可感知/可操作要求，下面是本产品的**设计与验收目标**，不声称已经获得适老化认证或达到完整 WCAG AAA。CSS px 不是对 dp/pt 条款的机械换算，需真机看实际大小；工信部参考规范建议主要文字≥18dp/pt、支持更大字体与足够行距。

| 项 | 标准 |
|---|---|
| 字号 | 问题正文默认 32px、可随系统放大；说明≥22px、辅助≥18px；无衬线字体，行高≥1.5、每行约12–16个汉字 |
| 对比度 | 文字与背景 ≥ 7:1；不用浅灰字 |
| 主按钮 | 直径 ≥ 160px，位于屏幕下半部、单手拇指能够到；整页只有一个主按钮 |
| 次要操作 | 最多 2 个，用**带文字的**链接（"这个不想说""我想打字"），点击区域 ≥ 60px 高，与主按钮间距 ≥ 40px，避免误触 |
| 手势 | 只用"点一下"；不用长按、滑动、双击 |
| 图标 | 每个图标都配文字，不用只有图标的按钮 |
| 状态 | 每个状态同时用**文字 + 颜色 + 形状**表示（录音中按钮变红、显示计时、声音波动条），不能只靠颜色 |
| 时间压力 | 没有倒计时；1 分钟只做温和提示 |
| 布局 | 单列、首屏优先放问题和主按钮；**不强制一屏/禁止滚动**，小屏大字体/横屏允许自然滚动。保留安全区，软键盘不遮住输入与发送 |
| 微信字体放大 | 微信最大字体及浏览器200%放大时测试，不截字、不隐藏主操作；允许问题变高 |
| 文案 | 口语、短句、不用"上传""授权""提交"等术语；说"发给孩子们""点「允许」" |
| 出错 | 不露代码/技术堆栈，但明确“没开始录 / 还没发出 / 已保存到手机 / 请找小明帮忙”的不同状态；不能用“不用管它”掩盖失败 |
| 加载 | 在约定的大陆4G测试网络，目标问题首屏≤3秒；超时给“还在等，再试一次”而非空白页。编码模块后台预加载，只在点击后申请权限 |
| 辅助技术 | TalkBack/VoiceOver可读出问题、按钮名字与状态；键盘/读屏能操作；减少动画设置有效。计时不每秒播报扰乱录音 |

“只有一个按钮”指每个状态只有一个醒目的主操作；“这个不想说”“我想打字”等是分开的辅助文字入口，并非要求全页只能有一个可交互节点。每步说清下一步，失败时主按钮就变成“再试一次”或“让家人帮忙”，不同时给五个选择。

- 示例“23段·31分钟”实际统计只含 ready 且未删记录；音频时长与文字篇数分开显示。
- 为空时给子女“抽一题”，长辈页仍可自发讲；全部删完显示空状态，不误报故障。单段下载不使用公开永久对象地址。
- “连续播放这一章”、多讲述人过滤是第二版，需再测试移动端播放限制。

## 4. 问题库

### 4.1 分类体系

每道题有以下字段：

| 字段 | 取值 | 用途 |
|---|---|---|
| `stage` 人生阶段（主分类） | 童年 / 求学 / 工作 / 恋爱结婚 / 养孩子 / 那个年代 / 心里话 | 抽题筛选、故事墙章节、年度书章节 |
| `depth` 深浅 | **温柔**：轻松、具体、容易开口 / **深度**：可能触及痛苦、遗憾、去世的人 | 深度题有提示、前 4 次不随机抽到、老人可跳过 |
| `type` 题型 | 场景（"那天什么样"）/ 人物（"那个人"）/ 物件（"那台自行车"）/ 选择（"为什么那样选"）/ 感受（"心里怎么想"） | 保证一个阶段里题型多样；场景和物件题最好开口 |
| `audience` 适用对象 | 通用 / 父亲 / 母亲 / 祖辈 | 渲染称呼，"你和妈妈第一次见面"要知道问的是谁 |
| `era_fit` 年代适配 | 出生年份范围，如 1945–1962 | "恢复高考那年你在干嘛"只发给当年在适龄阶段的人 |
| `followups` 追问提示 | 1–2 句 | 给听众"写追问"时一键填入的灵感 |

`心里话`是在 PRD 六类之外加的一类，放"你最后悔的一件事"这类回望性问题，全部是深度题。

模板：`{称呼}，你第一份工资花在哪儿了？`，`{称呼}`由讲述人的"称呼"填入（爸 / 妈 / 爷爷 / 外婆……）；需要对方配偶时用 `{配偶称呼}`（问爸时是"妈妈"）。

### 4.2 抽题策略

- **从温柔、具体的事开始**：前4次只随机温柔题，优先场景/物件；避免“你的一生最遗憾什么”作为首次开场。
- 深度题随机默认关闭；子女主动选择需确认“愿意谈这个”，家族已有≥4段回答后才提示可开启。**回答够4段不等于长辈同意创伤话题**，长辈仍可跳过，深度题不伪装成温柔题。
- 同一讲述人问过/跳过的 bank_question_id 8周不再随机出现；后端使用 ask 快照记录去重，不只在单台手机记已抽题。随机无可选时换分类或自写，不强推旧题。
- 出生年代可空；像1977年的题若年代不明，不默认抽到。只有粗出生年代时保守筛选有明确适龄交集的问题，子女可主动选；不要问“你那年高考在哪”这种先假定参加考试的题。
- 婚恋/养孩子题按实际关系选择，**不假定每个人都结过婚、有孩子、配偶仍在世**；配偶去世/关系敏感时可关闭整个分类或把相关题提升为深度。
- 静态题库是共享模板，不含家族答案；发送时后端检查题号、版本、长度并保存实际文字。自写题由家人确认深浅，文字纯文本展示。
- 本方案给30条作内容样稿；若确认按 PRD 的200+题上线，建议**210题、七类各30题，温柔约70%**，另安排2个工作日扩写/审核。内部首轮试用可先30题，扩大试用前补到200+，范围变化需用户确认。

## 5. MVP 开发拆分与排期

以下按单人全职、一个后端、可招到试用家庭、已有可用基础资源估算；不是交付承诺。只有用户批准后才进入0阶段，不运行初始化/部署命令。

| 阶段 | 估算工作日 | 依赖与工作 | 验收 / 决策门 |
|---|---|---|---|
| **0 可行性筛查** | 2天 | 确认平台用途/数据地域；匿名无Qoder登录可达；4个手机组合各3次录60秒/3分钟、跨端播放；拒绝授权、来电/锁屏、4G断网、本地写入失败；Sites Cookie转发、签名直传、Range播放 | 按1.1选择D/E或C′+A。没有真机/资源授权就不能勾选通过；备案/审批等待另计 |
| **1 数据与家族身份** | 4–5天 | 新项目仅一个后端；family/member/session等表、约束/索引；创建、邀请、老人受限会话、独立管理恢复、限频/CSRF；建立真实小规模隔离试验 | 家族A不能访问B的故事/签名/删除；不能选择昵称恢复管理员；撤销旧会话生效 |
| **2 录音与子女闭环** | 4–5天 | 停止/发送/成功状态；编码、IndexedDB、幂等签名直传/完成核验；提问快照、抽题、复制失败兜底；家属代录/文字 | 真实手机走完“发题→录→发→另一人听”，错误不丢已有成功录音、不假报发送完成 |
| **3 听众与故事墙** | 3–4天 | 然后呢按成员去重、追问及续讲；并发唯一约束；主段/续讲排序、按分类/记录时间；纯文字播放外的读法；单段下载/删除、退出及成员重新邀请 | 两位听众同时反应不产生重复续讲；重试不重复故事；删除后不可再签名 |
| **4 内容与适老验收** | 2–3天 | 30题首轮可用，扩大前扩写到210题并审核；隐私说明；最大字体/软键盘/读屏/旧机；未发退出、本地草稿和断网状态 | 无横向溢出、可正常放大、明确一个主动作。首次仅口头说明研究目的，不替长辈点击；卡住记录后提供帮助 |
| **5 首轮家庭试用** | 5个工作日左右（与日历周同步） | 用户自家 + 2–3个**明确同意**的家庭，年龄含60–69、70+及低熟练用户；观察成功/失败/放弃，修阻塞问题 | 验证第一次能不能用，而不是一周宣称4周留存 |
| **6 留存观察与长期准备** | 再3个日历周 | 每周1题，真实家人收听/追问，不靠研究者催；正式长期存档前完成整族“音频+元数据”可携带导出和备份恢复试验（预留1–2开发日） | 可评估试用第4周留存；决定是否扩大、做年度书或换平台 |

开发合计约 **17–20个工作日**（不含首轮招募/试用、备案和公众号/平台审批），即约3–4周；首轮试用约1周，周留存必须再看3周。走E需额外1–3开发日接账号签名/转存与60秒分段；新域名备案常需数周日历等待。

**范围不变的降风险顺序**：先30题内部试用、少量家庭、单讲述人、一种录音实现；不是删掉隐私/权限来抢上线。200+题属于 PRD MVP，扩大前补齐；若用户希望正式MVP也只30题须明确同意。

**不在 MVP**：自动语音转写、年度书/PDF、金句卡、多位老人、家族合并、小程序、自动提醒、孙辈语音追问、章节连续播放、支付。整族导出虽不是核心娱乐功能，但长期保存真实家族内容前应完成，不能无限拖到“第二版”。

### 验证指标（试用第4周才看留存）

| 指标 | 定义与目标假设 |
|---|---|
| 长辈首次无帮助完成 | 能打开/同意/录下可听内容/发送成功，**含授权失败和放弃的全部受试者为分母**；目标≥80%，小样本报告实际人数，不做统计有效性的承诺 |
| 第4周仍有新回答的家族 | 第1周成功参与家族中，第4周仍新增ready回答，目标≥50%；代录与本人直录分开统计 |
| 获得然后呢的故事 | 至少有1名非讲述人成员反应的ready故事占比，目标≥50%；不把按钮点击当“听完” |
| 续讲完成 | 形成有效续讲请求的故事里，7天内新增续讲的比例，目标≥30%；不会用的家庭单独分析 |
| 成员真实收听 | 经同意只记最少的播放开始/到达尾部事件，不记录私密内容；技术事件不能证明注意力。配合问“你听到了哪段”访谈 |
| 关系体验 | 家人能复述一个以前不知道的故事、长辈是否觉得被认真听、不感到作业或被催；不靠数据替代这项判断 |

2–4个家庭是定性试用，阈值用于方向判断；不要以1个家庭坚持就宣称市场需求成立。

## 6. 主要风险

| 风险 | 应对 |
|---|---|
| 微信打不开、录不出或跨端不能播放 | 未备案/境外不等于必封；分别查网络/域名/微信权限/编码。0阶段真机筛查；失败家庭走A/C′。备案/资源批准不压缩进2天 |
| 授权、听写或文件选择难以理解 | 大字解释、一次主动作、明确失败状态；输入法话筒由用户操作；不引导长辈反复尝试复杂设置，家属帮助 |
| 邀请转发、冒充昵称、管理身份丢失 | 高熵链接+口令只能降低风险，不认证真人；老人权限有限；管理员独立恢复；撤销对应会话，明确已签URL残余期 |
| 子女三分钟热度 | 一周一题，主动听再问；更新话术不替代人工回来查看。不打卡、不做“你的孩子三天没来听”的压力提示 |
| 深度题触发痛苦 | 默认不随机、个人经历适配、可以悄悄跳过；可关闭整类。失亲/关系敏感时温柔题也可升深度 |
| 音频丢失或虚假“发好了” | 以实际本地/服务端状态展示；幂等补传、停止后释放资源、来电恢复试验；缓存不是备份，长期前导出与恢复演练 |
| 重复反应造成数据失真 | 一成员一票；并发唯一约束；计数不当播放人数，不做虚假“有人听完” |
| 家族长期资产依赖一个小产品 | 每段下载、长期前整族导出、备份地域/期限告知；停服有出口，不把免费等同永不失效 |

## 8. 内部评审与本地实施修订（2026-11-17）

用户已授权评审通过后直接开发，不再逐项等选择。本节覆盖旧文中的“仅方案/等待确认”及云平台前置限制；旧第0–7节保留为设计历史。

### 8.1 三视角结论：有条件通过

- **产品**：一族一位讲述人；抽题/自填→发送邀请→回答→家属收听→然后呢/文字追问→讲述人看到具体追问并续讲→故事墙串联。停止不代表同意分享，改为停止进入草稿、试听后“发给家人”。成功只表示服务器保存，不表示任何人已经听过。
- **录音**：首次先展示保存/分享范围，由用户同意，再在真实点击后申请系统麦克风。中断/到限只保留草稿，不自动上传。浏览器 MIME 检测不是播放保证；本地录音选择 Web Audio + AudioWorklet 采集 **16kHz单声道PCM WAV**，降低MP4/WebM容器与跨端播放复杂度；需要HTTPS或回环安全上下文以及实际麦克风许可，失败给文字/知情合法导入。
- **隐私**：Node TS + SQLite + 非public私有音频目录，同一服务真正共享。每次音频/Range/导出/删除均校验有效会话和故事归属；不发公开永久音频地址。邀请高熵随机串＋随机六位辅助码只准入listener，不恢复管理员；辅助码用随机盐scrypt慢哈希。撤成员会话，撤收听成员也使其持有的旧收听邀请失效；轮换老人链接撤老人全部会话。单独轮换普通邀请仅阻止后续新加入，不注销其他现有成员。

### 8.2 具体取舍

1. 栈固定：移动H5 + Vite + TypeScript + pnpm；仅pnpm-lock.yaml。Preact视图，Node TS开发服务，SQLite磁盘持久化；开发/测试/构建均用pnpm。
2. 本地前端优先127.0.0.1:5215，后端优先5216，Vite同源代理/api。回环HTTP用于本机内测，不支持宣传为公网/手机微信已可用；不创建公众号/云资源、不付费。
3. PCM录音分块写入IndexedDB；只显示实际保存状态，停止后组装WAV，试听可解码才允许确认发送。后台/麦克风轨道结束自动停止为草稿，继续需再次点击。清缓存或系统终止仍可能丢失最后未持久化片段。
4. 合法已有录音导入检查客户端可解码和服务端真实文件类型/时长/大小（20MiB、5分钟）；保留原容器，私有音频按实际MIME服务；播放失败提示更换WAV/MP3而不是假称全端可播。不读取普通微信聊天。
5. 上传意图有成员/家族范围的幂等标识与内容哈希，响应不明用同标识核查；未确认发送的草稿绝不自动传。原声存入私有目录，服务器重启后可读；不以各设备localStorage假装多人共享。
6. 续讲唯一性只限制**当前未答**父故事，回答后仍能产生新一轮真实追问；本次未呈现的新追问保留。反应一成员一票，不称为播放人数。
7. 本地会话HttpOnly/SameSite=Strict，写接口核验固定Origin，拒绝缺失/null Origin；接口同源、回环监听、访问范围服务端校验。凭据仅存哈希；本地HTTP非Secure例外、没有真人认证/远程运营加固，必须诚实披露。
8. 本人内容导出为包含元数据及原声base64的JSON档案；发起人可导出全族档案。本人可删除自己的内容，发起人可管理删除家族内容；listener不得删除他人。已下载/缓冲的副本无法撤回，本地机主仍能读取数据目录。
9. 先内置30条审核样题，不做210题扩写、年度书、收费、转写、公众号、小程序、推送；本次用户已批准本地内测范围收敛。

**复核中实际修正**：

- 六位辅助码改为随机盐scrypt，仅辅助持有高熵邀请的新收听成员；角色由服务端产生。独立256位管理恢复码一次使用并轮换，不靠昵称/加入码恢复权限。

- Vite源码服务也明确禁止访问`.local-data/`、`.test-data/`、测试目录、环境/证书文件；普通路径和`/@fs/`直读数据库均验收403。仅把音频放在非public目录还不够，不能让开发服务器绕过API鉴权。
- 音频GET/HEAD/单Range、导出、删除逐次服务端核验会话/家族/资源权限；不提供公开静态音频地址。不接受符号链接音频；数据目录700、SQLite及原声600。启动仅清理自身命名的孤文件，不删除陌生文件。
