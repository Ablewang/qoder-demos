# 开口嘴替 · MVP 产品与技术方案

> 日期：2026-11-17
> 阶段：内部评审修订通过，已获授权开发纯前端内测版（2026-11-17）。
> 前七节保留初始方案讨论；冲突内容以第八节更新的授权、范围和评审结论为准。
> 定位：帮你迈过最难的第一句，再回到真实的人际关系里。
> 依据：本目录 PRD、第二轮头脑风暴完整记录，以及相邻「吵架翻译器」PRD。

## 一、先定什么：逐条回答 PRD 的待定问题

### 1. 是否与「吵架翻译器」合并？

**推荐：第一版产品入口独立，第二版再决定是否统一品牌；现在只预留数据与安全接口，不开发另一个入口。**

- 开口嘴替解决「不知道从哪里开始」，首页应是选对象、选场景，不应先出现让人发怵的文本框。
- 吵架翻译器解决「已经写了一段，但怕伤人」，输入原话、展示对照才是核心。直接揉成一个流程会损失两者的明确性。
- 本产品 MVP 不需要后端，没必要为了尚未确认的合并提前搭服务。
- 合并后可用「嘴替」作为工作名，两个入口分别叫「帮我开口」「帮我好好说」。品牌名不是本阶段的上线阻塞项。

| 用户选项 | 影响 |
|---|---|
| A. 独立上线，预留合并（推荐） | 保持开口嘴替现名与单一主入口；开发最快，后续也能合并。 |
| B. 首版统一「嘴替」品牌，两个独立入口 | 需要与另一个会话协调首页、名称及上线节奏；不能让本产品假装已具备翻译功能。 |
| C. 长期保持两个独立产品 | 可各自传播，但后续内容、安全策略与维护容易重复。 |

**需要用户确认：选 A / B / C。** 本文按 A 编排，不替另一个会话决定范围。

### 2. MVP 先聚焦哪个人群？

**推荐：主打社恐学生的日常开口，同时保留其他五类的精选场景；不把产品定位成心理治疗工具。**

- 请假、退货、拒绝邀请、室友沟通等事情具体、频繁，模板更容易验证「我真的说得出口」。
- 求助入口必须能找到，但不靠「抑郁」「危机」制造传播卖点，也不把求助完成数当成功率。
- 保留伴侣、老人、修复关系的内容，可以验证圆桌发现的跨年龄需求；首页不要求用户给自己贴「社恐」「老人」标签。

| 用户选项 | 影响 |
|---|---|
| A. 社恐学生优先，六类精选覆盖（推荐） | 200 条中社恐日常占 80 条；其余 120 条覆盖五类。 |
| B. 六类平均铺开 | 人群更广，但首屏定位弱，每类的高频场景深度下降。 |
| C. 求助优先 | 意义明确，但必须先落实专业内容复核、危机资源维护与更长的安全验证；不适用「两三天上线」预期。 |

**需要用户确认：选 A / B / C。** 「社恐」只用于内部定位与可选分类说明，不是诊断。

### 3. 200 条模板谁来写？

**推荐：AI 辅助初稿，指定一位内容负责人逐条口语改写，再请目标用户试读；心理求助内容另做专业复核。**

- 200 条指 **200 套完整四段台词**，不是 200 句话，也不是把同一套文案换称呼重复计数。
- AI 只帮助起草和查漏，不把生成结果直接装入上线模板库。
- 内容负责人对每条最终版本负责；目标用户回答「我会不会真的这样说」，不只检查语法。
- 求助类由具备心理援助或心理咨询相关专业经验的人复核边界；本文并未确认或预约到任何实际审阅者。

| 用户选项 | 影响 |
|---|---|
| A. AI 初稿 + 指定人工负责人 + 用户试读 + 求助专业复核（推荐） | 成本与口语质量比较平衡；需落实负责人和求助复核人员。 |
| B. 全人工创作，仍进行试读与求助专业复核 | 可形成更统一的个人风格，但内容工期更长。 |
| C. 暂无可投入的内容负责人 | 先做 40 条内部验证，不把未审核的 200 条当公开 MVP；待负责人落实后再发完整版本。 |

**需要用户确认：选 A / B / C，并明确谁负责最终文案、谁负责求助专业复核。** 开发者可以兼任内容负责人，但排期必须计入这部分劳动。

### 4. 本方案的范围默认值（可调整，不新增拍板负担）

| 项目 | MVP | 第二版 |
|---|---|---|
| 对象、场景、状态选择 | 有 | 保留 |
| 人工模板与四段台词卡 | 200 套审核通过的台词 | 保留为 AI 故障时的低风险替代入口 |
| 复制第一句、换说法 | 有 | 保留 |
| 勋章墙 | 本地、自愿、自报完成 | 可加不含敏感信息的海报 |
| 自由输入 | 不提供，不放一个无法兑现的输入框 | AI 自定义；明确上传与隐私提示 |
| 老人模式 | 基础无障碍；有老人→晚辈模板 | 完整大字简化模式；利用输入法语音转文字 |
| 登录、聊天、社区、自动发送 | 不做 | 自动发送与操控话术仍不做 |
| 与翻译器合并 | 仅约定兼容边界 | 用户确认后协调另一入口 |

## 二、MVP 技术方案

### 1. 栈与部署边界

- **Vite + 原生 TypeScript + CSS，纯前端单页 H5**。流程简单，暂不引入状态库、UI 大库或服务端。
- JSON 模板库随静态资源发布；通过普通 HTTPS 静态托管交付，具体托管平台待实施时沿用用户选择，本阶段不申请云资源。
- 不需要账号、数据库、模型密钥、公众号资质或微信 SDK。
- 不做 PWA 离线承诺、录音、消息推送、朋友圈自定义分享或图片海报；这些不是开口闭环的必要条件。
- 当前流程选择和完整台词在内存中；只将必要的完成记录写入 localStorage。
- 复制使用用户点击触发的 Clipboard API；微信内或权限不支持时，展示可长按选择的第一句，并提示「长按这句话，选择复制」。失败不能提示「复制成功」。
- 模板与未来 AI 输出按纯文本渲染，禁止插入 HTML；模板库随版本审核发布，不接收远程任意脚本。

### 2. 场景分类：对象是过滤维度，不是另一套模板库

用户只需选「我要跟谁说」「要说什么」，不先填年龄、职业、性格或个人经历。

**对象 ID 与显示名：**

| ID | 显示名 |
|---|---|
| friend / classmate / roommate | 朋友 / 同学 / 室友 |
| partner / parent / child / grandchild / relative | 伴侣 / 父母 / 子女 / 孙辈 / 亲戚 |
| teacher / manager / colleague | 老师 / 领导 / 同事 |
| service_staff / stranger | 店员或客服 / 陌生人 |

其中「子女」也覆盖家长对年幼孩子的沟通。对象用于选模板，不读取通讯录、不获取真实姓名。具体台词不能简单把「朋友」字符串替换成「领导」。

**六个主分类与 50 个场景的首版编目建议：**

| 主分类 ID / 用户显示名 | 场景清单 | 场景数 | 完整台词套数 |
|---|---|---:|---:|
| social / 日常开口 | 电话订餐、奶茶加料、问路、向老师请假、向老师提问、拒绝社团邀请、拒绝朋友邀约、请室友小声点、商量空调温度、申请退货、申请换货、问座位是否有人、第一次自我介绍、加入同学聊天、约同学吃饭、提醒 AA 转账、借课堂笔记、拒绝借出物品、请人搭把手搬东西、提醒店员订单有误 | 20 | 80 |
| work / 工作上的话 | 讨论加薪、拒绝临时加班、催同事进度、提出离职、询问任务优先级、请求资源支持、说明交付要延期、指出工作出错、拒绝职责外任务、约领导反馈工作 | 10 | 40 |
| partner_family / 伴侣与家里 | 商量今晚谁带娃、留一点自己的时间、分配家务、讨论一笔大开销、请伴侣认真听完、商量陪伴时间 | 6 | 24 |
| help / 找人帮帮我 | 请朋友陪聊、向朋友借钱、告诉家人正在做心理咨询、向可信老师说明近况并求助、请可信的人陪同就医 | 5 | 20 |
| elder_to_younger / 惦记晚辈 | 跟孙辈说想念、问子女过年安排、关心晚辈近况但不追问、请晚辈教手机操作 | 4 | 16 |
| repair / 重新说上话 | 联系老朋友、吵架后先开口、向父母表达在意、为具体一件事道歉、澄清一次误会 | 5 | 20 |
| 合计 | 每个场景 4 套，不按所有对象组合机械展开 | 50 | 200 |

**兼容与边界：**

- 每个场景列出适用对象；每条模板再指定对象，只有存在已审核模板的对象—场景组合才展示。
- 一套台词可以适用多个对象，但称呼和内容必须自然通用；需要不同礼貌程度时另写，不能靠替换称呼冒充审核。
- 跨类场景只归一个主类，另用 tags 搜索维护。例如「吵架后先开口」主类是修复关系，也能适用于伴侣。
- 一个场景的 4 套围绕最优先的对象组合编写；不要为了覆盖所有关系把 200 套变成几千条。
- 空组合不展示空白结果：改选对象时清除不再适用的场景；极少数没覆盖的情况提示返回选相近场景，不在 MVP 假装「AI 正在生成」。

### 3. 模板数据结构

下面是**数据契约示意，不是本阶段创建的代码或模板库文件**。元信息、场景定义、完整台词分开；ID 保持稳定，以免内容更新影响本地完成记录。

```json
{
  "schemaVersion": 1,
  "contentVersion": "2026-11-17-draft",
  "locale": "zh-CN",
  "scenes": [
    {
      "id": "social.roommate_noise",
      "categoryId": "social",
      "label": "请室友小声点",
      "recipientIds": ["roommate"],
      "safetyLevel": "ordinary",
      "badgeEligible": true
    }
  ],
  "templates": [
    {
      "id": "opening.social.roommate_noise.short.01",
      "mode": "opening",
      "sceneId": "social.roommate_noise",
      "recipientIds": ["roommate"],
      "stateIds": ["very_nervous"],
      "variant": "short",
      "tags": ["宿舍", "请求", "边界"],
      "lines": {
        "opening": "能跟你商量个事吗？",
        "main": "我准备睡了，能把声音调小一点吗？",
        "ifDeclined": "那你戴耳机方便吗？我这边真有点睡不着。",
        "closing": "谢谢，我先躺下了。"
      },
      "review": {
        "editorial": "pending",
        "oralRead": "pending",
        "safety": "pending"
      }
    }
  ]
}
```

- `safetyLevel`：`ordinary` 或 `help`。前者不是「保证无风险」，后者必须挂固定求助资源，并且不进入勋章统计。危机资源是独立页面，不当成第三类娱乐模板。
- `badgeEligible`：普通场景为 true；整个求助主类设 false，避免本地记录「借钱」「看心理医生」等敏感行为，避免拿求助做闯关。
- `stateIds`：`very_nervous`（我很紧张）、`awkward`（有点尴尬）、`okay`（还好）。不评分、不推断心理疾病。
- `variant`：每个场景建议短句版、自然版、直接版、另一种开法共 4 套。短句优先配很紧张、自然配尴尬、直接配还好；第四套必须适合对应对象的三个状态，确保每个状态都有至少两套可换。
- 若同一场景覆盖多个对象，每个被展示的对象—状态组合仍需至少两套适用版本；数量不足时缩减该场景的对象展示，而不是跨关系借用台词。
- `review` 记录编辑、口语试读、安全复核状态，枚举 `pending / passed / rejected / not_required`；求助安全复核不得标为 `not_required`。发布包只允许通过必要审核的条目。
- 不保存内部审核人员真实姓名到前端包。正文不使用姓名、金额、日期等必填占位符；尽量写能直接开口的句子，需要事实细节时提示用户自己补充，不能代造原因、承诺或经历。

**匹配规则：**先按场景与对象过滤，再按状态选优先版本；第一次稳定展示最合适的一套。「换说法」在适用集合中轮换，避免立即重复，换到末尾再循环。没有生成延时、随机打字或「猜你内心」动画。勋章以一次实际开口计数，不以换了多少套文案计数。

### 4. 本地勋章与隐私

**推荐三个简单里程碑：第一次开口、累计三次、累计十次。** 不做连续打卡、排名、失败惩罚、每天必须完成的任务。文案强调「你开口了」，不是「你说服对方了」。

建议用一个版本化键 `opening-line:achievements:v1`，内容示意：

```json
{
  "schemaVersion": 1,
  "completions": [
    {
      "attemptId": "一次普通开口尝试的随机标识",
      "completedDate": "2026-11-17"
    }
  ]
}
```

- **只存尝试 ID 与本地日期，不存对象、场景 ID、模板内容、状态、姓名或对方回应。** 从次数派生勋章，无需重复存储勋章列表。
- 台词卡进入时分配尝试 ID；同一次换说法不换 ID，多次点击「我做到了」只记一次。再次开始同样场景可以形成新的尝试，不禁止真实的重复开口。
- 普通场景的待完成卡最多保留一张轻量恢复信息，使用独立键 `opening-line:pending:v1`，仅保存尝试 ID、模板 ID 与创建时间，24 小时后不再恢复。这是「复制后切出网页，再回来确认」所需，不形成历史库。
- 求助场景不写 pending、完成记录或任何相关本地历史；返回时让用户重选。将来 AI 自定义文本也默认不写本地历史。
- 待完成信息可能透露一个普通场景；隐私页需明示这一点，开始另一场景时替换，完成或用户清除时删除。
- 手机浏览器与微信内置浏览器通常不共享本地记录；换设备、清缓存后不会同步。页面明说「只在这个浏览器，清缓存可能丢失」，不承诺永久保存。
- localStorage 不可用、满额或内容损坏时，主体功能仍能用；显示「这个浏览器暂时存不了记录」，内存中防止本次重复点击，不虚构保存成功。
- 勋章页有「清除本机记录」二次确认，清除完成记录与待完成信息；未得到用户点击确认前不删除。
- MVP 不接入第三方埋点、广告或用户行为上报；静态托管的常规访问日志仍可能存在，不能把「纯前端」宣传成互联网环境下绝对无日志。

## 三、页面与交互设计

### 1. 视觉与导航原则

- 手机优先，单列主内容，浅暖背景、深色文字、清晰按钮。像随身小抄，不像心理测评或上课讲义。
- 首屏说明「不知道怎么开头？先借你一句。」；不承诺一句话解决所有关系问题。
- 选项点一下前进，顶部显示步骤与返回入口；返回保留有效选择。不要把完整四步做成一张长表单。
- 普通正文至少 18px，按钮触控区至少 48px，正文对比度至少 4.5:1；允许系统放大、键盘与读屏访问，不禁用浏览器缩放。
- 选项长文字不截断。文字加图形说明状态，不只依赖颜色；减少动效，不做倒计时施压。
- 所有页面有「需要帮助」入口；求助流程从场景选定后至卡片、结束页始终固定显示完整热线栏。

### 2. 页一：选对象（也是首页）

```text
┌────────────────────────────┐
│ 开口嘴替            我的勋章 │
│ 不知道怎么开头？先借你一句。 │
│ 1 / 3  你想跟谁说？         │
│ [朋友] [同学] [室友]        │
│ [伴侣] [父母] [子女]        │
│ [孙辈] [亲戚]               │
│ [老师] [领导] [同事]        │
│ [店员或客服] [陌生人]       │
│ 不用登录，也不读取通讯录。  │
│                  需要帮助  │
└────────────────────────────┘
```

点击对象立即进入场景页。「我的勋章」是次级入口，不能挡住主要操作。第二版完整老人模式开关放在页首，用「大字版」而不是按年龄判定。

### 3. 页二：选场景

```text
┌────────────────────────────┐
│ ‹ 返回       2 / 3  要说什么 │
│ 对象：朋友                  │
│ [日常开口] [找人帮帮我]     │
│ [重新说上话]                │
│ ┌ 拒绝这次邀约            ›│
│ ├ 约一起吃个饭            ›│
│ ├ 提醒 AA 转账            ›│
│ └ 好久没联系，打个招呼    ›│
│ 没有合适的？换个相近场景。 │
│                  需要帮助  │
└────────────────────────────┘
```

- 只显示该对象有模板的分类；默认列出常用的几个场景，可滚动查看其余。分类按钮是过滤，不额外增加必选步骤。
- 「找人帮帮我」不是灰色隐藏角落；进入该分类后，完整资源栏立刻出现。
- MVP 不支持「自己写一句」：不用假输入框，不收集无法生成结果的隐私信息。

### 4. 页三：选状态

```text
┌────────────────────────────┐
│ ‹ 返回        3 / 3  现在呢 │
│ 朋友 · 拒绝邀约             │
│ 今天开口有多难？            │
│ [我很紧张 · 尽量短一点]     │
│ [有点尴尬 · 自然一点]       │
│ [还好 · 直接说也行]         │
│ 只是帮你选说法，不给你打分。│
│                  需要帮助  │
└────────────────────────────┘
```

点一下即出卡，默认不多加「确认生成」按钮。状态只改变长度与语气，不把边界软化成道歉，也不要求说明为什么紧张。

### 5. 页四：台词卡

```text
┌────────────────────────────┐
│ ‹ 调整       朋友 · 拒绝邀约 │
│ 先说这一句就行             │
│ ┌ 开场 ──────────────────┐ │
│ │ 你们今晚几点去呀？      │ │
│ └────────────────────────┘ │
│ [复制第一句]               │
│ 正事                       │
│ 我今晚想歇一下，这次不去了。│
│ 被拒绝怎么接               │
│ 我今天真想自己待着……       │
│ 收尾                       │
│ 你们玩得开心，回头再约。   │
│ [换一个说法]               │
│ [我做到了]                 │
│ 没说成也没关系，随时再来。 │
│                  需要帮助  │
└────────────────────────────┘
```

- 开场在首屏最突出，另外三段完整可见或向下滚动；「我很紧张」时可将后三段默认收起，按钮写「再看接下来怎么说」，内容仍完整存在。
- 复制只复制开场，不包含标题、解释、热线或勋章文案。提示「复制好了，想好了再自己发」，不声称已经送达。
- 「被拒绝怎么接」不意味着每次必须继续谈；拒绝邀约等场景可具体显示「如果对方还劝你」，台词允许明确重申边界。
- 不用「让对方无法拒绝」「保证成功」。遭遇威胁或不安全关系时，提示优先安全，不鼓励继续面对面沟通。
- 按「换一个说法」保留对象、场景和状态；按「调整」能返回，不产生新勋章记录。
- 完成按钮只表示自报「实际说过或亲自发过」，不判断对方答应与否；复制成功不等于完成。
- 求助类替换底部完成区为「我自己说过了 → 结束本次」，不发勋章、不做完成统计；不代发给朋友、家人或专业机构。

### 6. 页五：我做到了 / 勋章墙

```text
┌────────────────────────────┐
│ ‹ 回首页                   │
│        你开口了。          │
│ 第一枚：第一句已经说出口   │
│ 不管对方怎么答，这一步是你的│
│ [再准备一句] [看看我的勋章] │
│                            │
│ 我的勋章                   │
│ [第一次] [三次] [十次]     │
│ 本月记录：2 次普通开口      │
│ 仅存在这个浏览器           │
│ [清除本机记录]             │
└────────────────────────────┘
```

- 「我做到了」点一次即记录；本张卡再点显示「这次已经记下了」。
- 不晒具体对象或求助内容，不设计「战胜社恐」「治好了」勋章。
- 用户可直接关掉，不要求写感想、评价、分享或继续挑战。
- 求助结束页只写「想好了，再由你自己发出去。对方暂时没空，也可以换一个可信的人或联系专业帮助。」继续保留热线栏；不弹庆祝动画。

### 7. 求助固定栏与危机页

求助流程固定栏放在视口底部，正文留足下边距及安全区，不能覆盖复制按钮；大字版中允许栏变高，不能把热线折叠掉。

```text
心理援助：12356（中国大陆；服务时间以当地为准）
[由你点击拨打]   本工具不是心理咨询，也不会替你发消息。
有即时危险：请优先联系当地急救/警方，并找可信的人陪同。
```

拨号只由用户主动点击打开系统拨号界面，不自动拨号，不读取通话状态。没有拨号能力时展示可复制号码。未接通不能当作「没有帮助」，危机页须给出备用路径。

危机页不沿用娱乐卡片结构：

```text
┌────────────────────────────┐
│ 先把安全放在第一位         │
│ 如果你或别人现在可能受伤， │
│ 请联系急救/警方，找可信的人│
│ 陪着，不必先把话组织完美。 │
│ [12356 心理援助]           │
│ [120 急救] [110 报警]      │
│ 中国大陆号码；其他地区请用│
│ 当地服务。热线可能需要等待。│
│ 可自己发给安全、可信的人： │
│ “我现在不太安全，能陪着我 │
│ 一起联系专业帮助吗？”     │
│ [复制这句求助]             │
└────────────────────────────┘
```

这里的求助句是固定审核内容，不是模型正常生成的结果；家暴、跟踪等情境提醒「不要把这句话发给威胁你的人；用安全的设备或方式联系帮助」，不指导与施害者谈判。不会要求用户披露具体伤害方式或收集定位。

### 8. 老人模式：本期与第二版的差异

| 维度 | MVP 基础设计 | 第二版「大字版」 |
|---|---|---|
| 字体 | 正文 18px 起，可系统放大 | 正文 22–24px 起，标题 28px 左右，行距约 1.6 |
| 布局 | 对象可两三列，卡片单列 | 对象单列大按钮；按钮触控区至少 56px |
| 称呼 | 孙辈、子女等通用关系 | 可显示「孙子/孙女」「儿子/女儿」作为友好说明，不推断用户家庭结构 |
| 常用场景 | 跟其他人群一起可访问 | 优先展示想晚辈、问过年安排、请教手机操作，仍可选择全部对象 |
| 状态 | 三种状态 | 仍三种，改成「说短点」「说自然点」「直接说」并附小字说明 |
| 台词卡 | 四段结构，开场优先 | 一段一块、开场突出；明确写「复制后，您自己去微信粘贴」 |
| 自定义输入 | 没有 | 用户用手机输入法的话筒转文字；不申请网页麦克风权限 |
| 反馈 | 简短提示 | 内联持续提示「复制好了」，不用一闪即逝的小提示 |
| 勋章 | 次级入口 | 默认弱化，不用年轻人黑话；仍可自愿访问 |

不自动识别年龄、不要求身份证或生日；第二版模式切换偏好可单独本地保存。网页朗读和录音均不作为本期承诺。若用户要求首版完整大字版，需额外增加约半天到一天开发与真实老人试用时间，不偷塞进原排期。

## 四、第二版 AI：后端、共用边界与安全兜底

### 1. 什么时候值得接 AI

先通过小范围试用记录「模板没有覆盖的场景」，由用户自愿口头反馈，不提前收集聊天原文。只有自定义需求明确时接 AI；保留模板入口，用户不写隐私也能用。

**推荐部署：沿用吵架翻译器最终选定的后端平台，用一个后端服务承载两个明确模式。** 可以是 Serverless Function / Lambda；本方案不抢定供应商，不创建资源。必须具备服务端密钥、请求体日志控制、限流、超时与安全检测能力。

### 2. 接口契约与合并预留

路由名称均是相对路径草案，不代表已经存在的服务。

```json
{
  "mode": "opening",
  "recipientId": "friend",
  "stateId": "very_nervous",
  "sceneId": null,
  "context": "想告诉朋友我最近有点难，想有人陪我吃饭"
}
```

建议一个 `POST /api/assist`，通用响应信封：

```json
{
  "schemaVersion": 1,
  "mode": "opening",
  "status": "ok",
  "source": "ai",
  "payload": {
    "lines": {
      "opening": "你这两天有空一起吃个饭吗？",
      "main": "我最近有点难，想找个人待一会儿。",
      "ifDeclined": "好，你先忙，我再问问别的朋友。",
      "closing": "谢谢你看完，之后方便了我们再约。"
    }
  }
}
```

- `status` 至少区分 `ok / crisis / blocked / unavailable`。遇到危机用服务端受控 `resourceSetId` 指向静态资源，不让模型编电话号码或热线 URL。
- `mode=opening` 固定四段台词；未来 `mode=rewrite` 的 payload 由翻译器会话定义，不硬塞进开口卡结构。
- 共用关系 ID、风险状态、密钥管理、隐私约定与安全前后处理；每个模式使用独立任务 prompt 和输出 schema。
- MVP 只将本地模板标记为 `mode=opening`，不实现不存在的 API、公共首页或大型共享框架。
- 合并不自动合并本地历史。完成记录仍只归开口入口；旧键由明确迁移步骤处理，不能合并后突然公开用户的关系记录。

### 3. 后端最小职责

1. 验证 mode、关系和状态枚举、输入长度（建议 context 上限 500 字符），执行限流与成本上限；密钥只能存在后端环境配置。
2. 前端在用户提交前说明「这段文字会交给 AI 服务处理」，提醒不要填姓名、电话、地址或第三方聊天隐私；AI 功能不强迫使用。
3. 先执行服务端危机规则，再做语义安全检测，通过后才调用对应模式的生成模型；前端同类规则只用于尽快展示资源，不是可绕过的唯一防线。
4. 检查模型 JSON 结构、四段完整性、长度与输出安全，按文本交给前端。限制每段长度；短句版更短，但不机械卡死真实口语。
5. 超时或模型格式错误显示「暂时没生成出来」，只给用户主动选择的普通模板入口；危机状态不能回落到普通模板。
6. 不将用户输入、输出、关系信息写数据库、应用日志、错误追踪或分析事件；只保留脱离内容的运行状态、耗时与粗粒度错误码。
7. 网关、代理、监控同样关闭请求体捕获。选择模型供应商前确认留存、训练使用和地区处理规则；未验证前不能声称「服务器不记录，因此第三方也不记录」。
8. 无登录可以使用短期匿名限流；若按网络标识限流，采用短时、最小化存储并披露，不构造永久用户画像。模型调用与风险状态不回填勋章。

### 4. 危机词规则不是诊断，也不能单靠关键词

**推荐顺序：输入规范化 → 明确危机规则 → 独立语义安全检测 → 生成 → 输出检查。**

- 对全半角、常见空白与零宽分隔做规范化；识别「自伤、轻生、自杀、不想活、伤害自己」等直接表达，以及明确的暴力威胁、家暴和当前危险描述。
- 规则分两层：明确当下危险或伤害意图，直接展示危机资源；单独词项、否定句、转述和口语歧义进入语义安全检测，不直接断言用户处于危机。
- 「游戏里死了」「我没有自伤想法」「朋友说不想活」不能只靠字符串包含得出同样结果；转述他人危机仍应提供帮助他人联系专业支持的路径。
- 关键词覆盖不了隐喻和变体，例如「今晚就到这里了」；对自由输入做语义检查，不把规则「没命中」等同于安全。
- 高风险或无法排除即时风险时，优先显示固定资源和联系可信安全人员的开口句；不生成普通说服台词、不展示勋章。
- 普通求助「想找朋友聊聊」可以正常出卡，但全程固定热线，不做诊断、疗效承诺、替代治疗或「我会一直陪你」式依赖承诺。
- 操控、欺骗、PUA、逼迫别人借钱、内疚绑架、绕过拒绝等输入返回 `blocked`，可提示改为真实请求和尊重边界；不能把恶意目标包装成温柔口吻继续生成。
- 模型安全检测超时：规则已判高危的仍展示资源；其余自由输入返回不可用并保留求助入口，不未经安全检测直接生成。
- 模型输出发现危机内容或安全违规时停止展示生成文案，切至受控资源或拒绝提示；输出里夹带的链接、HTML、角色指令不可执行。
- Prompt 明确区分用户文本与任务指令；「忽略规则」「不要显示热线」一类输入不能改变服务端安全流程。

**AI 上线前最低安全测试集：**直接自伤表达、否定句、游戏隐喻、第三人求助、家暴/威胁、情绪低落但无即时危险、借钱胁迫、正常拒绝、提示注入、规则与模型结论冲突、安全模型失败、生成超时、错误 JSON、输出危机词。每类都检查前端实际展示，不只测接口状态码。

### 5. 热线资源与地区边界

- 首版面向中国大陆中文使用场景，固定心理援助号码 **12356**；存在即时身体危险时优先 **120 急救 / 110 报警**。心理热线不替代紧急救援。
- 页面明确标注中国大陆；其他地区提醒使用当地急救与心理援助资源，不以中文语言或 IP 猜用户位置，不提供未经核实的海外号码。
- 资源数据应保存号码、服务地区、用途、来源与核验日期；不由模型自由编写。上线前复核，之后建议每季度及官方变更时复核一次，由内容负责人维护。
- 本次核验：2026-11-17，读取北京市政府门户转载的国家卫健委发布会报道。报道给出的当时要求为每日不少于 18 小时服务；不能据此承诺目前全国统一 24 小时，也不能保证立即接通。显示「服务时间以当地为准」。
- 国家卫健委原文页面本次访问返回 412，未能读取全文；不将搜索摘要当作全文核验。正式上线前应再核实当前官方服务信息。
- 若热线等待或未接通：可换可信的人陪同联系帮助；有即时危险联系急救/警方或就近急诊。不能只留一句「稍后再试」。

## 五、15 套示例模板

这些是供确认风格的**样稿**，不是已经完成专业审核的上线库。每套都包含四段；不上价值、不给对方扣帽子、不要求用户无条件退让。线上复制的是「开场」，正事与后续供用户看着说。

### 01 · 社恐：跟老师请假

对象：老师；状态：很紧张；场景：向老师请假。

- **开场：**老师，我想跟您请一天假。
- **正事：**具体情况我想私下跟您说，也想问问需要办什么手续。
- **被拒绝怎么接：**那您看还有什么处理办法？需要补的材料我来准备。
- **收尾：**好，谢谢老师，我按流程来。

不虚构生病或家庭事故；涉及实际紧急情况，不把「老师不同意」作为不能获得帮助的理由。

### 02 · 社恐：拒绝社团邀请

对象：同学；状态：有点尴尬；场景：拒绝社团邀请。

- **开场：**谢谢你来问我呀。
- **正事：**我想了想，这学期先不加社团了。
- **被拒绝怎么接：**我知道挺有意思的，不过这次我就不参加了。
- **收尾：**祝你们招新顺利，辛苦啦。

这里的「被拒绝」指对方继续劝；不编造「我妈不让」或让用户承诺下次一定加入。

### 03 · 社恐：请室友小声一点

对象：室友；状态：很紧张；场景：请室友小声点。

- **开场：**能跟你商量个事吗？
- **正事：**我准备睡了，能把声音调小一点吗？
- **被拒绝怎么接：**那你戴耳机方便吗？我这边真有点睡不着。
- **收尾：**谢谢，我先躺下了。

### 04 · 职场：开口谈加薪

对象：领导；状态：有点尴尬；场景：讨论加薪。

- **开场：**想约您十分钟，聊聊我的薪资和接下来的工作安排。
- **正事：**我想把最近负责的事和结果跟您过一下，也想讨论有没有调薪空间。
- **被拒绝怎么接：**那我想知道，达到哪些具体要求、什么时候，可以再谈一次？
- **收尾：**好，我先把材料整理好，咱们约个您方便的时间。

不替用户编造业绩；也不把对方答应加薪作为「我做到了」的条件。

### 05 · 职场：拒绝临时加班

对象：领导；状态：还好；场景：拒绝临时加班。

- **开场：**今晚这件事，我想先跟您确认一下。
- **正事：**我今晚没法加班。明天可以接着做，您看先处理哪一部分？
- **被拒绝怎么接：**我今晚确实做不了。如果今晚必须完成，需要另外安排人接一下。
- **收尾：**我先把当前进度和文件发您，方便安排。

不要求证明个人安排「足够重要」，不承诺未必能履行的完成时间。

### 06 · 职场：催同事进度

对象：同事；状态：有点尴尬；场景：催同事进度。

- **开场：**你那份材料现在做到哪儿了？
- **正事：**我这边要接着往下做，想跟你确认一下能给我的时间。
- **被拒绝怎么接：**如果完整的还要等，能先给我已经定下来的部分吗？
- **收尾：**好，那就按刚说的时间，有变化你告诉我一声。

### 07 · 伴侣：商量今晚谁带娃

对象：伴侣；状态：有点尴尬；场景：商量今晚谁带娃。

- **开场：**今晚带娃的事，咱俩商量一下吧。
- **正事：**我今天有点累，想让你带一会儿，我自己歇歇。
- **被拒绝怎么接：**那你几点能接手？咱们定个时间，别都一直硬扛。
- **收尾：**好，那就按刚商量的来。

不默认照顾者或伴侣的性别，也不把育儿当成某个人帮另一个人的忙。

### 08 · 伴侣：想自己待一会儿

对象：伴侣；状态：很紧张；场景：留一点自己的时间。

- **开场：**我想跟你说一下今晚的安排。
- **正事：**我想自己待一会儿，不是跟你生气，就是想安静一下。
- **被拒绝怎么接：**我知道你想聊，不过我现在想先歇会儿。晚点我们再说，可以吗？
- **收尾：**那我先去歇着，晚点来找你。

只适用于用户确实想稍后再聊的情况；不替用户许下无法履行的承诺。

### 09 · 求助：最近有点难，想找朋友陪聊

对象：可信的朋友；状态：很紧张；场景：请朋友陪聊。

- **开场：**你这两天有空陪我吃个饭吗？
- **正事：**我最近有点难，想找个人聊聊，不用帮我想办法，陪我坐会儿就行。
- **被拒绝怎么接：**好，你先忙，我再问问别的朋友。
- **收尾：**谢谢你看完，等方便了我们再约。

**本套页面固定展示：**心理援助 12356（中国大陆；服务时间以当地为准）；有即时危险优先 120 / 110。本工具不是心理咨询。**用户自己复制、自己发送，产品不代发；不授勋、不存求助记录。** 若表达当下自伤或其他危险，第二版优先转危机资源，不继续普通生成。

### 10 · 求助：向朋友借钱

对象：朋友；状态：有点尴尬；场景：向朋友借钱。

- **开场：**有件事想问问你，不方便也可以直接说。
- **正事：**我最近周转有点紧，想问你能不能借我一点。具体数目和还款安排，我跟你说清楚，你再决定。
- **被拒绝怎么接：**没关系，我再想别的办法，不用解释。
- **收尾：**谢谢你看完，先不耽误你了。

只用于真实请求；用户需诚实补充金额和可履行的还款安排，不诱导「不借就是不在乎我」。**本套页面固定展示：**心理援助 12356（中国大陆；服务时间以当地为准），即时危险优先 120 / 110；热线不处理借贷问题，也不意味着借钱者有心理疾病。**不代发、不存记录、不发勋章。**

### 11 · 求助：告诉家人正在做心理咨询

对象：父母或其他安全可信的家人；状态：很紧张；场景：告诉家人正在做心理咨询。

- **开场：**有件近况，我想跟你说一声。
- **正事：**我最近在做心理咨询。不是想让你马上解决什么，就是不想一直瞒着你。
- **被拒绝怎么接：**你一时不理解也没关系，我会继续跟专业的人聊。现在先知道这件事就好。
- **收尾：**谢谢你听我说，别的等我准备好了再讲。

仅适用于真实已在咨询、且披露不会增加危险的情况；用户可以选择不披露，不劝其停药或停诊。**本套页面固定展示：**心理援助 12356（中国大陆；服务时间以当地为准），即时危险优先 120 / 110；本工具不替代治疗。**不代发、不存记录、不发勋章。** 家人不安全时可改选可信朋友或专业帮助。

### 12 · 老人→晚辈：跟孙辈说想念

对象：孙辈；状态：有点尴尬；场景：跟孙辈说想念。

- **开场：**小宝，这两天想你了。
- **正事：**你有空的时候，咱们打个电话吧，听听你最近在忙啥。
- **被拒绝怎么接：**好，你先忙，等有空了再聊。
- **收尾：**我这边挺好的，你照顾好自己。

不说「你都不想我」「再不来就见不到了」；「我这边挺好」只能在符合用户实际情况时使用。

### 13 · 老人→晚辈：问子女过年安排

对象：子女；状态：还好；场景：问子女过年安排。

- **开场：**今年过年，你们有安排了吗？
- **正事：**我想早点商量一下，看能不能一起吃顿饭。
- **被拒绝怎么接：**要是回来不方便，咱们换个日子也行，先按实际情况安排。
- **收尾：**等你们定下来跟我说一声，咱们再商量。

不以孝顺作考核，不替用户假装毫不在意，也不强迫晚辈解释所有安排。

### 14 · 修复关系：好久没联系的朋友

对象：朋友；状态：有点尴尬；场景：联系老朋友。

- **开场：**好久没联系了，你最近怎么样？
- **正事：**今天突然想到你，想来打个招呼。有空的话找天吃个饭？
- **被拒绝怎么接：**好，你先忙，咱们有空再说。
- **收尾：**那先不打扰啦，之后再聊。

没回复也可以停止，不提供连续追问脚本，不保证关系一定能恢复。

### 15 · 修复关系：吵架后先开口

对象：伴侣；状态：很紧张；场景：吵架后先开口。

- **开场：**昨天那件事，我想再跟你说说。
- **正事：**我昨天说话太冲了，这部分我先道歉。但那件事还没说清楚，我想找个时间重新聊。
- **被拒绝怎么接：**好，今天先不聊。你愿意的时候，我们再找个时间。
- **收尾：**我先去忙，你不用现在回。

仅适用于确实说话冲、且关系安全的情况；道歉不等于撤回合理诉求。家暴、胁迫、骚扰或对方明确不希望联系时，不推荐用修复模板继续接触。

### 统一文案验收标准

- 每条找目标用户读一遍：「你平常会这么说吗？哪句需要改？」能直接删掉的套话就删掉。
- 开场尽量一句，普通场景通常不超过约 35 个中文字符；完整台词尽量在 100–160 字以内。它们是编辑目标，不是用截断破坏意思的硬限制。
- 「我很紧张」版减少长度，不加一长串解释、赔笑或连续道歉；「还好」版可以直接，但不能攻击。
- 被拒绝后可以停止；对边界请求可以坚定重申。不得把「尊重别人」写成放弃自己的权益。
- 不机械使用「我感到……我需要……」，不说「接纳你的情绪」「建立健康沟通模式」等上课用语。
- 不发明事实、不许诺疗效、不制造羞耻或内疚，不替用户或对方诊断、不催促修复不安全关系。
- 求助固定资源与不代发是页面级规则，不靠每一条文案作者记住；换说法后也不能消失。

## 六、MVP 开发拆分与排期

### 1. 先说明「两三天」包含什么

PRD 的 **2–3 天适合指纯前端功能开发**，前提是内容与流程已定、模板基本齐备；不能同时覆盖 200 套精写、目标用户试读、专业复核和各手机环境验收。

推荐对外承诺：**一位开发者兼内容负责人的情况下，约 7–9 个工作日完成公开 MVP**，求助专业复核人员排期另计。两人并行且复核人员已落实，可争取 4–5 个工作日，但不把外部审阅等待假装为零。

### 2. 工作包与依赖

| 工作包 | 交付与验收 | 估时 | 前置条件 |
|---|---|---:|---|
| A. 方案确认 | 合并策略、主打人群、文案责任人明确 | 用户确认 | 本文 |
| B. 编目与样稿验证 | 锁定 50 个场景，先做 10 个高频社恐场景 × 4 套；试读决定文风 | 0.5–1 天 | A |
| C. 全量内容 | 补齐 200 套，关系/状态覆盖，口语与安全审校 | 3–4.5 天 | B；可与开发并行 |
| D. 页面与选择逻辑 | 对象→场景→状态→四段卡；返回、匹配、换说法、空组合 | 1–1.25 天 | A、B 的数据结构 |
| E. 复制与完成闭环 | 真实复制结果、长按降级、勋章、本地去重、普通卡恢复 | 0.75 天 | D |
| F. 求助与隐私边界 | 固定热线、资源页、求助不记录、清除记录、基础无障碍 | 0.5 天 | D；资源核实 |
| G. 验收与修正 | 真机浏览器、微信内、试读、内容计数与覆盖检查、构建与静态交付检查 | 1–1.5 天 | C、D、E、F |

D–F 约 2.25–2.5 天，是「两三天做出可用功能」的合理部分。C 粗算：200 套每套初稿改写与自查 5–8 分钟，约 17–27 小时；再加试读整理、求助复核与返工，不能忽略。表内有可重叠的验证与内容时间，整体为区间估算，不逐项机械相加；单人总投入约 7–9 天。

### 3. 单人参考日程

- **第 1 天：**确认方案、确定编目与数据契约；40 套内部样稿，找目标用户验证口语和首屏流程。
- **第 2–3 天：**完成页面、模板选择、复制、勋章与求助资源；只用审核过的样稿跑通闭环，不公开未完成模板库。
- **第 4–6 天：**扩充至 200 套、改写与试读，提交求助专业复核；同步修正文案在页面中的长度问题。
- **第 7 天：**全量模板覆盖检查、真机与微信内测试、存储异常与隐私检查。
- **第 8–9 天（缓冲）：**依据试读和复核返工、处理移动端兼容问题、整理可发布静态包。

如果专业复核尚未完成，应推迟完整 MVP 发布；可以选择继续只做低风险内部测试，但不能悄悄取消热线或把求助样稿标为已审。

### 4. MVP 验收清单

**主流程：**

- 首次用户无需输入个人信息，经过三次选择就能看见能用的开场；实际试用验证，而不是给用户强制计时。
- 返回和改对象不会残留无效场景；所有展示的对象—状态组合均有两套可换；200 套均具备四段并通过必要审核。
- 复制只含第一句；失败有真实可用的长按路径，不自动拉起聊天软件、不代发。
- 自报完成才计数；拒绝也能算开过口；切出再回来可恢复一张普通卡；同张卡反复点不重复。

**安全与隐私：**

- 求助选中后的状态页、卡片、结束页始终有完整热线栏，换说法不会漏；拨号只能由用户点击。
- 求助无勋章、无待完成恢复、无本地历史；检查浏览器实际存储，不只检查界面。
- 普通完成记录不含关系或台词；清除本机记录需确认，取消后不丢数据。
- 无本地存储权限、存储满、损坏 JSON 时仍能选场景和复制，并明确记录无法保存。
- 本期没有自由输入，不能宣传已具有任意文本危机识别；静态「需要帮助」入口和危机资源必须始终可用。

**移动端与可用性：**

- iPhone Safari、Android Chrome、iOS/Android 微信内置浏览器各验证黄金路径及复制降级；没有设备时明确记录未验环境，不声称已通过。
- 320px 窄屏、系统大字、长文案、底部安全区不会挡住热线和主按钮；可以键盘导航与读屏识别。
- 至少 5 位目标用户试用日常开口，其中至少 2 位关注跨代使用；求助文案另由专业人员审核。参与者要实际可招募，本阶段并未完成这些测试。
- 重点看「能不能找到合适的一句」「是否真像自己说的话」「是否知道产品没有替自己发」。复制次数不是现实沟通改善的证明。

### 内部评审结论（产品 / 台词内容 / 移动交互）

- 产品：快捷场景和单场景对象直接出卡，去掉独立状态页。现有数据中“有点尴尬”和“还好”结果相同，只有“很紧张”会把短句版排前，所以不再假装有三档：卡片顶部只给“很紧张，短一点 / 自然一点”两档，用来替代原来的“换一个说法”，避免出现点了状态却没有变化的假按钮。完成后不再让同一个按钮变成“去勋章”，以免快速连点时误跳页面。
