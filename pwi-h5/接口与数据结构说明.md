## 1. 架构、版本与持久化职责

```text
调用方 await LocalBackend.request(method,path,body,options)
  → 单实例Promise队列
  → 参数校验 / requestId防重 / 内存revision预检
  → structuredClone(current state) → new Game(candidate)
  → domain执行 → validateSnapshot(candidate.state)
  → IndexedDB同一readwrite事务：requests防重 + saves/current CAS + meta
  → transaction.oncomplete → adopt已提交record → 返回ok/data/meta
失败：candidate丢弃，数据库事务abort，不更新backend内存、不扣费、不发奖
```

- `Game`仅管理domain状态、规则、日志与结算，不自行存localStorage或IndexedDB；`Game.export()`只是JSON序列化。直接调用Game/equipmentAction/productionAction/economyAction不能代替API提交。
- `IndexedStore`负责三store、读写事务和revision历史索引；`LocalBackend`负责迁移、串行、幂等、CAS、克隆执行、校验与统一响应。
- `equipmentAction`要求调用方克隆后提交；`economyAction`内部还克隆player，规则拒绝不会留下直接调用的部分经济修改。
- GET是本实例内存或脱离原状态的查询，返回structuredClone；不会提交存档、发奖或写审计，不生成装备UID、消耗随机数或初始化生产持久状态。经济查询在克隆上刷新本地日视图，不修改持久化日期。公开api.game getter也返回克隆Game（含message），不是已采用内存的可变引用；修改它不等于提交。
- 初始未建角色的运行态为`{version:2,player:null,journal:[],battle:null}`，可以bootstrap/state/backup/history/api/equipment/catalog；它不是可导入的角色快照。`validateSnapshot`要求player为对象。

源码：`src/core/game.js`、`src/core/api.js`、`src/core/storage.js`、`src/core/economy.js`。

## 2. 数据库：3个object store

默认数据库名`pwi-text-backend`，`DATABASE_VERSION=1`。可在open时传databaseName建立另一份本地数据库，但不构成多账号服务。来源/浏览器/设备不同则数据库不同；localhost端口变化也改变origin。

| store | keyPath / 索引 | 用途 / 实际字段 |
| --- | --- | --- |
| saves | id；无其他索引 | 当前角色唯一记录，id固定current；schemaVersion/revision/updatedAt/snapshot |
| requests | id；索引revision（非unique） | 每个成功command一条完整审计与防重复凭据；id/path/signature/data/revision/createdAt |
| meta | key；无其他索引 | schema版本信息；legacyMigration旧档原始备份 |

### 2.1 saves/current

| 字段 | 类型与实际约束 | 样例 |
| --- | --- | --- |
| id | string，写入固定current | `"current"` |
| schemaVersion | number，adopt要求严格等于2 | `2` |
| revision | safe integer，adopt要求≥1；成功新命令递增1，CAS比较当前revision；空库期望0 | `12` |
| updatedAt | ISO时间字符串，commit生成；adopt未单独验证它 | `"2026-11-18T06:00:00.000Z"` |
| snapshot | SnapshotV2，读取/提交均经validateSnapshot | 见第5节完整样例 |

record不是导入对象：导入的是record.snapshot，不能把id/revision等整条record当snapshot。每次仅覆盖current，不保存完整历史快照。

### 2.2 requests审计/防重复凭据

| 字段 | 类型与生成方式 | 样例 |
| --- | --- | --- |
| id | string，API requestId：1—100个ASCII字母/数字/下划线/连字符，`^[a-z0-9_-]{1,100}$`（不区分大小写匹配但字符串ID仍区分大小写） | `"mall-buy-001"` |
| path | string，成功POST路由；迁移特殊路径/migration | `"/v1/mall/buy"` |
| signature | string，JSON.stringify([path,canonical(body)])；对象键递归排序，数组顺序保留；options不在签名里 | `"[\"/v1/mall/buy\",{\"productId\":\"hp1\",\"quantity\":2}]"` |
| data | object，完整业务结果与message，不是只留摘要，也不是完整旧snapshot | `{"result":{"action":"shop.buy"},"message":"业务提示"}`（此处仅说明嵌套形状，实际订单/奖励不截短） |
| revision | number，此命令成功提交后的revision | `12` |
| createdAt | ISO时间字符串，commit时生成 | `"2026-11-18T06:00:00.000Z"` |

实际data总为`{result: domainReturn ?? null, message: candidate.message}`；经济/装备返回的完整订单、逐次开奖、奖励与装备实例都保留。普通Game命令大多result=null，battle/turn可能为null或win/lose/escape。失败命令无成功receipt；同ID同path/body重放不追加receipt、不重新随机、不扣费；同ID异参数拒绝。

requests没有100条上限、没有清理/删除API；商城orders和drawHistory各100条上限与此无关。迁移也是一条特殊receipt（id=`legacy-migration-v2`）。审计无失败日志store，无单条receipt查询路由；通过history分页读取，底层receipt方法主要用于幂等。

### 2.3 meta

```json
{"key":"schema","value":{"databaseVersion":1,"snapshotVersion":2}}
```

```json
{"key":"legacyMigration","value":{"source":"pwi-text-adventure-v1","original":"旧localStorage中的完整JSON原字符串","migratedAt":"2026-11-18T06:00:00.000Z"}}
```

`schema.value`为版本对象；`legacyMigration.value.source/original/migratedAt`均字符串，original保留原档而非转换后档。没有迁移时第二条不存在。schema每次新提交更新；迁移备份只在迁移事务参数存在时写入，不因日常保存删除。

来源：`src/core/storage.js`。

## 3. 调用、返回、幂等与CAS

### 3.1 生命周期与请求形式

```js
import { LocalBackend, ApiError } from './src/core/api.js';

const api = await LocalBackend.open();
// 可选：open({databaseName:'pwi-text-backend', legacyStorage:window.localStorage})
const bootstrap = await api.request('GET', '/v1/bootstrap');
try {
  const reply = await api.request('POST', '/v1/mall/buy',
    { productId: 'hp1', quantity: 2 },
    { requestId: 'mall-buy-001', expectedRevision: api.revision });
  // 仅reply成功后刷新视图/提示到账；此例需已创建角色且有6绑定元宝。
  console.log(reply.data, reply.meta);
} catch (error) {
  if (error instanceof ApiError) console.log(error.toJSON());
  else throw error;
}
api.close();
```

这是模块调用，不可直接用fetch/curl请求这些路径；没有HTTP监听、网络鉴权、token、cookie、远程用户、HTTP请求头或跨域服务。method严格使用`GET`或`POST`，没有PUT/PATCH/DELETE。

| request参数 | 类型 / 默认 / 校验 |
| --- | --- |
| method | string；GET查询或POST命令；未知method/path为NOT_FOUND |
| path | string；精确匹配第4节，无自动尾斜杠/查询字符串解析 |
| body | 普通对象，默认{}；不能数组；顶层未知字段拒绝；GET分页参数也放body对象而非URL查询串 |
| options.requestId | 可选string；缺省crypto.randomUUID()；仅POST使用；推荐调用方固定一个ID重试同一逻辑操作 |
| options.expectedRevision | 可选safe integer；缺省本实例revision；非整数或与内存revision不等，先拒绝；事务再与数据库current比较 |

接口字段标记`?`才可省略，省略=undefined；null不是省略。string最长1000 UTF-16码元（业务可再要求非空/枚举）；integer通用校验为安全整数0—10000000，业务会再要求1—99等；boolean严格true/false；nullableString为null或≤1000长度string；object为非数组对象。body外层原型仅Object.prototype或null；snapshot嵌套按schema处理。

**API与domain默认值不同**：economyAction默认quantity/count为1，但对应API字段没有`?`，请求中必须显式给出。equipment.socket可选index：新/固定省略选首null，没有空孔拒绝；显式index须0基、小于已开sockets.length且为空，不靠镶嵌造孔。仅legacy保留首null/末尾追加行为，index可等于length且小于limit，不准跨孔。

### 3.2 成功包装

```json
{"ok":true,"data":{"result":null,"message":"已保存到IndexedDB。"},"meta":{"version":2,"requestId":"save-001","revision":12,"duplicate":false}}
```

| 字段 | 含义 |
| --- | --- |
| ok | 成功严格true |
| data | GET为对应视图/快照/数组；POST为{result,message}，不是自动把新snapshot一起返回 |
| meta.version | 2（当前快照版），不是URL v1或数据库版本 |
| meta.requestId | POST使用的ID；GET为null |
| meta.revision | 当前backend采用的已提交revision，未建角色空库0 |
| meta.duplicate | 防重重放true；普通成功/GET为false |

同ID重放返回原receipt.data，但先adopt数据库最新current，因此meta.revision可以高于那条receipt.revision；要查操作发生的版本用history.rows中的revision。重放优先于expectedRevision检查，不以改options触发再次执行。省略与显式默认参数形成不同body签名；例如travel省teleport和teleport=false不是同一签名。

### 3.3 CAS与串行限制

单实例包括GET在内进入队列，一个拒绝不会卡住后续请求；双实例/标签的数据库CAS在同一三store事务中执行，无检查后写入空窗。事务oncomplete之前不adopt候选内存。

CAS拒绝后该实例内存仍旧。GET/state也读旧内存，不能承诺它会自动同步另一标签；应close再open或浏览器刷新，重新展示当前版本，并由用户决定是否用新ID发新的操作。不要更改body却复用原requestId；不要用改expectedRevision假装已同步。没有自动合并、BroadcastChannel、云同步、后台任务、离线收益。

随机数已经在候选中调用、但提交失败时奖励与消耗都丢弃；重试一个从未成功的ID会重新执行随机，而成功ID重放固定原结果。不能把本地审计理解为可验证随机公证。

来源：`src/core/api.js`、`src/core/storage.js`。

### 4.12 区域行走与靠近交战的UI契约

正式游历椭圆半径为18×15局部单位，原预览7.3×5.9，面积比约6.27；地标保留原比例。0.5单位网格A*、静态障碍包围盒与连续段碰撞用于真实根节点位移，手动方向归一化并支持碰撞滑动；高树冠/屋顶遮挡淡化仅影响渲染，不移除障碍。局部行走使用场景内的x/z坐标，不修改`player.location`、角色资源或快照结构。`player.location`仍是30个已有地区ID，跨地区旅行继续由原POST `/v1/world/travel`校验链接、等级、修真与费用；场景坐标不是官方坐标。方向行走、点地面、目标选择、停止和视野切换不发送POST，不产生存档revision或奖励。

- `getWorldMovement()`返回只读普通数据或null：`location/x/z/moving/enabled/overview/nearbyId/distance/targetId/available`。`distance`是到选中怪物的局部距离，未选目标为null，不是技能射程。`scene-movement`事件用于更新坐标、距离和按钮，不把Three对象交给后端。

## 5. 快照与player完整结构

### 5.1 基础类型与校验边界

下表`N`=有限非负number≤1e12，`I`=非负integer≤1e12；1e12低于MAX_SAFE_INTEGER。特殊字段再缩窄。string长度为JS UTF-16长度，不能一律等同中文“字数”。普通schema.string要求非空，表述“可空”的日志等按各自规则。

safeTree全树约束：嵌套深度≤20，每个数组≤1000项、对象≤1000键、string≤4000码元；所有数字0—Number.MAX_SAFE_INTEGER（因此NaN/Infinity/负数不允许；各字段N/I默认上限仍1e12）、其余仅boolean/null/array/object；禁止任何层字段名__proto__/prototype/constructor。它不是全字段白名单：大多数嵌套对象允许额外安全字段，字段语义仍以代码消费为准。

SnapshotV2={version:2,player:Player,journal:JournalEntry[],battle:Battle或null}。导入可version1，返回总为version2；journal≤60。根部返回仅保留这四个字段。未知顶层业务对象不是支持的新系统。

### 5.3 daily、任务、统计、奇遇与纪行

Encounter正常生成形状为`{id,zone,mob}`：id为merchant/chest/spring/beast/stele/child/taoist/bandit，zone必须等于player.location且为野外。schema只接受上述三个键；mob可省略，若存在则非空string≤100，不强制等于地图怪物名。domain生成时beast用当地精英名，其余用可选普通怪名。encounter可省略/null，旧v2缺字段仍有效，不补造未发生的奇遇；无DB升级或v2→新版本迁移。

十职业`hpCon/mpMag/accuracyDex/evasionDex`来自`ATTRIBUTE_SOURCE`指向的官方属性说明442—490行；武侠15/9/10/10、法师10/14/5/2、羽芒13/11/8/6、羽灵10/14/5/2、妖兽17/14/8/8、妖精12/12/7/6、刺客13/10/8/6、巫师10/14/5/2、剑灵15/9/10/10、魅灵10/14/8/6（完整表见玩法17.2）。暴击的DEX×0.0005支持每20敏捷1个百分点，但本作连续计算，不模拟端游整20取整；基础值、额外职业暴击、概率转换/上限、初始属性、等级成长、攻击/防御与评分公式仍本地。`STAT_ADAPTATION.hit/defense`分别说明rating换算及Def/Res/缺键回退边界。

关键公式及取整：STR/CON/DEX/MAG均含装备四维，G为装备＋有效套装，C为累计修真，B为本场增益；E仅逐件装备防御、S仅有效套装防御。公式及概率转换为本地规则，源系数范围如上。

```text
G = 穿戴每件equipStats之和 + 有效套装setStats
装备：新装base+grade固定refineGain+addons+gems；legacy/固定为百分比精炼基础（weapon双攻/armor双防/饰品非dodge）+addons+gems
0耐久：整件有效数值×0.5；不计套装；所有套装阈值累计
speed=clamp(1+Gspeed+Bspeed,1,3)
普攻击数=floor(speed)+Bernoulli(speed−floor(speed))，技能hits保持配置
HP=round((100+CON×职业hpCon+(lv−1)×职业hpLv+Ghp+Chp)×(1+GhpPct+Bhp))
MP=round(60+MAG×职业mpMag+(lv−1)×职业mpLv+Gmp+Cmp)
crit=clamp(0.03+DEX×0.0005+Gcrit+Ccrit+Bcrit+(羽芒/刺客?0.04:0),0,0.75)
accuracyRating=DEX×职业accuracyDex；evasionRating=DEX×职业evasionDex+GevasionRating
accuracy=clamp(1+accuracyRating×0.0001+Gaccuracy+Baccuracy,0.1,10)
dodge=evasion=clamp(0.02+evasionRating×0.00005+Gdodge+Bdodge,0,0.5)
命中=clamp(1−clamp(defender.evasion+额外闪避,0,0.9)/max(0.1,attacker.accuracy),0.1,1)
Edef=逐件有效装备def合计；EelemDef=逐件有该Def键则取该值，否则取该件mdef（0不回退）
SelemDef=有效套装有该Def键则取该值，否则取套装mdef；E不包含套装
物防=round((STR×1.2+CON×1.2+lv×2+Gdef)×(1+CdefPct+Bdef)+Edef×BequipmentDefPct)
法防=round((MAG×1.4+CON×0.8+lv×2+Gmdef)×(1+CmdefPct+Bmdef))
elemDef=round((MAG×1.4+CON×0.8+lv×2+EelemDef+SelemDef)×(1+CmdefPct+Bmdef)
              +BelemDef+(elem为earth?EearthDef×BequipmentEarthDefPct:0))
critDamage=clamp(2+G+B,1,5)
gap=clamp(attacker.attackLevel−defender.defenseLevel,−300,300)
等级倍率=gap>=0 ? 1+0.01gap : 1/(1−0.01gap)
有效防御=对应防御×(1−破甲合计夹至0.9)×(1−对应穿透夹至0.8)
有elem伤害再乘(1−对应Res夹至0.8)，无elem不查五抗
物理减免倍率=type为phys ? 1−clamp(defender.physicalReduction,0,0.8) : 1
combatDamage统一应用于普攻/技能/连击/反击/敌人/宠物攻受及对应物理DOT，不转法术或五防
猎魔倍率=非arena ? 1+attacker.huntLevel×0.001 : 1
气魄倍率=(1+attacker.spirit×0.0005)/(1+defender.spirit×0.0005)
创世倍率=1+attacker.creation×0.05
伤害=round(本击攻击×技能/潜行/暴击/装备双倍/随机倍率×100/(100+0.32有效防御)
           ×等级倍率×元素倍率×物理减免倍率×猎魔倍率×气魄倍率×创世倍率×目标破绽倍率)
目标破绽倍率=Monster.intent为exposed时1.5，否则1（DOT/宠物亦适用，不能重复乘）
实际伤害至少1、不超剩余HP；未命中0伤害且不附伤害技能状态
channel=clamp(G+B,0,0.75)
实际CD=原CD0时0，否则max(1,round(原CD×(1−channel)))；新CD当轮不减
hpRegen/mpRegen=max(0,round(1+G+B))，合法回合结束存活恢复且不超上限
```

区间优先固定attackRanges，否则具名ruleVersion2/历史ruleVersion1武器ranges。scale=refineScale×(durability===0?0.5:1)×(1+累计修真atkPct+buff.atk)，具名/固定refineScale=1+REFINE_BONUS[refine]，只有历史ruleVersion1为1。Min/Max=max(1,round(对应总攻击+(原端点−原区间均值)×scale))；总攻击已含四维/addons/宝石与精炼，新精炼仅平移均值，不重复扩大半宽。普攻/伤害技能每命中按attackBasis选key：phys→patk、magic→matk、未指定→atk，再从对应keyMin/Max抽样（相等时取key均值）；仍独立命中/暴击并叠[0.9,1.1)波动，自动expectedAttack也取该key均值，双倍特效用1.2期望。伤害type与攻击basis独立：magic有elem时查目标elemDef、缺失回退mdef（显式0不回退），无elem用mdef；phys用def，再按通道用对应穿透及Res。ar2以patk造成金伤；wz7以matk将基数等分火系magic/无元素phys，两分量分别减伤后求和，只在总和取整/夹剩余HP，共享当击命中/暴击/随机/破绽，不重复倍率；vm4直接wood、DOT取matk均值并存fire/magic。指定基础/通道来自所标源记录，倍率/概率/减伤/时序仍本地，不将真实区间退化成显示文字。

人物完整公式/38属性见总文17.3；现行具名词条见6.7，历史ruleVersion1池/预算及legacy兼容另见总文17.8，不能将历史池当新获取。历史套装2/4/5及12阶精炼见总文10.5—10.7，legacy重洗仍用无放回池。攻速不增加技能段数，吟唱不改变DOM计时/回合先后。

### 6.6 旧ruleVersion1规格与合法历史实例

本节公式仅描述gearSpec/makeEquip历史生成/校验，不驱动新创建、商店、掉落、任务、生产或活动。整节“新/当前/实际配方/副本奖励”均指旧ruleVersion1，旧系列链及获取覆盖已退出；当前见4.8、4.10、6.7。显式q0本地预算可用于具名运行适配，但须单列，不恢复旧工厂获取链。

### 6.7 ruleVersion2具名模板、实例与保存完整契约

NAMED_EQUIPMENT共675＝207来源原表＋468明确本作训练，包含referenceOnly（不等于675件可获取）。源169普通武器主要只有等级/需求，38神月保留属性/材料；未映射类型或>105记录只参考，不误映射拳套/利刃等。训练1及5—100每5级共21档：五护甲三类、披风/项链/腰饰/物法两戒/匕首/魂球全档，其他六武器仅1级。5高阶样本独立，不加入named工厂。

`namedSpec(templateId)`仅structuredClone精确模板，不RNG/UID/write。模板恒定字段完整为：`ruleVersion,kind,q,cls,setId,socketLimit,maxDurability,initialSockets,id,templateId,name,desc,slot,lv,grade,stars,nameColor,series,type,weaponType,armorType,attackType,classes,requirements,wear,sourceStats,sourceRecord,source,materials,base,ranges,affixes,addons,addonBudget,adaptedFields,runtimeAdaptation,status,referenceOnly,price,adaptation`。未知grade/stars/nameColor=null不补；训练源字段缺项保留null，sourceRecord/source=null。sourceRecord含原始名称/类型/等级/需求/基础/词条/材料及页面/表格/行号/sha256，与运行适配分列。

来源ordinary攻击缺失只使用精确源lv的q0本地预算单列base/ranges与runtimeAdaptation.values/ranges/note、adaptedFields，sourceStats不回填；q0仅旧记账，不乘属性/推色或随机星数。未支持词条原文/理由保留，不转移为其他stat。物理减免明确映射physicalReduction，只按combatDamage独立作用phys通道，上限0.8，含普攻/技能/连击/反击/敌人/宠物路径，不转五防或magic减免。

`makeNamedEquip(templateId,{origin?})`只允许origin非空≤80，拒绝referenceOnly。新增唯一uid、refine0、durability=max100、bound=false、sockets=[]、rerolls/upgrades0及affixRolls。每条supported affix（按源顺序）范围各独立掷一次，按precision取离散包含端点值；min=max直接存定值，不RNG。affixRolls保存每条结果（含定值），addons按stat求和至6位小数；不抽品质/不追加词条。此实例不是纯预览，成功获取/生产后完整保存，重开/回执重放不重掷。

`matchesNamedEquip`要求ruleVersion2/已知templateId/referenceOnly=false，模板除addons外每个字段必须存在并深度完全相同，null也须保留；只准额外mutable字段`uid,refine,sockets,bound,durability,rerolls,upgrades,origin,locked,affixRolls`。affixRolls长度恰好为supported词条数，每值有限/范围/精度合法，重建addons须完全相等。mutable仍受validateEquipment约束：rerolls/upgrades恒0、locked若有为boolean、合法UID/培养/孔及宝石部位品阶；grade=null必须refine0/sockets=[]且精炼/开孔/镶嵌/分解均拒绝。

schema先走具名校验，再高阶/历史分支；删ruleVersion/templateId、sourceRecord/affixes等恒定字段、删完后保留具名名称或元数据、越范围词条/改基础/改来源/多余键均拒绝，不降级legacy。合法v1迁移及无新字段legacy、合法ruleVersion1保存兼容，不重写为named；DB1/快照2与防重/CAS/整次事务失败不变。结构合法并不证明资源或装备自然获得，非远程防作弊。

### 7.4 Buff、日志与Pet

Buff={id:非空string≤100,name:非空string≤100,values:Record<BuffKey,number0—100>,turns:integer0—100或null,shield?:N,hot?:number0—1}。BuffKey=36个STAT_NAMES加atk/shield/lifesteal/regen/equipmentDefPct/equipmentEarthDefPct，共42键；允许键不代表模型逐键等效使用。values为比例或点数：atk/def/mdef/hp为指定比例，五Def为加法点数，五Res为减免比例，hpRegen/mpRegen为恢复点数。equipmentDefPct/equipmentEarthDefPct只追加有效装备物防/土Def，不加成裸属性、修真或套装。hot/regen是每回合生命比例；shield是剩余吸收点数，values.shield是施放系数，不能混淆；变身turns=null。

含任一装备防御百分比键的buff另受严格wz3校验：player.cls必须wizard、id='wz3'、已学wz3阶数R>0且0.1×R≤1，两键必须同时精确等0.1×R，turns为0—5整数，不得有buff.shield字段或values.shield键。新施放用5回合；源181装备物防/土防10%×R与CHI30已落实，源15分钟改回合，MP28/CD6/gain15仍本地。一般schema允许的旧有效吸收护盾快照（包括旧wz3）继续保留，不迁移；再次施放同ID会按新装备加成替换，不承诺旧护盾就是当前效果。

当前wz3第1阶生成示例：

```json
{"id":"wz3","name":"磐石护甲","values":{"equipmentDefPct":0.1,"equipmentEarthDefPct":0.1},"turns":5}
```

旧合法wz3护盾兼容片段仍可为`{"id":"wz3","name":"金石盾","values":{"shield":3},"turns":5,"shield":120}`；这里只展示保留旧形状，不作为新施放输出。

```json
{"id":"cl5:hot","name":"生生不息","values":{},"hot":0.08,"turns":4}
```

以上对应`src/data/high-equipment.js`、`src/core/combat.js`与`src/core/schema.js`的本轮高阶18/18组验收：攻防特效20%受控随机触发、合法回合到期、0耐久不触发、太清咒真实连击及破甲/buff的domain续存/schema校验均通过。equip:axe19a源获受限schema支持，太清咒连击使用独立turns2 buff；合法回合到期边界已覆盖。受控随机不是统计实测20%，domain续存/schema不代表所有装备buff逐个IndexedDB实际断点重开，也未验证高阶自动副本全程。

BattleLog={text:非空string≤1000,kind:system/damage/heal/victory/danger}，没有time字段；例`{"text":"战斗胜利！","kind":"victory"}`。与journal的text<1000/可空规则不同。

Pet必需name:非空string≤100、maxHp:N且>0、hp:N且≤maxHp、atk/def/mdef:N。可选五Def各number0—1e7，生成时为召唤角色对应五Def×0.6（不另round），旧缺分项防御时战斗退mdef。生成另有accuracy/attackLevel/defenseLevel/penetrationP/penetrationM/五Res/huntLevel/spirit/creation:number，继承召唤时player stats，arena时huntLevel=0；这些其他扩展字段schema只受safeTree，非逐键限1e7。宠物伤害沿用本作猎魔/气魄/创世倍率，历史缺省按0。没有长期UID、经验、品质、装备、忠诚度或存档外pet服务。

```json
{"name":"灵狐","hp":240,"maxHp":240,"atk":48,"def":24,"mdef":30,"accuracy":1.2,"attackLevel":3,"defenseLevel":2,"penetrationP":0,"penetrationM":0.08,"metalRes":0,"woodRes":0.1,"waterRes":0,"fireRes":0,"earthRes":0}
```

宠物每波重建，召唤当轮攻击，物理攻击用其accuracy与攻等/物穿。存活宠物优先承受敌人攻击，敌人该分支不额外做闪避/暴击，致死溢出不转给player。HP降0才能重新召唤。

### 7.5 回合/护符/耐久持久化

1. 结束/死亡/清场检查；校验动作和目标，不合法在候选写日志、不推进；API判定无效后丢弃候选并拒绝。
2. 记旧cooldowns、round+1、存活护符检查。
3. 合法startRound：HOT/regen→buff减时/过滤→盾同步；gear:*:guard的turns1在此移除，crit/speed的turns2减至1；DOT/非stun减时（包括equip:axe19a破甲）；清场可能直接win。非法行动不提前使装备效果到期。
4. 玩家行动→清场；宠物→清场；敌人逐个按intent行动，stun消耗真实行动机会并打断heavy；死亡时羽灵被动复生优先，否则lose；存活时完美格挡反击/元气+15，再护符检查。非终局后存活敌人重掷下回合intent，包括被stun跳过者；反击清场可win。
5. 旧CD减1；存活护符检查和hpRegen/mpRegen；胜利/撤退快捷路径也调用endRound。致命死亡不能靠护符复活。
6. Game结果结算每件穿戴durability−1（不是每回合）；上限夹取/发奖/战败资源处理；整个snapshot通过API事务写入。

护符charms.hp/mp为消耗储量：黄金护身符每枚600000生命、黄金守神符每枚900000真气，可在战斗外追加装填；当前HP≤战斗最大HP50%、MP≤战斗最大MP75%且人存活时，补`min(max−current,reserve)`并等量扣reserve。不直接治疗，没有自动向钱包收费。原版两符分别有10秒/5秒冷却；本作按上述回合检查点触发，明确不模拟秒冷却，也不折算为10/5回合。同一回合多个检查点可继续触发并扣储量，死亡不能靠护符复活。技能缺蓝先校验，不因后来预计触符而放行。

源码：`src/core/schema.js`、`src/core/combat.js`、`src/core/game.js`、`src/data/high-equipment.js`。

### 7.6 完美格挡、破绽与已到账BattleRewards

防御调息恢复`max(3,round(stats(p,b).mp×0.04))`真气并占行动。非heavy普通防御承伤×0.45；heavy未受磐龙甲guard时倍率2.4，防御的parry系数为`0.25/2.4`，所以同次基础伤害最终×0.25、免该击暴击，之后仍经护盾吸收。玩家闪避、宠物代受或敌人被眩晕时不走玩家完美格挡反击；死亡检查未终结才反击。

反击给元气15（上限300），基数**`stats(p,b).atk×0.7`**；使用职业atkType和enemyDefense，以及combatDamage的攻防等级/穿透/猎魔（非arena）/气魄/创世，最后hurtMonster取整至少1、不超剩余HP。不是0.75倍，不抽模板攻击区间、随机波动/暴击/装备双倍，也不是按敌人本次伤害反弹。exposed的1.5倍入伤同时用于玩家伤害技能/普攻与hurtMonster（DOT/宠物），敌人exposed输出0.6倍。磐龙甲guard取消后续heavy额外1.4倍，按普通倍率，不再使用旧每3回合1.5倍规则。

BattleRewards是普通field/dungeon胜利时的**结算摘要**，不是RewardDefinition/DeliveredReward，不包含完整Equipment或uid：

| 字段 | 类型 / schema约束 / 生成语义 |
| --- | --- |
| exp / sp / gold | 非负integer≤1e12；exp为本次实际经验（已含expBoost翻倍），sp/gold为怪物奖励合计；gold不包含满包装备自动折售额外收入 |
| loot | Array<{name:非空string≤80,q:integer0—4}>，最多10；生成装备摘要，包括最终波保底；可能因满包已自动折售，不表示全部入bag |
| items | Array<{id:已知ITEMS ID,qty:integer1—1e7}>，最多10；按结算前后持有数正差生成，包括首领/通关材料；不同于DeliveredReward的itemId/quantity |
| levelUps | 非负integer≤105；awardExp返回本次升了几级，不是当前lv |
| quest | null或{title:非空string≤100,done:integer0—1e7,total:integer0—1e7}，done≤total；优先本场匹配主线击杀，否则悬赏击杀，非全部任务、不含ready字段 |

rewards可省略或null；有对象时schema要求battle.result='win'，但不另外限制context或证明资源来源。domain仅普通野外/副本胜利生成，cult/arena继续原纪行摘要。旧v2胜利缺rewards仍合法，不能据旧日志补发。当前升级主线可能ready但rewards.quest=null；UI任务按钮检查实际questProgress，不只读此摘要。

```json
{"exp":40,"sp":22,"gold":21,"loot":[],"items":[],"levelUps":0,"quest":null}
```

这是battle.rewards片段，须配win战斗；不是完整快照，也不是本次新增样例运行通过记录。经验/元神/金币、掉落和升级已在Game.resolveBattle一次结算，随后snapshot与receipt由原API事务提交。没有新增rewards/claim路由；查看结算、GET、刷新、成功requestId重放不再发奖。battle/turn和battle/auto的result仍为null/win/lose/escape，奖励从snapshot.battle.rewards取得，不改原返回为奖励对象。

源码：`src/core/combat.js:384—448`、`src/core/game.js:378—421`、`src/core/schema.js:83—89、164—166`。探索/意图原验证11.6现为历史，当前限定回归见11.9，不把任何旧特效/意图通过转作新装备/地图证据。

## 8. 钱包、订单、开奖、events、cosmetics结构

### 8.1 Wallet、Mall与Order

Wallet={yuanbao:I,boundYuanbao:I}，上限均1e12，无负余额。经济模块检查gold/sp也为整数≤1e12。Mall={daily:{day:真实本地日期,counts:Record<CounterKey,I>},orders:Order[]}。

CounterKey只支持`shop:<66商品ID>`（计数≤product.dailyLimit）、`$wallet.daily`（≤1）、`$wallet.exchange`（≤100）；其他key在v2拒绝。每日换日清counts，但orders不清。单次quantity≤99，不等于每日兑换100上限。

| --- | --- | --- |

| productId | 已知SHOP_PRODUCTS ID | "hp1" |
| name | 非空string≤100；schema未要求恰等当前商品名，保留历史展示名称 | "金创药（10份）" |
| quantity | integer1—99，购买份数 | 2 |
| unitPrice | 必须=当前product.price | 3 |
| currency | 必须=当前product.currency | "boundYuanbao" |
| cost | 必须=unitPrice×quantity | 6 |
| rewards | DeliveredReward[]，1—100项，完整实际到账 | hp1×20 |

```json
{"id":"local-1794895200000-hp1-1","time":"2026-11-18T06:00:00.000Z","productId":"hp1","name":"金创药（10份）","quantity":2,"unitPrice":3,"currency":"boundYuanbao","cost":6,"rewards":[{"type":"item","itemId":"hp1","quantity":20,"name":"金创药"}]}
```

### 8.2 RewardDefinition与DeliveredReward

配置奖励和已到账奖励形状不同：

| type | 配置RewardDefinition | 已到账DeliveredReward / schema |
| --- | --- | --- |
| item | {type,itemId,quantity} | 加name；itemId已知，quantity正integer≤1e7 |
| equip（随机） | {type:'equip',slot,quality:0—3,quantity,level:'player'} | {type:'equip',quantity:1,equipment:完整Equipment,name} |
| equip（固定） | {type:'equip',templateId:已知ID,quantity:1}；无slot/quality/level，禁止混填 | 同样包含完整equipment（templateId/stage/q4/固定元数据/培养状态），用makeHighEquip而非makeEquip |
| cosmetic | {type,cosmeticId,quantity:1} | 首次同形并加name；ID已知，quantity必须1 |

### 8.5 Cosmetics与Charms

Cosmetics={owned:已知cosmeticId string[]，无重复；outfit/mount/flyer:已拥有且对应slot的ID或null}，只有7个定义，无自由上传、3D、坐骑属性、骑乘动画。flyer定义minLevel30，佩戴后player.flight=true；卸下不设false；schema不比较flight与当前槽位，因此合法卸下后flight仍true。

```json
{"owned":["outfitCloud","mountDeer","flyerKite"],"outfit":"outfitCloud","mount":"mountDeer","flyer":null}
```

Charms={hp:I,mp:I}是永久剩余储量：例`{"hp":600000,"mp":900000}`；CHARM_CONFIG={charmHp:{slot:'hp',charge:600000,minLevel:1},charmMp:{slot:'mp',charge:900000,minLevel:1}}。charmHp=黄金护身符，charmMp=黄金守神符，配置charge逐项等于ITEMS.value。装填count枚的返回charge=count×对应配置charge，reserve为追加后的总剩余量，真实消耗items；触发阈值HP≤50%/MP≤75%，恢复真实扣储量。本作按回合检查，不模拟原版10秒/5秒冷却（见7.5）；无脱卸退回物品/退款API。

容量：bag80；items每ID≤1e7；钱包≤1e12；orders100；drawHistory100；里程碑永久认领独立于裁剪。含装备池最坏每次1格（鸿运/两箱），count批预留count格；不足整批拒绝，不自动折售传奇；两粽无装备可满包开，仍受钱包/材料上限。重复外观补120绑定也受钱包上限，任何后续失败整批回滚。

来源：`src/core/schema.js`、`src/core/economy.js`、`src/data/economy.js`、`src/data/high-equipment.js`。

### 9.1 审计分页

`GET /v1/history`默认limit100，只允许1—100。beforeRevision可省，若传须通用integer0—1e7；不能传null（它不是integer?省略）。按revision降序，下一页严格revision<beforeRevision，无offset页码。rows达到limit时nextBeforeRevision=末条revision，否则null；恰好满页但已没有后续时仍给游标，下一页空后为null。

```js
const first = await api.request('GET', '/v1/history', {limit:20});
const cursor = first.data.nextBeforeRevision;
if (cursor !== null) {
  const next = await api.request('GET', '/v1/history', {limit:20,beforeRevision:cursor});
}
```

返回`{ok:true,data:{rows:RequestReceipt[],nextBeforeRevision:number或null},meta}`。审计长期revision可增长，但分页beforeRevision接口有1e7通用上限，当前没有为极长存档扩展该范围；这是现实现限制，非无限历史分页承诺。orders与drawHistory查询直接返回最近100，不支持独立分页。

### 9.2 导出/导入与断点战斗

```js
const exported = await api.request('GET', '/v1/save/export');
// 调用方可JSON.stringify(exported.data)下载，API本身不弹文件对话框。
await api.request('POST', '/v1/save/import',
  {snapshot:exported.data,confirm:true}, {requestId:'import-001'});
```

导入要求无进行中战斗。API没有文件名/文件扩展/1MB字节限制，UI原文件读取约束不能代替schema。支持v1/v2对象，v1规范化为v2。重新open读取已提交battle：若result=null可继续turn；若dungeon小怪波result=win可next；leave后battle清空不能续。刷新不退次数、不重掷已成功开奖；UI自动计时/弹窗/选中目标不存。

## 10. 错误、失败恢复与迁移

### 10.1 ApiError契约

request失败是Promise reject，抛ApiError，**不是resolve一个ok:false对象**。调用方catch后toJSON取得统一错误：

```json
{"ok":false,"error":{"code":"REVISION_CONFLICT","message":"存档已被其他标签页更新，请刷新后重试；本次操作未扣费。","status":409}}
```

ApiError字段name='ApiError'、code:string、message:string、status:number，toJSON无data/meta。status是本地错误语义，不代表实际HTTP响应码。错误包装位于request队列内部；LocalBackend.open的存储打开错误可能直接为StorageError，调用方生命周期也必须catch，不能保证open一律ApiError。

| code | 典型status | 真实来源 / 行为 |
| --- | ---: | --- |
| NOT_FOUND | 404 | 未知路径或非GET/POST命令 |
| INVALID_BODY | 400 | body不是普通对象 |
| INVALID_FIELD | 400 | 未知字段、缺必填、错误类型/通用范围；history limit不在1—100 |
| INVALID_REQUEST_ID | 400 | requestId格式或长度非法 |
| CONFIRM_REQUIRED | 400 | 创建替换、导入或sell-common未确认；扩展bind/decompose/craft/ascend/transfer及produce的confirm=false由RULE_REJECTED表示，缺字段/类型错误仍走参数校验 |
| NO_CHARACTER | 400 | 未创建角色访问受限路由 |
| REQUEST_ID_REUSED | 通常409 | API receipt预检查同ID异签名明确409；事务内并发才发现的StorageError经errorOf默认400，不能声称所有分支都是409 |
| REVISION_CONFLICT | 409 | 内存expectedRevision或事务CAS失配，失败不扣费 |
| INVALID_RECORD | 400 | adopt存档schemaVersion/revision元信息无效；open捕获为loadError时不走request错误响应 |
| INVALID_ACTION | 400 | battle/turn或战斗内items/use：候选回合未变且无result，取候选战斗日志原因并拒绝，不提交 |
| RULE_REJECTED | 400 | domain或validateSnapshot普通Error：等级/资源/日期/结构/容量等；battle/auto无战斗或无效自动行动 |
| STORAGE_UNAVAILABLE | 503（request映射；open原错误） | 不支持IndexedDB或打不开，拒绝，无localStorage降级 |
| STORAGE_BLOCKED | 503（同上） | 数据库升级被其他标签阻挡 |
| STORAGE_CLOSED | 503 | close后读写或连接失效；history交易创建原生异常可能未编码而落RULE_REJECTED |
| STORAGE_READ_FAILED | 503 | readonly事务abort |
| STORAGE_WRITE_FAILED | 503 | readwrite事务abort，无成功写入/扣费/内存采用 |

errorOf保留现有ApiError；其他异常用e.code或RULE_REJECTED，STORAGE开头503，REVISION_CONFLICT409，其余默认400。业务错误不是每种都有独立等级/金币/背包code，不杜撰API未实现的错误枚举。

### 10.2 一次性旧localStorage迁移

1. `IndexedStore.open`创建/打开数据库三个store；优先读saves/current。存在record就尝试adopt，不再读旧键；revision在校验前记录。
2. current元信息/快照无效时，open返回backend但设置loadError、rawBackup=current.snapshot，不删除record。GET/bootstrap给出loadError；GET/backup可导出原对象。不要以空角色页面理解为原档已删除。
3. 空current才读取legacyStorage.getItem('pwi-text-adventure-v1')。无字符串则保持未建角色；读取受限返回提示，不伪造新角色。
4. 有旧字符串：rawBackup保存原字符串→JSON.parse→validateSnapshot。v1必须核心player本身合法，补装备扩展/经济缺字段与daily.arena0，battle=null；journal筛选/修整至60条，kind规范化，输出v2。
5. commit(snapshot,expectedRevision0,operation={id:'legacy-migration-v2',path:'/migration',signature,data:{message:'旧存档已迁移。'}},migration={source,original,migratedAt})。三store原子写record/receipt/schema/legacyMigration。
6. 成功adopt；原localStorage始终不删。重开已有current优先，不重复发300初始元宝、不重置已有经济字段、不重复迁移。ensure函数仅补缺字段，已有错误结构不静默修复。
7. 双标签迁移CAS冲突时读取已成功current并adopt；其他失败设置loadError并保留原字符串，数据库事务不留半条备份/receipt。

GET/backup优先rawBackup，再meta.legacyMigration.value.original，最后game.state。可能是JSON字符串或对象，调用方须辨别：旧字符串需要外部保留原文，修正后parse才可import；坏rawBackup并不因此变有效。新open已成功current而rawBackup为空时仍可取迁移original。

### 10.3 恢复与明确不支持的能力

- 先用backup保存原始数据或export保存有效快照，再处理坏数据；无自动清库、自动重建或删除旧档行为。
- 有效备份经显式import与confirm事务替换；若正在战斗先结束/撤退。重建已有正常角色必须confirm=true。
- 写入abort不改已采用内存；解除存储限制/关闭阻挡标签并重新open。不要把失败的candidate截图当已到账。
- 不支持历史revision完整快照回滚、按审计逆向恢复余额、物品邮寄补发、远程客服找回、跨设备自动同步；requests里的data不是每版snapshot。
- 导入只做结构/关联校验，不校验真实资产来源，单机允许导入后重新玩；不要用于真钱权益或排行榜。
- 浏览器清数据/无痕关闭/换origin可丢库，只有玩家自行导出备份。无后台服务器保底、服务器日期、远程账户。
