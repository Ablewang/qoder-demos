文档核对日期：2026-11-17。

这是从原始 [3a.html](3a.html) 逆向拆分的第一人称射击体验，使用 Vite、TypeScript 和 Three.js。基础玩法和数值保留原实现；按后续需求新增 IndexedDB 本地玩家档案、设置保存和历史战绩，这部分及其菜单入口不是原 HTML 的既有功能。另新增 `server/` 局域网联机服务：2–4 人进同一房间，由房主统一出击，互相看到程序化关节士兵队友及其动作；敌人、战斗与任务进度仍在各自设备本地运行。原 HTML 是纯单人游戏。

## 快速运行

在本项目目录执行：

```bash
pnpm install --frozen-lockfile
pnpm dev
```

以终端输出的地址为准。需要使用本次开发时的端口：

```bash
pnpm dev --port 5181 --strictPort
```

检查和构建：

```bash
pnpm typecheck
pnpm build
pnpm preview --port 5182 --strictPort
```

生产产物输出到 `dist/`，需通过 HTTP 服务打开，不能直接双击 HTML 代替运行。

### 局域网联机（新增）

一台电脑当主机，执行：

```bash
pnpm lan
```

它会先构建，再在端口 4207 启动联机服务，同时提供游戏页面。终端会打印 `http://192.168.x.x:4207` 这类局域网地址；同一 Wi-Fi 下的电脑和手机打开这个地址即可。

1. 一人在“局域网联机”中创建房间，成为房主；其他人输入 4 位房间号加入。
2. 非房主点“准备”（可取消）；房主无需准备，等其他成员全部准备后点“全员出击”。标题/暂停房间条也可操作。
3. 全队倒计时 3 秒后自动开始任务，无须各自点“开始行动”；电脑端首次点击再请求鼠标锁定，触屏照常操作。

入房后，原开始/重试按钮也改为房主出击或队员准备；离房后恢复单人操作。房主可二次确认移出队员或移交房主；房主离开后由剩余最低槽位队员继任，并清除继任者的准备状态。详见 [联机玩法](GAMEPLAY.md#新增局域网联机)。

- 端口被占用时换一个：`PORT=4300 pnpm lan`。
- 边改代码边联机：一个终端运行 `pnpm dev:server`，另一个运行 `pnpm dev`；Vite 会把 `/ws` 转发到 4207（用 `LAN_PORT` 修改）。
- 服务没有启动时，单人游戏照常运行，只是联机面板会显示连接失败。
- 首次运行时操作系统可能询问是否允许 Node 接受网络连接，需要允许才能被其他设备访问。

## 一分钟了解玩法

1. 点击“开始行动”，进入几猫港区四号泊位。
2. 寻找堆场 A、仓库 B、码头 C 三处中继，靠近并按住交互约 2.4 秒；顺序不限。
3. 使用唯一的“几猫九式突击步枪”应对机械飞鸥和机械猎犬。每切断一处中继都会引来增援。
4. 三处全部切断后，前往南端撤离艇；进入撤离范围自动完成，无须消灭所有敌人。
5. 生命降到 0 失败；超过 4 秒不受伤会自动回血。重试会重新开始整个任务。

PC 使用 WASD、鼠标左右键、R、E、Space、Shift、C/Ctrl、Esc/P。触屏使用左侧动态摇杆、右侧拖动视角和屏幕按钮。

## 版本与重要说明

- 包管理器：pnpm 12.4.2；仅授权 `esbuild` 的依赖构建脚本。
- 锁定版本：Three.js / @types/three 0.180.0、TypeScript 5.9.3、Vite 7.3.8。
- 原页面包含“Fable5.2”“3A大作”等展示文案；它们不是实际引擎或品质认证。当前可核对的技术实现是 Three.js / WebGL 和 Web Audio。
- 菜单虽列出近战按键，但正常游戏没有对应玩家近战攻击实现；Q 的备用动作也未被玩法消费。
- [本地用户数据](DEVELOPMENT.md#12-本地用户数据indexeddb)保存在 IndexedDB：稳定用户 ID、可修改昵称、玩家设置、累计统计和历史战绩。标题、暂停、死亡和结算菜单均可打开“玩家档案”。
- 首次使用自动迁移旧 localStorage 设置；不保存未完成任务现场，没有登录、云同步、补给拾取、换枪或升级系统。
- [局域网联机](DEVELOPMENT.md#13-局域网联机服务)是新增功能，协议 v2 支持房主、准备与全员倒计时出击，并同步队友位置、朝向、姿态和开火标记，使用无外部资源的程序化关节士兵模型；敌人、射击判定、伤害、生命和中继进度仍各端独立，不是真正共享战斗，也没有公网匹配或账号。
- 运行联机服务需要 Node.js 22.18 或更高版本（直接运行 `.ts`，不需编译服务端）。
- 关键数据均从现有源码核对。文档中的攻略是建议，文档中的规则和数值才是当前实现。
- 数值、参数、运行方式发生变化时，应同步更新这两份参考文档；模型顶点、完整着色器和程序化生成算法以链接的源码为准。
